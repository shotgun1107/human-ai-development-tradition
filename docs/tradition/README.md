# 인간–AI 공동 개발 전통

이 디렉터리는 인간과 AI가 실제 개발·외주·공모전에서 얻은 경험을 모델 밖에 보존하고, 세션과 모델 세대가 바뀌어도 다음 AI가 이어받게 하는 공동 작업 전통을 연구·기획한다. 주된 목적은 사용자의 개인 성장 기록이 아니라, **AI 측 운영 능력이 반복 실수를 줄이고 검증된 작업방식을 계승하도록 만드는 것**이다.

여기서 **전통(tradition)**은 오래 보관한 기록이나 고정 교리가 아니다. 출처·맥락·반례·적용 결과·버전이 연결되고, 다음 작업에서 다시 시험되며, 틀리면 수정·축소·폐기할 수 있는 계승 가능한 작업 기억이다. 초기 목표는 모델 파인튜닝이 아니라 외부 기억·Skill·테스트를 통해 여러 AI 세대 사이의 운영 연속성을 만드는 것이다.

목적과 가치 판단의 기준은 [목적과 철학 헌장](./purpose-and-philosophy.md)에 둔다. 인간은 최종 승인과 외부 책임을 가지지만, 이는 체계를 인간 교육용으로 축소하기 위한 것이 아니라 AI의 잘못된 자기강화를 막고 계승 효과를 검증하기 위한 경계다.

> **현재 작업 방향 — 중앙 시스템 v2**  
> 이 프로젝트를 프로젝트마다 복사하는 작은 도구가 아니라, 여러 프로젝트·AI·작업 결과를 연결하고 다음 작업에 필요한 경험과 작업 자산을 돌려주는 **하나의 중앙 시스템**으로 기획·설계한다. 두 독립 설계의 통합, 독립 외부 심사, v2.1 제한 수정과 재심사를 완료했고 현재 v2.1은 `S0 합성 논리 선행조건 시험 준비 가능` 판정을 받았다. 이전 `candidate-system-design-v1.md`는 전체 제품의 최종 설계가 아니며, 향후 중앙 시스템 안의 행동 규칙 관리 하위 구성요소로 재평가할 참고안이다. 아직 구현·실제 자료·Project Brain 연결 단계는 아니다.

## 한 페이지 개요

```text
사실·사건
  ↓ 출처 보존, 비밀 제거, 사실/해석 분리
검증된 경험
  ↓ 재현·삼각검증·반례 탐색
교훈 후보
  ↓ 월간 사람 심사
프로젝트 교리 ── 반복성과 전이성 입증 ──→ 개인 범용 교리
  ↓
체크리스트·프롬프트·테스트·템플릿
  ↓ 다음 프로젝트에서 적용 여부와 버전 기록
효과 측정
  ↓ 유지 / 수정 / 범위 축소 / 강등 / 폐기
새 판본
```

핵심 안전장치는 다음과 같다.

- 사건, 성공, 실험, 결정, 근접 실패, 반례를 모두 수집하되 곧바로 교리로 승격하지 않는다.
- `확인된 사실`, `분석자의 추론`, `향후 제안`을 레코드와 문서에서 분리한다.
- 교훈은 적용 조건, 금지 조건, 반례, 출처, 증거 등급, 소유자, 재검토일을 가져야 한다.
- 개인 범용 교리는 서로 다른 프로젝트·상황에서의 반복 근거가 없으면 만들지 않는다.
- 새 규칙은 먼저 가역적인 프로젝트 실험으로 적용하고, baseline 또는 비교군과 효과를 비교한다.
- 생성형 AI가 작성한 요약·분류·점수는 사람 승인 전까지 효력이 없다.
- 원본의 비밀·개인정보는 전통 저장소에 복제하지 않고, 필요한 경우 비식별 요약과 접근 제한된 포인터만 둔다.
- 교리가 오래됐거나 반례가 생기면 조용히 덮어쓰지 않고 상태와 대체 관계를 남긴다.

## 원천 오케스트레이터 저장소와의 관계

이 전통 연구는 오케스트레이터 저장소와 분리된 독립 프로젝트다. 원천 저장소의 `tools/implementation-log/`와 `docs/operations/implementation-incidents/`는 **개발 incident 사건 계층**이다. JSON 원본, 재현 절차, 증거 종류, 근본 원인, 검토 대안, 회귀시험, 검증, 남은 위험, 결정적 Markdown 렌더링은 좋은 기반이지만 이 하네스를 범용 전통 저장소로 억지로 확장하지 않는다.

원천 저장소의 `docs/operations/codex-revision-log.md`는 시간순 작업·검증 일지이자 과거 문서 판본의 근거가 될 수 있다. 그러나 단일 장문 로그이므로 검색 단위, 교훈 상태, 반례, 적용 결과, 효력 있는 최신 판본을 스스로 표현하지 못한다. 전통 프로젝트는 향후 승인된 비식별 입력 묶음이나 제한된 참조로만 이 자료를 사용하며, 자동 복제하거나 원천 형식을 바꾸지 않는다.

현재 확인된 사실은 B1 순차 실행 구성요소와 실제 smoke가 완료됐지만, 범용 오케스트레이터 전체는 아직 구축·테스트 단계이고 B0/B1 반복 비교도 남아 있다는 것이다. 개발 incident는 형식 점검용 사례일 뿐 전통 운영 효과의 증거가 아니다. T0는 반복 가능한 실제 작업 흐름, 개입 전 기준선, 안전한 내부 trial이 준비된 뒤에만 시작한다.

## 이 설계가 하지 않는 것

- 모델 파인튜닝, 자동 자기수정, 무승인 교리 배포
- AI의 의식·인격·법적 책임을 증명하거나 특정 모델의 정체성을 보존하는 일
- 사용자의 자기계발 일기나 AI 활용 홍보문구를 최종 성과로 삼는 일
- B1 코드, benchmark, 동결 설계·연구 문서 변경
- incident 하네스의 스키마 변경이나 전통 시스템 구현
- 모든 과거 로그의 소급 구조화
- 법적·보안 사고 조사 절차의 대체
