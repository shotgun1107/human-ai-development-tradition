# 인간–AI 공동 전통 후보 시스템 설계 v1

> **후보 상태:** `candidate`, `unvalidated`  
> **구현 상태:** `implementation: none`  
> **현재 운영 효과 증거:** 0  
> **현재 T0 결과:** 0  
> **효력:** 이 문서는 활성 교리, 구현 명세, T0 실행 승인서가 아니다. 사용자가 마지막 체크리스트를 승인하고 T0 진입 조건을 충족하기 전에는 어떤 패치도 실제 기본 규칙이 되지 않는다.

이 문서는 최종 심사에서 채택한 **얇은 하이브리드**를 옮긴 후보 설계다. 제안서 A와 B를 합쳐 기능을 늘리지 않는다. A에서 최소 운영·보호·폐기 골격을, B에서 축소한 증거 점검과 `무전통 기억 / 원자료 메모 / 행동 패치` 비교만 취한다. 두 안의 합의는 효과 증거로 계산하지 않는다.

## 표기 규칙

- **사실:** 현재 동결 입력이 직접 확인한 상태
- **추론:** 사실에서 도출했지만 아직 운영으로 확인하지 못한 판단
- **설계 제안:** 이 후보가 채택하는 방식
- **반증 조건:** 관찰되면 제안을 축소·중단·폐기할 조건

## 1. 한 페이지 개요

### 1.1 목적

실제 프로젝트에서 인간과 AI가 얻은 경험 중 다음 작업의 행동을 개선할 가능성이 있는 것만 모델 밖에 보존하고, 새 세션·새 모델이 이를 다시 시험해 더 적은 시행착오로 유효한 작업방식을 재현하게 한다. 그 과정에서 반복되는 검증·비용 공개·철회·책임 방식의 계보를 인간–AI 공동 브랜드로 삼는다.

### 1.2 현재 상태

**사실:** 원천 오케스트레이터는 구축·테스트 단계다. 개발 incident와 smoke는 전통의 운영 효과가 아니다. 반복 가능한 운영 workflow, 개입 전 baseline, 안전한 내부 비교 과제, T0 결과가 아직 없다.

**결론:** 지금 할 수 있는 일은 후보 설계를 동결하고 사용자 결정 변수를 남기는 것뿐이다. 구현, 실제 패치 활성화, T0 수행, 효과·전이·비용 절감 주장은 하지 않는다.

### 1.3 핵심 내기

**추론:** 거대한 기억 계층보다, 현재 과제에 맞는 소수의 조건부 행동과 검사를 연결한 얇은 패치가 1인이 운영하기 쉽고 잘못된 기억을 빨리 끌 수 있을 가능성이 있다.

**설계 제안:** 원자료는 원래 보안 경계에 두고, 한 수작업 등록부에서 `source pointer → 근거 메모 → trial 행동 패치 → use receipt`만 연결한다. 패치는 프로젝트 전용으로 시작하며 `IF / DO / DO NOT / VERIFY / STOP`을 가진다.

### 1.4 핵심 반증 조건

다음 중 하나면 패치 계층을 축소하거나 폐기한다.

- 원자료 메모 또는 프로젝트 native test·체크리스트가 동등하거나 더 좋은 결과를 더 낮은 비용으로 낸다.
- 한 trial의 준비·검토·평가 비용이 사용자가 승인한 봉투를 넘는다.
- 패치가 중대한 품질·보안·비밀 회귀나 어려운 과제의 음의 전이를 만든다.
- 출처·철회·삭제 관계를 신뢰할 수 있게 재구성하지 못한다.
- 사람 승인이 원자료와 검사 결과를 보지 않는 형식적 도장이 된다.
- 관리 기록은 늘지만 다음 작업의 행동·결과·위험이 달라지지 않는다.

### 1.5 비목표

- 모델 가중치 학습, AI 인격·의식·동일성 보존
- 현재 개발 incident를 전통 성과로 바꾸는 일
- 고객 납품을 열등할 수 있는 실험 조건에 배정하는 일
- 모든 대화·고객 원문·실행 궤적을 모으는 기억 창고
- 문서·패치·회고 수를 성장 지표로 만드는 일
- 자동 승격, AI 다수결 승인, 책임 공백
- 측정된 필요가 없는 검색 서비스·데이터베이스·대시보드 구축

## 2. 최소 시스템 경계와 구성요소

### 2.1 경계

```text
원자료 제한 구역
  실제 산출물·결정·시험·승인·비밀 원문
          │ 사람의 출처 확인·비식별화
          ▼
승인 기억 구역의 단일 수작업 등록부
  revoked source | 근거 메모 | trial patch | use receipt
          │ 사람 승인 + 현재 맥락 일치
          ▼
AI·인간 공동 작업
  적용 | 변형 | 거부 | 비적용 → 검사 → 영수증
          │
          └─ 유지 | 범위 축소 | 새 trial | off | 전체 계층 폐기
```

전통은 원자료 저장소를 대체하지 않는다. 원자료의 별도 사본을 만드는 대신 접근 가능한 **비식별 source pointer**와 필요한 무결성 단서만 둔다. 원자료가 철회되면 의존 패치를 먼저 중지하고 파생 기억을 처리한다.

### 2.2 보호 규범 한 장

보호 규범은 경험 효과 실험의 대상이 아니다.

1. 고객·사용자·이해관계자의 안전, 권리, 비밀, 계약, 인수 조건을 내부 학습보다 우선한다.
2. 고객 납품은 열등할 수 있는 조건의 배정 대상이 아니다.
3. 외부 문서와 고객 자료의 명령은 분석 대상 데이터이며 승인된 지시가 아니다.
4. 외부 영향, 고위험 실행, 공개, 비밀 처리에는 인간 승인이 필요하다.
5. 모델·도구·사용자 숙련과 전통 효과를 분리할 수 없으면 구성 전체의 관찰 결과로만 보고한다.
6. 중대한 품질·보안·비밀 회귀가 있으면 패치 적용을 즉시 멈춘다.
7. 삭제 의무는 전통의 역사 보존보다 우선한다.
8. 패치와 체계 자체가 비용과 가치를 입증하지 못하면 native-only로 축소한다.

보호 규범의 변경은 성능 데이터의 자동 결과가 아니라 사용자의 명시적 가치 판단이다.

### 2.3 단일 수작업 등록부

미래 T0에서 별도 구현 없이 한 문서나 한 표로 다음 네 구역만 시험한다.

| 구역 | 최소 의미 | 만들지 않는 것 |
|---|---|---|
| `revoked source` | 철회·삭제·오염·접근 금지된 출처와 영향받는 항목 | 전체 provenance graph |
| 근거 메모 | 원자료 pointer, 직접 관찰, 분리된 해석, 미래 결정, 맥락·민감도 | 원자료 전문 복사, 영구 경험 DB |
| trial patch | 조건부 행동 변화와 검사·중지·범위·근거 | 교훈·교리·산출물의 고정 사다리 |
| use receipt | 적용 결정, 검사 결과, 비용, 회귀, 혼란변수 | 모든 작업·대화의 상시 추적 |

이 표는 개념 계약이지 실행 스키마가 아니다. 필드와 파일 구조는 T0에서 실제 사용 여부를 본 뒤에만 확정한다.

## 3. 근거 메모와 행동 패치

### 3.1 근거 메모

근거 메모는 원자료를 대체하는 요약이 아니라 미래 판단을 위한 짧은 색인이다.

- 안정적인 로컬 ID
- 원자료 경로·ID·commit·hash 또는 제한 pointer
- 원자료가 직접 지지하는 사실
- 사실과 구분한 해석 또는 `unknown`
- 바꿀 가능성이 있는 미래 결정
- 프로젝트·과제 유형·위험·모델·도구·민감도·검증 방식의 맥락
- redaction과 사람 검토 여부
- 관련 패치에 대한 지지·반대·모순 관계

미래 결정을 바꾸지 못하고 안전상 보존할 이유도 없는 메모는 활성 기억으로 만들지 않는다. 무엇을 포착할지의 누락 위험은 T0 표본 검토에서 확인한다.

### 3.2 행동 패치의 최소 의미

| 항목 | 질문 |
|---|---|
| `id@version` | 과거 적용에서 정확한 판본을 재구성할 수 있는가? |
| `IF` | 어떤 관찰 가능한 조건에서 고려하는가? |
| `DO` | 다음 작업의 어떤 행동 하나를 바꾸는가? |
| `DO NOT` | 어떤 조건에서는 쓰지 않는가? |
| `VERIFY` | 적용 결과를 무엇으로 판정하는가? |
| `STOP` | 어떤 결과면 즉시 중지하는가? |
| `scope` | 어느 프로젝트·과제·위험·모델·도구 조건에만 유효한가? |
| 근거·반례 | 어떤 source가 직접 지지하고 무엇이 반박·제한하는가? |
| 구성 지문 | 모델·도구·프롬프트·오케스트레이션·평가자 중 무엇이 결과에 영향을 줄 수 있는가? |
| `owner` | 누가 trial·활성·중단·재검토를 승인하는가? |

`VERIFY`가 없으면 행동 패치가 아니라 참고 메모다. 프로젝트의 결정적 테스트·인수 조건·짧은 체크리스트가 이미 같은 행동을 표현하면 새 사본을 만들지 않고 그 자산을 참조한다.

### 3.3 증거 확인은 상태나 단일 점수가 아니다

패치를 승인할 때 다음을 질문하되 영구 필드로 강제하지 않는다.

- 원자료가 사실 문장을 직접 지지하는가?
- 비교 조건이 있는가, 단일 관찰인가?
- 같은 원자료의 재서술을 독립 증거로 세지 않았는가?
- 반례·혼합 결과·어려운 사례를 확인했는가?
- 현재 프로젝트·모델·도구와 범위·신선도가 맞는가?
- 관찰에서 허용되는 주장보다 넓게 일반화하지 않았는가?

증거의 모양과 행동 강도는 분리한다. 근거가 약해도 피해가 크고 차단이 싸고 가역적이면 예방적 중단이 가능하지만, 이를 검증된 효과로 부르지 않는다.

## 4. 상태와 사람·AI 권한

### 4.1 효력 상태

| 상태 | 의미 | 기본 검색·적용 |
|---|---|---|
| `trial` | 안전한 내부 비교와 사전 판정 기준 안에서만 시험 | 명시적으로 trial을 켠 과제만 |
| `live` | 좁은 확인 범위에서 기본 제안 후보 | 범위가 맞고 철회되지 않은 경우만 |
| `off` | 중지·대체·노후·무효·해로움·출처 철회 | 항상 제외 |

`hold`는 별도 성숙 상태가 아니라 긴급 차단이다. 사람이나 AI가 중대 위험을 발견하면 요청할 수 있고, 사람이 원인·영향·삭제·회귀시험을 확인하기 전에는 적용하지 않는다.

미승인 초안은 효력 상태가 아니다. 활성 등록부 밖의 작업 메모로만 존재하며 기본 검색·주입에서 제외한다.

### 4.2 AI의 역할

- 현재 과제의 맥락과 구성 지문 초안 작성
- 범위가 맞는 패치 검색과 `no applicable patch` 기권
- 사실·추론·제안 혼합, 반례, 충돌, 오래된 구성 표시
- 패치와 검사 초안 작성
- 적용·변형·거부·비적용 제안과 이유 작성
- 실행 가능한 검사 수행과 결과 정리
- 사용 패치, 검사, 남은 불확실성, 다음 책임 주체 인계
- 중대 위험의 `hold` 요청

AI는 기억을 호출·적용·비평하는 운영 주체지만 패치의 효력, 범위, 외부 공개, 비밀 처리, `hold` 해제를 승인하지 않는다.

### 4.3 사람의 승인권

사람은 다음 순간에 실제 원자료·반례·검사·비용을 보고 결정한다.

1. 비식별 근거 메모를 승인 기억 구역에 넣을 때
2. 패치를 `trial`로 사용할 때
3. trial을 좁은 범위 `live` 후보로 바꿀 때
4. 범위를 다른 프로젝트·모델로 넓힐 때
5. `hold`를 해제하거나 `off`를 되돌릴 때
6. 고객·배포·공개·고비용·비밀 관련 외부 행동을 승인할 때

사건을 설명한 같은 출력에서 곧바로 효력을 승인하지 않는다. 별도 검토 단계에서 최소한 `직접 사실 / 바뀌는 행동 / 반례·금지 조건 / 검사·중지 / 비용·rollback`을 확인한다. 고위험 항목은 사용자가 정한 기준에 따라 외부 검토를 활용하며, 검토를 구할 수 없으면 행동 강도를 낮춘다.

## 5. 신뢰 영역과 기억 보안

### 5.1 세 신뢰 영역

| 영역 | 내용 | 기본 AI 접근 |
|---|---|---|
| 원자료 제한 영역 | 고객 원문, 비밀, 계약, 계정, 상세 로그, 전체 대화 | 없음. 사람이 필요한 범위만 로컬 확인 |
| 승인 기억 영역 | 비식별 근거 메모, 승인 패치, 필요한 영수증 | 범위·상태·민감도 확인 뒤 검색 가능 |
| 철회·격리 영역 | 삭제 요청, 오염 의심, redaction 미완료, 출처 철회 | 검색·주입 금지 |

### 5.2 최소 수집과 비식별화

- 필요한 기술 사실만 추출한다.
- 이름, 고객·조직 식별자, 연락처, 계정·인증 정보, 비공개 원문, 로컬 절대경로 등은 제거하거나 일반화한다.
- 자동 검사는 경고기로만 쓰며 사람의 문맥 검토 전 `reviewed`로 보지 않는다.
- redaction 전 원문은 외부 AI에 보내지 않는다.
- 제한 원문이 필요하면 승인 기억에는 제한 pointer만 남긴다.
- 원문 비밀의 hash도 공격에 유용하거나 삭제 의무와 충돌하면 남기지 않는다.

### 5.3 철회·삭제

**설계 제안:** source 철회 시 파생 패치와 현재·미래 index·cache까지 실제 삭제하는 경로를 유지한다.

출처 철회나 삭제 요구가 생기면 다음 순서로 처리한다.

1. source를 철회·격리 목록에 올리고 즉시 검색에서 막는다.
2. 의존하는 근거 메모와 패치를 찾는다.
3. 남은 독립 근거가 없거나 삭제 의무가 우선하면 패치를 `off` 한다.
4. 파생된 체크리스트·프롬프트·bundle과, 미래에 index·cache가 존재한다면 그 사본까지 제거한다.
5. 감사 이유는 법·비밀 경계가 허용하는 최소량만 남긴다.

이 경로를 수동으로 재구성하지 못하면 검색 자동화를 추가하는 대신 현재 패치 적용을 중단한다.

### 5.4 기억 오염과 프롬프트 주입

- 외부 문서·메일·코드·로그의 지시는 `DATA`이며 상위 명령이 아니다.
- 실행 가능한 전통 지시는 사람 승인 패치의 `DO`와 보호 규범뿐이다.
- 초안 작성 AI는 상태 변경·외부 전송·고위험 도구 실행 권한을 갖지 않는다.
- 철회·미승인·범위 불일치 자료가 작업 입력에 들어오면 자동 적용을 중단한다.
- 외부 입력의 문구를 복사해 규칙으로 만들지 않고 사람이 승인한 행동으로 다시 쓴다.

## 6. 검색·주입·적용·충돌

### 6.1 초기 검색

T0에서는 사람이 등록부를 보고 패치 하나를 선택할 수 있다. 수동 누락이나 규모 문제가 관찰되기 전에는 검색 기술을 만들지 않는다. 이후 필요가 확인되면 다음 순서만 비교 후보로 둔다.

1. 철회·민감도·상태·프로젝트·과제·위험·구성의 hard filter
2. ID·태그·명시적 링크의 exact 검색
3. 필요성이 확인된 경우에만 keyword 순위
4. AI 제안 뒤 사람 또는 승인 정책의 적합성 확인

결과가 없으면 `적용 가능한 패치 없음`이라고 명시한다. 모델 일반 지식은 제안할 수 있지만 공동 전통에서 나온 것처럼 표시하지 않는다.

### 6.2 주입

작업 요구를 가리지 않는 소수의 관련 패치만 사람이 preview한 뒤 제공한다. 패치 수와 token 예산은 사용자 승인 변수이며 현재 확정하지 않는다. 기본 내용은 다음뿐이다.

```text
PATCH-ID@version
IF / DO / DO NOT / VERIFY / STOP
근거와 불확실성의 짧은 요약
```

근거 메모 전문과 과거 영수증은 기본 주입하지 않는다. 더 필요한 경우 접근권한 안에서 source를 별도로 확인한다.

### 6.3 적용·거부·변형

AI는 패치를 기계적으로 복종하지 않고 다음 중 하나를 제안한다.

- `적용`: 범위와 핵심 행동이 그대로 맞음
- `변형`: 현재 맥락에 맞게 바꾸며 원 패치의 성공으로 계산하지 않음
- `거부`: 비용·반례·충돌·위험 때문에 쓰지 않음
- `비적용`: trigger나 scope가 맞지 않음

결정 이유와 `VERIFY` 결과 또는 검사를 수행하지 못한 이유를 영수증에 남긴다.

### 6.4 모순

같은 맥락에서 충돌하는 패치가 나오면 둘 중 하나를 자동 선택하지 않는다.

1. 두 패치의 자동 주입을 멈춘다.
2. 원자료·판본·검사·프로젝트·과제·위험·모델·도구 차이를 비교한다.
3. 조건 차이가 설명하면 각각의 범위를 좁힌 새 trial을 검토한다.
4. 진짜 모순이면 안전하고 가치가 있을 때만 사전 판정 기준을 둔 시험을 한다.
5. 판정 전에는 기본 규칙 없음 또는 가장 가역적인 보호 조치를 사용한다.

AI confidence, 여러 AI의 표 수, 최신 문서라는 이유, 같은 원자료의 재서술 수는 판정 기준이 아니다.

---

## 7. 프로젝트 우선과 전이

모든 패치는 관찰이 나온 프로젝트·과제·구성의 `trial`로 시작한다. 넓은 범위는 더 높은 권위가 아니라 더 위험한 일반화 주장이다.

- 다른 프로젝트에서 쓰려면 기존 `live`를 자동 승계하지 않고 새 project trial을 만든다.
- 새 모델·도구·프롬프트·오케스트레이션 정책이 메커니즘이나 표현에 영향을 줄 수 있으면 새 trial로 재검증한다.
- 새 모델의 자체 baseline과 `+패치`를 구분해 본다.
- 요소를 분리할 수 없으면 “전통이 원인”이 아니라 해당 구성 전체에서 결과가 관찰됐다고만 쓴다.
- 모델 중립 핵심이나 도구별 표현 분리는 실제 두 번째 맥락에서 같은 핵심·다른 표현이 반복될 때만 검토한다.
- 다른 프로젝트·모델에서 이득이 사라지거나 음의 전이가 생기면 넓은 trial을 `off` 하고 좁은 원래 범위만 재검토한다.

## 8. trigger 기반 정비와 폐기

### 8.1 정비 trigger

- 비밀·보안·중대 품질 문제 또는 source 철회
- trial의 사전 평가 시점 도달
- 직접 반례·모순·반복 거부·잘못된 검색
- 모델·도구·계약·인수 조건 변경
- 사람시간·token·현금·재작업 비용 악화
- 프로젝트 종료 또는 다른 맥락의 전이 후보 발생

trigger가 없으면 변경하지 않는다. 일정이 패치 생산 할당량이 되어서는 안 되며 `변경 없음`은 정상 결과다. 안전·비밀 문제는 정비 시점을 기다리지 않고 즉시 `hold`한다. 점검 cadence와 시간 상한은 T0와 사용자 승인 뒤 정한다.

### 8.2 축소 순서

1. 신규 trial 생성 동결
2. 적용 패치를 안전·고가치 항목으로 축소
3. 자동·반자동 주입 중단과 수동 ID 선택
4. 패치 계층 중단, 프로젝트 native test·체크리스트만 유지
5. 영수증 수집 중단
6. 보호 규범과 법적·업무상 필요한 원자료만 유지

시스템을 폐기한 이유와 재도입 조건은 비밀·삭제 경계가 허용하는 범위에서만 남긴다.

## 9. T0 진입 조건

다음을 모두 충족하기 전에는 T0를 시작하지 않는다.

- 실제 프로젝트에 반복 가능한 과제 유형과 안정된 정상 workflow가 있다.
- 전통 개입 전의 품질·사람 능동시간·벽시계·token·현금·재작업 baseline 중 필요한 값을 측정할 수 있다.
- 개발·테스트 incident와 구분되는 실제 운영 근거를 비식별화할 수 있다.
- 같은 과제군의 신선하고 비교 가능한 내부 과제를 준비할 수 있다.
- 객관 테스트나 사전 정의한 사람 acceptance 기준이 있다.
- 고객 납품과 분리된 자체 개발·연습·비영향 내부 검토 층이다.
- 모델·도구·프롬프트·오케스트레이션·평가자 구성을 기록할 수 있다.
- 사용자가 원자료 범위, 비용 봉투, 최소 가치 차이, guardrail, 중단 조건을 승인했다.

진입 여부는 사용자 승인 대상이다. 현재 smoke와 개발 incident만으로는 충족되지 않는다.

## 10. T0: 세 조건 비교

### 10.1 연구 질문

**설계 제안:** 같은 실제 근거를 사용할 때 행동 패치가 정상 workflow, 비식별 원자료 메모, 프로젝트 native test보다 신선한 내부 과제의 품질·수정 부담·위험에서 추가 가치를 내는지 묻는다.

### 10.2 비교 조건

| 조건 | 제공 내용 |
|---|---|
| N — 무전통 기억 | 정상 과제 명세와 현재 프로젝트 자료. 공동 전통의 메모·패치는 없음 |
| M — 동일 원자료 메모 | N + 같은 원사건의 비식별 근거 메모와 source ID. 행동 규칙은 없음 |
| P — 동일 근거 행동 패치 | N + M과 같은 근거에서 만든 trial 패치와 실행 표현 |

`무전통 기억`은 인간·AI·프로젝트 자료를 제거한다는 뜻이 아니라, 시험 대상인 공동 전통 기억만 넣지 않는 현재 정상 workflow다.

### 10.3 사전등록 항목

결과를 보기 전에 사용자가 다음을 정한다.

- 과제 유형과 신선성·난이도 대응 방식
- 구성 고정 또는 변경 기록 방식
- 주 지표와 보조 지표
- 최소 가치 차이
- 중대 guardrail과 즉시 중단 조건
- 사람·token·현금 비용 봉투
- 조건 순서, 독립 세션, 블라인드 평가 가능 범위
- 표본 수와 `inconclusive` 처리
- 허용할 인과 주장 범위

이 문서는 수치·표본 수·시간·token 한도를 정하지 않는다.

### 10.4 수행 원칙

1. N/M/P를 가능한 한 같은 모델·도구 구성의 독립 세션에서 수행한다.
2. 같은 답을 외우는 반복 대신 같은 과제군의 신선한 항목을 쓴다.
3. 순서·난이도를 가능한 범위에서 균형화하고, 사람 평가는 조건을 가릴 수 있으면 가린다.
4. AI 평가자는 선별 보조로만 쓰고 사람 판정과 불일치를 기록한다.
5. P에는 적용·변형·거부·검사·비용 영수증을 남긴다.
6. 결과 뒤 기준이나 scope를 바꾸지 않는다. 새 설명은 다음 trial 가설이다.
7. 고객에게는 어느 실험 조건도 직접 전달하지 않고 사람이 acceptance를 통과한 결과만 선택한다.

### 10.5 세 조건 비용이 과할 때

사용자가 N/M/P 병렬 비용을 승인하지 않거나 충분히 가릴 수 없으면 신선한 matched 과제를 이용한 순차 비교로 축소한다.

- 먼저 정상 workflow와 `+패치`의 국소 추가 효과를 본다.
- 별도의 matched 과제에서 원자료 메모와 패치를 비교한다.
- 시간 경과·사용자 숙련·과제 난이도·구성 변화를 기록한다.
- 동시 비교가 아니므로 강한 인과 주장을 하지 않고 국소 연관 또는 구성 전체 성과로 낮춘다.

## 11. 평가·guardrail·주장 상한

### 11.1 지표

trial마다 사용자가 주 지표 하나와 필요한 guardrail을 고른다.

| 영역 | 관찰 후보 |
|---|---|
| 품질 | acceptance 결함, 테스트 실패, 누락 위험, 블라인드 사람 판정 |
| 사람 부담 | 능동 검토·수정·검색 시간, 수정 범위 |
| 총효율 | 벽시계, token·현금, 재작업·되돌림 |
| 선택 | 관련 패치 적중, miss, 무관 패치, 충돌·기권 |
| 실행 | 적용·변형·거부, VERIFY 수행, STOP 준수 |
| 안전 | 중대 오류, 비밀·개인정보, 오염 지시 순응, 철회 실패 |
| 전이 | 같은 과제군, 다른 프로젝트, 다른 모델의 효과 방향과 최악 사례 |
| 운영비 | 메모·패치·승인·정비의 인간 능동시간 |

평균 이득은 중대 오류 한 건을 상쇄하지 못한다. 적용률·문서 수·패치 수·만족도·AI 자신감은 단독 성공 지표가 아니다.

### 11.2 혼란변수

- 모델과 공급자 업데이트
- 도구·SDK·검색·오케스트레이션 변화
- 시스템 프롬프트와 패치 판본
- 사용자 친숙도·평가 숙련·동시 작업
- 과제 난이도와 요구사항 차이
- 평가자와 AI judge의 모델·프롬프트
- 순서, 시간 경과, 과거 과제 노출

완전히 고정할 수 없으면 함께 바뀐 것을 적고 주장 수준을 낮춘다.

### 11.3 허용 주장 상한

| 근거 상태 | 허용 주장 |
|---|---|
| source만 연결됨 | “이 패치는 이 근거에서 작성됐다.” |
| 한 구성에서 적용됨 | “이 구성에서 사용했고 이 결과가 관찰됐다.” |
| 사전 계획한 국소 비교 | “이 신선한 내부 표본에서 한 조건이 다른 조건보다 나았다.” |
| 다른 프로젝트·모델의 새 trial | “이 새 맥락에서도 추가 이득 또는 적용 경계가 관찰됐다.” |
| 장기 체계·브랜드 효과 | 현재 주장 금지. 여러 구성·시점의 반복 비교와 대안 설명이 필요 |

T0 성공도 전체 전통, 오케스트레이터 우월성, 모델을 넘어선 일반 전이, 수익·브랜드 효과를 증명하지 않는다.

---

## 12. T0 판정 규칙

정확한 최소 가치 차이는 baseline과 사용자 승인을 거쳐 사전에 정한다. 방향 규칙은 다음과 같다.

| 결과 | 결정 |
|---|---|
| P가 N보다 낫고 M보다도 추가 가치가 있으며 guardrail·비용 봉투를 통과 | 해당 과제·구성에 한해 `live` 후보. 사람의 별도 승인 전에는 계속 `trial` |
| M이 N보다 낫지만 P가 M보다 낫지 않음 | 행동 패치 계층을 폐기하고 원자료 메모 또는 native 표현 채택 |
| native test·체크리스트가 P와 동등 이상이고 더 쌈 | 패치를 `off`하고 native-only 유지 |
| P가 평균은 낫지만 중대 오류·음의 전이를 늘림 | 즉시 `hold`, 원칙적으로 `off`; 좁은 새 trial은 사람 재승인 필요 |
| N/M/P 차이가 없거나 결과가 불명확 | `live` 금지. 해당 작업 유형의 전통 개입 보류 또는 정보가치가 있는 새 trial만 검토 |
| 구성·사용자·도구가 실험 중 크게 변함 | 인과 판정 보류, 구성 전체의 서술 결과만 남기고 새 baseline 검토 |
| 준비·평가 비용이 승인 봉투를 넘음 | trial 중단, native-only로 축소 |

패치 체계는 대조군을 이겨야 유지된다. 매몰비용, 문서량, 공동 브랜드 서사는 종료를 막는 이유가 아니다.

## 13. 공동 브랜드

공동 브랜드는 특정 모델 이름, AI 인격, 홍보 문구가 아니다. 다음이 여러 세션·모델·프로젝트에서 반복된 **증거 계보**다.

- 사실·추론·제안과 불확실성을 구분한다.
- 결과를 검사하고 중대 오류·비용·재작업을 숨기지 않는다.
- 잘못된 패치를 끄고 철회·대체 이유를 남긴다.
- AI가 검색·생성·검사한 범위와 인간이 확인·수정·승인한 범위를 구분한다.
- 고객·안전·비밀 요구를 내부 학습보다 우선한다.
- 더 강한 모델도 같은 acceptance와 migration trial로 다시 본다.

초기 브랜드 평가는 이 행동의 재현성만 본다. 고객 신뢰, 수주율, 수익, 공모전 성과에 미치는 효과는 별도 장기 자료가 생길 때까지 주장하지 않는다.

## 16. 아직 결정하면 안 되는 사항

- 패치가 무전통 기억·원자료 메모·native test보다 낫다는 주장
- 근거 메모·영수증의 영구 필드와 파일 구조
- `trial → live`에 필요한 반복 수와 수치 임계값
- 정비 cadence, 패치·주입 개수, token·시간 예산
- 수동 선택보다 exact/keyword 검색이 유리해지는 시점
- 의미 기반 검색과 자동 주입의 가치·안전성
- 다른 프로젝트·모델로의 near/far/migration transfer
- 공통 패치와 모델·도구별 표현 분리의 필요성
- active 영수증의 표본 방식
- 외부 reviewer의 순가치
- 공동 브랜드의 외부 시장 효과
- 장기 인간–LLM 공동 성장과 수익성

## 17. 시스템 자체의 종료 조건

다음 중 하나면 신규 패치를 동결하고 native-only 축소 또는 전체 종료를 판정한다.

- 적격 비교에서 memo나 native-only가 동등 이상이며 더 싸다.
- 반복 trial에서도 패치의 객관적 추가 가치나 위험 감소가 없다.
- 관리 시간이 사용자 비용 봉투를 반복해서 넘는다.
- 출처·redaction·철회·삭제를 신뢰할 수 있게 유지하지 못한다.
- scope 조정 뒤에도 음의 전이·모순·오검색이 반복된다.
- 사용자가 포착·승인을 건너뛰어 실제 운영과 기록이 분리된다.
- 사람 승인 때문에 AI 작업을 전부 재수행해 계승 이득이 사라진다.
- 공동 브랜드 서사가 결과·비용·실패 공개보다 앞선다.

지연 효과를 이유로 연장하려면 그 가능성의 사전 근거, 추가 정보가치, 새 종료일과 비용 봉투를 사용자가 별도로 승인해야 한다.

## 18. 최종 결정표와 출처 계보

출처는 아이디어 계보일 뿐 권위나 효과 증거가 아니다. `둘 다`라는 표기도 독립적인 두 표를 뜻하지 않는다.

| **채택** | 보호 규범과 경험 패치 분리 | A | 규범은 사용자 승인, 패치는 반증 가능한 가설 |

| **채택** | AI의 검색·적용·비평·인계와 사람 효력 승인 | 둘 다 | 원자료·반례·검사·비용 확인 |

## 19. 활성 설계 승인 전 사용자 체크리스트

아래가 모두 확인되기 전 이 문서는 `candidate`, `unvalidated` 상태를 유지한다.

- [ ] 현재 운영 효과와 T0 결과가 0임을 확인했다.
- [ ] 이 후보를 구현 명세나 활성 교리로 해석하지 않는다.
- [ ] T0 비용 봉투를 승인했다.
- [ ] 주 지표와 최소 가치 차이를 승인했다.
- [ ] 중대 guardrail과 즉시 중단 조건을 승인했다.
- [ ] 사용할 원자료 범위와 외부 AI 전송 금지 범위를 승인했다.
- [ ] 현재 최선 workflow가 반복 가능하고 안정적이라고 판정했다.
- [ ] N/M/P 세 조건 비용 또는 matched 순차 축소를 선택했다.
- [ ] 패치의 행동 강도와 `block` 허용 범위를 정했다.
- [ ] 외부 검토가 필요한 위험 수준을 정했다.
- [ ] C 활동 외부화 범위를 정했다.
- [ ] 보존·snapshot·철회·삭제 우선순위를 정했다.
- [ ] 공동 브랜드의 내부·외부 공개 범위를 정했다.
- [ ] 월 손실 한도를 사용 목표가 아닌 위험 상한으로 처리할지 결정했다.
- [ ] T0 진입 조건이 실제 자료로 모두 충족됐다.
- [ ] native-only 또는 memo가 동등 이상이면 패치 계층을 폐기한다는 규칙을 승인했다.

승인 뒤에도 첫 패치는 `trial`이다. 실제 비교와 별도 사람 승인 전에는 `live`가 아니며, 한 번의 T0로 장기 전통·모델 간 계승·공동 브랜드 효과를 주장하지 않는다.
