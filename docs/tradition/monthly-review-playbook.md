# 월간 전통 회고 플레이북

## 1. 목적과 운영 약속

월간 회고의 목적은 지난달을 멋지게 요약하는 것이 아니라 다음 달 기본 행동을 소수의 검증 가능한 변경으로 갱신하는 것이다. 회고의 성공 기준은 교리 수가 아니라 다음과 같다.

- 중요한 경험이 출처와 함께 포착됐는가?
- 사실·추론·제안이 분리됐는가?
- 반례와 실패한 적용을 먼저 검토했는가?
- 승인한 규칙이 실행 산출물과 평가 계획을 가졌는가?
- 오래되거나 해로운 규칙을 강등·폐기했는가?

권장 cadence는 매월 1회, 60~90분이다. 사건량이 적으면 억지로 교리를 만들지 않고 “변경 없음”을 정상 산출물로 인정한다. 심각한 보안·비밀·안전 문제는 월간 회고를 기다리지 않고 즉시 적용 중지와 별도 대응을 한다.

## 2. 역할

개인 시스템에서도 같은 시간에 역할을 섞지 않는다.

- 기록자: 월중 경험을 짧게 포착하고 출처·redaction을 확인한다.
- AI 보조 분석자: 중복·군집·기존 교리·반례 후보와 누락 필드를 제안한다.
- 사람 분석자: 인과·적용 조건·증거 등급·실험을 판단한다.
- 사람 승인자: 효력 발생, 범위 확대, 강등·폐기를 결정한다.
- 평가자: 지난달 trial의 효과와 부작용을 사전 지표에 따라 판정한다.

한 사람이 모든 역할을 맡을 때는 준비 세션과 승인 세션을 분리한다. 가능하면 하루 이상 간격을 두고, 고위험 범용 교리는 외부 독립 검토 없이 `active`로 만들지 않는다.

## 3. 월중 상시 수집

### 3.1 포착 trigger

다음 중 하나면 5분 이내의 capture note를 남긴다.

- 실패, 근접 실패, 중요한 오류 발견
- 계획과 다른 성공 또는 예상을 크게 넘은 효율
- 장기 영향이 있는 설계·도구·모델 결정
- 가설과 비교 기준이 있는 실험 완료
- 같은 현상의 두 번째 등장
- 기존 교리를 적용했는데 결과가 어긋남
- 교리를 면제했거나 찾지 못해 사용하지 못함

### 3.2 최소 capture note

```text
날짜 / 프로젝트 / 단계
예상한 것
관찰한 것
즉시 근거 링크
영향
민감도와 redaction 필요 여부
기존 교리와 충돌 가능성
```

사건 직후에는 “교훈”을 확정하지 않는다. 시간 압박 하의 원인 추정은 `interpretation`으로 표시한다.

## 4. 회고 전 준비(D-3~D-1)

### 4.1 입력 동결

회고 대상 기간의 snapshot을 정한다.

- incident entry와 index
- `codex-revision-log.md`의 해당 월 추가 부분
- 실험·benchmark 결과와 commit/hash
- 결정 기록과 주요 diff
- 지난달 doctrine/application/evaluation
- 면제·비적용·검색 실패 목록

입력 목록과 기준 commit/hash를 review record에 기록한다. 회고 후 발견된 자료는 소급해 결과를 바꾸지 말고 추가 검토로 연결한다.

### 4.2 개인정보·비밀 게이트 G0

통과 조건:

- 외부 모델에 보내는 모든 텍스트가 redaction 검토를 마침
- 계정·token·이메일·절대경로·고객/조직 식별자 제거
- 민감 원본은 복제하지 않고 제한 포인터 사용
- 분류가 불명확한 자료는 AI 분석 입력에서 제외

실패 시 해당 항목은 사람이 로컬에서만 검토하거나 제외한다. 회고 전체를 멈출 필요는 없다.

### 4.3 AI 보조 초안

AI에 허용할 작업:

- 경험을 유사 주제별로 묶고 각 묶음의 원본 ID 나열
- facts/interpretations/proposals 혼합 표시
- 기존 active/trial/retired 교리와의 관계 검색
- 지지 증거와 반례 후보를 별도 열로 작성
- 누락된 도구 버전, 결과 지표, 검증 한계 표시
- 조건부 lesson claim과 판별 실험 초안

AI 출력의 각 주장은 원본 ID를 가져야 한다. AI가 추가한 일반 지식은 별도 `external suggestion`으로 두며 경험 증거로 계산하지 않는다. AI는 등급·승격·폐기 결정을 내리지 않는다.

### 4.4 사람 사전 검토 게이트 G1

각 경험에 대해 확인한다.

- 원본이 실제로 존재하고 링크가 맞는가?
- facts는 원본이 직접 지지하는가?
- 같은 원본의 여러 요약을 독립 증거로 잘못 세지 않았는가?
- 성공과 실패 모두 시행 조건과 결과가 있는가?
- 보고되지 않은 실패, 생존자 편향, 도구 버전 변화 가능성을 적었는가?
- 재현되지 않은 원인 가설을 사실처럼 쓰지 않았는가?

통과하지 못한 항목은 `needs-evidence`로 다음 달까지 보류한다.

## 5. 회고 회의 절차(60~90분)

### 5.1 0~10분: 목표와 지난 action 확인

- 지난달 승인 action의 완료·미완료·막힘을 확인한다.
- 완료 여부가 아니라 효과 검증 여부를 본다.
- 미완료 action은 자동 연장하지 않고 여전히 가치 있는지 재승인한다.
- 이번 회고에서 변경할 수 있는 규칙 수를 1~3개로 제한한다.

### 5.2 10~25분: ground truth 재구성

AAR 질문을 개인 개발에 맞게 사용한다.

1. 무엇을 하려 했는가? 성공 기준은 무엇이었는가?
2. 실제로 무엇이 일어났는가? 어떤 원자료가 있는가?
3. 무엇이 잘됐고 무엇이 어긋났는가?
4. 차이를 설명하는 기여 요인과 대안 설명은 무엇인가?

시간순 기록과 지표를 우선하고 회상으로 빈칸을 조용히 채우지 않는다. “모름”을 허용한다.

### 5.3 25~40분: 패턴과 반례

각 후보 묶음에 대해 묻는다.

- 같은 메커니즘의 반복인가, 제목만 비슷한가?
- 성공은 규칙 덕분인가, 우연·더 쉬운 작업·다른 모델 때문인가?
- 실패가 없는 것이 탐지되지 않은 것인지 실제 부재인지 알 수 있는가?
- 기존 교리가 적용됐지만 효과 없었던 사례는?
- 반대 방향의 결과를 가진 프로젝트·도구 버전은?
- 어떤 결과가 이 교훈을 반박할 것인가?

반례가 적용 범위를 드러내면 후보를 버리기보다 조건을 좁힌다. 조건을 무한히 추가해 반증 불가능해지면 기각한다.

### 5.4 40~55분: lesson candidate 심사 게이트 G2

후보별 체크:

- [ ] 규범 또는 예측이 한 문장으로 명확하다.
- [ ] 적용 조건과 금지 조건이 있다.
- [ ] 예상 메커니즘이 `interpretation`으로 표시됐다.
- [ ] 원본 경험과 반례가 링크됐다.
- [ ] E0~E4 등급 근거가 설명됐다.
- [ ] 실패시킬 수 있는 판별 기준이 있다.
- [ ] 다음 실험이 작고 가역적이다.
- [ ] 예상 비용과 부작용 guardrail이 있다.

결정은 `approve-trial`, `revise`, `needs-evidence`, `reject` 중 하나다. 단일 경험은 일반적으로 프로젝트 `trial`을 넘지 않는다.

### 5.5 55~70분: 기존 교리 재검토 게이트 G3

모든 active 교리를 매월 읽지 않는다. 다음 trigger가 있는 것만 깊게 검토한다.

- review_due 도달
- 새 반례 또는 mixed/contradicts 평가
- 핵심 모델·SDK·도구·위험 환경 변경
- 두 번 이상 면제 또는 검색 실패
- 산출물 준수율 저하
- 다른 교리와 충돌

결정:

- `keep`: 판본·범위 유지
- `revise`: 명료화 또는 조건·산출물 개선
- `constrain`: 적용 범위 축소
- `demote`: 범용→프로젝트 또는 active→trial
- `deprecate`: 신규 적용 중지, 이행 필요
- `retire`: 효력 제거

강등과 폐기는 실패가 아니라 잘못된 교훈의 고착을 막는 정상 학습이다.

### 5.6 70~85분: 실행 산출물과 평가 승인 게이트 G4

승인할 각 trial/active 교리에 대해 정한다.

- 어떤 체크리스트·프롬프트·테스트·템플릿이 바뀌는가?
- 사람이 실제 변경을 검토할 것인가?
- 다음 어느 프로젝트·작업에서 적용할 것인가?
- 적용 전에 어떤 baseline과 primary metric을 고정할 것인가?
- guardrail과 중단 조건은 무엇인가?
- 누가 언제 효과를 판정할 것인가?

산출물 변경 없이 기억만 하겠다는 교리는 기본적으로 승인하지 않는다. 단, 의도적으로 행동하지 않기로 한 결정은 그 이유와 관찰 지표를 기록할 수 있다.

### 5.7 85~90분: 최종 사람 승인 게이트 G5

승인자는 다음을 한 번에 확인한다.

- AI 생성 내용은 원본과 대조됐는가?
- 민감 정보가 새 산출물과 검색 색인에 섞이지 않는가?
- 범용 승격 기준을 실제로 충족하는가?
- 규칙 수와 프롬프트 크기가 운영 가능 범위인가?
- rollback 판본과 재검토일이 있는가?

서명 전에는 모든 변경이 draft다.

## 6. 월간 산출물

매월 최소 산출물은 하나의 review record와 작은 변경 묶음이다.

### 6.1 Review summary

```markdown
# 2026-08 monthly tradition review

## 입력 snapshot과 제외 범위
## 확인된 사실
## 검증 한계
## 패턴과 반례
## 결정 표
| 대상 | 이전 상태 | 결정 | 근거 | 승인자 |
## 교리·산출물 변경
## 다음 달 실험과 사전 지표
## 미해결 모순
## 개인정보·비밀 검토
```

### 6.2 필수 부속물

- 신규·수정 experience 목록
- lesson candidate 결정 목록
- doctrine changelog
- 변경된 artifact와 파생 교리 판본
- 다음 application/evaluation 계획
- rejected/deprecated/retired 목록과 이유
- 미확인·제외한 범위

“변경 없음”인 달에도 입력 snapshot, 검토 범위, 변경 없음의 이유, 다음 review_due는 남긴다.

## 7. 승인 규칙 요약

| 변화 | 최소 근거 | 필수 사람 승인 | 추가 조건 |
|---|---|---|---|
| 경험 수집 | E1 가능 | redaction | 사실/추론 분리 |
| lesson candidate | E1 | 후보 문장 | 반증 기준 |
| 프로젝트 trial | E2 | 예 | 가역 실험·guardrail |
| 프로젝트 active | E3 | 예 | 의도적 적용 효과 |
| 범용 trial/active | E4 | 예 | 독립 맥락·전이 경계·외부 검토 권장 |
| 범위 확대 | 해당 범위 증거 | 예 | 반례 재검색 |
| 자동 적용 산출물 | E3 이상 권장 | 예 | rollback·회귀시험 |
| 강등·폐기 | 반례·노후·무효 | 예 | 이유·대체 관계 |

## 8. AI 보조 프롬프트 계약

월간 분석 AI에는 다음 계약을 둔다.

```text
역할: 증거 정리 보조자. 최종 승인자가 아니다.

1. 입력에 없는 사실을 만들지 않는다.
2. 모든 사실 주장에 source ID를 붙인다.
3. 사실, 추론, 제안을 별도 섹션으로 쓴다.
4. 지지 증거와 반례를 같은 비중으로 찾는다.
5. 같은 원자료의 재서술을 독립 증거로 세지 않는다.
6. 범용화를 제안할 때 적용 조건과 금지 조건을 쓴다.
7. 증거가 부족하면 '미확인'이라고 쓰고 등급을 높이지 않는다.
8. 비밀·개인정보로 보이는 문자열은 재출력하지 않고 위치만 경고한다.
9. retired/rejected 문서는 현재 규칙이 아니라 역사·반례로 표시한다.
10. 최종 출력은 사람이 원본 대조하기 쉬운 표로 작성한다.
```

prompt 판본, 사용 모델, 입력 snapshot을 review에 기록한다. AI를 바꾸면 같은 입력 일부를 재실행해 분류 일관성과 누락률을 비교한다.

## 9. 월간 품질 지표

운영 자체의 건강을 다음처럼 본다.

- provenance completeness: 필수 출처가 있는 경험 비율
- fact/inference separation defects: 샘플 감사에서 혼합된 주장 수
- redaction defects: 사람 검토에서 추가 발견한 민감 정보 수
- review latency: capture부터 사람 판정까지 일수
- action closure가 아니라 verified action rate: 효과 판정까지 끝난 action 비율
- doctrine application/waiver rate와 waiver 이유
- stale doctrine count: review_due 초과 active 교리 수
- contradiction resolution time
- retrieval precision@k: 실제로 관련 있는 교리가 상위 k개에 나온 비율
- negative learning rate: 강등·폐기된 교리 비율을 벌점이 아닌 건강 지표로 관찰

교리 수, 문서 길이, AI가 만든 후보 수는 성공 지표가 아니다.

## 10. 중단 조건

다음이면 새 승격을 멈추고 체계를 수리한다.

- 출처 없는 AI 요약이 교리로 승인됨
- 비밀·개인정보가 검색 색인 또는 prompt에 노출됨
- retired 교리가 현재 프로젝트에 자동 주입됨
- 적용 판본을 재구성할 수 없음
- 반례가 있는데도 범용 교리가 자동 유지됨
- 회고 action backlog가 두 달 연속 증가하고 효과 판정이 거의 없음
- 문서 관리 비용이 측정된 이득보다 지속적으로 큼
