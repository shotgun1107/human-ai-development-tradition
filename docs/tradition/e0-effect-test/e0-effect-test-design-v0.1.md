# E0 전통 효과시험 설계 v0.1

- 상태: `제안 — 독립 심사 전`
- 제안 라벨: `E0`는 아직 동결된 공식 단계가 아니다.
- 기준선: `central-system-v2.1-s0-preparation`
- 범위: 설계만 수행한다. 자료, 정답, 숨은 oracle, 코드, runner, 실행 결과를 만들지 않는다.
- 주된 질문: 정제된 외부 전통을 받은 새 AI 세션이 전통을 받지 않은 새 세션보다 표면이 달라진 후속 과제에서 더 나은 판단을 하는가?

## 1. 사실, 추론, 제안

### 1.1 확인된 사실

1. 저장소는 S0 준비 단계이며 S0, 중앙 시스템, Project Brain 통합, 운영 안전성, 경제성, 모델 간 전승은 구현되거나 검증되지 않았다.
2. 사용자의 1차 목표는 자기계발 일지가 아니라, 검증된 경험을 모델 밖에 보존해 다음 세션과 향후 AI가 더 낮은 시행착오로 재사용하게 하는 것이다.
3. S0와 이 시험은 다른 원인을 조작한다. S0는 같은 사실의 표현 방식을, 이 시험은 경험 내용의 제공 여부와 종류를 다룬다.
4. E0 설계는 S0의 유효 결과가 있기 전에는 `selected_representation_ref`를 채울 수 없다.
5. 현재 E0 합성 자료, 정답, 숨은 oracle, 실행 도구, 실행 결과는 없다.
6. 초기 계승 수단은 모델 파인튜닝이 아니라 검색 가능한 문서의 선택과 문맥 주입 또는 결정적 검색이어야 한다.

### 1.2 이 설계가 채택한 추론

1. `전통 없음`과 `정제된 전통`의 두 조건만으로도 전달 패키지 전체의 총효과가 있는지 가장 싸게 반증할 수 있다.
2. 그러나 그 비교에서 이겼다는 사실만으로 관련 전통 내용, 추가 입력 토큰, 형식, 주의 환기, 일반적 조언의 효과를 분리할 수 없다.
3. 따라서 두 조건 파일럿은 선별용이며, **관련 전통 내용의 고유 효과**를 주장하는 확인시험에는 길이·형식 일치 무관 대조가 필요하다.
4. 원본 기록 조건은 “정제가 원본 접근보다 낫다”는 추가 질문에만 필요하다. 첫 반증 시험에 자동으로 네 조건을 넣으면 비용과 다중 비교만 늘어난다.
5. 관련 과제만 평가하면 전통의 과잉 적용을 숨길 수 있으므로, 최소 파일럿에도 비적용·경계·오래된 교리 과제가 포함되어야 한다.
6. 기계적 전달 성공은 인과 효과가 아니다. 해시·가시성·배정이 맞더라도 결과가 좋아지지 않거나 비용·위해가 커질 수 있다.

### 1.3 후속 게이트에 제안하는 사항

1. 가장 작은 파일럿은 두 조건, 짝지은 합성 과제, 조건마다 독립된 새 세션으로 수행한다.
2. 파일럿은 효과 “통과”가 아니라 실행 가능성, 방향성, 위해, 분산을 확인하는 단계로만 사용한다.
3. 확인시험의 기본 조건은 `전통 없음 / 길이·형식 일치 무관 대조 / 정제된 전통`으로 한다.
4. `원본 기록`은 정제의 추가 가치를 판단할 필요와 예산이 함께 승인될 때만 별도 진단 조건으로 추가한다.
5. 효과, 위해, 비용의 임계값과 최대 표본·호출·현금·사람시간은 자료 작성 전에 고정한다.

## 2. 인과 질문과 추정 대상

### 2.1 좁은 인과 질문

> 같은 모델 판본, 시스템 지시, 과제, 도구, 출력 한도와 시간창에서, 과거의 별도 합성 경험으로부터 정제된 관련 전통 문서를 문맥에 받은 독립된 새 세션은 그 문서를 받지 않은 독립된 새 세션보다 중대 판단 오류가 적고, 관련 근거를 더 정확히 사용하며, 비적용·철회 상황에서 과잉 적용하지 않는가?

### 2.2 개입 단위와 분석 단위

- 개입 단위는 **한 과제–한 조건–한 새 세션**이다.
- 1차 분석 단위는 **후속 과제 인스턴스**다. 같은 인스턴스를 각 조건의 독립 세션에 제공해 짝을 만든다.
- 반복 호출을 사용하더라도 호출 하나를 독립 표본으로 부풀리지 않는다. 반복은 과제 안에 중첩하고 사전 규칙으로 과제 수준 결과로 합친다.
- 모델의 무작위성은 개입이 아니며, 같은 자원 봉투와 무작위·교차 배치로 통제한다.

### 2.3 목표 추정량

1. **전달 패키지 총효과:** 정제된 전통 조건과 전통 없음 조건의 과제 수준 수용 가능 판단률 차이.
2. **관련 내용의 특이 효과:** 정제된 전통 조건과 길이·형식 일치 무관 대조 조건의 차이.
3. **정제의 추가 효과:** 정제된 전통 조건과 원본 기록 조건의 차이. 이 추정은 원본 조건이 승인된 경우에만 한다.
4. **위해 차이:** 비적용·경계·stale/withdrawn 층에서 과잉 적용, 현재가 아닌 교리 사용, 무관 근거 인용, 거짓 확신, 중대 오류의 조건 간 차이.
5. **비용 차이:** 입력·출력 토큰, 지연, 재시도, 사람 검토·수정 시간, 현금 비용의 조건 간 차이.

## 3. 개입 계약

### 3.1 정제된 전통이 뜻하는 것

정제된 전통은 과거의 별도 합성 경험에서 도출되고 검토된, 출처·판본·적용 범위·금지 조건·반례·상태가 연결된 외부 문서 묶음이다. 이 정의는 형식을 확정하지 않는다. 실제 표현은 승인된 `selected_representation_ref`가 정한다.

전통 문서는 다음을 포함할 수 있지만 특정 과제의 정답을 포함해서는 안 된다.

- 과거 관찰에서 검증된 판단 원리와 그 근거 연결
- 적용 조건과 비적용 조건
- 불확실할 때 확인·보류·축소하는 기준
- active, superseded, withdrawn 같은 현재 상태와 판본 관계
- 대표 반례의 추상적 설명

### 3.2 전달 방식

초기 시험은 다음 중 하나를 사전에 하나만 선택해 모든 관련 조건에 동일하게 적용한다.

1. 동결된 문서 묶음을 그대로 문맥에 넣는 결정적 문서 주입
2. 동결된 검색 색인과 결정적 질의·상태 필터가 고른 문서를 문맥에 넣는 제한적 검색

가장 작은 시험에는 첫 방식이 우선이다. 이것은 내용 적용 효과와 검색 실패를 분리한다. 검색의 가치와 오류는 이후 별도 요인으로 시험한다. 어느 방식도 모델 가중치를 바꾸지 않으며 “모델 학습”으로 보고하지 않는다.

### 3.3 답 누출 금지

전통 패키지는 후속 과제의 답 또는 답을 거의 복원할 수 있는 근접 복사를 포함할 수 없다. 다음 중 하나라도 있으면 해당 과제군은 실행 전에 격리한다.

- 후속 과제와 동일하거나 치환만 한 이름, 수치, 식별자, 문장 배열
- 선택지나 결론을 직접 가리키는 템플릿
- oracle 판정을 역산할 수 있는 고유 표현 또는 동일한 근거 조합
- 표면만 바꾸고 핵심 증거·제약·예외의 배치가 복제된 사례
- 과제 작성 뒤 결과에 맞춰 전통을 보완한 흔적

누출 감사는 전통과 과제를 모두 볼 수 있지만 실행 출력과 조건별 결과를 보기 전에 끝낸다. 결함을 발견하면 결과를 보지 않은 새 작성자가 과제군을 교체하고 새 판본·해시·사전등록을 만든다. 문구 몇 개를 바꿔 같은 항목을 살리는 방식은 허용하지 않는다.

### 3.4 개입 충실도와 효과의 분리

다음은 기계적 정합성 확인일 뿐 성과 지표가 아니다.

- 동결 해시와 실제 주입 파일의 일치
- 조건별 허용 문서만 보였다는 확인
- 모델·도구·출력 한도·시스템 지시의 일치
- 각 실행이 과거 대화가 없는 새 세션이었다는 확인
- 조건 배정표와 익명 출력 ID의 일치
- 누락·재시도·중단 사유의 완전한 기록

하나라도 실패하면 해당 블록은 인과 분석에서 제외하고 원인을 수정한 새 판본으로만 다시 시작한다. 기계적 성공률을 전통 효과에 합산하지 않는다.

## 4. 비교 조건: 무엇이 최소이고 무엇이 진단용인가

| ID | 조건 | 묻는 질문 | 최소 파일럿 | 내용 특이 확인시험 | 정제 진단 |
|---|---|---|---:|---:|---:|
| A | 전통 없음 | 전달 패키지 전체가 없는 경우보다 나은가 | 필수 | 필수 | 필수 |
| B | 길이·형식 일치 무관 대조 | 관련 내용이 추가 토큰·형식·주의 환기보다 나은가 | 제외 가능 | 필수 | 권장 |
| C | 원본 기록 | 정제가 같은 원천 기록 접근보다 나은가 | 제외 | 선택 | 필수 |
| D | 정제된 전통 | 시험할 개입 | 필수 | 필수 | 필수 |

### 4.1 가장 작은 falsifiable 파일럿: A 대 D

- 장점: 가장 적은 호출로 패키지의 총효과, 심각한 음의 전이, 비용 폭증을 조기에 발견한다.
- 제한: D가 나아도 관련 내용 때문인지, 더 긴 문맥이나 문서 형식 때문인지 분리하지 못한다.
- 허용 주장: “이 동결 설정에서 D 패키지를 함께 제공한 출력이 A보다 나을 가능성이 관찰되었다.”
- 금지 주장: “정제된 전통 내용의 인과 효과가 입증되었다.”

파일럿이 무효하거나 위해 신호를 내면 조건을 늘리지 않고 먼저 중단·수정한다. 파일럿이 방향성만 보이더라도 확인시험 없이 효과 통과로 올리지 않는다.

### 4.2 관련 내용 확인시험: A, B, D

B는 D와 문서 수, 표현 구조, 대략적 입력 토큰, 상태·출처 표기의 밀도는 맞추되 시험 과제의 결정 패턴과 무관한 별도 합성 내용이어야 한다. 일반적인 “꼼꼼히 검토하라” 같은 조언을 B에서 빼고 D에만 남기면 비교가 깨지므로, 보편적 실행 안내는 모든 조건의 공통 wrapper로 이동한다.

D가 A와 B 모두보다 사전 임계값을 넘고 위해·비용 guardrail을 통과할 때만 관련 전통 내용의 제한적 효과를 지지할 수 있다. A보다만 좋고 B와 같으면 추가 문맥·주의 환기 또는 형식 효과와 구별되지 않는다.

### 4.3 원본 기록 진단: C의 선택적 추가

C는 같은 과거 합성 원천에 접근하지만 정제된 교리·적용 범위·상태 연결은 받지 않는다. C는 다음 판단이 실제로 필요할 때만 추가한다.

- 정제 작업이 단순한 과거 기록 열람보다 가치가 있는가
- 정제가 품질을 높이는 대신 중요한 맥락을 잃는가
- 정제 비용을 유지할 근거가 있는가

C와 D의 길이가 본질적으로 다르면 같은 입력 상한 아래 사전 고정된 중립 선택 규칙을 적용하고, 잘린 비율과 누락을 기록한다. 같은 상한에서 의미 있는 원본을 제공할 수 없으면 C–D는 깨끗한 인과 비교가 아니므로 탐색 결과로만 보고한다.

### 4.4 네 조건을 모두 쓰는 경우

네 조건은 한 번에 세 질문—총효과, 내용 특이성, 정제의 추가 가치—을 모두 답할 예산과 표본이 있을 때만 정당화된다. 네 조건 자체가 더 과학적인 것은 아니다. 표본을 조건 수로 나눠 각 비교가 무력해지거나, 조기 위해 신호를 늦게 발견한다면 오히려 나쁘다.

## 5. 과제군 설계 원칙

이 절은 구조 원칙만 정하며 후보 과제, 답, 수치, 도메인, 선택지 또는 oracle을 만들지 않는다. 아래의 추상 범주는 미래 항목으로 그대로 사용하지 않는다.

### 5.1 원천 경험과 후속 과제의 관계

1. 먼저 검증하려는 **잠재 결정 패턴**을 문장 수준이 아니라 관계 수준으로 고정한다. 예: 어떤 정보가 결정적이고, 어떤 제약이 우선하며, 어느 경계에서 확인 또는 비적용이 필요한지 같은 구조다.
2. 원천 경험과 후속 과제는 이 관계만 공유한다.
3. 후속 과제는 행위자, 산출물 종류, 수치, 명명, 문장 순서, 무관 정보, 제약의 표면 표현을 바꾼다.
4. 정답을 결정하는 근거와 예외의 논리는 보존하되, 원천 사례를 떠올리지 않아도 현재 과제 자체만으로 풀 수 있어야 한다.
5. 전통이 없는 조건에도 충분한 현재 과제 정보가 있어야 한다. D만 답을 알 수 있는 지식 주입 시험으로 만들지 않는다.
6. 과제는 전통 문서 작성 전에 별도 계획에서 파생되며, task/oracle 작성자는 최종 D 패키지를 보지 않는다.

### 5.2 필수 층

- **관련 전이:** 잠재 패턴과 적용 조건이 실제로 맞으며 전통 사용이 판단을 도울 수 있다.
- **비적용 유사성:** 표면은 비슷하지만 결정 패턴 또는 필수 적용 조건이 달라 전통을 적용하면 안 된다.
- **경계·불충분 정보:** 관련성은 있으나 필요한 확인이 없어 단정 대신 질문·보류·가역 조치가 맞다.
- **stale/withdrawn:** 과거에는 맞았지만 현재 조건 또는 상태 표지가 바뀌어 철회·대체 교리를 사용해야 한다.
- **무관 검색 저항:** 검색이나 문서 묶음에 무관한 기억이 있어도 근거로 채택하지 않아야 한다. 검색 자체가 개입이면 이 층을 별도 표시한다.

가장 작은 파일럿도 관련 전이와 위해 도전 층을 모두 포함한다. 확인시험에서는 각 층을 둘 이상의 독립 과제군에 분산해 특정 표현이나 한 가족의 난이도에 결과가 매이지 않게 한다.

### 5.3 stale/withdrawn 처리

오래된 교리 시험은 두 형태를 구분한다.

1. **상태 필터 시험:** withdrawn 항목이 현재 bundle에 나타나지 않아야 한다.
2. **상태 해석 시험:** 감사 목적 등으로 보이는 비현행 항목을 모델이 현재 지시로 사용하지 않아야 한다.

어느 형태를 쓰는지 사전에 고정한다. 철회 항목을 정답처럼 숨겨 넣고 모델이 알아서 눈치채기를 기대하지 않는다. 현재 상태와 대체 관계는 `selected_representation_ref`가 허용하는 명시적 표지로 제공한다.

### 5.4 독립성·누출 감사

실행 전 감사자는 다음을 pass/fail로 판정한다.

- 원천 경험과 후속 과제가 구체 서술을 공유하지 않는가
- D 패키지가 과제 또는 oracle 작성 뒤 수정되지 않았는가
- A/B/C/D가 공통 과제 정보를 동일하게 받는가
- B가 실제로 무관하고 D의 보편적 조언을 몰래 제거하지 않았는가
- C가 정제된 결론이나 상태 요약을 포함하지 않는가
- 후속 과제가 전통 없이도 자족적이며, 외부 비밀 지식을 요구하지 않는가

감사 불통과는 해당 가족 전체의 비보상 실패다.

## 6. 측정해야 할 음의 전이

전통의 적용률을 높이는 것은 목표가 아니다. 다음을 각각 관찰한다.

1. **과잉 적용:** 적용 조건이 맞지 않는데도 교리를 사용한다.
2. **stale/withdrawn 사용:** 현재가 아닌 판본을 결정 근거로 삼는다.
3. **무관 검색 채택:** 검색된 문서가 현재 증거보다 권위 있다고 취급된다.
4. **거짓 확신:** 근거가 부족한데도 확정적 결론과 높은 자신감을 보인다.
5. **확인 회피:** 전통 문구를 이유로 필요한 검증·질문·보류를 생략한다.
6. **비용 팽창:** 출력·검색·사람 수정이 늘어 순편익이 사라진다.
7. **탐색 억제:** 현재 과제의 반례나 더 적합한 대안을 검토하지 않는다.

관련 전이의 이득은 critical 위해를 보상할 수 없다. 세부 오류 등급과 분석 규칙은 측정 계획이 정한다.

## 7. 새 세션, 모델, 프롬프트 통제

### 7.1 새 세션 통제

- 각 과제–조건 실행은 대화 이력, 이전 출력, 다른 조건의 문서, 공유 agent memory가 없는 새 세션이다.
- 같은 세션에 A와 D를 순서대로 주는 진짜 crossover는 금지한다. 여기서 crossover는 과제 수준의 조건 교차이지 대화 내 교차가 아니다.
- executor는 다른 조건의 출력, 숨은 oracle, 채점 기준, 원천 경험을 보지 않는다.
- fixture-authoring 세션을 executor 세션으로 전환하거나 fork하지 않는다.
- 캐시나 공유 검색 상태가 조건 간 내용을 전달할 수 있으면 비활성화하거나 조건별 격리하고 확인한다.

### 7.2 모델·도구 통제

한 실행 블록 안에서 다음을 고정·기록한다.

- 정확한 모델 ID와 공급자에게 노출되는 버전·snapshot 정보
- 실행 날짜·시간창, service tier, region 등 가용한 환경 정보
- 추론 수준, temperature/top-p/seed처럼 노출되는 생성 설정
- system/developer/task wrapper의 판본과 해시
- 도구 목록, 검색 색인 판본, 네트워크·파일 가시성
- 입력·출력·시간·재시도 한도

공급자가 실행 중 모델을 바꿨을 가능성이 있거나 같은 모델 ID 아래 동작 변화가 감지되면 블록을 멈추고 전부 같은 새 블록에서 다시 수행하거나 `model-version-confounded`로 무효 처리한다. 모델 업그레이드 전후 결과를 이어 붙이지 않는다.

### 7.3 순서 효과

같은 과제를 A와 D에 모두 쓰되 각 실행은 독립 세션으로 하고, 조건 실행 순서를 과제군 안에서 무작위·균형 배치한다. 짧은 시간창에 A/D를 교차 배치해 시간 추세와 공급자 변화를 줄인다. 작업 난이도 순서, rate-limit, warm-cache, 운영자 피로가 한 조건에 몰리지 않게 블록화한다.

### 7.4 모델 간 전승의 별도 지위

초기 시험은 한 동결 모델에서 세션 간 외부 문서 효과만 본다. 다른 모델에서 같은 프로토콜을 독립적으로 반복하고 각 모델 안의 A/B/D 비교가 사전 기준을 통과하기 전에는 모델 간 전승을 주장하지 않는다. 더 강한 새 모델의 절대 성능 증가는 전통 효과가 아니다.

## 8. `selected_representation_ref` 인터페이스

이 설계는 S0가 D 또는 어떤 형식을 선택했다고 가정하지 않는다. 후속 CONTROL 통합 게이트가 다음 연결 정보만 채운다.

| 연결점 | 필요한 의미 | E0에서의 사용 |
|---|---|---|
| `selected_representation_ref` | 선택 표현 후보의 버전·해시 또는 승인된 단순 대체 기준선 | B/C/D의 표현 계약 고정 |
| `runner_visibility_contract_ref` | executor에게 보이는 필드와 숨겨야 할 필드 | 조건 가시성·누출 감사 |
| `evidence_citation_contract_ref` | 근거 ID를 표현하는 방식 | 출처 사용 채점의 공통 규칙 |
| `resource_envelope_ref` | 모델, 추론, 시간, 출력, 재시도 상한 | 조건 간 자원 동일화 |
| `known_limitations` | S0가 입증하지 못한 범위와 편향 | 주장 제한과 감도 분석 |

규칙:

1. 연결 정보는 표현 형식을 고정할 뿐 전통의 유효성을 말하지 않는다.
2. 모든 내용 조건에 같은 표현 계약을 적용한다. A의 공통 wrapper도 호환되게 고정한다.
3. S0가 유효 후보를 선택하지 못하면 E0가 임의로 D나 다른 형식을 승자로 채우지 않는다.
4. 그 경우 CONTROL은 E0를 보류하거나 가장 단순한 공개 표현 기준선으로 축소 시험을 별도 승인한다.
5. 실제 참조가 채워지고 해시가 확인되기 전에는 자료 작성, 구현, 실행 게이트를 열지 않는다.

## 9. 역할과 정보 격리

아래 역할은 미래 게이트가 열릴 경우의 최대 입력 경계다. 한 사람이 여러 역할을 맡아야 한다면 정보 노출 순서와 충돌을 기록하고, tradition curator와 task/oracle author, executor와 adjudicator는 겸임하지 않는 것을 최소선으로 한다.

| 역할 | 허용 입력 | 금지·책임 |
|---|---|---|
| CONTROL | 동결 설계, 해시, 심사 결과, 비용 승인 | 조건 결과를 보기 전 게이트·소유권·참조를 관리 |
| protocol owner | 이 설계 패키지와 승인 기준선 | 자료·정답·조건 결과를 만들지 않고 사전등록 동결 |
| source/tradition curator | 승인된 합성 원천 경험, 표현 계약 | 후속 과제·oracle·실행 출력 접근 금지 |
| task/oracle author | 동결된 잠재 결정 패턴 계약과 독립 합성 세계 규칙 | 최종 전통 패키지·조건 출력 접근 금지; 숨은 oracle은 저장소 밖 통제 |
| matched-control author | D의 길이·형식 통계와 무관 합성 원천 | 후속 과제·oracle·D의 정답성 서사 접근 금지 |
| leakage auditor | 동결 D/B/C와 후속 과제, 계보 기록 | 실행 결과를 보기 전에 근접 복사·관련성만 판정 |
| packager/scheduler | 통과한 조건 자료, 무작위 배정, 자원 봉투 | oracle 접근 금지; 익명 출력 ID 생성 |
| executor | 한 조건의 과제와 허용 문서·도구만 | 다른 조건, 원천 기록(해당 조건 제외), oracle, 결과 접근 금지; 매 실행 새 세션 |
| adjudicator | 익명 출력, 과제, 동결 oracle·결정 규칙 | 조건 라벨·전통 패키지·다른 채점 결과 접근 금지 |
| analyst | 잠긴 채점표, 조건 매핑, 비용 기록, 사전 계획 | 결과를 본 뒤 제외·임계값·비교를 변경하지 않음 |
| independent reviewer | 독립 심사 brief가 정한 최대 공개 입력 | 읽기 전용; 자료·oracle·실행을 만들지 않음 |

워크트리는 편집 충돌을 줄일 뿐 비밀 격리가 아니다. 숨은 oracle과 condition mapping은 executor가 볼 수 있는 저장소·세션·worktree 밖에서 통제해야 한다.

## 10. 통과가 지지할 수 있는 것과 없는 것

| 증거 단계 | 지지 가능한 주장 | 지지할 수 없는 주장 |
|---|---|---|
| 기계적 preflight 통과 | 계획된 비교가 실행 가능함 | 성능 개선 |
| A–D 파일럿 방향성 | 특정 동결 설정에서 패키지 총효과의 후속 확인 가치 | 관련 내용의 고유 효과, 정제 우위 |
| A/B/D 확인시험 통과 | 특정 모델·과제군·전달 방식에서 관련 정제 전통 내용이 출력 판단을 개선했다는 제한적 인과 근거 | 원본 대비 정제 우위, 모델 간 전승, 실전 가치 |
| C–D 진단 통과 | 같은 원천·자원 계약에서 정제가 원본 접근보다 나았다는 제한적 근거 | 모든 정제 방식의 우위 |
| 여러 동결 모델의 독립 반복 | 시험한 모델들에서 외부 전통 효과가 재현됐다는 근거 | 미시험 모델·세대로의 일반 전승 |

어떤 통과도 중앙 시스템 전체, Project Brain 통합, 실제 고객·공모전 프로젝트, 운영 안전성, 경제성, 장기 지속성 또는 파인튜닝 효과를 검증하지 않는다.

## 11. 현재 미결정 사항

다음은 결과를 보기 전에 후속 CONTROL·독립 심사·사용자 승인으로 정해야 한다.

1. `selected_representation_ref`와 나머지 연결 정보의 실제 판본·해시
2. 첫 모델·정확한 버전, 자원 봉투, 전달 방식
3. 잠재 결정 패턴 수와 과제군 구성
4. 최소 가치 효과, 최대 허용 위해, 비용 guardrail
5. 파일럿 뒤 A/B/D 확인시험으로 갈 조건
6. 원본 기록 C가 의사결정 가치가 있는지
7. B의 무관성·형식 일치를 누가 어떻게 독립 승인할지
8. 숨은 oracle의 저장소 밖 보관자와 결정적 adjudication 절차
9. 사람시간·토큰·현금의 stop-before-authoring 상한

이 미결정을 채우지 못하면 자료 작성이나 실행으로 진행하지 않는다.
