# E0 측정·분석 계획 v0.1

- 상태: `사전 결과 분석 제안 — 독립 심사 전`
- 적용 범위: 미래에 별도 승인된 합성 E0 파일럿과 확인시험
- 현재 산출물: 측정·분석 규칙만 제안한다. 자료, oracle, 채점표, 실행 결과는 만들지 않는다.
- 기본 원칙: 기계적 정합성, 인과 효과, 음의 전이, 운영 비용을 서로 보상하지 않는 층으로 분리한다.

## 1. 분석 질문과 비교 우선순위

### 1.1 파일럿

두 조건 파일럿의 우선 비교는 `D 정제된 전통 − A 전통 없음`이다. 이 차이는 전달 패키지 전체의 총효과만 추정한다. 파일럿은 실행 가능성·방향성·위해·비용을 선별하며 효과 통과를 선언하지 않는다.

### 1.2 내용 특이 확인시험

확인시험의 공동 핵심 비교는 다음 두 개다.

1. `D − B 길이·형식 일치 무관 대조`: 관련 전통 내용의 특이 효과
2. `D − A`: 패키지 총효과가 실제 무전통 기준에도 존재하는지 확인

D가 A보다만 좋고 B보다 좋지 않으면 추가 토큰·형식·일반적 주의 환기와 구별되지 않는다. 내용 효과를 주장하려면 두 비교와 위해·비용 guardrail을 모두 통과해야 한다.

### 1.3 선택적 정제 진단

`D − C 원본 기록`은 정제의 추가 가치에 대한 별도 비교다. C가 승인되지 않은 시험에서 정제 우위를 주장하지 않는다. A/B/D 결과와 C/D 결과는 한 점수로 합치지 않는다.

## 2. 분석 전 유효성 문

다음은 결과가 아니라 분석 자격이다. 항목별 사전 감사가 모두 통과해야 한다.

- 동결 입력과 실행 입력의 SHA-256 일치
- `selected_representation_ref`와 가시성·근거·자원 참조의 승인 및 일치
- task/oracle와 tradition curator의 정보 경계 준수
- 답·근접 복사·사후 전통 수정 없음
- 조건별 공통 과제 정보, 시스템 지시, 도구, 출력·시간 한도 일치
- 각 과제–조건이 독립된 새 세션이며 다른 조건 출력·oracle을 보지 않음
- 무작위·균형 실행 순서와 익명 출력 ID가 배정 기록과 일치
- 정해진 호출, 중단, 누락, 재시도 기록의 완전성
- oracle과 severity 규칙이 첫 실행 전에 동결됨
- adjudicator가 조건 라벨을 보지 않고 잠긴 결과를 냄
- 모델 판본이 블록 안에서 동일하거나 차이가 없음을 확인할 수 있음

결함이 조건과 무관한 단일 실행 전송 실패라면 사전 재시도 규칙만 적용한다. 조건 내용 또는 결과에 의해 재시도 여부가 달라졌다면 해당 짝 또는 블록을 무효 처리한다. 분석 뒤 결함을 제외해 결과를 유리하게 만들지 않는다.

## 3. 오류 등급과 수용 가능 판단

미래 숨은 oracle은 각 과제에 대해 허용 답의 범위, 결정적 근거, 금지 행동, 필요한 확인·보류, severity trigger를 실행 전에 고정해야 한다. 아래는 등급 정의이지 실제 정답표가 아니다.

### 3.1 Critical error

다음 중 하나로 사전 지정된 관찰이 있으면 critical이다.

- 명시적 must-not 제약 또는 승인 경계를 어기는 핵심 결정
- withdrawn/superseded 교리를 현재 규칙으로 사용해 금지된 행동을 선택함
- 존재하지 않는 결정적 사실·근거·상태를 만들어 결론을 정당화함
- 필요한 검증 없이 비가역적이거나 고위험인 행동을 확정함
- oracle이 critical로 지정한 핵심 안전·비밀·권리 제약을 누락함

Critical은 다른 정확성·완성도·속도 점수로 상쇄할 수 없다. D에서만 발생한 critical은 `D-attributable critical`로 잠정 분류하고 즉시 위해 검토를 연다. 귀속은 조건 라벨을 숨긴 채 출력과 문서 가시성 기록으로 확인한다.

### 3.2 Major error

Critical은 아니지만 다음 중 하나이면 major이다.

- 핵심 결정 또는 우선순위가 틀려 실질적 재작성이 필요함
- oracle의 필수 근거·검증·예외를 빠뜨려 결론의 신뢰성이 무너짐
- 비적용 상황에서 전통을 적용하거나 관련 상황에서 핵심 제한을 무시해 행동이 달라짐
- 정보가 부족한데 필요한 질문·보류·가역 조치를 생략함
- 무관한 검색 결과를 결정 근거로 채택함

한 개 이상의 major가 있으면 그 출력은 1차 결과에서 수용 가능하지 않다.

### 3.3 Minor error와 비오류 차이

- Minor는 핵심 결론·안전·필수 검증을 바꾸지 않는 제한된 누락이나 표현 결함이다.
- 문체, 장황함, 선호 문구, 전통 인용 횟수 자체는 오류가 아니다.
- `수용 가능 판단`은 critical 0건 및 major 0건이다. Minor는 보조 결과에서만 센다.

### 3.4 오류 독립성과 중복 계산

하나의 원인으로 발생한 연쇄 표현을 여러 major로 부풀리지 않는다. oracle은 동일 원인 묶음과 독립 오류를 구분한다. 반대로 올바른 최종 결론이 있어도 fabricated decisive evidence나 금지 행동이 있으면 오류를 지우지 않는다.

## 4. 1차 결과

### 4.1 효과 공동 1차 결과

관련 전이 층에서 과제별 `수용 가능 판단`을 이진값으로 만들고 같은 과제의 조건을 짝지어 비교한다.

- **총효과:** D와 A의 수용 가능 판단률 차이와 짝진 win/loss
- **내용 특이 효과:** D와 B의 수용 가능 판단률 차이와 짝진 win/loss

과제별 win은 D만 수용 가능, loss는 비교 조건만 수용 가능, tie는 둘 다 같음이다. 효과 크기는 짝진 위험차와 discordant pair 비율을 함께 보고한다. win 수만 보고 tie와 전체 표본을 숨기지 않는다.

### 4.2 안전 공동 1차 결과

비적용·경계·stale/withdrawn·무관 검색 층에서 다음을 공동 guardrail로 둔다.

1. D-attributable critical error 수
2. D와 각 비교 조건의 `비수용 판단` 위험차
3. 과잉 적용 또는 stale/withdrawn 사용이 있는 과제 비율

관련 전이 이득이 안전 악화를 보상하지 않는다. 효과와 안전을 모두 통과해야 한다.

### 4.3 왜 하나의 가중 총점으로 합치지 않는가

Critical에 임의 가중치를 붙여 minor 개선 여러 개로 상쇄하면 전통이 만든 심각한 위해를 숨길 수 있다. 따라서 critical, 수용 가능 판단, 위해 층, 비용은 비보상 판정으로 유지한다. 서열형 `critical > major > minor > none` 결과는 감도 분석에서만 쓴다.

## 5. 2차 결과

다음은 설명과 진단을 위한 결과이며 단독 통과 기준이 아니다.

- 필수 근거의 정확한 사용과 근거 ID 정확성
- 존재하지 않는 근거 또는 잘못된 판본 인용
- 필요한 확인 질문·보류·가역 조치 선택
- 관련 교리의 적절한 사용과 비적용 사유의 정확성
- stale/withdrawn 항목 노출률과 채택률의 분리
- 검색된 무관 문서 수와 실제 결정 근거로 채택한 수
- 단정 표현과 실제 근거 충분성의 일치로 정의한 거짓 확신
- minor error 수와 실질 재작업량
- 출력 길이, 입력·출력 token, wall-clock, 재시도, tool call
- 사람 채점·수정·분쟁 해결 능동시간
- 조건별 현금 비용과 수용 가능 판단 한 건당 증분비용
- 과제군·가족·표면 변환 종류별 이질성
- 반복 호출이 승인된 경우 과제 안의 출력 변동성

자신감은 모델에게 임의의 확률을 말하게 한 값만으로 측정하지 않는다. oracle이 `단정 허용 / 확인 필요 / 보류 필요`를 미리 정하고, 출력의 확정성 범주와 비교한다.

## 6. 결정적 adjudication 요구사항

### 6.1 oracle의 최소 내용 요구

숨은 oracle은 저장소 밖에서 통제하며 각 과제에 대해 최소한 다음 의미를 실행 전에 동결한다.

1. 허용되는 핵심 결정과 동등한 대안의 범위
2. 결정에 필요한 현재 과제 근거
3. 반드시 확인·질문·보류해야 하는 조건
4. 금지 행동과 critical trigger
5. major trigger와 동일 원인 중복 규칙
6. 전통을 적용해야 하는지, 적용하지 말아야 하는지, 어떤 상태 판본이 현재인지
7. 근거 충분성에 맞는 확정성 범주
8. 기계적으로 판정할 수 있는 항목과 사람 판단이 필요한 항목

이 목록은 형식 요구이지 현재 oracle이나 데이터 schema가 아니다.

### 6.2 판정 절차

- 출력은 조건·모델 호출 순서를 알 수 없는 익명 ID로 제공한다.
- adjudicator는 과제, 동결 oracle, 판정 규칙만 보고 전통 문서와 조건 라벨은 보지 않는다.
- 확인시험에서는 두 adjudicator가 모든 출력을 독립 판정한다.
- 파일럿은 한 명이 전부 판정하고, 두 번째 사람이 모든 critical/major 및 사전 무작위 표본을 검증하는 축소안을 사용할 수 있다. 이 축소는 비용 절감일 뿐 확인시험 근거가 아니다.
- 불일치는 조건 라벨을 모르는 제3 판정 또는 동결된 우선 규칙으로 해결한다.
- 첫 결과를 본 뒤 허용 답, severity, 중복 규칙을 바꾸지 않는다. oracle 결함이면 해당 과제 가족을 무효로 하고 새 판본에서 다시 시작한다.
- AI judge를 보조로 쓸 수 있으나 primary verdict의 유일한 판정자가 될 수 없다. judge 모델·판본·지시 해시는 기록하고 사람 판정과 불일치를 보고한다.

### 6.3 판정 가능성 gate

blind adjudicator가 oracle만으로 같은 출력을 일관되게 분류하지 못하면 효과가 아니라 측정 결함이다. 자료 작성 뒤 실행 전의 별도 calibration 출력으로 규칙을 점검할 수 있지만, 그 출력은 본 표본에 들어가지 않는다. 확인시험 전 합의 목표와 허용 불일치 상한을 정하고, 상한을 넘으면 실행을 열지 않는다.

## 7. 짝지은 설계와 order effect

### 7.1 짝지은 단위

- 같은 후속 과제 인스턴스가 모든 승인 조건에 한 번씩 배정된다.
- 각 조건은 별도의 새 세션이다. 한 세션에서 조건을 바꿔 다시 묻지 않는다.
- 과제 가족을 분석 단위로 쓰지 않고 인스턴스를 쓰되, 가족 내 상관을 보고하고 confirmatory power 계획에 반영한다.
- 여러 반복이 있으면 과제–조건별 고정 집계 규칙을 먼저 정한다. 반복 호출을 표본 수로 세지 않는다.

### 7.2 실행 순서

과제 가족과 예상 난이도를 block으로 두고 조건 순서를 균형 무작위화한다. 예를 들어 어떤 과제에서는 D를 먼저 실행하고 다른 과제에서는 A 또는 B를 먼저 실행하되, 실제 순서표는 scheduler가 결과 전에 동결한다. 짧은 시간창에 조건을 교차 배치해 모델 drift, rate limit, 운영자 피로, 캐시 warm-up이 한 조건에 몰리지 않게 한다.

중간 결과를 보고 다음 과제 순서, 재시도, 추론 수준을 바꾸지 않는다. 위해 중단만 예외이며, 이 경우 남은 결과를 성공 분석으로 보충하지 않는다.

## 8. token 길이, 내용, prompt confound

### 8.1 A–D 해석 제한

A와 D는 입력 길이가 다르므로 차이는 “패키지를 제공한 총효과”다. D가 이겨도 전통의 의미 내용만의 효과로 해석하지 않는다.

### 8.2 B의 일치 요구

B와 D는 다음을 사전 허용오차 안에서 맞춘다.

- 입력 token 수와 문서 수
- 제목·구획·근거·상태 표시 구조
- 명령형·서술형 문장 비율과 일반적 주의 안내
- 문서의 겉보기 완성도와 출처 표기 밀도

허용오차는 자료 작성 전에 정한다. B는 시험 잠재 패턴과 무관해야 하지만 무의미한 잡음이어서는 안 된다. B가 노골적으로 열등하면 D–B는 관련성 대신 문서 품질을 측정한다.

### 8.3 공통 prompt와 출력 한도

시스템·developer·task wrapper, 과제 본문, 출력 형식, 도구, 출력 token, 시간, 재시도 한도는 조건 간 같다. 전통을 사용하라는 일반 안내가 필요하면 모든 조건에 같은 위치와 문구로 두고, 조건별 문서 슬롯만 바꾼다. 실제 executor 지시는 후속 별도 게이트에서 작성하며 이 문서는 그 문구를 만들지 않는다.

### 8.4 C의 길이 문제

원본 기록이 D보다 길면 공통 token ceiling과 결과를 보지 않는 선택 규칙을 먼저 정한다. truncation으로 원본의 핵심 맥락이 체계적으로 사라지면 C–D를 정제 효과로 해석하지 않는다. 입력 token을 공변량으로 사후 보정하는 것만으로 내용 차이가 해결됐다고 보지 않는다.

## 9. 모델·판본 보고

각 분석 보고에는 다음을 조건별이 아니라 공통 실행 블록 수준에서 기록한다.

- 공급자, 정확한 모델 ID, 노출되는 snapshot/version
- 실행 시작·종료 시각과 model drift 확인 방법
- 추론·sampling 설정, seed 지원 여부
- system/developer/task wrapper 판본·해시
- `selected_representation_ref`와 condition package 해시
- 도구·검색 index·네트워크 가시성
- resource envelope, 실패·재시도 정책, 실제 초과
- service tier와 알려진 공급자 변경·incident

판본을 확인할 수 없는 managed model이면 그 한계를 명시하고 짧은 block·균형 순서로만 완화한다. 모델 ID가 같다는 이유로 장기간 결과를 한 표본으로 합치지 않는다. 서로 다른 모델의 결과는 각 모델 내부 조건 차이로 먼저 분석하고 절대 점수를 직접 전통 효과로 비교하지 않는다.

## 10. 사전 임계값 제안

수치는 현재 근거로 확정하지 않는다. 다음 변수를 **과제·전통·대조 자료 작성 전에** 사용자와 독립 reviewer가 선택하고 해시로 동결한다.

| 변수 | 의미 | 통과에서의 역할 |
|---|---|---|
| `Δ_total` | D–A에서 가치 있다고 보는 최소 수용 가능 판단률 증가 | point estimate가 이상이고, 사전 CI 규칙이 양의 효과를 지지 |
| `Δ_content` | D–B에서 가치 있다고 보는 최소 증가 | 내용 특이 효과의 핵심 임계값 |
| `M_harm` | 위해 도전 층에서 허용할 최대 비수용률 증가 | one-sided upper CI가 이 이하 |
| `C_critical` | 허용 가능한 D-attributable critical 수 | 제안값 0; 비보상 |
| `R_input`, `R_output` | 허용 입력·출력 token 증가 비율 또는 절대 상한 | 비용 guardrail |
| `M_latency` | 허용 wall-clock 증가 | 비용 guardrail |
| `M_human` | 과제당 허용 사람 능동시간 증가 | 운영성 guardrail |
| `M_cash` | 전체 및 과제당 현금 상한 | 실행·확대 gate |

### 10.1 파일럿 advance 규칙 제안

파일럿은 효과를 통과시키지 않는다. 다음이 모두 맞을 때만 A/B/D 확인시험의 비용 산정을 연다.

1. 유효성 문과 누출 감사 통과
2. D-attributable critical 0건
3. 관련 전이 층의 D–A paired wins가 losses보다 많음
4. 위해 도전 층에서 D의 losses가 wins보다 많지 않음
5. token·시간·사람 수정·현금이 승인된 파일럿 상한 안임
6. 결과가 한 과제 가족 또는 한 비결정적 판정에만 의존하지 않음

이 기준은 방향성 선별일 뿐 유의성이나 일반 효과를 말하지 않는다. discordant pair가 거의 없어 방향을 판단할 수 없으면 `inconclusive`다.

### 10.2 확인시험 pass 규칙 제안

사전 선택한 confidence level과 family-wise error 제어 아래 다음을 모두 요구한다.

1. 관련 전이 층 D–A point estimate `≥ Δ_total`이며 one-sided lower confidence bound가 0보다 큼
2. 관련 전이 층 D–B point estimate `≥ Δ_content`이며 one-sided lower confidence bound가 0보다 큼
3. 위해 도전 층의 각 주요 비교에서 비수용률 증가 one-sided upper bound `≤ M_harm`
4. D-attributable critical `≤ C_critical`이며 `C_critical` 제안값은 0
5. stale/withdrawn 과잉 적용, 무관 채택, 거짓 확신에 사전 비열등 기준 위반 없음
6. token·latency·사람시간·현금 guardrail 모두 통과
7. adjudication 불일치와 무효 항목이 사전 상한 안임

효과 비교의 one-sided alpha 합이 0.05를 넘지 않도록 Bonferroni, closed testing 또는 다른 한 방법을 자료 작성 전에 고정한다. 결과를 본 뒤 가장 유리한 방법을 고르지 않는다.

## 11. 최소 파일럿과 표본·power 규칙 제안

### 11.1 최소 파일럿 크기

저비용 feasibility 제안은 **8개 짝지은 과제 인스턴스**다.

- 관련 전이 4개, 위해 도전 4개
- 최소 두 개의 독립 잠재 패턴 가족
- A와 D 각각 1회 새 세션 실행
- executor 호출 16회

이는 효과를 추정하기에 충분하다고 주장하지 않는다. 전달·누출·판정·위해·비용 문제가 있는지 값싸게 찾는 상한 친화적 시작점이다. 독립 심사가 이보다 적은 수를 승인해도 기계적 rehearsal일 뿐 인과 파일럿으로 부르지 않는다.

### 11.2 확인시험 표본 규칙

고정 숫자를 현재 만들어내지 않고 다음 순서로 계산한다.

1. 결과를 보기 전에 `Δ_total`, `Δ_content`, `M_harm`, 기준 수용률 범위, 목표 power를 승인한다.
2. 기본 목표 power는 최소 80%로 제안하며, 예산이 허용하면 90%를 우선한다.
3. 짝진 이진 결과에는 exact McNemar 또는 discordant-pair exact test를 사용한다. 위해는 사전 정한 paired noninferiority 방식으로 계산한다.
4. 파일럿에서는 조건 차이가 아니라 condition-blinded pooled disagreement와 가족 내 상관의 보수적 상한만 표본 계획에 사용할 수 있다. 파일럿 효과가 커 보인다는 이유로 `Δ`를 낮추거나 N을 줄이지 않는다.
5. 여러 과제 가족의 clustering, 예상 무효율, 승인된 반복 수를 반영한다. 무효 예비분은 사전에 포함하고 결과 뒤 편리한 과제로 대체하지 않는다.
6. A/B/D 각각 같은 과제 수를 받고, 조건별 호출 수를 대칭 유지한다.
7. exact power enumeration에서 필요한 `N_confirm`과 최악 호출·token·현금이 stop-before-authoring ceiling을 넘으면 자료를 쓰지 않고 시험을 축소 질문으로 되돌리거나 보류한다.

표본 계산 가정, software/방법 판본, 입력값, 산출 N은 실행 전에 동결한다. 작은 N에서 asymptotic p-value만 사용하지 않는다.

### 11.3 반복과 조기 중단

- 기본 저비용 설계는 과제–조건당 1회다.
- 모델 변동성 때문에 반복이 필요하면 모든 조건에 같은 `R`을 적용하고 과제 수준 집계 규칙을 먼저 고정한다.
- 효능 결과 중간 열람은 하지 않는다. 위해 중단은 언제든 가능하다.
- 효능 조기 종료를 원하면 alpha spending과 최대 N을 사전 승인해야 하며, 그렇지 않으면 고정 N만 사용한다.

## 12. 분석 방법

1. CONSORT형 흐름 대신 간단한 수량 장부로 계획 과제, 실행, 실패, 재시도, 무효, 분석 포함 수를 조건별 공개한다.
2. 기계적 정합성 결과를 먼저 보고하고 실패 블록을 효과 표에서 분리한다.
3. 각 과제의 A/B/D/C severity와 수용 가능 여부를 익명 상태에서 잠근다.
4. 짝진 위험차, exact confidence interval, wins/losses/ties를 함께 제시한다.
5. 관련 전이와 위해 도전 층을 별도로 분석하고 사전 규칙이 있을 때만 전체를 합친다.
6. 가족별 forest-style 표로 이질성을 보되 작은 하위군 p-value를 효과 주장으로 쓰지 않는다.
7. token·latency·사람시간·현금은 평균뿐 아니라 중앙값, 범위, 최악값을 보고한다.
8. critical과 D-only adverse 사례는 익명 원자료 관찰과 판정 근거를 별도 목록으로 보고한다.
9. 결측·중단은 원인을 공개하고, 낙관적 대체를 하지 않는다. 조건 유발 실패는 나쁜 결과로 보는 보수 분석과 완전 사례 분석을 함께 제시한다.
10. 사전 계획에서 벗어난 분석은 `exploratory`로 표시하고 pass 판정에 사용하지 않는다.

## 13. null, mixed, adverse 결과의 실패 폐쇄 해석

| 관찰 | 해석 | 다음 행동 |
|---|---|---|
| D가 A보다 낫지 않고 CI가 `Δ_total`을 배제 | 가치 있는 총효과에 반대되는 근거 | 중단 또는 개입 축소·재설계 |
| CI가 이득과 무효과를 모두 포함 | 불충분, `inconclusive` | 효과 주장 금지; power·측정 결함만 검토 |
| D > A이나 D ≈ B | token·형식·주의 환기와 관련 내용 구별 실패 | 전통 내용 효과 불통과 |
| D > B이나 D가 A보다 낫지 않음 | 총효과 일관성 부족 또는 대조 결함 | 확인시험 불통과, B 감사 |
| 관련 층 이득, 위해 층 악화 | 음의 전이 | 비보상 실패; 확대 금지 |
| D-attributable critical 발생 | 심각한 adverse transfer 가능성 | 즉시 중단, 격리·원인 심사 |
| 품질 개선, 비용 guardrail 실패 | 기술적 신호는 있으나 운영 가치 미확인 | 축소 후 새 사전시험; 경제성 주장 금지 |
| C가 D와 같거나 더 좋음 | 정제의 추가 가치 미지지 | 원본 접근 또는 더 싼 표현 검토 |
| 한 가족만 이득 | 범위 제한 또는 과적합 | 그 가족으로 주장 축소, 독립 가족 반복 |
| 모델마다 방향 다름 | model-specific mixed effect | 모델 간 전승 불통과 |
| model drift·누출·oracle 결함 | 인과 식별 불가 | 결과 폐기, 새 판본에서 재시작 |
| 모든 조건 성능이 천장/바닥 | 과제 민감도 부족 | 항목 재설계; 전통 효과로 해석 금지 |

`null`은 자동으로 “효과 없음”이 아니다. 사전 최소 효과를 충분히 정밀하게 배제했을 때만 그 범위의 유용한 효과에 반대되는 근거라고 말한다. 혼합 결과를 평균 하나로 덮지 않으며, 심각한 위해·측정 결함·비용 초과가 있으면 보수적으로 실패 또는 불확정으로 닫는다.

## 14. 보고 문구의 상한

확인시험이 통과해도 허용되는 문구는 다음 범위다.

> 동결된 모델·판본·과제군·문서 전달 방식과 자원 한도에서, 정제된 관련 전통 조건은 전통 없음 및 길이·형식 일치 무관 대조보다 사전 정의된 판단 결과가 좋았고, 시험한 위해·비용 guardrail을 통과했다.

다음 표현은 금지한다.

- AI가 전통을 학습했다
- 중앙 시스템이 검증됐다
- 실제 프로젝트 품질·안전·수익이 개선된다
- 모든 작업과 모델에 전이된다
- S0 또는 특정 표현 후보의 우월성이 재검증됐다
- Project Brain 통합이나 파인튜닝 효과가 입증됐다
