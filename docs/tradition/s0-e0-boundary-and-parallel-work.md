# S0–E0 경계와 병렬 작업 규칙

- 문서 상태: `CONTROL 경계 제안 v0.1`
- 기준선: `central-system-v2.1-s0-preparation`
- 작성일: `2026-08-07` (KST)
- 범위: 연구·기획·설계 작업의 분리와 연결 규칙
- 구현, 합성 문제 작성, 실행, 채점, 봉인 자료 접근 승인: **없음**

## 1. 이 문서가 필요한 이유

현재 프로젝트에는 서로 다른 두 질문이 있다.

1. AI에게 같은 경험을 **어떤 형태로 보여줘야** 판단 오류가 적은가?
2. 경험을 전달하는 전통 시스템이 **실제로 다음 작업을 개선하는가?**

첫 번째는 S0, 두 번째는 이 문서에서 임시로 E0라고 부른다. 두 시험을 한 설계에 섞으면 “표현 방식이 좋아서 나아진 것”과 “전통 내용이 유용해서 나아진 것”을 구별하기 어렵다. 반대로 S0가 완전히 끝날 때까지 E0 설계를 시작하지 않으면 독립적으로 진행할 수 있는 기획 작업이 불필요하게 멈춘다.

따라서 **설계는 병렬로 진행하되, 자료 작성·구현·실행은 각 게이트와 의존성에 따라 순차적으로 연다.**

## 2. 현재 확인된 상태

### 확인된 사실

- 저장소는 아직 S0 준비 단계다.
- URC-0.4 질문 계약 후보는 독립 심사에서 재설계 판정을 받았다.
- S0, 중앙 전통 시스템, Project Brain 연결, 운영 안전성, 경제성, 모델 간 전승 효과는 구현되거나 검증되지 않았다.
- 봉인 후보, 숨은 정답, 실제 S0 실행은 현재 닫혀 있다.

### CONTROL의 제안

- `E0`는 “전통 효과 소규모 시험”을 가리키는 작업 이름으로 사용한다.
- E0는 아직 기존 기준선에 동결된 공식 단계가 아니다. 별도 설계와 독립 심사를 거쳐야 한다.
- S0와 E0의 설계는 분리된 세션·작업 경로에서 병렬로 진행할 수 있다.

## 3. 한눈에 보는 경계

| 구분 | S0 | E0 |
|---|---|---|
| 핵심 질문 | 같은 사실을 어떤 구조로 보여줘야 AI 판단이 좋아지는가? | 검증된 경험을 전달하면 다음 작업의 AI 판단이 실제로 좋아지는가? |
| 바꾸는 것 | 사실의 표현 형식 | 제공하는 경험의 종류와 유무 |
| 고정해야 하는 것 | 사실 내용, 질문, 모델, 기회, 시간·출력 한도 | 작업 내용, 모델, 표현 형식, 기회, 시간·출력 한도 |
| 대표 비교 | 동일 사실의 표현 A–D | 전통 없음, 대조 기억, 원본 기록, 정제된 전통 |
| 1차 결과 | 후속 시험에 사용할 기본 경험 표현 후보 | 전통의 유효성·부작용·비용에 대한 제한된 근거 |
| 현재 허용 | 공개 질문 계약 v0.5 재설계 | 효과시험 방법 설계 |
| 현재 금지 | 문제·정답·실행·S0 결론 | 문제 묶음·구현·실행·효과 결론 |

`전통 없음 / 대조 기억 / 원본 기록 / 정제된 전통`은 E0가 검토할 초기 비교안이지 이 문서가 확정한 시험 조건이 아니다.

## 4. 의존성 규칙

### 병렬로 가능한 작업

- S0 질문 계약 v0.5의 의미 체계, 채점 관찰, 공정성·비용 시험 설계
- E0의 효과 가설, 비교 조건, 결과 지표, 부작용, 비용 상한, 중단 규칙 설계
- 각 작업의 독립 심사 기준 작성

### S0 결과 전에는 열 수 없는 E0 작업

- 최종 경험 표현 형식을 전제로 한 E0 입력 패키지 작성
- E0 합성 작업·정답·평가 자료 작성
- E0 실행 도구 구현
- E0 모델 세션 실행과 효과 판정

E0 설계는 S0 결과가 아직 없을 때 `selected_representation_ref`라는 빈 연결점만 정의한다. 실제 값은 S0가 유효한 표현 후보를 선택하고 CONTROL이 별도 통합 게이트에서 승인한 뒤에만 채운다.

S0가 명확한 표현 후보를 선택하지 못하면 E0는 임의로 D나 다른 형식을 우승자로 가정하지 않는다. 가장 단순한 공개 기준선으로 제한된 별도 시험을 할지, E0를 보류할지 CONTROL이 다시 판단한다.

## 5. 세션과 작업 경로 분리

### CONTROL 세션

책임:

- 공통 경계, 게이트, 해시, 파일 소유권 관리
- 두 설계가 서로의 결과를 미리 가정하지 않는지 확인
- 각 독립 심사 후 연결 여부 판단

CONTROL은 설계 경쟁자의 초안을 대신 작성하거나, 한쪽 결과를 다른 쪽에 정답처럼 전달하지 않는다.

### S0 설계 세션

- 제안 브랜치: `codex/s0-question-contract-v05`
- 전용 출력 경로: `s0-lab/control/f0-public/question-contract-v0.5/`
- 다음 게이트: `F0-PUBLIC QUESTION CONTRACT V0.5 REDESIGN OPEN`
- 입력: 승인된 공개 S0 기준선, v0.4 실패 근거, 이 경계 문서
- 금지: E0 초안, 봉인 자료, 실행 결과, 효과 주장

### E0 설계 세션

- 제안 브랜치: `codex/e0-effect-test-design`
- 전용 출력 경로: `docs/tradition/e0-effect-test/`
- 다음 게이트: `E0 TRADITION EFFECT TEST DESIGN OPEN`
- 입력: 목적·철학, 중앙 시스템 공개 기준선, 로드맵·평가 문서, 이 경계 문서
- 금지: S0 봉인 자료, S0 문제·정답, 미완성 v0.5 초안, 실제 고객·개인·비밀·과거 프로젝트 자료

두 세션은 서로의 초안을 읽지 않는다. 각 설계가 완료되고 해시가 고정된 뒤 CONTROL이 처음으로 함께 비교한다.

## 6. 워크트리의 역할과 한계

- 별도 워크트리는 파일 충돌과 실수로 인한 혼합 커밋을 줄이는 용도다.
- 별도 세션은 대화 기억과 추론의 상호 오염을 줄이는 용도다.
- 워크트리 분리만으로 비밀이나 숨은 정답이 보호된다고 보지 않는다.
- 봉인 자료와 숨은 정답은 이후 승인된 역할에서도 저장소·실행 세션과 별도 통제해야 한다.
- 두 브랜치는 같은 기준 커밋에서 시작하고, 각자 소유한 경로 밖의 파일을 수정하지 않는다.

## 7. E0 설계가 반드시 답해야 할 질문

E0 설계 세션은 구현 없이 최소한 다음을 결정해야 한다.

1. “전통의 효과”를 어떤 관찰 가능한 변화로 정의할 것인가?
2. 전통 내용의 효과와 추가 토큰·설명량의 효과를 어떻게 분리할 것인가?
3. 전통 없음, 길이·형식이 비슷한 대조 자료, 원본 기록, 정제된 전통 중 어떤 조건이 최소 설계에 필요한가?
4. 과거 사례의 문장을 복사하는 문제가 아니라, 겉모양이 다른 새 상황에 교훈을 적용하는 능력을 어떻게 시험할 것인가?
5. 같은 실수 감소뿐 아니라 잘못된 과잉 적용과 오래된 교훈 고착을 어떻게 측정할 것인가?
6. 모델·버전·추론 수준 변화와 전통 효과를 어떻게 구분해 보고할 것인가?
7. 오류, 완성도, 토큰, 시간, 비용 중 무엇을 우선 판단할 것인가?
8. 어느 수준의 비용·효과에서 중단, 수정, 확대할 것인가?
9. 한 사람이 운영할 수 있도록 가장 작은 시험 단위는 무엇인가?
10. 어떤 결과도 중앙 시스템 전체의 유효성이나 모델 파인튜닝 효과로 과장하지 않게 할 것인가?

## 8. S0가 E0에 전달할 최소 연결 정보

S0가 유효한 결론을 얻었다면 E0에는 결과 전체가 아니라 다음 연결 정보만 전달한다.

- `selected_representation_ref`: 선택된 표현 후보의 버전과 해시
- `runner_visibility_contract_ref`: AI가 볼 수 있는 필드와 볼 수 없는 필드
- `evidence_citation_contract_ref`: 근거 ID를 표현하는 공통 방식
- `resource_envelope_ref`: 모델, 추론 수준, 시간, 출력 크기, 재시도 상한
- `known_limitations`: S0가 입증하지 못한 범위와 발견된 편향

E0는 S0 점수나 우승 서사를 프롬프트에 넣지 않는다. 연결 정보는 표현 형식을 고정하기 위한 것이지, 전통이 유효하다는 사전 결론이 아니다.

## 9. 통합 게이트

두 설계가 각자 독립 심사를 마치면 CONTROL은 다음만 확인한다.

1. S0와 E0가 서로 다른 원인을 조작하고 있는가?
2. E0가 S0 결과를 전통 효과로 잘못 세지 않는가?
3. S0가 E0 효과 가설에 맞춰 표현 우승 조건을 바꾸지 않았는가?
4. 공통 모델·자원·출력 규칙을 재사용할 수 있는가?
5. 전체 예상 비용과 사람 운영 시간이 승인 가능한가?
6. 다음 단계가 설계, 공개 자료 작성, 구현, 실행 중 무엇인지 명확한가?

한쪽이 실패하면 다른 쪽 설계를 자동 폐기하지 않는다. 다만 실패한 결과에 의존하는 작업은 보류하고, 대체 연결점이나 축소 시험을 별도 승인한다.

## 10. 권장 진행 순서

```text
이 경계 문서 검토·고정
  ├─ S0 세션: 질문 계약 v0.5 재설계 → 독립 심사
  └─ E0 세션: 전통 효과시험 설계 → 독립 심사
                 ↓
            CONTROL 통합 검토
                 ↓
      S0 공개 자료·구현·실행 게이트 판단
                 ↓
   유효한 표현 후보가 있을 때만 E0 자료·구현 게이트 판단
```

## 11. 중단 조건

다음 중 하나라도 발생하면 관련 작업을 멈춘다.

- S0와 E0가 같은 초안이나 결과를 서로의 정답으로 사용함
- E0가 S0의 미검증 표현을 이미 선택된 기준으로 가정함
- 실제 고객·개인·비밀·과거 프로젝트 내용이 시험 자료로 들어감
- 봉인 자료나 숨은 정답이 일반 저장소·실행 세션에 노출됨
- 결과를 본 뒤 표본, 임계값, 비용 상한, 비교 조건을 유리하게 변경함
- 작업 경로가 겹치거나 다른 브랜치의 소유 파일을 승인 없이 수정함
- 설계 결과를 구현·효과 검증 완료로 표현함

## 12. 이 문서가 승인하지 않는 것

이 문서는 병렬 설계를 위한 경계만 제안한다. 다음을 승인하거나 입증하지 않는다.

- URC-0.5 또는 다른 질문 계약의 정답성
- E0 비교 조건이나 통계 방식의 적절성
- 합성 자료, 숨은 정답, 구현, 실행, 채점
- S0 또는 E0의 통과
- 전통 시스템, 중앙 시스템, Project Brain 연결의 유효성
- 운영 안전성, 경제성, 실제 프로젝트 효과, 모델 간 전승
