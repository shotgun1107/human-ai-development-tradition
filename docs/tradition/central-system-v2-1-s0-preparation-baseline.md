> 비의미: 구현 완료, S0 합격, 실제 자료·운영·효과·안전·브랜드 승인 아님

## 1. 결정

`central-tradition-system-v2-integrated-candidate-v2.1.md`를 S0 준비의 활성 기획·설계 기준선으로 사용한다.

독립 제한 재심사의 최종 판정은 `현재 v2.1로 S0 준비 가능`이다. D01–D14는 충분 반영 8개·부분 반영 6개이며, N01–N06은 모두 충분히 반영됐다. 부분 반영 6개는 실제 자료·검색·도구 권한·고위험 심사·운영 확대·외부 브랜드 전에 완결해야 할 후기 관문이다. 현재 합성·격리·비권한 S0 준비를 막지 않는다.

## 3. 현재 허용되는 최대 범위

다음 S0 준비 문서를 기획·설계하고 동결할 수 있다.

1. S0 프로토콜
2. 공개 fixture와 봉인 fixture의 작성·보관·공개 규칙
3. fixture 작성자·실행자·독립 판정자의 정보 접근 경계
4. 네 대안의 동일 corpus·표현·전처리·권한·사람 시간 회계
5. 표현 중립적인 기대 결과와 판정자 불일치 처리
6. 주요 결과, 즉시 중지, 누출 폐기와 재시험 규칙
7. 파일별 SHA-256과 동결 순서

실제 fixture 내용, 실행 코드, 저장소 구조, 실행 자동화는 별도 요청과 승인 없이 만들지 않는다.

## 4. 아직 허용되지 않는 것

- S0 구현 완료 또는 합격 주장
- 실제 고객·개인·비밀·과거 프로젝트 자료 사용
- 실제 검색·네트워크·외부 전송·도구 권한
- 실제 프로젝트·사람·고객에 대한 행동 영향
- 복수 자산·다중 프로젝트로의 일반화
- Project Brain 실제 연결이나 메시지·API·파일 규격 확정
- 모델 이주 완료 또는 Sol Ultra–Sol Pro 비교 완료 주장
- 실제 효과·안전·경제성·운영 순가치·중앙화 우월성 주장
- 내부·외부 브랜드·인증·대외 가치 주장
- 24개 기준의 완전 통과 또는 23개 판단 불가 치명 조건의 해제

## 6. S0 준비에서 닫아야 할 잔여

S0 실행 전 별도 프로토콜은 다음을 구체화해야 한다.

- 봉인 입력·기대 답·해시의 보유자, 공개 시점, 접근 로그와 누출 폐기 범위
- 기대 판정의 독립 검토와 판정자 불일치 처리
- 네 대안이 볼 수 있는 원천 corpus, 표현, 전처리와 수동 정리 시간
- 특정 계보 객체명을 사용하지 않는 표현 중립적 판정
- 단일 봉인 묶음 과적합을 막는 손대지 않은 변형과 실패 뒤 새 봉인 묶음
- S0 자원 상한, 중단 신호, 변경·재시험 판본 규칙

이 내용은 다음 작업의 기획·설계 범위다. 아직 작성되거나 실행됐다고 간주하지 않는다.

## 7. 다음 결정

다음 단계는 `S0 프로토콜 설계`다. 프로토콜이 작성되면 실제 fixture나 코드를 만들기 전에 다음을 확인한다.

1. 이 기준선의 허용 범위를 넘지 않는가
2. 실행자에게 봉인 답이 노출되지 않는가
3. 네 대안이 같은 자원과 표현 중립 결과로 비교되는가
4. 결과를 보기 전에 합격·중단·누출·재시험 규칙이 동결되는가
5. 사용자가 사람 시간·위험·비용 한도를 승인했는가
