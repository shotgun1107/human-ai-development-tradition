# 회사 PC 정리·세션 전환의 연구 경계 및 영향 기록

> 일자: 2026-09-16
> 분류: **CONTROL/유지보수용 기록 — 독립 심사·실행자의 기본 입력이 아님**
> 작성 주체: 정리 작업을 수행한 현재 CONTROL 세션. 자기 작업에 대한 영향 점검이며 fresh 독립 검토 인증이 아니다.
> 범위: 회사 PC 폴더 정리·단일 작업 경로 안내·문서 탐색 변경과, 그 결과를 다음 세션으로 전달할 때의 접근·독립성·재검증 영향.

## 1. 결론

1. 이 작업을 마무리하기 위해 보호 자료의 원문, 숨은 정답, 다른 조건의 실행 결과를 새로 열 필요는 없었다. **새 F0 내용 접근 예외나 S0/E0 실행 게이트는 적용하지 않았다.**
2. 현재 세션은 설계 선택, 공개 시험, 과거 감사 판단과 정리 내역을 이미 알고 있다. 다음 실험의 fresh 실행자나 동일 후보의 독립 심사자로 취급할 수 없다.
3. 새 세션을 만들거나 현재 세션을 폐기하는 것만으로 독립성이 복구되지 않는다. 문서·검색 색인·로그·초기 프롬프트·공유 사본으로 정보가 전달될 수 있다.
4. 이번 조치는 root 정책에 입력 경계를 영속적으로 명시하고, 파생 문서에 역할별 용도 경고를 붙이는 것이다. 파일 접근을 OS 수준에서 차단하거나 격리 환경을 구현·검증한 것은 아니다.
5. 과거 기술 결과를 일괄 무효화할 근거는 없지만, 현재 정책·경로·환경에 그대로 적용할 수 없는 결과가 있다. 아래 §6에서 역사적 판정 유지와 현재 재사용 차단을 구분한다.
6. 앞선 worktree 제거에서 미분류 상태에 관한 사전 중단 규칙을 좁게 적용한 절차상 문제를 기록한다. 현재 사용자 허용을 소급 적용해 당시 준수 여부를 바꾸지 않는다.

## 2. 관련 제한과 이번 권한의 범위

| 제한 | 이번 작업과의 관계 | 적용한 판단 |
|---|---|---|
| 세 F0 경로의 내용 접근 기본 금지 | 중복 백업·worktree 정리에 보호 자료가 포함돼 있었음 | 기존 무결성 업무 범위의 목록 집계·크기·해시 동일성 확인만 사용. 원문·내부 파일명을 모델 입력으로 공개하지 않음 |
| hidden oracle 저장·전달 제한 | 모든 자료를 한 폴더로 모으라는 요청을 무제한 수집으로 해석할 위험 | hidden oracle·자격증명·다른 프로젝트 자료를 수집하거나 저장소로 이동하지 않음 |
| 역할별 허용 입력과 fresh 역할 | 정리 세션이 과거 판단을 알고 있고 요약을 생성했음 | 이 세션의 대화·문서를 새 실행자나 독립 심사자의 기본 맥락으로 전달하지 않음 |

| 동결 바이트·해시 보존 | 운영 정책과 문서 안내가 바뀜 | 후보 소스·프로토콜·schema·시험·기대값을 수정하지 않음. 새 정책 해시와 역사적 시험 해시를 구분 |
| 자료·조건·자원의 대칭성 | 문서와 검색 결과가 일부 실행자에게만 추가 맥락을 줄 수 있음 | 실제 실험 전에 역할별로 정확한 파일·해시·공통 입력·조건별 입력을 동결해야 함. 이 작업에서 새 실험 입력을 만들지 않음 |
| Git 변경 전 미분류 상태 차단 | 메인에 미분류 상태 항목 1개가 남아 있음 | 이번 점검에서 이름·내용을 공개하거나 제거하지 않음. 추가 Git 관리·게시 작업은 보류 |
| 세션 폐기와 기록 보존 | 사용자가 후속 작업을 새 세션에서 진행할 예정 | 이 세션에서 추가 기술 작업을 하지 않도록 정책에 기록. 세션·로그의 실제 삭제나 보안 소거는 수행하지 않음 |

### 예외 적용 기록

- 사용자 허용으로 수행한 변경: `AGENTS.md`의 프로젝트 공통 운영 정책, root README·문서 안내·지원서 요약의 역할 분류 경고, 이 영향 기록과 같은 이름의 SHA-256 sidecar.
- 목적: 후속 역할이 공개·요약 자료를 자동으로 허용 입력으로 오해하는 것을 막고, 기존 결과의 재사용 조건을 남기기 위함.
- 기간: 현재 세션은 이 유지보수·영향 기록 완료까지. 후속 기술 작업은 새로운 CONTROL 세션에서 다시 범위를 정한다.
- 새로 허용한 보호 내용 접근·비공개 추론 접근·실험 실행: **없음**.
- 변경하지 않은 것: F0 접근 게이트, 숨은 정답 경계, 조건별 결과 접근, scoring·질문·자원 상한, candidate 역할 분리, Git 게시 승인 요건.
- 이번 권한은 향후 모든 연구 역할의 공통 권한이 아니다. 별도 예외가 실제 필요해지면 정확한 읽기·쓰기 대상, 역할, 이유, 파생물 전달 범위, 영향받는 결과와 재검증 조건을 사전에 승인·기록해야 한다.

## 3. 현재 세션의 노출과 다음 세션으로 이어지는 경로

현재 세션이 확인한 것은 공개 목적·설계·프로토콜·공개 코드와 시험 기록, 과거 감사 결과, 폴더·Git 상태 및 유지보수 결과다. 이 기록은 긴 과거 세션 전체의 접근 이력을 완전히 독립 인증했다는 뜻이 아니다.

| 전달 경로 | 발생할 수 있는 영향 | 조치·남은 한계 |
|---|---|---|
| 현재 대화의 fork·전체 복사·자동 요약 | 과거 원인 가설, 채택한 설계, 결과 해석이 새 역할의 판단을 선점 | 연구 역할에 이 대화를 이어 붙이지 않음. 새 CONTROL도 인계 내용을 운영 맥락으로만 사용하며 독립 판정 근거로 승격하지 않음 |
| root README·DOCUMENT-GUIDE | 안내 링크를 따라 과거 판정이나 다른 버전 자료까지 읽음 | CONTROL/운영 자료 경고 추가. 링크가 역할 허용 목록을 확장하지 않음을 AGENTS에 명시 |
| 지원서 요약과 다른 프로젝트에 첨부한 사본 | 감사 발견 사항과 설계 선택이 압축된 형태로 전달됨 | 연구 입력이 아니라 지원서·CONTROL용 2차 자료로 표시. 이미 외부 프로젝트에 붙인 옛 사본은 이번 변경으로 자동 갱신·회수되지 않음 |
| `.mkdocs-site`와 검색 색인 | 원문을 직접 열지 않아도 제목·요약·검색 결과로 평가 설계와 심사 판단을 접함 | 전체 문서 사이트를 기본 실험 입력으로 사용하지 않음. 현재 색인 1,117개 entry 중 E0 경로 entry 580개를 확인했으며 이는 문서 수나 실험 수가 아니라 검색 항목 수임 |
| Codex 로그·기록·공유 노트·검색 결과 | 다른 역할의 산출물이나 원자료가 요약·도구 출력에 섞여 들어옴 | 원 대화·JSONL·혼합 도구 응답을 통째로 전달하지 않음. 필요한 공개 근거만 허용 필드에서 선별하고, 사적 추론·권한 밖 자료는 제외 |
| 같은 파일시스템·Git·휴지통 | 세션이 달라도 보호 파일이나 백업에 접근할 가능성이 남음 | 내용 접근 금지는 그대로 유지. 휴지통 이동·worktree 삭제·새 세션을 비밀 소거나 강제 격리의 증거로 삼지 않음 |
| 이전 평가에 맞춘 후속 수정 | 이미 본 실패·답안에 과적합하거나 조건별 정보량이 달라질 수 있음 | 변경 버전과 노출 이력을 기록하고, 필요한 새 시험은 frozen protocol과 역할별 gate를 따라 별도 수행 |

파일 경고와 운영 규칙은 절차적 통제다. 도구가 허용 목록 밖 파일을 실제로 읽지 못한다는 보안 검증을 이번에 수행하지 않았다. 새 역할을 시작하기 전에 해당 실험이 요구하는 격리 수준을 확인해야 하며, 확인하지 못한 격리 수준을 달성했다고 주장하지 않는다.

### 역할 템플릿에서 주의할 점

현재 `s0-executor.toml`은 일반적으로 frozen protocol을 읽으라고 적지만, 공개 canonical protocol에는 CONTROL·검토자용 조건 설명도 포함된다. 공개 protocol §3의 실행자 표현 제한과 실제 release 범위를 함께 적용해야 한다. **템플릿 문구만으로 전체 CONTROL 프로토콜·조건 대응표를 실행자에게 제공하면 안 된다.** 역할용 입력이 아직 동결되지 않았다면 시작하지 않는다. 이번 작업에서 프로토콜을 다시 쓰거나 실행자용 새 입력을 생성하지 않았다.

## 4. 새 세션·역할의 시작 조건

### 새 CONTROL

1. 현재 프로젝트의 `AGENTS.md`를 먼저 읽는다.
2. branch·HEAD와 미커밋 변경, 필요한 공개 파일의 해시를 확인한다. HEAD만 같다고 현재 작업 상태가 같다고 보지 않는다.
3. 이 기록과 문서 안내는 운영 맥락으로 읽을 수 있지만, 자기 판단을 fresh 독립 리뷰로 표시하지 않는다.
4. 새 기술 gate가 열리는 경우에만 기존 역할 분리와 pre-CODE freeze를 적용한다. 유지보수 허용을 이어받아 구현·실험을 시작하지 않는다.
5. 현재 미분류 상태 항목 1개는 별도 승인 범위에서 분류되기 전까지 Git 관리·게시의 차단 조건으로 유지한다.

### 독립 검토자·실행자·판정자

| 역할 | 허용 입력의 원칙 | 이번 세션에서 넘기지 않을 기본 자료 |
|---|---|---|
| 새 독립 검토자 | 해당 후보의 동결된 요구·소스·증거를 먼저 검토. 과거 판정과의 비교는 허용된 단계에서만 | 현재 대화, 유지보수 판단, 지원서 요약, 무제한 문서 검색 결과 |
| 구현·시험·문서 역할 | 새 gate의 역할별 정확한 경로·해시·출력 범위. 동일 후보에서 역할을 겸하지 않음 | 다른 역할의 권한 밖 자료·숨은 정답·비공개 추론 |
| S0 실행자 | 자신의 역할에 공개된 frozen protocol 부분과 해당 불투명 조건 입력·지시만 | 조건 대응표, 선호 대안, 작성자·판정자 자료, 다른 조건 결과, 전체 문서 사이트 |
| fixture 작성자 | 승인된 frozen protocol과 허용된 위험 개념 | 실행자 대화·결과를 본 상태에서 독립적으로 출제했다고 주장하는 것 |
| 사전 봉인 검토·사후 판정 | 프로토콜이 정한 시점과 자료. 두 역할을 임의로 합치지 않음 | CONTROL의 선호 결론, 권한 밖 비용·조건 식별 정보, 다른 역할의 전체 대화 |

초기 프롬프트·첨부·검색까지 포함해 역할, candidate/version, 실제 제공한 입력 목록·해시, 이전 노출, 작성 가능한 출력 경로를 기록한다. 이 파일 자체도 독립 역할의 입력으로 자동 전달하지 않는다.

누출이 확인되면 해당 역할을 중단하고 증거·이유를 보존한다. canonical protocol §10은 oracle·scoring·다른 조건 결과 누출 등을 전체 suite 무효 사유로 두며, 봉인 입력 노출 뒤의 기술 실패와 사후 oracle 결함에도 별도 재시험 규칙을 둔다. 로그 삭제나 세션 교체만으로 같은 시험을 계속하지 않는다. 이번에 실제 suite를 실행하거나 무효 판정·재시험을 수행한 것은 아니다.

## 5. 앞선 폴더 삭제 절차에 대한 정정

Documents의 worktree 14개를 제거하기 직전 각 대상의 status·ignored·skip-worktree·assume-unchanged는 0이었고, 해당 HEAD는 기존 Git 참조에 보존돼 있었다. 제거 전후 메인 작업 상태와 branch/tag/remote-tracking 참조의 동일성도 확인했다. 백업 53개는 메인 보존본과 해시가 모두 일치했다.

그러나 메인 저장소의 미분류 상태 항목 1개는 남아 있었다. 당시에는 대상 worktree가 깨끗하다는 범위로 판단해 Git 관리 작업을 진행했다. 이는 root AGENTS의 **미분류 상태가 있으면 Git 변경을 차단한다는 문구보다 좁게 적용한 것**이다.

- 이 기록에서는 이를 **사전 중단 조건 적용의 절차상 미준수**로 남긴다.
- 현재 사용자의 접근·수정 허용은 당시 절차를 소급 승인한 것으로 사용하지 않는다.
- 관찰된 보존 검사는 데이터 손실 위험을 낮추는 근거이지만, 독립성·정책 완전 준수의 인증은 아니다.
- 현재 남은 미분류 항목을 읽거나 삭제해 문제를 없앤 것처럼 처리하지 않는다.

이 문제 때문에 기존 모든 연구 결과를 자동으로 무효로 판정하지 않는다. 영향을 평가해야 하는 것은 정리 작업의 절차 준수 주장과 변경된 위치·환경을 현재 실행 근거로 재사용하는 주장이다. 후보 코드·동결 실험 결과가 바뀌었다는 증거는 이번 점검에서 확인하지 않았다.
