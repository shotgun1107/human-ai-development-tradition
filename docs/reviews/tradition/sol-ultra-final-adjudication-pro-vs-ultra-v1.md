## 3. 제안서 A의 철학과 최소 시스템을 선의로 재구성

### 3.1 철학

A가 해결하려는 중심 문제는 “경험을 어떻게 많이 정제할까”가 아니라 **과거에서 가져온 한 행동 변화가 지금의 최선 작업방식에 순이익을 더하는지 어떻게 싸게 반증할까**이다. 전통의 단위는 지식 문장이 아니라 `IF + DO + DO NOT + VERIFY + STOP + 근거 포인터`가 결합된 작업 패치다.

A는 특히 두 가지를 분리한다.

1. 고객 의무·비밀·인간 책임과 같은 **보호 규범**은 성능 실험으로 승패를 겨루지 않는다.
2. 품질·시간·비용을 개선한다고 주장하는 **경험 패치**는 좁은 범위의 가설이며 언제든 꺼질 수 있다.

공동 브랜드는 별도 서사가 아니라 출처, 검사, 비용, 철회, AI 기여와 인간 승인이라는 “검증 영수증의 계보”다. 모델 이름이나 인격 연속성은 브랜드가 아니다.

### 3.2 최소 시스템

A의 T0 논리 구성요소는 네 가지이며, 실제로는 하나의 Markdown 표에 함께 둘 수 있다.

1. 보호 규범 한 장
2. 만료 가능한 신호 메모
3. `trial/live/off` 상태를 갖는 작업 패치
4. 사용·변형·거부·비적용과 결과·비용을 남기는 사용 영수증

운영 흐름은 `원자료 포인터 → 짧은 신호 → 사람 승인 trial 패치 → 조건 일치 시 AI 제안·적용 → VERIFY와 영수증 → live/trial/off`다. 중대 위험에는 상태 심사를 기다리지 않는 `hold`를 둔다. 프로젝트 전용이 기본이며, 여러 맥락에서 같은 메커니즘이 확인돼도 기존 패치를 “범용 권위”로 승격하지 않고 새 공통 trial을 분기한다.

초기 검색은 수작업 또는 exact 조건 일치다. 원로그 자동 주입, RAG, 벡터 DB, 자동 승격, 대시보드, 소급 변환, 파인튜닝은 구축하지 않는다. 운영 예산을 넘기거나 더 단순한 프로젝트 테스트가 같은 가치를 내면 패치 체계 자체를 폐기한다.

### 3.3 A의 선의의 핵심 내기

**추론:** A의 내기는 “복잡한 계보 모델의 손실보다 짧은 패치의 맥락 압축 손실이 작다”는 것이다. 이는 현재 입증된 사실이 아니라 비용을 우선한 설계 가설이다.

**반증 조건:** 짧은 패치가 대표 반례와 복잡한 결정 맥락을 반복적으로 잃어 잘못 적용되거나, 원자료 메모·사례 묶음·다단계 선례보다 더 비싸고 덜 정확하면 A의 중심 구조를 폐기해야 한다.

## 4. 제안서 B의 철학과 최소 시스템을 선의로 재구성

### 4.1 철학

B도 전통의 중심을 문서 축적이 아니라 **미래 작업의 특정 결정을 바꾸는 출처 연결 행동 패치**에 둔다. 고정된 `사실→경험→교훈→교리` 사다리 대신 원자료에서 가장 싸고 검증 가능한 표현—테스트, 체크리스트, 프롬프트 조각, 예시·반례, 임시 차단—으로 “컴파일”한다.

B의 특징은 증거를 단일 등급으로 줄이지 않는 데 있다. 직접성, 비교, 반복, 전이, 신선도, 반례, 출처 독립성을 `증거 프로필`로 나눠 보고, `advisory/default/block`이라는 행동 강도와 분리한다. 또한 효과 주장을 C0 출처부터 C4 장기 체계 효과까지 제한해 현재 말할 수 있는 범위를 명시한다.

공동 브랜드는 별도 홍보 저장소가 아니라 적용 영수증, 비용 공개, 철회 이력, 모델 이주 결과를 읽어 만든 “브랜드 증거 뷰”다.

### 4.2 최소 시스템

B는 미래 T0에서 한 개 Markdown 등록부 안의 다음 구역만 쓴다.

1. 철회·차단 출처 목록
2. 근거 메모
3. `draft/trial/active/off` 행동 패치
4. trial 적용 영수증

세 지식 단위는 공통 맥락 서명을 공유한다. 사람 게이트는 기억 반입, 행동 변경, 외부 영향, 범위·자동화 확대의 네 지점에만 둔다. 초기 검색은 철회·민감도·상태·범위 hard filter 뒤 exact/keyword를 쓰며, 주입은 소수 패치로 제한하고 검색 실패 시 기권한다.

B의 첫 T0는 같은 모델·도구 구성과 신선한 내부 과제에서 다음 세 조건을 직접 비교한다.

- A: 정상 작업 흐름, 전통 기억 없음
- B: 같은 원사건의 비식별 근거 메모
- C: 같은 근거에서 만든 행동 패치

블라인드 평가와 사전 지표로 C가 A뿐 아니라 B보다 추가 이득을 내는지 본다. B가 더 낫다면 정제 패치 체계를 폐기하고 원자료 메모를 채택한다.

### 4.3 B의 선의의 핵심 내기

**추론:** B의 내기는 “세 단위·네 상태·증거 프로필 정도의 추가 구조가 패치의 맥락과 인과 주장을 보존하는 최소 비용”이라는 것이다. 한 파일로 물리적 복잡성은 줄였지만, 판단 필드와 게이트의 인지 비용은 A보다 크다.

**반증 조건:** 증거 프로필과 네 게이트를 채우는 시간이 판단 품질·검색 정확성·철회 안전을 개선하지 못하거나, 한 사람이 일관되게 쓰지 못하면 프로필을 줄이고 A식 서술 근거 또는 더 단순한 원자료+체크리스트로 축소해야 한다.

### 5.1 점수 해석

**사실:** 어느 안에도 실제 운영 자료나 T0 결과가 없으므로, 이 점수는 설계의 논리·안전·시험 가능성 평가이지 효과 점수가 아니다.

**추론:** B의 1점 우위는 주로 첫 T0에서 정제 패치의 한계효과를 직접 식별하는 구조에서 나온다. 그러나 그 시험의 세 배 출력·블라인드 평가 비용이 실제로 과도하면 이 우위는 사라진다. 반대로 A의 낮은 운영비가 신호 누락이나 맥락 손실을 만들면 A의 운영성 우위도 사라진다.

**재검토 조건:** T0 준비 시 A/B/C 병렬 비용이 승인 예산을 넘거나 독립 세션·블라인드 평가가 불가능하면 B의 평가·경제성 점수를 낮춰야 한다. 실제 표본에서 A식 짧은 패치가 중요 예외를 놓치지 않고 더 적은 시간으로 같은 판정을 내리면 A의 계승·증거 점수를 높여야 한다.

## 6. 각 안이 더 강한 영역

### 6.1 A가 더 강한 영역

1. **보호 규범과 경험 가설의 분리:** 고객 의무·비밀·책임을 성능 증거 사다리에 넣지 않는다는 구분이 가장 선명하다.
2. **운영 예산과 WIP 축소:** 신호·패치·주입·C 활동의 상한과 초과 시 축소 순서가 구체적이다.
3. **최소 상태:** `trial/live/off + hold`는 미승인 초안을 효력 체계 밖에 둘 수 있다면 B의 네 상태보다 작다.
4. **정제 불필요 조건:** 프로젝트 native 테스트가 충분하거나 재탐색이 싼 경우 패치를 만들지 않는 판단이 상세하다.
5. **시스템 자체의 사망 경로:** 패치 → native 테스트 → 영수증 중단 → 보호 규범만 남기는 축소 순서가 명확하다.

**추론의 반증:** A의 신호 만료가 미래 패턴을 반복적으로 잃거나, 미승인 초안의 위치가 불명확해 감사가 깨지면 이 단순성은 강점이 아니라 누락 위험이다.

### 6.2 B가 더 강한 영역

1. **증거의 모양 보존:** 직접성·비교·반복·전이·신선도·반례·출처 독립성을 점수 하나로 합치지 않는다.
2. **주장 강도 통제:** C0~C4는 현재 관찰에서 장기 체계 효과로 과장되는 경로를 잘 차단한다.
3. **첫 T0의 식별력:** 무기억, 같은 원자료 메모, 정제 패치를 동시에 비교해 기억의 가치와 정제의 추가 가치를 나눈다.
4. **활성 패치 영수증 표본화:** trial은 전수, active는 예외·중대 결과·사전 표본만 기록해 지속 감시비를 줄인다.
5. **철회·삭제 연결:** revoked 목록과 source dependency로 파생 패치를 끄는 절차가 한 파일 MVP 안에서도 비교적 구체적이다.

**추론의 반증:** 사람이 증거 프로필을 일관되게 채우지 못하거나 세 조건 비교가 비용 때문에 실행되지 않으면 B의 이론적 식별력은 운영상 이점이 아니다.

## 7. 실제 차이, 겉보기 차이, 공통 구조

### 7.1 실제 차이

| 쟁점 | A | B | 심사 판단 |

### 7.2 겉보기 차이

- A의 “공통 패치 분기”와 B의 “범위를 넓힌 새 trial 판본”은 이름은 다르지만 **범용 지위를 자동 승격하지 않고 새 맥락에서 재시험한다**는 같은 통제다.
- A의 `VERIFY/STOP`과 B의 `required check/guardrail/off`는 거의 같은 실행 계약이다.
- A의 네 논리 구성요소와 B의 한 파일 네 구역은 물리 구조가 아니라 설명 단위의 차이다. 둘 다 실제 T0에서는 한 문서로 축소 가능하다.
- A의 주장 수준과 B의 C0~C4 사다리는 정밀도 차이는 있지만, 얽힌 변화를 전통 단독 효과로 귀속하지 않는다는 같은 원칙이다.
- A의 증거량 기반 검토와 B의 trigger 기반 정비는 모두 월간 60~90분 전면 회고를 거부하고, 짧은 정기 확인만 안전망으로 남긴다.

### 7.3 공통 구조

두 안의 실질적 공통 골격은 다음과 같다.

```text
원자료는 원래 보안 경계에 유지
→ 비식별 포인터/짧은 사실 메모
→ 좁은 프로젝트 범위의 조건부 행동 패치 1개
→ 검사·중지 조건과 사람 승인
→ 소수만 exact 조건으로 AI에게 제안
→ 적용/변형/거부와 결과·비용 기록
→ 유지/축소/중단/삭제
```

둘 다 다단계 교리 체계, 단일 E0~E4 점수, 장시간 의무 월간 회고, 원로그 자동 주입, 초기 RAG·파인튜닝·대시보드·자동 승격을 거부한다.

## 8. 공통 브리프가 만든 상관된 수렴

### 8.1 독립 합의로 볼 수 없는 부분

**사실:** 공통 브리프는 다음을 두 설계자 모두에게 명시했다.

- 정제 수명주기와 E0~E4를 정답으로 강제하지 않는다.
- `incident + 체크리스트 + 골든 테스트` 같은 최소안과 비채택·삭제를 허용한다.
- 원로그, 정제 기억, 무기억 또는 최소 체크리스트를 비교하라고 요구한다.
- exact/keyword 우선, RAG 보류, 프로젝트 우선, 모델 이주, 즉시 안전 루프, 사람 승인, 고객 실험 격리, 인과 주장 제한을 질문에 포함한다.
- 기능 수에는 가점을 주지 않는다고 선언한다.

**사실:** 두 제안은 이 지시를 넘어 표현 수준에서도 `행동 패치`, `적용 영수증`, 다단계 수명주기 거부, E0~E4 거부, 월간 60~90분 거부, exact 조건 필터, 한 파일 T0, 패치 1개라는 구조로 수렴했다.

**추론:** 이 합의의 상당 부분은 두 독립 설계자가 서로 다른 길로 같은 진리를 발견했다는 증거라기보다, 동일한 v1.1 연구와 공통 브리프가 강하게 만든 **상관된 수렴**이다. 특히 “패치”와 “영수증”이라는 동일 중심 은유는 효과에 대한 독립 표 두 개로 셀 수 없다. 다만 동일 제약 아래 두 문서 모두 일관된 최소안으로 완결할 수 있었다는 점은 이 구조의 **설명 가능성·설계 가능성**에 대한 약한 지지다.

**재검토 조건:** 제안서 작성 과정의 독립성이 별도 로그로 확인돼도 공통 입력에 의한 상관은 사라지지 않는다. 진짜 독립 지지는 다른 브리프나 다른 설계 패러다임에서 같은 최소 구조가 재도출되거나, T0에서 대조군보다 나은 결과가 나올 때 생긴다.

### 8.2 독립성의 실용적 결론

- 두 안의 공통 요소를 “2표”로 세지 않는다.
- 공통 요소는 헌장·브리프 준수 여부로 평가한다.
- 실제 채택 근거는 더 작은 대안과의 비용·효과 비교, 보안 경계, 반증 가능성이다.
- 서로 다른 부분—A의 보호 규범·비용 축소와 B의 증거 프로필·A/B/C 시험—만 비교 정보가 상대적으로 크다.

## 9. 빠진 대안과 양쪽 모두의 맹점

### 9.1 충분히 경쟁하지 않은 대안

1. **패치 계층 없는 native-only 안:** 프로젝트 테스트·인수 기준·한 장 체크리스트와 source pointer만 유지하는 안이 둘 다 폐기 후 fallback으로는 있으나, 처음부터 동등한 완성 설계로 전개되지는 않았다.
2. **조건부 사례 쌍 안:** 규칙으로 압축하지 않고 대표 사례와 반례 한 쌍을 현재 과제에 제시하는 방식은 B의 expression 선택지에만 부분적으로 있고, 패치와 동등한 주 설계로 비교되지 않았다.
3. **결정 기록 중심 안:** 반복 행동보다 되돌리기 어려운 의사결정의 맥락·대안·결과를 ADR식으로 계승하는 최소 체계가 독립 대안으로 경쟁하지 않았다.
4. **무기억 유지 안:** 반복 가능한 운영 자료가 생길 때까지 전통 계층을 전혀 만들지 않고 native test만 개선하는 것이 현재 최적일 가능성이 있다. 두 안 모두 이를 종료 상태로 인정하지만 현재 주결론 후보로 충분히 분석하지 않았다.
5. **외부화 우선 안:** C 활동을 공개 벤치마크·외부 심사·오픈소스 테스트에 최대한 외부화하고 내부에는 포인터만 두는 설계가 독립적으로 비교되지 않았다.

### 9.2 공통 맹점

- **패치 단위의 적합성 자체가 미검증:** 둘 다 가장 중요한 설계 가설을 같은 방식으로 채택했다.
- **포인터 부패와 재현성:** 원자료를 복제하지 않는 것은 안전하지만, 원본 이동·권한 소실·포맷 변경 뒤 무엇을 최소 보존할지 아직 결정되지 않았다.
- **분류 노동:** exact filter가 싸려면 project/task/risk/model 조건을 사람이 정확히 붙여야 한다. 이 선행 비용과 오분류율은 측정되지 않았다.
- **승인자 편향:** 별도 세션은 기억과 이해관계의 독립성을 만들지 않는다. 중요한 패치에서 언제 외부 검토가 필수인지 양쪽 모두 미결정이다.
- **희귀하지만 중대한 사건:** 적용 영수증 표본화와 신호 만료가 저빈도·고영향 반례를 잊게 할 수 있다. 안전 사건 예외는 있지만 분류 실패가 남는다.
- **패치 상호작용:** 패치 1개 시험은 가능하지만 둘 이상이 동시에 적용될 때 상쇄·증폭·우선순위를 평가하는 최소 방법은 부족하다.
- **평가자 비용과 오염:** 블라인드 사람 평가를 반복할 수 있는지, 같은 사람이 과제와 패치를 작성하면서 조건을 정말 가릴 수 있는지 미확인이다.
- **브랜드의 외부성:** 내부 행동 일관성을 브랜드의 필요조건으로 잘 잡았지만, 그것이 외부에 인식되거나 가치가 되는지는 양쪽 모두 의도적으로 미확인이다.
- **현재 최선 workflow의 이동:** 오케스트레이터·모델이 빠르게 변하면 T0의 기준선이 실험 중 이동할 수 있다. 기록과 주장 강도 하향은 있으나 충분한 안정 기간 기준은 없다.

**제안:** 이 맹점을 해결한다며 새 객체를 추가하지 않는다. T0 준비 단계에서 포인터 생존성, 분류 시간, 블라인드 가능성, 희귀 안전 신호의 별도 보존만 체크하고, 실패한 항목에 필요한 최소 통제만 추가한다.

**반증 조건:** 준비 점검만으로 반복 누락이 생기면 해당 맹점에 한해 별도 객체나 자동 검사를 조건부 도입한다.

## 10. 1인 운영 비용·실패 가능성·과잉 설계 위험

### 10.1 비용 비교

| 비용 항목 | A | B | 판정 |
|---|---|---|---|
| T0 기록 | 신호·패치·영수증, 서술 근거 | 근거 메모·패치·영수증, 7차원 증거 프로필 | A가 더 작다. |
| T0 실행 | 우선 2조건, 양수 뒤 표현 비교 | 3조건 직접 비교 | A가 싸고 B가 더 식별력 있다. |
| 정비 | 사건 기반 + 6주 15분, 90일 30분 | trigger 기반 + 월 30분 안전망 | 실제 사건량 전에는 우열 불명이다. |
| 장기 영수증 | 패치 제안 작업 기록으로 읽힐 여지 | trial 전수, active 표본 | B의 명시적 표본화가 장기 비용에 유리하다. |
| 인지 비용 | 상태·근거가 단순하나 맥락을 서술로 판단 | 프로필·이유 코드가 많으나 비교 가능성이 높음 | 운영자 선호와 오류율을 T0에서 봐야 한다. |

두 안이 제시한 `30분`, `45분`, `3건`, `2~3개`, `800/1,200 token`은 **관료주의를 막기 위한 취소 가능한 pilot 상한**이지 근거로 확정된 최적값이 아니다. 숫자 자체를 후보 설계 규범으로 동결하면 안 된다.

### 10.2 가장 가능성 높은 실패

1. 기록할 미래 가치 판단이 어려워 중요한 사건을 놓친다.
2. 패치의 scope를 잘못 붙여 exact retrieval이 정확하게 오적용한다.
3. 승인·영수증이 실제 판단을 바꾸지 않는 형식 작업이 된다.
4. 적은 표본과 이동하는 모델 때문에 `inconclusive`만 누적된다.
5. 테스트나 체크리스트에 이미 있는 규칙을 패치로 복제한다.
6. 안전·브랜드 명분으로 패치가 늘어나고 off가 실행되지 않는다.
7. 패치 단위가 복잡한 의사결정의 이유와 예외를 지워 음의 전이를 만든다.

### 10.3 과잉 설계 위험

**A:** 물리적 구조는 작지만, 보호 규범·신호·패치·영수증, 여섯 승인 게이트, 여러 시간·개수 상한을 모두 그대로 구현하면 “최소안”이라는 이름의 작은 관료제가 될 수 있다.

**B:** 한 파일이지만 세 단위, 공통 맥락 서명, 7차원 증거 프로필, 네 상태, 세 행동 강도, 네 게이트, 네 루프, C0~C4가 동시에 필수가 되면 인지적으로는 기존 다단계 시스템과 가까워질 수 있다.

**추론:** 1인 운영 가능성은 문서 수보다 **한 패치의 생성·판정에 드는 실제 인간 능동시간과 누락률**로 결정된다. 현재는 어느 안도 그 자료가 없다.

**재검토 조건:** 첫 적격 trial 하나를 준비하는 데 승인된 시간 상한을 넘거나, 필드의 20% 이상이 반복해서 `unknown/미사용`으로 남거나, native test로 같은 가치를 낼 수 있으면 구조를 줄인다. `20%`는 효과 임계값이 아니라 필드 삭제 검토를 여는 후보 규칙이며 사용자 승인 전 확정하지 않는다.

## 11. 현재 상태에서 가장 작은 안전한 다음 단계

### 11.1 지금 확정 가능한 것

**사실:** 현재는 원천 오케스트레이터 안정 운영, B0/B1 반복 결과, 실제 전통 운영 자료, T0 기준선이 없다. 따라서 지금 가능한 안전한 작업은 설계 결정을 문서로 좁히는 것뿐이다.

**제안:** 다음 `candidate-system-design-v1`에는 운영 효과를 주장하지 않고 다음 최소 골격만 확정한다.

1. 고객·비밀·인간 책임·인과 주장 제한을 담은 보호 규범
2. 원자료를 복제하지 않는 비식별 source pointer와 철회 목록
3. 좁은 프로젝트 범위의 trial 행동 패치 한 단위: `IF/DO/DO NOT/VERIFY/STOP`
4. 적용·변형·거부와 결과·비용을 남기는 최소 영수증
5. 사람의 trial/활성화/범위 확대/재활성화/외부 공개 승인
6. 중대 위험의 즉시 중단과 파생 삭제
7. T0 진입 조건을 충족하기 전 실행 금지
8. 진입 뒤 무기억·원자료 메모·패치의 작은 내부 비교

### 11.2 지금 확정하면 안 되는 것

- patch가 native test나 원자료 메모보다 우월하다는 주장
- `active` 승격에 필요한 횟수와 효과 임계값
- 월간·6주·90일 중 최적 cadence
- 패치·token·시간 상한의 구체 숫자
- 범용 패치 계층, core/adapter, semantic RAG, 자동 주입
- 공동 브랜드의 고객·수익 효과
- 오케스트레이터의 효율·장기 이득
- 파인튜닝 또는 자동 승격

### 11.3 1부의 잠정 주결론

**잠정 판정: `하이브리드`.** 단, 두 문서를 평균내는 하이브리드가 아니다. **A의 더 작은 보호·운영 골격을 기본으로 하고, B의 더 강한 증거 표현 중 필요한 부분과 무기억/메모/패치 직접 비교만 선택적으로 결합**한다. B의 모든 프로필·게이트를 옮기지 않으며, A의 순차 T0와 임의 상한도 그대로 채택하지 않는다.

이 판정은 설계 채택이지 효과 인정이 아니다. T0 진입 조건이 충족돼도 첫 실험 결과가 나오기 전 패치는 `trial`일 뿐이며, B식 A/B/C 비교에서 원자료 메모나 무기억 조건을 이기지 못하면 패치 계층을 폐기한다.

**반증 조건:** B의 최소 증거 프로필을 추가한 하이브리드가 한 패치 준비에서 승인 시간·누락률을 악화시키거나, native-only 안이 같은 안전성과 계승 효과를 더 싸게 내면 주결론을 `둘 다 기각하고 더 작은 검증`으로 바꾼다.

## 12. 사후 감사의 범위와 효력

1부를 파일에 기록한 뒤 다음 순서로 두 파일을 읽었다.

1. `docs/reviews/tradition/claude-independent-review-human-ai-tradition.md`
2. `docs/reviews/tradition/codex-adjudication-claude-independent-review.md`

두 리뷰는 v1.0 기준선에 대한 judge-side audit이며, A/B가 따라야 했던 새 공통 설계 입력으로 취급하지 않는다. Claude의 해법·점수와 Codex의 역사적 T0 설계가 A/B의 정답이라고 가정하지 않았고, 1부 점수도 이에 맞춰 다시 쓰지 않았다.

특히 Codex 판정 상단의 **후속 정정**이 현재 효력 판단의 기준이다. 원천 오케스트레이터가 아직 구축·테스트 단계라는 사용자 정정에 따라 “즉시 T0를 먼저 수행”한다는 최초 권고는 폐기됐다. 현재 순서는 `v1.1 보정 → A/B 설계·비교 → 운영 준비 조건 충족 뒤 T0`다.

### 13.2 리뷰가 틀리거나 현재 상태에 의해 대체된 부분

1. **“지금 수작업 T0부터 수행” 권고는 현재 효력이 없다.** 사용자 정정과 v1.1의 현재 단계 경계가 대체했다. 개발 incident는 형식 리허설에 쓸 수 있어도 전통 운영 효과의 증거가 아니다.
2. **Claude의 C3 Critical 등급은 과했다.** v1.0 문서가 고객 과제 배정을 명령한 것은 아니고 경계가 모호했다. Codex의 `부분 수용·안전 경계 수정`이 더 정확하며 v1.1에서 해결됐다.
3. **Engelbart가 1인 C 활동을 부정했다는 해석은 과했다.** 원문은 공동 수행의 비용 이점을 말하면서 독자적 소규모 시작도 허용한다. 후보 설계는 1인 C를 금지할 것이 아니라 비용 상한과 외부 자원 활용을 정해야 한다.
4. **역량 이주 테스트가 C2를 우회한다는 Claude의 표현은 불완전하다.** 이주 통과율은 목적 적합한 직접 지표지만 전통 on/off가 없으면 새 모델 자체의 향상과 외부 전통 효과가 여전히 섞인다.
5. **Claude의 74점은 v1.0 기준선 점수다.** v1.1 A/B 점수와 합산하거나 추세 수치로 비교할 수 없다.
6. **Codex 본문의 네 개발 incident 고정 T0와 2시간 통과 기준은 역사적 안이다.** 문서 상단 후속 정정과 v1.1이 이를 대체했다. 현재 운영 자료·baseline 없이 실행하거나 효과 근거로 삼지 않는다.

### 13.3 감사 뒤 새로 선명해진 잔존 위험

- **패치 중심 수렴:** Claude가 예측한 “두 안이 세부만 다른 같은 설계가 될 가능성”이 실제로 상당 부분 나타났다. v1.1이 최소안 선택을 열어 편향을 교정했지만, 동일 연구·brief가 `패치/체크리스트/골든 테스트` 방향을 강하게 제시했기 때문이다.
- **native-only 대조군의 지위:** 두 안 모두 fallback으로 인정하지만 완성된 제1 후보로는 다루지 않았다. B의 A/B/C가 이 공백을 실험에서 보완한다.
- **C 활동 외부화:** A는 구체적이고 B는 약하다. B의 한 파일 최소화만으로 외부 심사·공개 시험·공식 자료 재사용 결정을 대신할 수 없다.
- **선택과 침묵:** 무엇을 기록했는가뿐 아니라 무엇이 미래 결정 가치 판단에서 탈락했는지에 편향이 생길 수 있다. 그렇다고 모든 비기록을 기록하면 역설적으로 비용이 폭증하므로, 전체 로그가 아닌 제한 표본 감사만 향후 실험 후보로 남긴다.
- **configuration/migration 대안:** 두 안 모두 구성 지문과 이주 시험을 포함하지만, “구성+통과한 테스트만 관리”하는 급진적 대안을 패치와 동등한 주 설계로 비교하지 않았다. native test 대조군에 포함해 간접 시험할 수 있다.

## 14. 사후 점수 조정

1부 원점수는 바꾸지 않는다. 다음 표가 유일한 감사 조정이다.

| 제안 | 1부 원점수 | 감사 조정 | 감사 후 점수 | 이유 |
|---|---:|---:|---:|---|
| A | 92.0 | `+0.0` | **92.0** | v1.0의 주요 지적을 v1.1과 제안 안에서 모두 처리했고, C 활동 외부화까지 명시했다. 새 감사 항목은 1부의 맥락 압축·native-only 맹점에 이미 반영돼 중복 감점하지 않는다. |
| B | 93.0 | `-0.5` | **92.5** | v1.1의 주요 지적은 대부분 해결했고 증거·실험 설계는 강하다. 다만 공통 brief가 명시적으로 선택하게 한 “1인 C 활동 중 무엇을 외부화할지”에 대한 결정이 A보다 약해 1인 운영 가능성에서 0.5점을 조정한다. |

**해석:** 감사 후 0.5점 차이는 통계적·실무적 우승 차이가 아니다. B 전체를 채택할 근거가 아니며, A의 운영 골격과 B의 평가 장치를 선택적으로 조합한다는 1부 잠정 결론을 바꾸지 않는다.

**재검토 조건:** B가 후보 합성 전에 외부화 목록과 내부 C 시간 상한을 A보다 더 낮은 비용으로 제시하면 -0.5 조정은 철회할 수 있다. 반대로 A의 짧은 패치가 사례 맥락을 보존하지 못하면 A도 0.5점 이상 내려야 한다.

## 15. 주결론

### 판정: **하이브리드**

이 판정은 A와 B의 기능을 합쳐 더 큰 체계를 만든다는 뜻이 아니다.

- **운영 골격:** A의 보호 규범 분리, 3상태+hold, 명시적 비구축, 비용 초과 시 단계적 폐기를 채택한다.
- **증거·시험:** B의 증거 프로필 개념을 영구 필드가 아닌 승인 체크로 축소하고, 무기억·원자료 메모·행동 패치의 직접 비교를 채택한다.
- **공통 요소:** 원자료 포인터, project-first, VERIFY/STOP, 영수증, 철회·삭제, 사람 승인, exact 우선은 두 안에서 가져오되 합의 자체를 효과 근거로 세지 않는다.
- **폐기:** 두 안에서 서로 다른 숫자 상한·cadence와 장기 기능 목록은 지금 확정하지 않는다.

**사실:** 현재 운영 자료와 T0 결과가 없으므로 A, B, 하이브리드 어느 것도 효과가 입증된 시스템이 아니다.

**추론:** 현재 설계 선택만 놓고 보면 A의 구조가 1인 비용을 더 잘 제한하고 B의 시험이 패치가 원자료 메모보다 낫다는 핵심 가설을 더 직접 반증한다. 둘은 같은 층의 기능이 아니므로 선택 결합이 가능하다.

**제안:** candidate-system-design-v1은 이 얇은 하이브리드만 명세하고 구현을 약속하지 않는다. 운영 준비 후 첫 비교에서 패치가 native-only 또는 원자료 메모를 이기지 못하면 주결론을 `둘 다 기각하고 더 작은 검증`으로 전환한다.

**반증 조건:** 하이브리드의 한 trial 준비·판정 비용이 사용자 승인 상한을 넘거나, 증거 체크가 결과·오류·삭제 안전을 개선하지 않거나, 패치가 중대한 음의 전이를 한 번이라도 유발하면 패치 계층을 중단하고 native test·체크리스트만 남긴다.

| 현재 개발 incident를 운영 효과 증거로 사용 | 둘 다의 비채택 | **폐기** | 형식 리허설·후보 탐색 외에는 T0 근거가 아니다. |
| 고객 과제의 열등 조건 배정 | 둘 다의 금지 | **폐기** | 관찰은 가능해도 실험 처치 배정은 금지한다. |
| 초기 vector DB·dashboard·knowledge graph | 둘 다의 비채택 | **폐기** | 측정된 병목 없이 구축하지 않는다. |
| 자동 활성화·범위 확대 | 둘 다의 비채택 | **폐기** | 사람 승인과 rollback을 유지한다. |
| 파인튜닝을 예정된 자연 단계로 취급 | A는 현 범위 폐기, B는 먼 gate | **폐기** | candidate v1의 로드맵에서 제거한다. 완전히 별개의 미래 연구 제안만 가능하다. |

## 17. 현 단계에서 확정 가능한 것과 T0 이후 사항

### 17.1 지금 확정 가능

1. 목적은 모델 가중치나 인격이 아니라 다른 세션·모델에서 재현되는 외부화된 작업 능력이다.
2. 고객·비밀·권리·인간 책임이 내부 학습보다 우선한다.
3. 원자료와 승인 기억을 분리하고 최소 수집·출처·철회·실제 삭제 경로를 둔다.
4. 경험 규칙은 project-first, 조건부, 반증 가능, 사람 승인, 즉시 중단 가능해야 한다.
5. fact/inference/proposal과 관찰/인과 주장을 구분하고 얽히면 주장 강도를 낮춘다.
6. 현재 개발 incident와 smoke는 전통 운영 효과가 아니다.
7. T0는 반복 workflow, 개입 전 baseline, 신선한 내부 과제, acceptance, 고객 격리, 사용자 예산 승인이 준비된 뒤에만 한다.
8. 초기 RAG·자동 승격·파인튜닝·전체 로그 수집은 하지 않는다.

### 17.2 T0 이후에만 확정 가능

1. 행동 패치가 무기억·원자료 메모·native test보다 나은가.
2. 근거 메모와 영수증이 필요한가, 어떤 필드가 실제로 쓰이는가.
3. 패치 생성·검토·검색의 총 인간 능동시간과 허용 상한.
4. `trial→live`에 필요한 반복 수와 최소 가치 차이.
5. 정기 정비가 필요한지, 필요하면 월간·6주·다른 trigger 중 무엇인지.
6. exact/keyword 검색이 수동 선택보다 나은 시점.
7. 다른 프로젝트·모델로 near/far/migration transfer가 있는가.
8. core/adapter와 공통 패치가 실제 중복을 줄이는가.
9. active 영수증을 어떤 표본률로 남길지.
10. 공동 브랜드가 외부 신뢰·수익에 영향을 주는가.

## 18. 후보 최종 설계의 최소 골격

```text
[보호 규범 1쪽]
  고객·비밀·권리·책임·인과 정직성
          │
          ▼
[단일 수작업 등록부]
  revoked source | 근거 메모 | trial patch | use receipt
          │
          ▼
[trial patch 1개]
  IF | DO | DO NOT | VERIFY | STOP
  source/counterevidence | scope/config | 사람 승인
          │
          ▼
[안전한 내부 T0]
  현재 정상 workflow(무기억)
  vs 같은 근거 메모
  vs 같은 근거의 patch
          │
          ├─ patch 추가 가치 + guardrail 통과 → 좁은 live 후보
          ├─ memo가 동등/우수 → patch 폐기, memo/native-only
          └─ 차이 없음/회귀/비용 초과 → 전통 개입 보류·축소
```

상태는 `trial/live/off`만 효력 상태로 두고 중대 위험은 `hold`로 즉시 차단한다. 미승인 초안은 활성 등록부 밖에 둔다. 증거 프로필은 영구 스키마가 아니라 승인 시 `직접 근거인가 / 비교가 있는가 / 반례가 있는가 / 범위·신선도는 무엇인가`를 묻는 체크로 시작한다.

## 20. 사용자 승인이 필요한 가치 판단

1. **T0 비용 봉투:** 한 trial의 준비·실행·평가에 허용할 인간 능동시간, token, 현금의 상한
2. **최소 가치 차이:** 품질·수정시간·비용 중 무엇을 주 지표로 삼고 어느 정도 차이를 실무적으로 의미 있다고 볼지
3. **중대 guardrail:** 한 번만 발생해도 패치를 중단할 품질·보안·비밀·고객 위험의 정의
4. **원자료 범위:** 어떤 실제 운영 자료를 비식별화해 쓸 수 있고 외부 AI에는 무엇을 절대 보내지 않을지
5. **안정화 판정:** 어느 workflow가 “현재 최선이며 T0를 할 만큼 안정적”인지
6. **3조건 비교 비용 수용:** 무기억·메모·패치 출력을 모두 만드는 비용을 지불할지, matched 순차 비교로 줄일지
7. **행동 강도:** 경험 패치를 기본 제안으로 둘지, 명시 호출만 허용할지, 어떤 안전 항목만 block이 가능한지
8. **외부 검토 기준:** 법·보안·고객 위해·큰 비용 중 어느 위험부터 외부 reviewer가 필수인지
9. **C 활동 외부화 범위:** 공개 benchmark·오픈소스 테스트·공식 자료·외부 심사를 어디까지 활용할지
10. **보존·삭제 정책:** pointer 부패에 대비해 무엇을 최소 snapshot으로 남기고, 삭제 의무와 감사 이력을 어떻게 우선할지
11. **브랜드 공개 범위:** 공동 브랜드를 내부 작업 규율로만 둘지, 어떤 증거가 쌓인 뒤 고객에게 설명할지
12. **월 손실 한도의 의미:** 25만 원을 사용 목표가 아닌 위험 상한으로 유지하며, 새 정보·재사용 자산·선택권이 없을 때 즉시 단순 손실로 처리할지

## 21. 핵심 판단과 재검토 조건 요약

| 성격 | 핵심 판단 | 반증·재검토 조건 |
|---|---|---|
| 사실 | 제안서와 기준선 해시가 모두 일치한다. | 동일 경로의 파일 해시가 바뀌면 이 심사는 해당 판본에 적용되지 않는다. |
| 사실 | 현재 운영 증거와 T0 결과는 없다. | 준비 조건을 갖춘 실제 T0 원자료가 생길 때만 갱신한다. |
| 추론 | B는 증거·시험에서, A는 1인 운영에서 상대적으로 강하다. | B의 실험이 과비용이거나 A의 압축이 맥락을 잃으면 강점 판단을 뒤집는다. |
| 추론 | 두 안의 공통 패치 구조는 상관된 수렴이다. | 다른 독립 브리프나 실제 대조 결과에서 같은 구조가 우세하면 독립 지지가 늘어난다. |
| 제안 | A 운영 골격+B 최소 증거·A/B/C 시험의 얇은 하이브리드를 채택한다. | native-only가 동등 이상이거나 하이브리드 준비비가 상한을 넘으면 둘 다 기각한다. |
| 제안 | 모든 수치 상한과 cadence는 T0 뒤 정한다. | 법·계약·안전상 즉시 필요한 상한은 사용자가 별도 승인할 수 있다. |
| 제안 | 효과 없는 패치 체계는 프로젝트 native test만 남기고 폐기한다. | 지연 효과에 대한 사전 근거가 있고 종료일·비용 상한을 둔 추가 시험의 정보가치가 더 클 때만 한 번 연장한다. |

## 22. 미확인 사항

- 행동 패치가 무기억, 원자료 메모, native test보다 실제로 낫다는 증거
- 패치 압축이 어려운 사례의 맥락·반례를 얼마나 잃는지
- 정확한 scope 분류와 수동 철회 추적의 누락률
- 한 사람이 블라인드 A/B/C 평가를 감당하고 조건을 충분히 가릴 수 있는지
- 모델·도구 변화 중 안정 baseline을 유지할 수 있는 기간
- 어떤 증거 프로필 차원이 실제 판정에 쓰이는지
- 정비 주기·패치 수·token·시간의 적정 상한
- 서로 다른 패치가 동시에 적용될 때의 상호작용
- 다른 프로젝트·모델로의 near/far/migration transfer
- 외부 reviewer의 순가치와 의무화할 위험 범위
- 별도 기준선 `.sha256` manifest의 실제 내용 일치 여부(이번 지정 입력 범위 밖)
- 공동 브랜드가 고객 신뢰·수익·공모전 성과에 미치는 효과
- 장기 인간–LLM 공동 전통의 복리 성장과 수익성

## 최종 한 문장

현재 채택할 것은 거대한 기억 체계가 아니라 **A의 안전하고 폐기 가능한 최소 운영 골격 위에서 B의 무기억·원자료 메모·행동 패치 비교로 패치 자체의 추가 가치를 먼저 반증하는 얇은 후보 설계**이며, 그 비교가 준비되기 전에는 구현도 효과 주장도 하지 않는다.
