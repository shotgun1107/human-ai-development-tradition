# Claude 독립 심사에 대한 Codex 판정

> 판정일: 2026-08-05  
> 대상: `claude-independent-review-human-ai-tradition.md` 455줄 전체  
> 상태: 기준선 변경 전 판정 기록  
> 최초 결정: A/B 설계 경쟁을 잠시 보류하고 수작업 T0 1회를 먼저 수행한다.  
> 후속 정정: **사용자가 원천 오케스트레이터는 아직 구축·테스트 단계라고 정정했다. 즉시 T0 권고는 폐기하며, v1.1 보정 뒤 A/B 설계를 먼저 수행하고 T0는 운영 준비 조건 충족 뒤로 미룬다.**

이 후속 정정은 아래 최초 판정의 역사적 근거를 삭제하지 않는다. 다만 현재 효력은 `docs/tradition/design-competition-baseline-v1.1.md`와 v1.1 문서에 있다.

## 1. 결론

Claude 심사의 중심 결론은 수용한다. 지금 바로 두 개의 큰 설계안을 만드는 것보다, 이미 로드맵에 정의된 수작업 T0 한 번으로 운영 부담과 실제 산출 가능성을 먼저 확인하는 편이 낫다.

다만 다음은 구분한다.

- T0는 정제된 기억이 원로그보다 우월하다는 H2를 입증하지 않는다.
- T0는 모델 효과와 전통 효과를 인과적으로 분리하지 않는다.
- T0가 제공하는 것은 실제 소요 시간, 버린 필드, 증거에서 살아남은 후보 수, 실행 가능한 산출물의 존재 여부다.
- 따라서 T0는 본 실험의 대체물이 아니라 **추측으로 설계할 부분을 줄이는 feasibility gate**다.

최종 순서는 다음과 같다.

1. 수작업 T0 1회
2. T0 실측과 이번 심사의 수용 항목을 반영한 기준선 v1.1
3. 같은 v1.1을 입력으로 한 독립 A/B 설계
4. 비교·합성 단계에서 이번 심사 보고서를 judge-side 반례 목록으로 사용

이번 심사 보고서 자체를 A/B 공통 입력에 넣지는 않는다. 수용한 전제 교정은 중립적인 기준선 문구로 반영하고, Claude의 해법과 대안 프레임은 최종 비교 때 사용한다. 보고서 전체를 공통 입력에 넣으면 두 설계가 Claude의 프레임으로 함께 수렴할 수 있다.

## 2. 재검증 범위

다음을 직접 대조했다.

- Claude 보고서 455줄 전체
- 헌장, 2차 조사, roadmap, monthly playbook, design brief, baseline의 관련 문구
- 현재 incident index와 incident JSON 목록
- METR 2026년 방법론 업데이트 원문
- Engelbart 1991년 원문 §9~§10
- `arXiv:2604.27003` 초록

외부 원문 재검증 결과:

- METR는 최신 추정이 불안정하다고 했지만, 선택 편향이 AI 가속 추정치를 아래쪽으로 편향시키며 2026년 초에는 2025년보다 더 가속됐을 가능성이 높다고도 명시했다. 기존 조사는 후반부를 빠뜨렸다.
- Engelbart는 C 활동의 공동 수행이 비용과 위험을 나눈다고 권고했지만, 개별 조직이 독자적으로 시작할 수 있다고도 명시했다. 따라서 외부화 비용 경고는 타당하나 독자적 C 활동을 원문에 반한다고 단정할 수는 없다.
- `arXiv:2604.27003`은 어려운 과제에 집중되는 음의 전이와, 세분화된 기억 조직이 전방 전이와 심각한 망각을 동시에 만들 수 있다는 결과를 실제로 담고 있다.

## 4. Claude 권고에서 그대로 채택하지 않는 부분

### 4.1 Critical 3건이라는 등급

C1과 C2는 A/B 입력의 구조 편향이므로 착수 전에 고친다. C3는 명시적 고객 실험 지시가 아니라 경계의 모호성이므로 한 단계 낮게 본다. 안전상 수정은 동일하게 선행한다.

### 4.2 T0가 C1·C2를 동시에 검증한다는 표현

T0는 C1의 운영 가능성과 C2의 측정 부담을 드러낼 수 있지만, 정제 기억의 비교 우위나 인과 분리를 검증하지 못한다. T0 결과를 그런 증거로 승격하지 않는다.

### 4.3 C1~C3를 보고서 형태로 A/B 공통 입력에 넣는 방안

수용하지 않는다. 수용된 문제는 기준선의 중립 문구로 고친다. 보고서는 설계자에게 숨겨야 할 비밀이 아니라, 두 설계가 같은 비판 프레임을 모방하지 않도록 최종 심사 자료로 보류하는 것이다.

### 4.4 모델 간 역량 이주 체계가 C2를 우회한다는 주장

이주 테스트 통과율은 매우 유용한 직접 지표지만, 그것만으로 모델 효과와 외부 전통 효과의 구분이 사라지지는 않는다. 동일 모델의 전통 on/off 또는 다른 비교가 없으면 새 모델 자체의 향상도 통과율에 섞인다. 다만 사용자의 실제 목적에는 인과 순도보다 `다음 AI가 필요한 행동을 재현하는가`가 더 중요할 수 있으므로 A/B가 반드시 고려할 강한 대안이다.

## 5. T0의 고정 범위

새 하네스·스키마·자동화를 만들지 않는다. 첫 T0는 roadmap이 작성될 때 이미 존재했고 권장 후보와 직접 연결되는 다음 네 사건으로 고정한다.

1. `DEV-20260804-001` — SDK에 없는 observe 기반 timeout 설계
2. `DEV-20260804-002` — approval mode 기본값에 따른 추가 모델 호출 위험
3. `DEV-20260805-001` — 동결 benchmark fixture의 placeholder commit
4. `DEV-20260805-002` — Windows Python launcher 가정

후속 incident는 첫 T0의 선택 편향을 줄이기 위해 입력에서 제외하고, 두 번째 표본 또는 반례로 보존한다.

기록할 실측은 다섯 개뿐이다.

- 총 인간 능동시간
- 실제 사용한 원자료와 revision log 범위
- 작성하려다 버린 필드와 이유
- 근거에서 살아남은 lesson candidate 수
- 다음 작업에 적용 가능한 실행 산출물과 사전 평가 기준의 존재 여부

T0 통과는 다음을 모두 만족할 때다.

- 원자료 연결과 redaction을 포함한 총 능동시간이 2시간 이내다.
- 근거가 연결된 lesson candidate가 최소 1개다.
- trial doctrine은 최대 1개이며 적용 범위와 반증 조건이 있다.
- 체크리스트·프롬프트·테스트 중 실행 산출물 1개와 사전 평가 계획 1개가 나온다.
- 적용 전이므로 효과를 주장하지 않는다.

통과하지 못하면 곧바로 큰 시스템을 설계하지 않는다. `incident 원문 + 체크리스트 + 골든 테스트`의 급진적 최소안을 기본 대조군으로 삼고, T0 형식을 더 줄인다.

## 6. v1.1 변경 묶음

T0 뒤 한 번에 다음 네 묶음만 수정한다.

1. **사실 정확성**: METR, Cochrane, 기억 세분화 반대 결과, Engelbart 비용 경계
2. **헌장 경계**: 고객 과제 실험 금지, 사용자 숙련 교란, AI 측 최소 관찰 신호
3. **경쟁 중립성**: 수명주기 기각 허용, 인과 분리의 정직성 기준, 구조 비채택 허용, 단순성 유인, 브랜드 평가
4. **판본 절차**: 외부 심사 반영 경로와 별도 기준선 hash manifest

v1.1은 철학 v2가 아니다. 헌장의 목적·공동 전통·계승·책임 원칙은 유지하고, 사실 오류와 경쟁 규격의 편향만 교정한다.
