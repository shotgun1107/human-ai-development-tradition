## 1. 결론

독립 심사의 `제한된 수정 후 첫 시험 준비 가능` 판정을 수용한다. 통합 후보의 중앙 제품 정의와 핵심 구조는 유지한다. 전체 구조를 다시 설계할 근거는 없지만 현재 문서 그대로 첫 시험을 준비해서도 안 된다.

수정의 핵심은 기능 추가가 아니다.

1. `첫 구축`을 전체 제품 검증처럼 읽히지 않게 **S0 합성 논리 선행조건 시험**으로 다시 명명한다.
2. 설계자와 구현자가 답을 미리 아는 공개 fixture만으로 합격하지 못하게 봉인 fixture와 독립 판정자를 둔다.
3. 선택한 최소 계보 구조를 단순 목록뿐 아니라 무개입·프로젝트 로컬·최소 공통 목록과 같은 조건에서 비교한다.
4. 실제 자료·실제 영향·Project Brain·브랜드로 넘어가는 관문을 문서에 명확히 둔다.
5. 설계 수준에서 빠진 참여·보고·거부·인센티브 문제를 보완한다.

## 2. 심사 숫자의 올바른 해석

`통과 0, 부분 통과 23, 실패 1`을 후보가 24개 중 1개만 만족했다는 뜻으로 읽으면 안 된다. 23개 부분 통과는 문서가 위험과 시험 방향은 다루지만 실제 운영 증거가 없다는 뜻이다. 현재는 구현과 운영을 하지 않았으므로 정상적인 상태다.

문서 수준의 명시적 실패는 R17 `참여·심리적 안전·인센티브`다. 이 항목은 수정판에 반영한다. 다만 1인 소유자의 합성 시험에 조직 전체의 신고 제도를 즉시 구축하라는 뜻은 아니다. 사람 협업자가 늘어나는 단계의 보호 장치와, 현재 AI·사람 평가가 실패·거부·불확실성 보고를 억압하지 않는 최소 원칙을 구분한다.

치명 조건 `판단 불가 23개`는 현재 위험이 확인됐다는 뜻이 아니라 관련 단계로 진입할 증거가 없다는 뜻이다. 합성·격리·비권한 시험에는 전부 해제할 필요가 없지만 실제 자료나 외부 영향이 생기기 전에 해당 조건을 다시 판정해야 한다.

## 5. S0 시험의 수정된 의미

S0는 제품의 첫 운영판이 아니다. 다음 논리가 최소한 모순 없이 작동할 가능성이 있는지만 확인하는 합성 시험이다.

- 원근거와 파생물의 구분
- 같은 원근거의 중복 집계 방지
- 프로젝트 권한 경계
- 반례 보존
- 자산 상태와 전달 차단
- 원근거 철회의 파급
- 판정 근거의 재구성

S0 비교 조건은 같은 합성 정보·권한·사람 시간 한도에서 다음 네 가지로 둔다.

1. 새 공통 계층 없음
2. 프로젝트 로컬 정리만 사용
3. 최소 공통 목록 사용
4. 최소 증거 계보 사용

비교 결과는 중복·철회·권한 오류, 잘못된 판정, 판정 불일치, 사람 능동시간, 설명 가능성을 함께 기록한다. 최소 계보가 오류를 줄이지 못하거나 비용만 늘리면 목표 구조의 관계를 줄인다.

## 6. 봉인 fixture와 판정 분리

- **공개 fixture:** 의미 규칙을 개발하고 명백한 오류를 잡는 용도다.
- **봉인 fixture:** 구현 또는 실행 절차가 동결된 뒤 처음 공개한다.
- **fixture 작성자:** 반례·권한 오류·중복 파생·철회 누락·악성 명령형 문구를 포함한 입력과 기대 결과를 만든다.
- **실행자:** 공개 fixture는 볼 수 있지만 봉인 fixture와 기대 답은 보지 않는다.
- **독립 판정자:** 결과를 고정 기준으로 판정하며 설계·실행자가 사후에 답이나 문턱을 바꾸지 못하게 한다.
- **재시험:** 실패 수정 뒤 새 봉인 fixture 또는 손대지 않은 봉인 부분으로 다시 판정한다.

이 역할은 처음부터 모두 다른 사람이어야 한다는 뜻은 아니다. 그러나 같은 사람이 역할을 겸하면 독립 증거라고 부르지 않고, 후기 고위험 단계에서는 겸임을 허용하지 않는다.

## 7. 실제 자료 단계 전 관문

S0가 통과해도 실제 자료로 자동 진입하지 않는다. 최소한 다음이 필요하다.

1. 문제 규모·분모·누락·예방 가능성 기준선
2. 데이터·비밀·IP·삭제 권한 검토
3. 재식별·간접 인젝션·오염·권한 외 행동 시험 계획
4. 이해충돌·이의·재심·중단 책임
5. 참여·거부·보복·검토 노동 측정 계획
6. 사람 시간·현금·토큰·대기·유지비와 중단 문턱
7. 계보·상태·권한·철회의 내보내기·복구 요구
8. 관련 치명 조건의 독립 재판정

세부 기술·법률 판정·수치 문턱은 실제 조건이 생길 때 정한다. 빈칸을 그럴듯한 숫자나 정책으로 채우지 않는다.

## 8. 유지할 통합 후보의 중심

다음은 수정 과정에서 유지한다.

- 중앙은 프로젝트 실행 엔진이 아니라 장기 계보·전이 통제면이다.
- 프로젝트 원본은 전용이 기본이고 승인된 파생만 공유한다.
- 같은 원자료의 여러 AI 요약을 독립 증거로 세지 않는다.
- 성공·실패·결정·실험·반례와 규칙이 되지 않는 경험도 보존한다.
- 현재 과제에는 소수 자산과 근거·반례·금지 조건만 전달한다.
- 프로젝트의 거부·변형을 유효한 피드백으로 취급한다.
- 삭제·철회·중지와 중앙 불능 시 로컬 실행 지속을 보존한다.
- 실제 효과·전이·경제성·브랜드는 운영 시험 전까지 주장하지 않는다.

## 9. 반영하지 않는 잘못된 해석

- 판단 불가 23개를 S0 전에 모두 해제하려고 하지 않는다.
- 합성 시험에 실제 고객·비밀 자료나 외부 도구 권한을 넣지 않는다.
- 첫 수정판에서 모든 법률·보안·운영 정책과 기술 스키마를 확정하지 않는다.
- 독립 심사 기준을 만족시키기 위해 문서·역할·승인 수를 무제한 늘리지 않는다.
- R17을 AI의 감정이나 인격 주장으로 해석하지 않는다. 사람의 안전한 보고와 AI의 실패·거부·불확실성 신호 보존 문제로 다룬다.
- 외부 브랜드를 현재 단계의 성공 지표로 올리지 않는다.

## 10. 다음 문서 판본

기존 통합 후보는 심사 대상 원문으로 보존하고 덮어쓰지 않는다. 다음 판본은 별도 파일 `central-tradition-system-v2-integrated-candidate-v2.1.md`로 만든다.

v2.1은 D01–D14와 N01–N06의 판정을 반영한 기획·설계 후보이며 구현 명세가 아니다. 새 SHA-256과 변경 장부를 동결한 뒤, 독립 외부 조사자에게 다음만 제한 재심사받는다.

1. 사전 기준이 완화되지 않았는가
2. 필수 문서 수정이 실제로 반영됐는가
3. S0의 주장 범위와 봉인 시험이 판별 가능한가
4. 실제 자료·권한·효과·브랜드 단계가 여전히 닫혀 있는가

제한 재심사가 통과하기 전에는 S0 구현을 시작하지 않는다.
