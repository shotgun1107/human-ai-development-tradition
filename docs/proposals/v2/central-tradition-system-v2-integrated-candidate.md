## 0. 문서의 지위와 읽는 법

이 문서는 두 독립 설계를 기능별로 합쳐 놓은 합집합이 아니다. 공통 목적을 기준으로 서로 같은 선택은 다시 의심하고, 충돌하는 선택은 항목별로 판정하며, 운영 가치가 불분명한 복잡성은 첫 구축에서 제외한 **하나의 v2 통합 후보**다. 외부 독립 심사와 사용자 판단을 통과하기 전에는 최종 설계, 확정 규격, 운영 효과로 부르지 않는다.

근거 위치는 아래 약어와 현재 동결 파일의 줄 번호로 표시한다.

- **통합 결정:** 이 후보가 목적과 비교 결과를 바탕으로 선택한 내용

### 2.2 핵심 충돌과 항목별 판정

| 쟁점 | Sol Ultra | GPT-5.6 Thinking | 통합 판정과 이유 |

### 2.3 각 설계의 고유 강점과 처리

| 고유 강점 | 근거 | 통합 처리 |
|---|---|---|

## 3. 통합 후보의 제품 정의

### 3.1 제품 한 문장 정의

**여러 프로젝트와 여러 AI 세대의 공동 작업 증거를 프로젝트 경계와 출처 계보를 지킨 채 연결하고, 그로부터 나온 조건부 선례와 실행 자산을 현재 과제에 최소한으로 전달한 뒤 실제 사용·거부·변형·결과와 철회를 다시 반영하는 중앙 계승 통제면이다.**

### 3.2 해결할 문제

모델 성능이 높아져도 세션·프로젝트·모델·도구가 바뀌면 실전 경험은 자동으로 이어지지 않는다. 목표는 기록량이 아니라 과거의 검증된 차이가 다음 AI의 행동 차이로 나타나게 하는 것이다(`PH:L21-L32`). 이를 위해 다음 질문을 끊김 없이 답해야 한다.

1. 어떤 프로젝트·작업·실행에서 무엇이 일어났는가?
2. 당시 인간·모델·도구·오케스트레이션·기억·평가·승인 구성은 무엇이었는가?
3. 무엇이 원근거이고 무엇이 관찰·해석·가설·결정인가?
4. 어떤 경험은 사례로 남고 어떤 경험은 선례·Skill·테스트 등으로 이어졌는가?
5. 어느 범위·조건·권한에서 그 자산을 제안할 수 있고 언제 쓰면 안 되는가?
6. 프로젝트가 이를 사용·거부·변형·오적용한 뒤 실제 결과가 어떻게 달라졌는가?
7. 새 반례·삭제·비밀·모델 변경이 생겼을 때 어디까지 즉시 중지·수정·폐기해야 하는가?

### 3.3 성공과 비목표

성공은 신선한 과제와 다른 구성에서 중대한 반복 오류 감소, 올바른 검색·선택, 실제 품질·비용·위험 개선, 빠른 음의 전이 탐지, 감당 가능한 인간 관리비가 관찰될 때만 주장한다. 모델 자체 향상과 사용자 숙련을 분리할 수 없으면 구성 전체의 관찰 결과로만 보고한다(`PH:L48-L62`, `DB:L250-L262`).

비목표는 다음과 같다.

- 모델 가중치 학습, AI 인격·법적 책임자 지위의 보존
- 모든 대화·고객 자료·파일의 중앙 영구 복사
- 실패 데이터베이스, 성공 홍보관, 행동 패치 저장소 하나로의 축소
- 모든 프로젝트에 같은 절차를 강제하는 단일 교리 엔진
- 프로젝트마다 중앙 시스템 완성본을 복사하는 구조
- Project Brain의 실제 메시지·API·파일·실시간 순서를 지금 정하는 일
- 고객 납품을 열등할 수 있는 실험 조건에 무단 배정하는 일
- 문서·에이전트·사용률·승인 수를 성장으로 간주하는 일

## 4. 전체 책임과 경계

### 4.1 중앙의 전체 책임

1. 프로젝트·작업·실행·팀 구성의 안정적 정체성과 장기 계보
2. 프로젝트별 신뢰·권한·비밀·삭제 경계
3. 같은 원자료에서 나온 파생물을 묶는 증거 계열과 상관 표지
4. 성공·실패·결정·실험·반례·비용·사람 수정·AI 충돌의 보존과 비교
5. 조건부 선례와 작업 자산의 범위·판본·효력·근거·반례 관리
6. 프로젝트 간 허가된 파생 공유, 공통 후보 생성, 분기, 중지, 철회
7. 현재 과제에 맞는 소수 자료의 권한·상태·조건 기반 선택
8. 채택·거부·변형·오적용·평가 결과의 환류와 실패 위치 진단
9. 모델·도구·오케스트레이션 변경 시 영향 분석과 이주 시험
10. 사건 기반 긴급 대응, 정기 종합, 체계 자체의 비용·오류 검토
11. 내부 공동 브랜드 근거와 승인된 외부 표현·정정의 연결

### 4.2 중앙이 책임지지 않는 것

- 프로젝트의 작업 분해, 일상 실행, 실시간 지휘
- Project Brain의 내부 역할 구성과 완료 판정
- 프로젝트 산출물과 고객 납품의 최종 승인
- 원자료 소유권의 자동 이전
- 프로젝트 native test·체크리스트보다 중앙 자산을 우선시키는 일
- 모순을 하나의 최신 답이나 다수결로 제거하는 일
- 중앙이 불능일 때 프로젝트 실행 전체를 멈추는 일

### 4.3 행위자와 승인 경계

| 행위자 | 책임 | 승인 없이 할 수 없는 일 |
|---|---|---|
| 인간 소유자 | 목적·가치·예산·위험 허용, 전체 중단, 외부 책임 | 삭제 의무를 계보 보존보다 낮추거나 AI 합의만으로 중요 결정을 확정할 수 없음 |
| 프로젝트 책임 인간 | 고객 의무, 로컬 비밀·권한, 고위험 적용·납품 승인 | 다른 프로젝트의 비공개 지식을 임의 공유할 수 없음 |
| Project Brain/대표 AI | 현재 맥락 대표, 중앙 요청, 로컬 선택·거부·변형, 결과 반환 | 중앙 자산을 자동 진리로 만들거나 사람 승인을 대신할 수 없음 |
| 프로젝트 실행 AI | 탐색·생성·시험·비평·적용, 불확실성과 기여 보고 | 자기 회고·자기평가를 독립 검증으로 승격할 수 없음 |
| 중앙 자동화 | 정규화, 중복·반례·모순·오염 후보, 검색·자산 초안, 결과 집계 | 프로젝트 간 공유, 공통 활성화, 고위험 해제, 외부 공개를 스스로 승인할 수 없음 |
| 중앙 책임자/큐레이터 | 범위·상태·충돌·철회 판정, 예외 대기열 처리 | 자료 소유자·외부 책임자의 권한을 우회할 수 없음 |
| 독립 검토자 | 고위험 결정과 브랜드 핵심 주장의 표본 검증 | 권한 없는 원자료 열람이나 최종 대외 책임 대행 불가 |

한 사람이 여러 인간 역할을 겸할 수 있지만, `자료 공유 승인`, `자산 효력 승인`, `외부 발행 승인`은 서로 다른 결정으로 기록한다. 역할 분리는 사람 수가 아니라 책임 경계다.

### 4.4 Project Brain과의 의미상 경계

Project Brain은 현재 프로젝트의 목표·제약·상태·로컬 권한·실행 결과를 대표한다. 중앙은 관련 기억과 자산을 권한에 맞게 선별해 조건·반례·효력·검증법과 함께 제공하고, Project Brain은 채택·거부·변형과 결과를 돌려준다. 중앙의 긴급 중지는 전달 금지 상태를 만들 수 있지만 실제 프로젝트 중단과 외부 조치는 프로젝트 책임 인간이 확인한다.

향후 교환에 필요한 의미 범주는 다음뿐이며, **메시지 필드나 순서가 아니다.**

- 요청 맥락과 원하는 도움 종류
- 권한·공개 가능 범위
- 선별된 전통 전달 묶음
- 채택·거부·변형 결정
- 적용·평가 결과와 사람 수정
- 철회·삭제·비호환 통지

API, 파일, 이벤트, 플러그인, 실시간·배치·사람 중계 여부는 미정이다.

정확한 스키마는 미정이지만 목표 제품이 잃어서는 안 되는 의미는 다음과 같다.

| 개념 | 의미 |
|---|---|
| 프로젝트 | 목적·권한·비밀·책임이 독립된 장기 맥락 |
| 작업 | 프로젝트 안의 목표·요청·인수 조건 단위 |
| 실행 | 특정 구성으로 작업을 해결하려 한 한 번의 시도 |
| 팀 구성 | 인간 역할, 모델/버전, 도구, AI 역할, 오케스트레이션, 기억·자산 판본, 평가·승인 정책, 예산·제약의 관찰 가능한 묶음 |
| 원근거 | 파일·로그·테스트·외부 평가·사람 수정 등 판단의 직접 출처 |
| 증거 계열 | 같은 원근거 또는 강하게 상관된 생성 경로를 공유하는 파생물 묶음. 독립 표 수를 부풀리지 않기 위한 의미 단위 |
| 관찰·사건 | 성공·실패·근접 실패·충돌·비용 이상 등 일어났다고 보고된 일과 신뢰 상태 |
| 결정 | 당시 선택지·제약·선택·거부·이유·승인·재검토 조건 |
| 실험 | 결과 전에 가설·비교 조건·지표·예산·중단 기준을 둔 시험 |
| 결과 | 품질·사용자 가치·비용·위험·지연·외부 평가 등 관찰된 귀결 |
| 기여 | 인간·AI·도구가 만든 부분과 사람의 수정·승인 |
| 사례/선례 | 맥락·사실·판단·이유·반례를 묶은 조건부 참고 경험 |
| 주장 | 사례를 설명하는 인과·판단 가설. 근거 자체가 아님 |
| 작업 자산 | 실제 행동을 돕는 Skill, 프롬프트, 체크리스트, 테스트, 템플릿, 판단 기준, 행동 규칙 |
| 적용 | 특정 맥락에서 특정 자산 판본이 제안·채택·거부·변형·오적용된 사건 |
| 평가 | 적용 후 기대 이익·비용·부작용·불확실성을 판정한 결과 |
| 범위·권한 | 어디에 관련 있는지와 누가 볼·전달·공개할 수 있는지의 독립 축 |
| 변경·철회 | 대체·범위 축소·중지·폐기·삭제와 이유 |
| 브랜드 주장 | 외부에 말하려는 제한된 명제와 내부 근거·승인·정정 상태 |

### 5.2 관계 불변조건

1. 원근거와 AI 요약·해석은 같은 것이 아니다.
2. 같은 증거 계열의 파생물 수는 독립 근거 수를 늘리지 않는다.
3. 한 사건은 여러 경쟁 주장을 낳을 수 있고, 아무 자산도 낳지 않을 수 있다.
4. 한 자산은 여러 근거와 반례를 가질 수 있고, 어느 근거가 철회됐는지 구별한다.
5. 프로젝트 전용 원본은 공통 영역으로 이동하지 않는다. 승인된 비식별·조건부 파생물만 새 계보로 만든다.
6. 적용 범위, 접근 권한, 공개 가능성, 증거 확실성, 행동 강도는 하나의 점수로 합치지 않는다.
7. `전체 공통`도 자동 명령이 아니며, `프로젝트 전용`도 강한 안전 금지일 수 있다.
8. 삭제 의무는 계보 완전성보다 우선한다.
9. 중앙 자산보다 더 강한 프로젝트 native test·절차가 있으면 중복 생성이나 자동 덮어쓰기를 하지 않는다.
10. 중앙 불능이나 추천 거부가 프로젝트 실행 불능을 뜻하지 않는다.

## 6. 정보·경험·작업 자산·배포·피드백의 전체 흐름

### 6.1 유입에서 경험 해석까지

1. 프로젝트 완료, 중요한 사건, 결정, 실험 결과, 비용 이상, 외부 평가 또는 중앙 요청이 발생한다.
2. 중앙 경계는 프로젝트 정체성, 자료 소유자, 접근권한, 비밀·개인정보, 삭제 상태, 신뢰 영역을 먼저 확인한다.
3. 외부 문서·코드·메일·로그·AI 회고의 명령형 문장은 운영 지시가 아니라 분석 대상 데이터로 격리한다.
4. 원근거를 보존하고 AI 추출·요약·번역은 파생물로 연결한다. 동일·상관 입력은 증거 계열로 묶는다.
5. 사실, 관찰 신뢰도, 해석, 사후 가설, 제안을 분리한다. 누락은 추정해 채우지 않고 `미확인`으로 남긴다.
6. 성공·실패를 과정의 적절성과 결과의 좋고 나쁨으로 나눠 운 좋은 성공과 좋은 과정의 나쁜 결과를 구분한다(`R2:L221-L230`).

### 6.2 비교와 조건부 선례 형성

7. 중앙은 작업 목표·위험·구성·도메인·자산 판본·평가법·비용 차원을 사용해 유사 사례와 반례를 찾는다.
8. 모순은 투표·최신순·강한 모델의 의견으로 덮지 않는다. 조건 차이, 평가 차이, 오류 상관, 실제 불확실성을 드러내 경쟁 선례로 병존·분기·보류한다.
9. 경험은 사례·결정·실험·브랜드 근거로만 남을 수 있다. 실행 자산이 되지 않는 것이 정상 종착점일 수 있다.
10. 자산 후보가 필요하면 핵심 기능, 적용·금지 조건, 근거·반례, 기대 이익·부작용, 판정 시험, 모델·도구 의존성을 함께 만든다.

### 6.3 작업 자산의 범위와 효력

자산의 효력 상태는 첫 기준으로 다음 다섯 개만 둔다.

| 상태 | 의미 | 기본 전달 |
|---|---|---|
| 후보 | AI·사람이 만든 검증 전 초안 | 전달하지 않음 |
| 제한 시험 | 사전 승인된 안전 범위·기간·판정 기준에서만 사용 | 지정 맥락에만 전달 |
| 활성 | 명시 범위에서 제안 가능 | 조건·반례·시험과 함께 전달 |
| 중지 | 음의 전이, 비밀, 근거 철회, 이주 미평가 등으로 즉시 차단 | 기본 검색·전달 금지 |
| 폐기·대체 | 일반 사용 종료, 대체 이유를 보존 | 역사·반례 질의에서만 보임. 삭제 의무는 별도 우선 |

`필수/권고/선택/금지` 같은 행동 강도, 프로젝트·모델별 비호환, 외부 공개 가능성은 상태와 별개다. 모든 경험이 이 상태들을 순서대로 지나지 않는다.

범위는 다음처럼 운용한다.

- **프로젝트 전용:** 기본값. 로컬 비밀·환경·팀 구성에 묶인다.
- **프로젝트 종류 공통:** 비슷한 조건 집합에서 제한 시험할 파생 자산이다. 고정 taxonomy보다 관찰된 조건을 먼저 쓴다.
- **전체 공통:** 여러 종류·구성과 반례 검토에서 제한적으로 재현됐거나, 위해가 크고 조치가 가역적인 안전 원칙의 범위 주장이다. 자동 우선권이 아니다.

공통화의 횟수·정량 문턱은 기준선이 없어 미정이다. 범위를 넓힐 때는 독립 증거 계열, 실제 적용 결과, 모델·도구 차이, 반례, 위해, 가역성, 선택 비용을 함께 본다.

### 6.4 검색·선택·배포

1. 프로젝트 또는 Project Brain이 목표·작업 유형·위험·구성·허용 권한·원하는 기억 종류를 의미상 제시한다.
2. 중앙은 권한과 프로젝트 경계를 관련성보다 먼저 적용한다.
3. 삭제·중지·폐기·비호환 자산을 기본 검색에서 제외한다.
4. 현재 조건에 맞는 사례와 자산뿐 아니라 반례·경쟁 선례·최근 음의 전이·native 자산 충돌·예상 적용 비용을 확인한다.
5. 소수의 후보만 `전통 전달 묶음`으로 제공한다.

전달 묶음의 의미 내용은 다음과 같다.

- 왜 현재 과제와 관련 있는가
- 추천 자산 판본 또는 참고 사례
- 적용 조건과 사용 금지 조건
- 핵심 근거, 증거 계열 수, 반례·경쟁 선례
- 현재 효력·범위·불확실성·오래됨·모델 의존성
- 필요한 사람 승인
- 실행 후 확인할 테스트·관찰과 즉시 중단 신호

이 목록은 실제 통신 스키마가 아니다. 첫 구축에서는 사람이 입력·확인하는 중립 묶음으로만 시험한다.

### 6.5 채택·변형·피드백과 수정

프로젝트는 채택, 일부 채택, 거부, 변형, 적용 불가, 오적용 가운데 하나로 응답할 수 있다. 거부는 자동 실패가 아니며 프로젝트 native 자산이 더 낫거나 중앙이 맥락을 잘못 이해했다는 유효한 신호일 수 있다.

결과는 다음 실패 위치를 구분해 환류한다.

| 위치 | 판정 질문 | 대표 대응 |
|---|---|---|
| 유입 | 필요한 사건·결과가 들어왔는가 | 완료·수집 경계 보완 |
| 권한 | 금지 정보·오염 지침이 노출됐는가 | 격리·전달 중지·영향 감사 |
| 검색·선택 | 필요한 것을 못 찾았거나 무관한 것을 골랐는가 | 조건·표지·순위·묶음 축소 |
| 채택 | 적절했지만 비용·신뢰·설명 문제로 거부됐는가 | 전달 방식·비용·정당한 거부 확인 |
| 실행·변형 | 핵심 기능대로 썼는가, 변형이 훼손했는가 | 표현·어댑터·제약 수정 |
| 자산 | 제대로 썼는데 결과가 나빴는가 | 범위 축소·중지·폐기 |
| 평가 | 기준선·판정 자료가 충분한가 | 결론 보류·측정 재설계 |

평가 결과는 자산의 범위·효력·확실성·표현을 바꿀 후보가 된다. AI는 후보와 영향 경로를 제안하고, 승인 경계에 해당하는 변화는 사람이 결정한다.

### 6.6 사건·정기·메타 순환

- **빠른 순환:** 비밀·개인정보·오염, 중대 품질 회귀, 음의 전이, 근거 삭제·철회, 위험한 오적용은 즉시 `격리/전달 중지 → 영향 추적 → 사람 판정 → 임시 방어 → 회귀시험 → 유지/수정/폐기`로 처리한다.
- **정기 종합:** 여러 프로젝트의 반복·모순, 검색·거부·미사용 자산, 비용 악화, 탐색 감소, 브랜드 근거를 묶어 본다. 새 근거가 없으면 `변경 없음`이 정상 결과다.
- **메타 순환:** 모델 교체, 반복 오검색, 평가 실패, 운영비 급증 때 검색·승격·평가·검토 주기 자체가 옳은지 검토한다.

`월간`은 초기 점검 후보이지 제품 불변조건이 아니다. 사건량과 관리비가 낮으면 더 느리게, 중대한 위험은 즉시 처리한다.

## 7. 보안·권한·사람 승인

### 7.1 신뢰 영역

목표 제품은 의미상 다음 영역을 구분한다. 물리 저장 위치는 미정이다.

1. 프로젝트 비밀 원자료
2. 프로젝트 내부 정제 기억
3. 공유 승인된 비식별·조건부 파생물
4. 공통 후보 격리 영역
5. 사람 승인된 활성 공통 자산
6. 외부 공개 승인 뷰

### 7.2 필수 안전 원칙

- 프로젝트 정보는 전용이 기본이며 다른 프로젝트 요청은 기본 거부다.
- 원자료는 정책상 프로젝트에 남고 중앙에는 제한 포인터와 최소 파생물만 둘 수 있다.
- 관련성 순위는 접근권한을 우회하지 못한다.
- 자료 열람, 파생 공유, 자산 활성화, 고위험 적용, 외부 발행은 별도 권한이다.
- 외부 입력과 AI 회고는 신뢰되지 않은 데이터에서 시작한다.
- 단일 문자열 필터나 단일 LLM 검수는 안전 보증이 아니다. 최소권한, 구조적 격리, 도구 호출 검증, 사람 승인, 회귀시험을 겹친다(`R2:L390-L407`).
- 삭제·철회 시 먼저 사용·전달을 중지하고 사례·주장·자산·적용·브랜드 주장까지 파급을 찾는다.
- 파급 추적이 불완전하면 영향 범위를 좁게 가정하지 않고 넓게 중지한 뒤 수동 감사한다.
- 중앙 불능 시 프로젝트는 로컬 실행을 계속하며 신규 중앙 자산을 자동 신뢰하지 않는다.

### 7.3 사람 승인 관문

사람 승인 없이는 다음을 활성화하지 않는다.

1. 프로젝트 간 원자료 또는 비식별 파생 공유
2. 프로젝트 종류 공통·전체 공통 자산의 첫 활성화와 범위 확대
3. 고위험 필수·금지 규칙의 설정과 중지 해제
4. 중요한 자산의 폐기·충돌 최종 판정
5. 삭제·보존 의무 충돌의 판단
6. 고객 품질에 영향을 줄 수 있는 실험 조건 배정
7. 외부 브랜드 주장과 사례 공개·정정 범위
8. 예산·위험 허용치·전체 중단 기준 변경

저위험·가역적·프로젝트 전용 제한 시험은 사용자가 사전 승인한 정책 안에서만 자동화를 실험할 수 있다. 자동 긴급 중지는 허용할 수 있지만 재활성화는 사람이 한다.

승인 피로를 막기 위해 AI는 원자료 전체가 아니라 변화, 반례, 예상 영향, 되돌림, 미확인점을 담은 예외 대기열을 제시한다. 사람의 능동시간과 잘못된 승인율을 함께 측정한다.

### 8.2 증거 우선순위와 인과 규율

평가 우선순위는 객관 실행 시험·고객 인수 조건, 독립 사람 검토·실제 사용 결과, 블라인드·시간 분리 홀드아웃, 사람 판정으로 보정된 AI 평가, 자기평가 순이다(`R2:L329-L345`). AI 평가자 수를 늘려도 오류 상관이 같으면 독립 표가 늘지 않는다.

안전한 자체 개발·연습 과제에서 가능한 경우 다음을 비교한다.

1. 전통 없음
2. 원로그·원사례만 제공
3. 정제된 선례·작업 자산 제공

모델 이주 때는 현재 모델과 다른 모델 각각에서 전통 있음·없음을 가능한 범위에서 비교한다. 과제는 신선하고 시간 분리된 사례를 쓰며, 고객 납품에는 열등할 수 있는 조건을 무단 배정하지 않는다.

모델·도구·사람 숙련·오케스트레이션이 함께 바뀌면 `새 구성에서 관찰된 변화`까지만 말한다. 표본이 적으면 효과 방향·최악 사례·불확실성과 원자료를 보존하고 통계적 확신을 가장하지 않는다.

### 8.3 비용 판단

월 25만 원 수준은 사용자의 탐색 위험 한도이지 학습가치나 제품 성공의 자동 기준이 아니다(`PH:L187-L201`, `R2:L355-L369`). 다음 장부를 분리한다.

- A 활동: 실제 프로젝트 수익·납품 품질·고객 가치
- B 활동: Skill·테스트·오케스트레이션 개선 비용과 재사용 효과
- C 활동: 검색·승격·평가·폐기 체계 자체의 비용과 개선 효과

손실은 새 정보, 재사용 자산, 후속 선택권 중 하나를 실제로 남겼을 때만 학습 옵션 후보로 본다. 중앙 관리비가 A/B 성과를 지속적으로 방해하면 C 활동을 먼저 줄인다.

## 10. 첫 구축 범위: 계보–선택–피드백 철회 커널

### 10.1 목적과 한 문장 범위

**세 개의 가상 프로젝트에서 나온 출처 있는 경험을 비교해 조건부 자산 하나를 사람 승인 아래 제한 시험 상태로 만들고, 새 가상 작업에 전달·거부·변형한 결과와 원근거 철회가 자산 상태까지 되돌아오는 한 번의 결정 가능한 왕복**을 첫 구축으로 한다.

이번 문서는 그 구축을 설계만 하며 구현하지 않는다.

### 10.2 고정된 합성 입력

- 서로 이름이 비슷하지만 권한이 다른 가상 프로젝트 3개
- 성공·실패·결정·비용·사람 수정이 섞인 소수 실행 기록
- 같은 원근거에서 파생된 AI 요약 2개 이상
- 독립 원근거 1개 이상과 반례 1개
- 프로젝트 비밀 원문 1개와 공유 승인된 비식별 파생 1개
- 조건부 작업 자산 후보 정확히 1개와 수신 대상 새 가상 작업 1개
- 채택·거부·변형·오적용을 각각 시험하는 고정 결과 시나리오
- 원근거 철회 1건과 `변경 없음` 종합 1건

합성 입력의 기대 판정은 사전에 동결한다. 실제 모델 성능이나 검색 모델을 평가하지 않고 규칙·권한·상태·계보의 논리만 본다.

### 10.3 포함 능력

1. 프로젝트·작업·실행·팀 구성의 최소 정체성
2. 원근거와 파생 요약의 구분 및 증거 계열 중복 방지
3. 프로젝트 비공개와 허가된 파생 공유
4. 사실·해석·조건부 주장·반례의 최소 연결
5. 후보→제한 시험→활성/중지/폐기·대체 상태 판정
6. 권한·효력·적용 조건에 따른 전달 또는 거부
7. 채택·거부·변형·오적용 결과의 구분
8. 결과가 자산의 범위·효력 변경 후보를 만드는 환류
9. 원근거 철회가 후속 전달과 브랜드 후보를 차단하는 영향 추적
10. 동일 입력·동일 승인정책에서 판정 근거를 재구성할 수 있는 감사 추적

### 10.4 명시적 제외

- 실제 Project Brain 연결, 메시지·API·파일·이벤트 규격
- 실제 고객·개인·비밀 자료와 외부 공개
- 벡터 검색, RAG, 그래프·관계형 DB, 특정 저장 기술
- 실시간 이벤트 처리, 자동 외부 수집, 대시보드
- AI 자동 추출·자동 공통화·자동 승인 품질 평가
- 실제 모델 이주, 장기 성과, 수익성, 공동 브랜드 효과
- 모든 자산 유형·권한 역할·10개 상황의 완전 구현
- 고정 월간 운영 자동화

### 10.5 첫 구축 합격 조건

- 권한 없는 프로젝트 간 전달이 한 건도 없다.
- 같은 증거 계열의 여러 요약이 독립 근거로 세어지지 않는다.
- 반례가 숨겨지지 않고 공통화 보류 또는 범위 축소가 가능하다.
- 승인 전 후보와 중지·폐기 자산은 전달되지 않는다.
- 적용 결과가 정확한 자산 판본·수신 맥락·팀 구성에 연결된다.
- 원근거 철회가 파생 자산과 전달·브랜드 후보의 중지까지 도달한다.
- `변경 없음`이 오류가 아닌 정상 종료로 처리된다.
- 동일 입력의 모든 판정을 어떤 근거·권한·규칙으로 내렸는지 재구성할 수 있다.
- Project Brain의 내부 구조나 실제 통신 기술을 발명하지 않고 왕복을 완료한다.
- 단순 목록 대안과 비교해 적어도 중복 증거 또는 철회 누락 한 종류를 더 잘 탐지한다. 그렇지 않으면 계보 관계를 축소한다.

### 10.6 첫 구축이 증명하지 않는 것

합격해도 실제 검색 유용성, 자동 추출 정확성, 인간 운영부담, 품질·시간·비용 개선, 모델 간 전이, 비식별 안전, 장기 수익성, 브랜드 가치를 증명하지 않는다. 구조의 논리·권한·철회가 의도대로 작동한다는 증거일 뿐이다.

## 12. 중단·축소 조건

### 12.1 즉시 중지 조건

- 중대한 프로젝트 간 비밀·개인정보 유출 또는 지속 기억 오염
- 삭제·철회가 파생 자산과 전달·외부 주장에 도달하지 못함
- 공통 자산으로 중대한 품질·안전 회귀가 발생하고 영향 범위를 모름
- 권한 밖 자료가 관련성 점수나 자동화 때문에 전달됨

이 경우 관련 범위의 신규 검색·전달을 먼저 중지하고, 영향 범위를 넓게 잡아 수동 감사한다. 해제는 권한 있는 사람이 승인한다.

### 12.2 기능 축소 순서

1. 자동 제안이 오검색·음의 전이를 만들면 수동 요청형으로 낮춘다.
2. 전달 묶음이 길어 오적용을 늘리면 위험 기반 최소 묶음으로 줄인다.
3. 프로젝트 종류 공통화가 실패하면 프로젝트 전용 사례·자산만 유지한다.
4. 복잡한 계보가 목록보다 낫지 않으면 출처·증거 계열·판본·적용·철회 관계만 남긴다.
5. 정제 자산이 원로그보다 낫지 않으면 정제 절차를 폐기하고 원사례+테스트 중심으로 돌아간다.
6. 정기 종합이 의례화되면 사건·모델 이주·비용 임계 신호 검토만 남긴다.
7. 외부 브랜드가 위험하거나 무가치하면 내부 근거 기능만 유지한다.
8. 중앙 원자료 보관이 비밀·삭제 위험을 키우면 프로젝트 포인터와 최소 비식별 파생만 남긴다.

각 축소는 `무엇을 줄였는가`, `왜 줄였는가`, `잃은 사용자 목적`, `다시 확대할 조건`을 기록한다.

### 12.3 전체 중단 조건

다음이 반복되고 위 축소로도 통제되지 않으면 신규 수집·배포를 중단하고 단순 기록 체계 또는 프로젝트 로컬 자산으로 되돌린다.

- 신선한 과제에서 전통 없음·원로그보다 결과가 지속적으로 나쁨
- 사람 능동시간·현금·토큰·대기·재작업의 총비용이 품질·위험·재사용 가치보다 지속적으로 큼
- 음의 전이와 중앙 단일문화를 통제할 수 없음
- 모델 교체 때 핵심 자산 이주가 거의 항상 무가치함
- 사용·거부·변형 피드백이 다음 선택을 바꾸지 않음
- 문서·자산·승인은 늘지만 실제 행동과 결과가 달라지지 않음
- 중앙 유지가 실제 프로젝트 수행을 지속적으로 방해함
- 외부 브랜드가 객관 근거 없이 오도하는 서사로만 남음

폐기 시 법·계약상 보존·삭제 의무를 먼저 지키고, 허용되는 범위에서 폐기 이유·반증된 가설·유효했던 좁은 범위·재시도 조건만 남긴다.

## 17. 후보 결론

이 통합 후보의 중심 선택은 단순하다. 중앙은 모든 프로젝트를 지휘하거나 모든 기록을 모으는 곳이 아니라, 프로젝트 경계가 보존된 원근거와 인간–AI 작업 계보를 연결하고, 그중 현재 과제에 유효할 가능성이 있는 소수의 조건부 선례·자산만 전달하며, 실제 결과와 철회를 다시 다음 선택에 반영하는 통제면이다.

목표 제품은 경험·작업 자산·배포·피드백·보안·평가·브랜드의 전체 책임을 유지한다. 그러나 첫 구축은 세 가상 프로젝트와 자산 한 개로 계보, 권한, 선택, 피드백, 철회의 논리만 검증한다. 그 조각이 통과해도 성능 향상이나 모델 간 계승을 주장하지 않는다. 외부 독립 심사가 실행자 편차와 핵심 결정을 감사하고, 사용자 가치 판단이 끝난 뒤에만 다음 판본과 실제 구축 범위를 확정한다.
