### 1.2 현재 상태의 재구성

- **[고정 사실]** 목표는 개인의 성장 일지가 아니라, 여러 프로젝트와 여러 AI 세대가 검증된 경험을 이어받는 인간–AI 공동 작업 체계다.
- **[고정 사실]** 중앙 전통 시스템과 원천 멀티 AI 오케스트레이터는 병렬 개발 중이며, Project Brain의 역할·로그·완료 보고·통신 방식은 아직 안정되지 않았다.
- **[고정 사실]** 현재 중앙 시스템의 운영 효과, Project Brain 통합 결과, 장기 전이 결과는 존재하지 않는다.
- **[연구 근거]** 저장된 기록은 검색·적용·검증·수정까지 이어질 때만 작업 기억으로 기능하며, AI의 성찰이나 다수 AI의 합의만으로는 교훈이 검증되지 않는다.
- **[설계 결정]** 따라서 목표 제품은 전체 계보와 책임을 설계하되, 첫 구축은 Project Brain 없이 중앙의 핵심 순환을 검증하는 독립 조각으로 제한한다.

### 1.3 문서의 주장 표기

이 문서는 다음 표기를 사용한다.

- **[고정 사실]** 사용자 목적, 헌장, 공통 브리프가 확정한 조건
- **[연구 근거]** 입력 조사 문서가 확인한 사실이나 반복적으로 지지한 원리
- **[설계 결정]** 이 제안서가 목적과 근거를 바탕으로 선택한 구조
- **[검증 전 가설]** 구현·운영·비교 시험 전에는 효과를 주장할 수 없는 제안
- **[미정]** 현재 확정하면 Project Brain이나 기술 선택을 부당하게 고정하는 사항

## 2. 제품 한 문장 정의

**여러 프로젝트의 실행 증거와 인간–AI 결정 계보를 권한별로 보존하고, 그 증거에서 나온 조건부 작업 자산을 현재 과제에 선별 전달한 뒤 실제 적용 결과로 다시 수정·철회하는 중앙 계승 시스템이다.**

## 3. 문제 정의와 비목표

### 3.1 해결할 문제

좋은 모델을 새로 쓰는 것만으로는 이전 프로젝트의 경험이 다음 세션과 다음 모델에 자동으로 이어지지 않는다. 대화와 로그는 흩어지고, 성공 원인은 사라지며, 실패는 설명만 바뀐 채 반복될 수 있다. 한 프로젝트에서 유효했던 프롬프트나 Skill은 다른 조건에서 음의 전이를 일으킬 수 있고, 새 모델의 성능 향상은 전통의 효과로 잘못 계산될 수 있다. 여러 AI가 같은 자료를 요약한 결과를 독립 증거로 세거나, 성공만 골라 공동 브랜드를 꾸미는 위험도 있다.

중앙 시스템이 풀어야 할 문제는 “무엇을 많이 저장할 것인가”가 아니다. 다음 연결을 장기간 잃지 않는 것이다.

1. 어떤 프로젝트·작업·실행에서 무엇이 실제로 일어났는가.
2. 어떤 모델·도구·오케스트레이션·인간 승인 조건에서 그런 결과가 나왔는가.
3. 무엇이 사실이고 무엇이 해석·가설·결정인가.
4. 어떤 경험이 사례로만 남고, 어떤 것이 실행 가능한 작업 자산이 되는가.
5. 그 자산이 어느 프로젝트·과제·모델에 적용 가능하며 언제 금지되는가.
6. 실제로 검색·채택·변형·사용된 뒤 결과가 좋아졌는가.
7. 근거가 틀리거나 삭제되면 파생 자산과 외부 주장까지 어떻게 멈추는가.

### 3.2 비목표

이 제품은 다음을 목표로 하지 않는다.

- 모델 가중치 학습, AI 인격이나 동일성의 보존
- 모든 대화·파일·고객 자료를 영구 복제하는 중앙 감시 저장소
- 실패만 모은 incident 데이터베이스 또는 성공 사례 홍보관
- 모든 프로젝트에 같은 프롬프트와 절차를 강제하는 표준화 엔진
- 프로젝트마다 중앙 시스템 완성본을 복사해 운영하는 구조
- Project Brain의 실제 메시지, API, 파일, 실시간 통신 순서를 지금 확정하는 일
- AI 합의나 자기평가를 자동 승인으로 바꾸는 일
- 사람의 법적·윤리적·대외 책임을 AI에 이전하는 일
- 월마다 교리나 문서를 일정 수량 생산하는 의례
- 문서 수, 검색 횟수, 에이전트 수, 내부 점수 자체를 성공으로 간주하는 일

## 4. 사용자 목적과 성공·실패의 정의

### 4.1 목적의 독립적 해석

**[설계 결정]** 사용자가 원하는 “전통”은 과거의 정답집이 아니라, 서로 다른 프로젝트와 모델 세대 사이에서 다음 네 능력이 반복되는 체계다.

1. **기억:** 원사건과 판단의 맥락을 잃지 않는다.
2. **선별:** 현재 과제에 맞는 소수의 경험과 자산만 고른다.
3. **재검증:** 과거 자산을 현재 구성에서 다시 시험한다.
4. **자기수정:** 반례·음의 전이·삭제 요구에 따라 범위를 줄이거나 철회한다.

공동 브랜드는 이 네 능력이 만든 관찰 가능한 작업 습관의 계보다. 특정 모델 이름이나 의인화된 AI 서사가 아니다.

### 4.2 제품 성공

제품은 다음 결과가 신선한 과제와 다른 구성에서도 관찰될 때 성공에 가까워진다.

- 중대한 반복 오류와 불필요한 시행착오가 줄어든다.
- 관련 경험을 찾는 비율뿐 아니라, 올바른 경험을 선택해 행동에 반영하는 비율이 높아진다.
- 검증된 Skill·테스트·체크리스트 등이 원로그만 제공한 조건보다 품질·시간·비용·위험 중 중요한 항목을 개선한다.
- 프로젝트 전용 지식이 허가 없이 다른 프로젝트로 새지 않는다.
- 새 모델에서도 핵심 작업방식의 이득이 재현되거나, 재현되지 않을 때 빠르게 비호환 판정을 내린다.
- 잘못된 자산과 외부 주장을 근거 계보를 따라 중지·수정·폐기할 수 있다.
- 사람의 능동 관리시간을 포함한 총비용보다 실제 재사용·품질·위험 감소 가치가 크다.
- 블라인드 산출물에서도 사실·추론 구분, 검증, 수정, 비용 정직성 같은 브랜드 특성이 반복된다.

### 4.3 제품 실패

다음 상태가 지속되면 기능 추가가 아니라 축소·중단을 검토한다.

- 기록과 요약은 늘지만 다음 프로젝트의 행동이나 결과가 달라지지 않는다.
- 검색된 자산이 오검색·선택 부담·음의 전이를 늘린다.
- 모델·도구 향상이나 사용자 숙련을 중앙 전통의 효과로 계속 오인한다.
- 프로젝트 간 비밀·권한 분리가 반복해서 깨진다.
- AI가 만든 후보를 사람이 실질적으로 검토하지 않고 도장만 찍는다.
- 반대로 사람이 모든 원기록을 다시 읽고 수작업 정리해야 해 중앙 자동화의 순가치가 음수가 된다.
- 중앙 공통 자산 때문에 프로젝트별 탐색과 다양성이 사라진다.
- 공동 브랜드가 성공 사례만 편집하는 서사가 된다.

## 5. 중앙 시스템의 의미와 책임 경계

### 5.1 “중앙”의 의미

**[설계 결정]** 중앙은 모든 데이터를 한곳에 무조건 복사한다는 뜻이 아니다. 다음 책임을 하나의 권위 있는 체계가 맡는다는 뜻이다.

- 프로젝트와 실행을 서로 혼동하지 않는 전역 식별과 계보
- 프로젝트별 권한·비밀 경계와 허용된 파생 관계
- 프로젝트 간 비교, 공통 후보 생성, 분기, 배포, 회수, 철회
- 자산 판본과 효력 상태의 단일 기준
- 적용 결과와 평가의 환류
- 삭제·철회가 파생 자산과 공개 주장까지 미치는 영향 추적
- 장기적인 공동 브랜드 근거와 변경 이력

원자료는 정책상 프로젝트 경계 안에 남고 중앙에는 제한 포인터와 비식별 파생물만 존재할 수도 있다. 저장 위치는 **[미정]**이지만, 권한 판단과 계보 책임은 중앙 시스템에 남는다.

### 5.2 중앙이 하지 않는 일

- 프로젝트의 일상 실행을 직접 지휘하지 않는다.
- Project Brain을 대체하거나 프로젝트 내부 역할 분배를 소유하지 않는다.
- 검색 결과를 프로젝트의 최종 명령으로 취급하지 않는다.
- 고객 납품의 최종 승인이나 법적 책임을 맡지 않는다.
- 프로젝트 native test·체크리스트가 더 적합하면 중앙에 중복 복제하지 않는다. 중앙은 해당 자산을 가리키고 계보·상태·효과만 연결할 수 있다.

### 5.3 Project Brain과의 의미상 경계

Project Brain의 실제 규격은 정하지 않되 책임의 의미는 분리한다.

- Project Brain은 현재 프로젝트의 목표, 작업 상태, 로컬 권한, 실행 선택, 결과 제출을 책임진다.
- 중앙 시스템은 요청 맥락에 맞는 기억과 자산을 선별하고, 적용 조건·반례·상태·철회 정보를 함께 제공한다.
- Project Brain은 자산을 채택·거부·변형할 수 있으며 이유와 결과를 돌려준다.
- 중앙은 그 피드백으로 검색 문제, 채택 문제, 실행 문제, 자산 문제를 구분한다.
- 중앙의 긴급 철회는 “사용하지 말라”는 안전 상태를 전달할 수 있지만, 프로젝트의 실제 중단과 외부 조치는 Project Brain과 인간 책임자가 확인한다.

향후 어떤 통신 수단을 택하더라도 필요한 의미 범주는 `요청 맥락`, `권한 증명`, `전달 묶음`, `채택·변형 결정`, `적용 결과`, `철회·삭제 통지`다. 이는 데이터 필드나 메시지 순서를 확정한 것이 아니다.

## 6. 사용자·AI·Project Brain·중앙 역할과 책임

| 행위자 | 주된 책임 | 할 수 없는 일 |
|---|---|---|
| 인간 소유자·책임자 | 목적·가치·예산·위험 허용치, 프로젝트 간 공유, 중요한 승격·폐기, 외부 공개, 최종 책임 | AI의 합의만 보고 근거 검토를 생략하거나 삭제 의무를 전통 보존보다 낮출 수 없음 |
| 프로젝트 책임 인간 | 고객 의무, 로컬 비밀·권한, 고위험 적용과 납품 승인 | 다른 프로젝트의 비공개 지식을 임의로 요청·공유할 수 없음 |
| Project Brain 또는 대표 AI | 작업 맥락 요약, 중앙 요청, 자산 채택·거부·변형, 로컬 실행 조정, 결과 환류 | 중앙 자산을 자동 진리로 간주하거나 인간 승인을 대신할 수 없음 |
| 프로젝트 실행 AI | 생성·분석·시험·비평·인계, 적용 충실도와 불확실성 보고 | 자신의 결과나 회고를 독립 검증으로 승인할 수 없음 |
| 중앙 수집·정리 AI | 분류, 중복·계보 후보, 비밀 위험 탐지, 사례·가설 초안 | 원자료를 조용히 고치거나 후보를 공통 규칙으로 자동 승격할 수 없음 |
| 중앙 비교·비평 AI | 프로젝트 간 유사점·차이·반례·모순·오류 상관 탐색 | 동일 근거의 여러 요약을 여러 독립 증거로 셀 수 없음 |
| 중앙 검색·전달 기능 | 권한·상태·범위에 맞는 최소 묶음 제안, 철회 차단 | 비공개 근거를 관련성 점수만으로 노출할 수 없음 |
| 중앙 평가 기능 | 적용 결과, 비용, 전이, 부작용, 운영 부담 집계 | 인과가 불분명한 관찰을 전통의 단독 효과로 선언할 수 없음 |
| 독립 검토자 또는 외부 평가자 | 고위험·고가치 결과의 독립 확인, 브랜드 주장의 표본 검증 | 필요한 비밀과 권한을 우회할 수 없음 |

한 사람이 여러 인간 역할을 겸할 수는 있다. 그러나 시스템 안에서는 “자료 소유자로 공유 승인”, “큐레이터로 자산 활성화”, “발행자로 외부 공개”를 서로 다른 결정으로 남긴다. 역할 분리는 인원 수가 아니라 판단 경계다.

## 7. 세 가지 전체 구조 대안

### 7.1 대안 A: 단계 관문형 중앙 창고

모든 프로젝트 경험을 중앙에 수집하고, `수집 → 정리 → 교훈 → 자산 → 배포 → 평가`의 공통 단계를 통과시키는 구조다.

- 장점: 상태가 단순하고 감사·자동화·운영 교육이 쉽다.
- 장점: 무엇이 아직 후보이고 무엇이 활성인지 한눈에 보인다.
- 약점: 모든 경험이 같은 사다리를 타야 해 결정·실험·반례처럼 규칙이 되지 않아도 중요한 자료를 왜곡한다.
- 약점: 중앙 단계가 병목이 되고, 공통화가 권위화되며 프로젝트 다양성을 줄일 가능성이 크다.
- 재검토 조건: 실제 경험 대부분이 비슷한 처리 단계를 따르고 예외 분기가 거의 없다면 더 단순한 이 대안이 우월할 수 있다.

### 7.2 대안 B: 프로젝트 셀 연합과 중앙 카탈로그

각 프로젝트가 자체 기억과 자산을 소유하고 중앙은 위치, 요약, 검색 표지, 공유 허가만 관리한다. 공통 지식은 프로젝트들이 발행한 항목을 모아 만든다.

- 장점: 프로젝트 비밀·자율성·도메인 다양성 보존이 강하다.
- 장점: 중앙 장애가 프로젝트 실행 전체를 멈추게 할 위험이 작다.
- 약점: 프로젝트마다 표현과 품질이 달라 비교·철회·중복 제거가 어렵다.
- 약점: 프로젝트가 종료되거나 Brain이 바뀌면 계보와 피드백이 다시 단절될 수 있다.
- 재검토 조건: 프로젝트별 법적·기술적 격리가 절대적이거나 공통 중앙 보관이 허용되지 않으면 이 대안의 비중을 높여야 한다.

### 7.3 대안 C: 증거 계보망과 범위별 자산 포트폴리오

원사건, 판단, 자산, 적용 결과를 하나의 고정 사다리가 아니라 출처가 연결된 계보망으로 관리한다. 동시에 실제 행동에 쓰이는 자산은 프로젝트 전용·프로젝트 종류 공통·전체 공통의 범위별 포트폴리오로 작게 관리한다. 검색과 적용 결과는 다시 계보망으로 돌아온다.

- 장점: 규칙이 되지 않는 성공·결정·실험·반례도 원래 가치대로 남길 수 있다.
- 장점: 같은 근거에서 여러 자산이 나오거나 하나의 자산이 여러 근거를 가질 수 있다.
- 장점: 범위, 증거 확실성, 행동 강도, 공개 권한을 서로 분리해 공통화의 권위화를 막을 수 있다.
- 약점: 관계와 상태가 많아지면 이해·검색·운영 비용이 커질 수 있다.
- 약점: 계보망 자체를 정교하게 만드는 일이 목적이 되는 과잉 설계 위험이 있다.
- 재검토 조건: 첫 세로 조각에서도 관계 추적의 이득이 단순 목록보다 작고 관리시간만 늘면 관계 종류를 줄이거나 대안 A의 간단한 관문을 채택해야 한다.

## 8. 대안 비교와 주설계 선택

평가는 `높음/중간/낮음`의 상대 판단이며 운영 결과가 아니다.

| 비교 기준 | A. 단계 관문형 | B. 프로젝트 셀 연합 | C. 계보망+포트폴리오 |
|---|---|---|---|
| 사용자 목적 전체 충족 | 중간: 실행 자산에는 강하나 경험 폭을 축소할 위험 | 중간: 다양성은 강하나 장기 중앙 계승이 약함 | 높음: 경험·자산·적용 결과를 함께 연결 |
| 여러 AI 세대의 장기 계승 | 중간 | 낮음~중간 | 높음: 구성과 판본 관계를 명시 |
| 프로젝트 분리 | 중간: 중앙 수집에 과잉 노출 위험 | 높음 | 높음: 권한 경계와 파생 관계를 별도 관리 |
| 자동화 가능성 | 높음: 선형 처리에 유리 | 중간: 프로젝트별 차이가 큼 | 중간~높음: 후보 생성은 쉽지만 승인·관계 판단 필요 |
| 검증 가능성 | 높음: 상태 전이가 단순 | 중간: 분산된 결과 수집이 어려움 | 높음: 근거부터 적용 결과까지 추적 가능 |
| 1인 운영 비용 | 초기 낮음, 예외가 늘면 높아짐 | 프로젝트 수 증가 시 높음 | 초기 중간, 예외 중심 자동화가 되면 중간 |
| 확장 위험 | 중앙 병목·단일문화 | 파편화·고아 지식 | 관계 과잉·검색 복잡성 |

**[설계 결정]** 주설계로 대안 C를 선택한다. 사용자의 목적은 작업 자산 저장만이 아니라 프로젝트·모델 세대를 가로지르는 경험과 수정의 계보다. 고정 사다리보다 계보망이 이 폭을 보존하고, 별도의 작은 자산 포트폴리오가 실행 시 과거 전체를 읽히지 않게 한다.

선택하지 않은 대안의 장점은 다음처럼 유지한다.

- A에서 `후보/시험/활성/중지/폐기`처럼 분명한 효력 상태와 사람 승인 관문을 가져온다.
- B에서 프로젝트 비공개를 기본값으로 두고, 로컬 자산 우선·중앙 자산 거부권·안전한 파생 공유를 가져온다.

**[검증 전 가설]** 이 결합이 단순 중앙 목록보다 검색 정확도와 철회 가능성을 높이면서 1인 관리비용을 감당 가능한 수준에 둘 것이라고 가정한다. 첫 구축에서 이 가정이 깨지면 계보 관계와 검토 의례를 줄인다.

| 공개 주장 | 공동 브랜드를 위해 외부에 표현한 제한된 명제 | 내부 근거, 공개 승인, 정정·철회 상태 |

### 10.2 관계 원칙

- 하나의 사건이 하나의 교훈이 된다고 가정하지 않는다.
- 여러 사건·결정·실험이 한 주장을 지지하거나 반박할 수 있다.
- 하나의 주장으로 여러 유형의 작업 자산을 만들 수 있고, 자산을 전혀 만들지 않을 수도 있다.
- 하나의 자산은 여러 근거를 가질 수 있으며, 어느 근거가 철회됐는지 구별해야 한다.
- 요약·번역·AI 재서술은 새 증거가 아니라 같은 증거 뿌리의 파생물이다.
- 범위가 넓다는 것은 증거가 강하거나 행동이 의무라는 뜻이 아니다.
- 접근 권한, 공개 가능성, 증거 확실성, 행동 강도, 적용 범위는 서로 다른 축이다.
- 원자료는 가능한 한 불변으로 보존하되, 비밀·개인정보 삭제 의무가 계보 보존보다 우선한다.

## 11. 프로젝트·작업·실행·모델·도구 계보

### 11.1 안정적 식별

**[설계 결정]** 프로젝트와 작업은 표시 이름이 아니라 안정된 내부 정체성으로 구분한다. 이름 변경은 정체성을 바꾸지 않으며, 같은 이름의 두 프로젝트는 다른 정체성을 갖는다. 복제·분기·후속 프로젝트는 별도 정체성을 만들고 선행 관계만 연결한다.

### 11.2 실행 계보

한 작업에는 여러 실행이 있을 수 있다. 각 실행은 적어도 다음 맥락을 보존한다.

- 당시 목표와 인수 조건
- 인간 역할과 승인 정책
- 사용한 모델과 확인 가능한 판본 정보
- AI 역할 구성과 오케스트레이션 정책
- 도구와 중요한 환경 조건
- 전달받은 기억·Skill·프롬프트 판본
- 평가 방법과 예산 맥락
- 결과물, 실제 결과, 사람 수정, 재작업, 비용

정확히 고정할 수 없는 구성요소는 `미상`이나 범위로 남긴다. 추정값을 사실처럼 채우지 않는다.

### 11.3 변경 해석

모델만 바뀌었다고 가정하지 않고 팀 구성 전체의 변경을 비교한다. 여러 요소가 동시에 바뀌면 결과는 “새 구성에서 관찰된 차이”로만 보고하고, 전통의 인과효과라는 주장을 낮춘다.

**재검토 조건:** 실행 맥락 기록이 실제 판단에 쓰이지 않고 수집 비용만 키우면, 전이·비용·위험 해석에 영향을 준 필드만 남긴다. 단, 모델·도구·자산 판본·인간 승인·결과의 연결은 제거하지 않는다.

## 12. 성공·실패·결정·실험·반례 처리

### 12.1 결과와 과정의 분리

성공/실패만으로 교훈을 정하지 않는다.

| 과정 판단 | 결과 판단 | 중앙 처리 |
|---|---|---|
| 적절 | 좋음 | 재현 후보. 다른 조건에서 원인 가설을 시험 |
| 적절 | 나쁨 | 환경 변화, 평가 오류, 우연, 통제 불가능 요인을 조사 |
| 부적절 | 좋음 | 운 좋은 성공 또는 근접 실패. 자산 승격을 보류하고 위험을 기록 |
| 부적절 | 나쁨 | 교정 후보. 단일 원인보다 여러 기여 조건을 보존 |

과정 판단도 AI의 자기평가가 아니라 당시 기준, 실행 흔적, 외부 평가, 사람 검토에 연결한다.

### 12.2 경험 유형별 처리

- **성공:** 재현할 핵심 기능과 우연·외부 요인을 분리한다. 성공 원인이 불명확하면 성공 사례로 남기되 작업 규칙으로 만들지 않는다.
- **실패·incident:** 영향, 당시 정보, 기여 조건, 완화·후속 결과를 남긴다. 사람 비난과 학습 분석을 분리하되 고의·법적 문제는 별도 절차로 넘긴다.
- **중요한 결정:** 선택지, 거부 이유, 제약, 승인, 나중에 드러난 결과와 대체 관계를 보존한다.
- **실험:** 사전 가설·비교 조건·측정·중단 기준과 사후 결과를 구분한다. 결과 뒤 만든 설명은 새 가설이다.
- **반례:** 기존 주장을 삭제하지 않고 적용 범위를 줄이거나 경쟁 주장을 만드는 근거가 된다.
- **근접 실패:** 실제 위해가 없었다는 이유로 성공 처리하지 않는다.
- **사람 수정:** AI 출력의 결함, 인간의 선호 변경, 고객 요구 변경을 구분하려 한다.
- **AI 간 충돌:** 의견 수가 아니라 근거 뿌리와 오류 독립성을 본다. 소수 의견을 보존한다.
- **비용 사건:** 현금, 토큰, 사람 능동시간, 대기, 재작업, 기회비용을 가능한 범위에서 분리한다.

### 12.3 규칙이 되지 않는 경험의 가치

모든 경험은 자산 후보가 될 필요가 없다. 원인이 불분명한 성공, 희귀한 반례, 한 번뿐인 결정도 이후 비교·위험 탐지·브랜드 정직성에 쓰일 수 있다. “자산으로 승격되지 않음”은 실패 상태가 아니라 정상 종착점이다.

## 13. 프로젝트 전용·종류 공통·전체 공통의 관계

### 13.1 세 범위

1. **프로젝트 전용:** 해당 프로젝트의 목표·환경·비밀·팀 구성에 묶인 사례와 자산. 기본값이다.
2. **프로젝트 종류 공통:** 유사한 과제·위험·도구 조건을 가진 프로젝트군에서 참고할 수 있는 조건부 자산.
3. **전체 공통:** 여러 종류와 모델에서 재검증됐거나, 안전상 폭넓게 적용할 이유가 있는 핵심 원칙. 그래도 조건부다.

### 13.2 이동이 아니라 파생

**[설계 결정]** 프로젝트 전용 항목을 공통 영역으로 “옮기지” 않는다. 원본은 원래 권한과 맥락에 남고, 허가된 근거에서 비식별·조건부 파생물을 새로 만든다. 따라서 공통 자산이 철회돼도 원래 프로젝트 사건은 삭제되지 않으며, 반대로 원근거 삭제 시 파생물의 효력을 다시 계산할 수 있다.

### 13.3 다섯 축의 분리

각 항목은 다음을 하나의 등급으로 합치지 않는다.

- 적용 범위: 어디에 관련 있는가
- 접근 권한: 누가 볼 수 있는가
- 증거 확실성: 근거를 얼마나 믿는가
- 행동 강도: 권고·선택·금지 가운데 얼마나 강한가
- 공개 가능성: 외부에 어떤 형태로 말할 수 있는가

전체 공통이라도 낮은 확실성의 시험 후보일 수 있고, 프로젝트 전용이라도 중대한 안전 금지일 수 있다.

### 13.4 공통화의 조건

공통화는 반복 횟수만으로 결정하지 않는다. 서로 독립된 증거 뿌리, 프로젝트·모델·도구 차이, 반례, 실제 적용 결과, 위해와 가역성을 함께 본다. 정확한 횟수와 수치 문턱은 **[미정]**이다.

**재검토 조건:** 프로젝트 종류 분류가 검색 선택 부담만 늘리고 실제 전이를 설명하지 못하면 종류 계층을 단순 태그나 조건 집합으로 축소한다.

## 14. 여러 프로젝트 비교와 공통화·분기·모순 처리

### 14.1 비교 방법

중앙은 프로젝트 이름이나 결과 문구만 비교하지 않는다. 가능한 범위에서 다음 차원을 사용한다.

- 과제 목표와 인수 조건
- 위험과 실패 모드
- 모델·도구·오케스트레이션 구성
- 데이터·도메인·고객 제약
- 사용한 자산과 판본
- 과정의 적절성, 결과, 비용, 사람 수정
- 평가 방법과 피드백 지연

AI는 유사 사례 군집과 잠재 반례를 제안할 수 있으나, 군집 자체는 공통 원인의 증거가 아니다.

### 14.2 독립 증거 계산

같은 로그를 여러 AI가 요약하거나 같은 AI 계열이 같은 프롬프트로 평가한 결과는 독립 표로 세지 않는다. 중앙은 증거 뿌리와 생성 계보를 따라 상관된 파생물을 묶고, 독립성은 별도 판단으로 남긴다.

### 14.3 모순 처리

모순되는 경험은 투표, 평균, 최신순으로 덮지 않는다. 중앙은 다음 중 하나를 선택할 수 있다.

- 두 주장을 서로 다른 적용 조건으로 병존시킨다.
- 더 구체적인 조건으로 하나의 주장을 분기한다.
- 기존 자산의 범위를 축소하거나 새 구성에서만 중지한다.
- 고위험 불확실성이면 우선 전달을 중지하고 재시험한다.
- 근거가 부족하면 결론을 내리지 않고 충돌 묶음으로 유지한다.

### 14.4 중앙집중과 단일문화 방지

- 프로젝트는 중앙 자산을 거부하거나 로컬 대안을 유지할 수 있다.
- 중요한 충돌에서는 경쟁 자산과 반례를 함께 전달한다.
- 공통 자산 하나를 전역 우승자로 만들기보다 조건별 고품질 대안을 유지한다.
- 복잡·창의·고위험 문제에서는 필요할 때 독립 초안을 먼저 만들고 나중에 비교한다.
- 동일 모델·프롬프트의 에이전트 수를 다양성으로 계산하지 않는다.

**[검증 전 가설]** 조건별 포트폴리오가 단일 공통 규칙보다 음의 전이를 줄일 것이다. 선택 부담이 더 커져 총성과가 나빠지면 경쟁 자산을 줄이고 검색 기준을 단순화한다.

## 15. Skill·프롬프트·체크리스트·테스트·템플릿·행동 규칙의 생명주기

### 15.1 자산 유형과 공통 원칙

작업 자산은 서로 다른 기능을 갖는다.

- Skill: 반복 가능한 절차와 판단 흐름
- 프롬프트: 특정 모델·상황에서 절차를 표현하는 지시 형태
- 체크리스트: 빠뜨리면 위험한 확인 항목
- 테스트: 결과나 회귀를 판정하는 실행 가능한 평가 자산
- 템플릿: 산출물의 구조와 필수 정보
- 판단 기준: 선택·검토의 기준
- 행동 규칙: 특정 조건에서 권고·금지되는 행동

어떤 유형도 자동으로 더 높은 권위를 갖지 않는다. 프로젝트에 더 좋은 native test나 템플릿이 있으면 중앙은 복사본 대신 참조와 효과 계보를 관리한다.

### 15.2 필수 의미

각 자산은 최소한 다음 질문에 답해야 한다.

- 무엇을 해결하며 핵심 기능은 무엇인가.
- 언제 사용하고 언제 사용하지 않는가.
- 어느 프로젝트·과제·모델·도구 조건에서 시험됐는가.
- 어떤 증거와 반례에서 나왔는가.
- 어떤 판본이 현재 유효하며 무엇을 대체하는가.
- 기대 이익과 가능한 부작용은 무엇인가.
- 무엇으로 성공·실패를 판정하는가.
- 누가 활성화·제한·철회했는가.

### 15.3 효력 상태

고정된 지식 사다리는 강제하지 않지만 실행 자산의 효력은 분명히 한다.

- **초안:** AI나 사람이 만든 후보. 전달 대상이 아님.
- **제한 시험:** 지정된 안전한 범위에서만 평가 가능.
- **활성:** 명시된 범위에서 제안 가능. 자동 의무가 아님.
- **제한:** 특정 구성·위험에서는 사용 금지 또는 추가 승인 필요.
- **중지:** 긴급 위험·근거 철회·음의 전이로 전달 차단.
- **폐기·대체:** 일반 사용 종료. 역사·반례 질의에서만 보이되 삭제 의무는 별도 처리.

상태는 자산 전체뿐 아니라 모델·도구·프로젝트 범위별로 다를 수 있다.

### 15.4 생성에서 폐기까지

1. AI는 사건·결정·실험에서 자산 후보와 반례를 제안한다.
2. 중앙은 원근거, 비밀, 중복, 기존 native 자산, 경쟁 자산을 확인한다.
3. 사람 또는 사전 위임 정책이 제한 시험 여부를 정한다. 프로젝트 종류 공통·전체 공통 활성화와 고위험 의무·금지는 사람이 승인한다.
4. 새 과제에서 검색·채택·충실도·적응·결과·비용을 따로 측정한다.
5. 결과에 따라 유지, 표현 수정, 적용 범위 분기, 중지, 폐기한다.
6. 근거 철회·삭제 시 파생 자산의 남은 근거를 재평가하고 필요하면 즉시 중지한다.

### 15.5 핵심 기능과 어댑터

**[검증 전 가설]** 모델을 넘어 계승하기 위해 자산의 `모델 중립 핵심 기능`과 `모델·도구별 표현`을 구분한다. 예를 들어 “근거와 추론을 분리해 검토한다”는 핵심 기능과 특정 모델용 프롬프트 표현은 다른 판본 관계를 가진다. 이 분리가 실제 전이를 돕지 않고 관리비만 늘면 단일 자산 안의 조건부 변형으로 단순화한다.

## 16. 검색·선택·전달·거부·변형·결과 회수 흐름

### 16.1 의미 흐름

1. Project Brain 또는 대표가 현재 과제의 목표, 위험, 구성, 허용 권한, 원하는 도움 종류를 중앙에 제시한다.
2. 중앙은 먼저 프로젝트·사용자 권한과 비밀 경계를 확인한다.
3. 중지·폐기·비호환 판본을 제외하고, 적용 범위·조건·현재 구성에 맞는 후보를 좁힌다.
4. 관련성뿐 아니라 반례, 최근 음의 전이, 근거 독립성, 예상 적용비용을 함께 비교한다.
5. 중앙은 소수의 자산과 필요한 사례만 전달한다. 전달 묶음에는 목적, 적용·금지 조건, 현재 상태, 핵심 근거, 반례, 검증 방법, 철회 여부가 포함된다.
6. Project Brain은 채택, 거부, 변형, 추가 근거 요청 가운데 하나를 결정하고 이유를 남긴다.
7. 사용했다면 어떤 판본을 어떤 변형으로 적용했는지와 결과·비용·사람 수정을 돌려준다.
8. 중앙은 결과를 원래 자산과 현재 구성에 연결하고 검색·자산 상태를 갱신할 후보를 만든다.

이는 통신 규격이나 필드 목록이 아니라 반드시 보존할 의미 순서다.

### 16.2 실패 위치 구분

| 실패 위치 | 판정 질문 | 가능한 대응 |
|---|---|---|
| 수집 실패 | 필요한 사건·결과가 중앙에 들어왔는가 | 입력 경계·완료 정의 보완 |
| 검색 실패 | 관련 자산을 못 찾았거나 무관한 것을 찾았는가 | 조건·표지·랭킹 수정 |
| 채택 실패 | 적절한 자산이 제안됐지만 왜 거부됐는가 | 비용·설명·적합성 또는 정당한 거부 확인 |
| 충실도 실패 | 핵심 기능대로 실행됐는가 | 표현·훈련·Project Brain 인계 개선 |
| 변형 실패 | 변형이 핵심 기능을 훼손했는가 | 어댑터 분리 또는 변형 제한 |
| 자산 실패 | 제대로 썼는데 결과가 나빠졌는가 | 범위 축소·중지·폐기 |
| 평가 실패 | 결과를 판정할 자료가 있는가 | 측정 설계 개선, 결론 보류 |
| 권한·오염 실패 | 금지 정보나 악성 지침이 전달됐는가 | 격리·긴급 중지·영향 추적 |

“사용되지 않음”은 곧바로 자산 실패가 아니다. 정당한 거부는 프로젝트 자율성의 신호일 수 있다.

## 17. 모델·도구·오케스트레이션 변경과 계승

### 17.1 업그레이드가 아니라 이주

새 모델·도구·오케스트레이션은 자동 상위호환으로 보지 않는다. 기존 자산의 과거 `활성` 상태는 기존 구성에서의 상태이며 새 구성에서는 `미평가`, `제한 시험`, `비호환` 중 하나가 될 수 있다.

### 17.2 이주 절차의 의미

- 변경 전후 팀 구성을 기록하고 함께 바뀐 요소를 드러낸다.
- 영향받는 자산과 대표 과제·실패 사례를 고른다.
- 가능한 경우 신선한 과제로 기존 자산 없음/있음, 기존·새 표현을 비교한다.
- 평균 품질뿐 아니라 최악 오류, 사람 수정, 시간, 비용, 오검색을 본다.
- 핵심 기능은 유지되지만 표현만 실패하면 새 어댑터를 만든다.
- 새 모델 자체가 해결해 자산 이득이 사라지면 자산을 불필요 또는 역사 자료로 낮춘다.
- 음의 전이가 나타나면 새 구성에 한해 즉시 중지하고 이전 구성의 결과를 지우지 않는다.

### 17.3 주장 강도

한 번의 모델 이주 성공은 모든 모델 전이를 증명하지 않는다. 여러 요소가 동시에 바뀌면 “새 팀 구성에서 재현됨”까지만 말한다.

**재검토 조건:** 대표 과제 이주 시험이 실제 운영 위험을 예측하지 못하면 과제 선정과 평가법을 바꾸고, 예측 실패가 반복되면 모델 중립 핵심 자산이라는 가설의 범위를 축소한다.

## 18. 자동화와 사람 승인

### 18.1 자동화를 기본으로 두는 영역

AI와 자동 처리는 다음을 기본적으로 수행할 수 있다.

- 완료 입력의 정규화와 누락 탐지
- 출처 연결, 동일 증거 뿌리 후보, 중복 후보 제시
- 비밀·개인정보·악성 지침 위험 탐지와 격리 제안
- 성공·실패·결정·실험·비용·사람 수정의 분류 초안
- 유사 사례, 반례, 모순, 오래되거나 사용되지 않는 자산 탐색
- 사례·주장·자산 초안과 적용·금지 조건 제안
- 권한·효력 상태에 따른 검색·전달 후보 생성
- 적용 피드백 분류와 평가 자료 집계
- 긴급 중지 대상으로 승인된 자산의 전달 차단과 영향 대상 알림
- 사람에게 전체 기록이 아니라 예외·결정 대기열을 제시

자동 분류와 요약은 되돌릴 수 있어야 하며 원자료를 대체하지 않는다.

### 18.2 사람 승인 없이는 할 수 없는 일

- 프로젝트 간 원자료 또는 비식별 파생물 공유
- 프로젝트 종류 공통·전체 공통 자산의 활성화
- 고위험 행동의 의무화 또는 금지 해제
- 중요한 자산의 폐기·범위 확대·충돌 최종 판정
- 삭제 의무의 예외 판단과 복구 불가능한 외부 공개
- 고객·공모전·공개 포트폴리오에 관한 브랜드 주장
- 예산·위험 허용치·평가 중단 기준의 변경

저위험·가역적·프로젝트 전용 시험은 인간이 사전에 정한 정책 안에서 자동 허용할 수 있다. 정책의 범위와 결과는 사람이 정기적으로 확인한다.

### 18.3 승인 피로 방지

- 사람에게 원자료 전체가 아니라 변경 이유, 반례, 예상 영향, 되돌림 방법을 보여준다.
- 영향이 없는 반복 결정은 사전 위임 정책으로 묶는다.
- 중대한 예외, 범위 확대, 외부 공개, 비밀·삭제만 높은 우선순위로 올린다.
- 월간 검토에서 승인 수가 아니라 사람 능동시간과 결정 품질을 측정한다.

**[검증 전 가설]** 예외 중심 검토가 수작업 전수 검토보다 안전을 유지하면서 관리시간을 줄일 것이다. 자동화 누락 때문에 중대한 문제가 늦게 발견되거나 승인자가 맥락을 이해하지 못하면 자동화 범위를 줄인다.

## 19. 개인정보·비밀·삭제·권한·기억 오염

### 19.1 기본 신뢰 원칙

외부 웹, 고객 메시지, 저장소 내용, 문서, AI 회고는 모두 처음에는 신뢰되지 않은 입력이다. 그 안의 문장은 분석 대상 데이터이지 중앙 시스템의 명령이 아니다.

### 19.2 프로젝트 격리와 최소권한

- 프로젝트마다 원자료 접근 경계를 둔다.
- 중앙 비교는 가능한 경우 비식별·최소 파생 정보로 수행한다.
- 검색자는 관련성보다 먼저 권한을 통과해야 한다.
- 자료 열람, 자산 활성화, 프로젝트 간 배포, 외부 발행은 서로 다른 권한으로 취급한다.
- 다른 프로젝트의 비공개 지식 요청은 기본 거부이며, 자료 소유자의 승인 아래 안전한 추상화만 새 파생물로 만들 수 있다.

### 19.3 비밀과 오염 처리

- 민감정보·계약상 비밀·개인정보 후보는 활성 기억 경로에서 격리한다.
- 원출처, 신뢰 영역, 파생 관계, 승인자를 잃지 않는다.
- 간접 프롬프트 주입이나 악성 지침 가능성이 있는 내용은 지시로 실행하지 않고 인용된 증거로만 다룬다.
- 한 번의 AI 필터를 안전 보증으로 보지 않는다. 권한, 구조적 분리, 사람 승인, 적용 결과 검사를 겹친다.
- 공개 자료라는 이유만으로 전체 공통 기억에 자동 흡수하지 않는다.

### 19.4 삭제와 철회

삭제 요청이나 법적 의무가 생기면 다음 순서를 따른다.

1. 원자료와 관련 파생물의 사용·전달을 우선 중지한다.
2. 계보를 따라 사례, 주장, 자산, 적용 묶음, 공개 주장에 미치는 영향을 찾는다.
3. 남은 근거만으로 유지 가능한 파생물은 다시 검토하고, 그렇지 않으면 범위 축소·철회·삭제한다.
4. 외부에 이미 공개된 주장은 가능한 정정·회수 절차로 연결한다.
5. 법적으로 허용되는 최소 삭제 이력만 남긴다. 삭제 의무가 그것도 금지하면 계보 완전성보다 삭제를 우선한다.

긴급 중지는 AI가 위험 신호에 따라 자동 발동할 수 있지만, 최종 삭제·공개 정정 범위는 권한 있는 사람이 결정한다.

**시스템 중단 조건:** 프로젝트 간 비밀 유출이나 기억 오염이 반복되고 격리·철회로 통제되지 않으면 공통 검색·자동 전달부터 중지한다.

## 20. 사건 기반 갱신과 월간 종합

### 20.1 사건 기반 빠른 순환

다음은 월간 검토를 기다리지 않는다.

- 비밀·개인정보 노출, 악성 지침, 권한 위반
- 중대한 품질 회귀나 음의 전이
- 근거 삭제·철회
- 활성 자산의 위험한 오적용
- 프로젝트 완료와 중요한 외부 평가 수신

AI는 격리·영향 추적·임시 중지·후속 시험 후보를 만들고, 사람은 고위험 유지·해제·외부 조치를 승인한다.

### 20.2 월간 또는 정기 종합의 역할

월간 종합은 개별 사건 처리와 다른 질문을 다룬다.

- 여러 프로젝트에서 반복되는 성공·실패·결정 패턴이 있는가.
- 기존 공통 자산과 모순되는 증거가 쌓였는가.
- 검색됐지만 거부되는 자산, 검색되지 않는 유용 자산, 사용되지만 효과 없는 자산은 무엇인가.
- 프로젝트·모델별 음의 전이와 비용 악화가 있는가.
- 오래됐거나 근거가 약해진 자산과 공개 주장은 무엇인가.
- 프로젝트들이 한 방식으로 수렴해 탐색 다양성이 줄었는가.
- 중앙 관리시간과 비용이 A 활동의 가치보다 커지는가.
- 브랜드가 주장한 행동 특성이 실제로 반복됐는가.

AI는 예외와 후보를 정리하며, 사람은 승격·분기·철회·공개·예산 결정을 한다. 충분한 새 근거가 없으면 **`변경 없음`**을 정상 결과로 기록한다. 문서나 교리 생산 할당량은 두지 않는다.

### 20.3 메타 검토

모델 교체, 평가 실패, 반복 오검색, 운영비 급증 같은 사건에서는 검색·승격·평가·월간 주기 자체가 유효한지 검토한다. 달력 주기의 최적 빈도는 **[미정]**이며 초기에는 월간을 기본 점검점으로 삼되 사건량과 관리비용에 따라 바꾼다.

## 21. 공동 브랜드의 내부 근거와 외부 표현

### 21.1 내부 브랜드 근거

브랜드의 내부 실체는 다음 계보다.

- 사실·해석·제안을 구분한 기록
- AI 기여, 사람 수정·승인, 외부 평가의 구분
- 성공과 실패, 근접 실패, 반례, 폐기된 자산의 대칭적 보존
- 품질·비용·위험·재작업을 숨기지 않은 결과
- 잘못된 판단을 중지·정정·폐기한 이력
- 모델이 바뀌어도 다시 시험한 작업방식

중앙은 이를 “브랜드 근거 묶음”으로 연결하되 별도의 홍보용 진실을 만들지 않는다.

### 21.2 외부 표현

외부 사례나 포트폴리오 주장은 내부 근거에서 파생한 제한된 표현이다.

- 공개 가능한 범위와 기간을 명시한다.
- 고객·개인·비밀정보를 제거하고 자료 소유자의 승인을 받는다.
- AI가 생성·검토·실행한 기여와 사람이 판단·수정·승인한 범위를 과장하지 않는다.
- 대표 성공만 제시할 때도 전체 모수와 선택 기준을 내부에 남긴다.
- 근거가 철회되거나 범위가 바뀌면 공개 주장도 정정·철회 대상으로 연결한다.
- 특정 모델 이름을 장기 브랜드의 핵심으로 삼지 않는다.

### 21.3 평가

좋아요·문서 수·AI 사용량보다, 블라인드 산출물에서 품질·검증·정직성 특성이 반복되는지와 공개 정정이 적시에 이루어지는지를 본다.

**[검증 전 가설]** 계보가 있는 정직한 정정도 공동 브랜드의 신뢰 자산이 될 수 있다. 실제 고객·관찰자 반응과 장기 효과는 아직 확인되지 않았으므로 홍보 성과를 약속하지 않는다.

## 22. 비용·품질·재사용·전이·위험 평가

### 22.1 평가 축

| 축 | 핵심 질문 | 대표 관찰치 |
|---|---|---|
| 품질·사용자 가치 | 실제 산출물이 좋아졌는가 | 인수 조건, 객관 테스트, 중대 결함, 사람 수정·재작업, 실제 사용 결과 |
| 비용 | 이득을 위해 무엇을 썼는가 | 현금, 토큰, 사람 능동시간, 대기시간, 재작업, 기회비용 |
| 검색·재사용 | 필요한 순간에 올바른 자산이 도달했는가 | 검색 기회, 적중·누락, 채택·거부 이유, 충실도, 적응 |
| 전이 | 다른 조건에서도 이득이 남는가 | 동일 템플릿, 가까운 전이, 먼 전이, 모델 이주를 분리한 결과 |
| 위험 | 최악 결과와 회복 능력이 좋아졌는가 | 중대 오류, 음의 전이, 비밀 사건, 중지까지의 시간, 철회 누락 |
| 유지·운영 | 중앙 자체가 감당 가능한가 | 사람 검토시간, 예외 대기열, 오래된 자산, 무사용 자산, 운영 장애 |
| 브랜드 | 주장한 작업 특성이 반복되는가 | 블라인드 검토, 기여·승인 투명성, 정정·폐기 이력 |

### 22.2 인과 주장 규율

- 실행 시 팀 구성 전체를 기록하고 함께 바뀐 요소를 밝힌다.
- 단순 전후 비교는 관찰적 차이로 보고한다.
- 가능한 안전한 내부 과제에서 `전통 없음`, `원로그`, `정제 자산` 조건을 비교한다.
- 신선한 과제와 시간 분리 홀드아웃을 사용해 기억 오염을 줄인다.
- AI 평가자는 선별 보조로 쓰고 객관 테스트·사람 검토·실제 결과를 우선한다.
- 고객 납품 과제에 열등할 수 있는 실험 조건을 무단 배정하지 않는다.
- 표본이 적으면 방향과 불확실성을 보고하고 과학적 확실성을 가장하지 않는다.

### 22.3 비용 판단

월 25만 원 수준은 사용자가 허용한 탐색 위험 한도이지 시스템의 자동 성공 기준이 아니다. 프로젝트 수익과 학습 자산 가치를 별도 장부로 보고, 손실이 새 정보·재사용 자산·후속 선택권을 남겼는지 확인한다. 중앙 시스템 관리비도 별도 비용으로 포함한다.

### 22.4 핵심 평가 가설

- 정제 자산이 원로그만 검색한 조건보다 실제 행동을 더 잘 바꾼다.
- 프로젝트 종류 공통 자산은 새 프로젝트에서도 양의 한계효과를 낸다.
- 두 번째 모델에서도 핵심 기능의 이득이 남거나 비호환을 빠르게 판정한다.
- 사건 기반 중지와 월간 종합이 중대한 반복 오류를 줄인다.
- 중앙 운영비보다 재사용·품질·위험 감소 가치가 크다.

각 가설이 반복해서 지지되지 않으면 해당 기능과 주장 범위를 축소한다.

## 23. 필수 사용 상황 10개의 처음부터 끝까지 흐름

### 23.1 프로젝트 하나가 완료됨

- **입력:** 프로젝트·작업·실행 구성, 산출물, 성공·실패, 결정, 비용, AI 기여, 사람 수정, 외부 평가.
- **중앙 판단:** 프로젝트 경계와 출처를 고정하고 사실, 해석, 누락, 비밀 위험을 분리한다. 모든 항목을 규칙으로 만들지 않는다.
- **AI 역할:** 정규화, 누락·비밀 후보 탐지, 사례·자산 후보 초안, 기존 유사 사례 제안.
- **사람 승인:** 비밀 분류, 프로젝트 간 공유, 중요한 자산 시험, 외부 브랜드 사용.
- **결과:** 프로젝트 계보, 사례, 결정·실험·비용 기록, 필요 시 자산 초안.
- **실패·복구:** 입력이 불완전하면 “미확인”으로 격리하고 원자료를 추정으로 채우지 않는다. 이후 보완 자료를 같은 실행에 연결한다.

### 23.2 성공했지만 원인이 불분명함

- **입력:** 좋은 결과와 불완전한 과정 증거.
- **중앙 판단:** `성공 결과·원인 미확인` 사례로 보존하고 자산 활성화를 보류한다.
- **AI 역할:** 가능한 원인, 우연 요인, 나쁜 과정의 운 좋은 성공, 반례와 다음 시험 제안.
- **사람 승인:** 안전한 재현 시험 여부와 비용.
- **결과:** 성공 사례와 검증 전 가설은 남지만 행동 규칙은 생기지 않을 수 있다.
- **실패·복구:** 설명이 그럴듯하다는 이유로 자산화됐다면 즉시 초안 또는 중지 상태로 낮추고 근거를 재검토한다.

### 23.3 세 프로젝트에서 비슷한 실패가 나타남

- **입력:** 서로 다른 모델·도구·조건의 실패 사례 세 건과 각 증거 뿌리.
- **중앙 판단:** 표면 유사성과 공통 기여 조건을 구분하고, 차이 때문에 분기해야 하는지 본다.
- **AI 역할:** 유사점·차이·공통 원인 가설·경쟁 가설·반례를 비교한다. 같은 원자료 파생 요약을 중복 계산하지 않는다.
- **사람 승인:** 프로젝트 종류 공통 시험 후보, 공유 가능한 비식별 파생물, 고위험 임시 금지.
- **결과:** 하나의 공통 자산이 아니라 조건별 두 자산이나 `공통화 보류`가 나올 수 있다.
- **실패·복구:** 공통 자산 적용 뒤 한 프로젝트에서 음의 전이가 생기면 그 범위에서 중지하고 분기한다.

### 23.4 기존 공통 원칙과 반대 결과가 나옴

- **입력:** 공통 자산의 예상과 반대되는 새 프로젝트 결과.
- **중앙 판단:** 기존 원칙을 덮어쓰지 않고 충돌 묶음을 만들며, 중대 위험이면 우선 전달을 중지한다.
- **AI 역할:** 구성 차이, 평가 오류, 적용 충실도, 진짜 반례 가능성을 분석하고 재시험안을 제안한다.
- **사람 승인:** 유지, 범위 축소, 분기, 긴급 중지 해제, 폐기.
- **결과:** 두 조건부 원칙의 병존, 기존 범위 축소, 또는 결론 보류.
- **실패·복구:** 단순 최신순이나 다수결로 처리됐으면 이전 판본과 근거를 복구하고 결정 이력을 정정한다.

### 23.5 새 모델로 교체됨

- **입력:** 새 모델이 포함된 팀 구성, 영향받는 자산, 대표 과제와 실패 사례.
- **중앙 판단:** 기존 자산을 새 구성에서 미평가로 보고 이주 시험 범위를 정한다.
- **AI 역할:** 핵심 기능과 모델별 표현을 구분하고 신선한 과제의 비교 결과를 정리한다.
- **사람 승인:** 고위험 자산의 새 모델 활성화와 이전 구성으로의 복귀 기준.
- **결과:** 새 어댑터, 기존 자산 불필요 판정, 제한 활성 또는 비호환 상태.
- **실패·복구:** 중대 회귀 시 새 구성 전달을 중지하고 이전 안정 구성·판본으로 되돌릴 선택지를 제시한다.

### 23.6 프로젝트 전용 지식을 다른 프로젝트가 요청함

- **입력:** 요청 목적·권한·프로젝트 맥락과 대상 지식.
- **중앙 판단:** 기본 거부 후, 원자료가 아니라 안전한 추상화가 가능한지 평가한다.
- **AI 역할:** 민감 요소와 재식별 위험을 표시하고 비식별 파생 후보를 만든다.
- **사람 승인:** 자료 소유자와 책임자가 프로젝트 간 공유 범위·목적·기간을 승인한다.
- **결과:** 거부, 제한된 참조, 비식별 파생 자산 중 하나.
- **실패·복구:** 과잉 노출이 발견되면 전달을 즉시 중지하고 수신처·파생물·공개 주장까지 영향 추적한다.

### 23.7 근거 삭제·철회 또는 비밀 문제

- **입력:** 삭제 요구, 출처 철회, 비밀 발견, 영향을 받는 증거 뿌리.
- **중앙 판단:** 원자료와 모든 파생물의 사용을 우선 중지하고 남은 근거를 재평가한다.
- **AI 역할:** 사례·주장·자산·전달·공개 표현의 의존 경로와 수신 대상을 찾는다.
- **사람 승인:** 법적 삭제 범위, 유지 가능한 최소 이력, 공개 정정·회수.
- **결과:** 삭제, 재파생, 범위 축소, 자산 중지·폐기, 외부 정정.
- **실패·복구:** 완전 추적이 불가능하면 영향을 좁게 추정하지 않고 관련 범위를 넓게 중지한 뒤 수동 조사한다.

### 23.8 중앙 자산을 거부·변형·오적용함

- **입력:** 전달 판본, 거부·변형 이유, 실제 실행 흔적과 결과.
- **중앙 판단:** 검색, 채택, 충실도, 변형, 자산 자체 가운데 실패 위치를 구분한다.
- **AI 역할:** 정당한 로컬 거부인지, 설명 부족인지, 핵심 기능 훼손인지, 실제 자산 실패인지 분석한다.
- **사람 승인:** 고위험 변형의 허용, 공통 자산 범위 변경, 긴급 중지.
- **결과:** 검색 조건 수정, 새 어댑터, 로컬 분기, 자산 범위 축소 또는 유지.
- **실패·복구:** 책임을 프로젝트에만 돌리지 않고 전달·표현·자산의 결함도 재검토한다.

### 23.9 사용자가 기간별 변화와 실제 재사용을 질문함

- **입력:** 기간, 프로젝트 범위, 관심 지표, 공개·내부 용도.
- **중앙 판단:** 프로젝트 수·구성 변화와 결측을 밝히고 기술 통계와 인과 주장을 구분한다.
- **AI 역할:** 반복 패턴, 실제 검색·채택·결과, 비용, 사람 수정, 철회·반례를 함께 요약한다.
- **사람 승인:** 인과 표현, 외부 공개, 비밀 제거와 브랜드 서술.
- **결과:** 성공만이 아니라 분모·불확실성·실패·폐기까지 포함한 기간 근거 묶음.
- **실패·복구:** 모델 향상이나 사용자 숙련이 섞였으면 전통 효과 문구를 낮추고 구성 전체의 관찰 결과로 정정한다.

### 23.10 월간 종합에 변경 근거가 없음

- **입력:** 기간 내 사건, 검색·적용 결과, 비용, 미해결 충돌과 결측.
- **중앙 판단:** 새 승격·수정·폐기의 근거가 부족하다고 판정한다.
- **AI 역할:** `변경 없음` 초안과 그 이유, 향후 관찰할 신호를 제시한다.
- **사람 승인:** 변경 없음, 추가 관찰, 특정 자료 보완 가운데 선택한다.
- **결과:** 교리 생산 없이 검토 이력과 현재 불확실성만 남는다.
- **실패·복구:** 변경 없음이 수집 누락 때문이면 회고를 반복하는 대신 입력 경계와 표본 점검을 고친다.

## 24. 목표 제품과 첫 구현 범위의 분리

| 구분 | 목표 제품 | 첫 독립 구축 조각 |
|---|---|---|
| 목적 | 여러 프로젝트·모델 세대의 장기 계승과 공동 브랜드까지 책임 | 중앙 구조의 핵심 한 바퀴가 논리적으로 작동하는지 검증 |
| 프로젝트 | 실제 여러 프로젝트와 각 권한 경계 | 가상 프로젝트 3개와 새 가상 작업 1개 |
| 경험 | 성공·실패·결정·실험·반례·비용·수정·충돌 전체 | 소수의 중립 입력 묶음으로 각 핵심 유형을 대표 |
| 자산 | 여러 유형·판본·범위의 포트폴리오 | 조건부 작업 자산 후보 1개와 경쟁·반례 1개 |
| 검색 | 권한·상태·구성·효과를 고려한 운영 검색 | 명시적 조건 기반 최소 선택 |
| 통합 | 다양한 Project Brain과 의미상 경계 유지 | Project Brain 없이 사람이 넣는 중립 요청·피드백 |
| 평가 | 실제 품질·비용·전이·위험·브랜드 장기 평가 | 상태, 권한, 계보, 철회와 흐름의 정확성만 시험 |
| 보안 | 실제 비밀·삭제·권한 체계 | 가상 비밀 표지와 삭제·철회 시나리오 |
| 공개 | 근거 기반 외부 브랜드 표현 | 포함하지 않음 |

첫 조각이 작다는 이유로 목표 제품의 능력을 삭제하지 않는다. 반대로 목표 제품의 모든 개념을 첫 조각에서 별도 구성요소로 만들지 않는다.

## 25. 오케스트레이터 없이 가능한 첫 독립 구현 조각

### 25.1 조각의 이름과 한 문장 범위

**“세 가상 프로젝트의 출처 있는 경험을 비교해 조건부 자산 하나를 시험 승인하고, 새 가상 작업에 전달한 뒤 거부·변형·적용 결과와 근거 철회까지 되돌리는 중앙 계보 한 바퀴”**를 첫 조각으로 한다.

### 25.2 포함하는 최소 능력

1. 서로 이름이 비슷해도 분리되는 가상 프로젝트와 실행 정체성
2. 성공·실패·결정·비용·사람 수정이 섞인 소수 입력과 증거 뿌리
3. 원자료와 AI 요약을 독립 증거로 중복 계산하지 않는 파생 관계
4. 프로젝트 비공개와 공유 가능한 파생물의 구분
5. 유사 사례와 반례를 함께 둔 조건부 주장
6. 사람 승인 전 초안, 승인 후 제한 시험이라는 효력 구분
7. 현재 맥락에 맞는 최소 전달 묶음
8. 채택·거부·변형·오적용·적용 결과의 구분
9. 원근거 철회 시 자산 전달 중지와 영향 추적
10. 충분한 근거가 없을 때 공통화·변경을 하지 않는 결과

첫 조각에서는 사건, 주장, 자산, 적용을 모든 세부 객체로 나누지 않아도 된다. 그러나 출처, 프로젝트 경계, 상태, 범위, 판본, 결과의 의미는 잃지 않는다.

### 25.3 의도적으로 제외하는 것

- 실제 Project Brain 연결과 메시지·API·파일 규격
- 실제 고객·개인·비밀 데이터
- 벡터 검색, RAG, 특정 데이터베이스나 저장 기술 선택
- 자동 외부 수집, 실시간 이벤트 처리, 대시보드
- 실제 모델 간 이주 효과와 장기 성과 주장
- 외부 브랜드 발행
- 모든 자산 유형과 모든 권한 역할의 완전 구현
- 월간 운영 자동화 전체

### 25.4 첫 조각의 통과 조건

- 프로젝트 경계를 넘는 허가 없는 전달이 없다.
- 같은 증거 뿌리의 여러 요약이 독립 근거로 세어지지 않는다.
- 반례가 공통 후보에 함께 연결되고, 공통화 보류가 가능하다.
- 중지·폐기 자산이 새 요청에 전달되지 않는다.
- 적용 결과가 정확한 판본과 구성에 연결된다.
- 원근거 철회가 파생 자산의 중지 후보까지 도달한다.
- 이 순환이 Project Brain의 실제 규격을 가정하지 않고도 끝난다.

### 25.5 첫 조각의 중단 조건

- 핵심 의미를 표현하려면 아직 정해지지 않은 Project Brain 내부 구조를 발명해야 한다.
- 프로젝트 분리와 철회를 단순한 예외 처리로도 검증할 수 없다.
- 제한된 입력인데도 사람이 모든 항목을 반복 해석해야 해 자동화 가치가 없다.
- 단순 목록과 비교해 계보 관계가 오류 발견이나 철회에 아무 이득을 주지 않는다.

## 26. 단위 시험·가상 흐름 시험·향후 효과 시험

| 시험 수준 | 무엇을 확인하는가 | 대표 시험 | 무엇을 증명하지 못하는가 |
|---|---|---|---|
| 단위 시험 | 개별 규칙과 상태의 논리적 정확성 | 동일 이름 프로젝트 분리, 증거 뿌리 중복 방지, 권한 필터, 중지 자산 차단, 판본 연결, 삭제 영향 추적, 승인 없는 공통 활성화 거부 | 실제 검색 유용성, 사람 운영 부담, 품질 향상 |
| 가상 프로젝트 흐름 시험 | 여러 능력이 한 흐름에서 연결되는가 | 완료 입력→사례→충돌→제한 자산→새 요청→거부·변형·사용→결과→철회, 그리고 변경 없음 | 실제 Project Brain 통합, 실제 비밀 공격, 장기 전이·수익성 |

| 향후 실제 효과 시험 | 전통의 한계효과와 모델 전이 | 안전한 내부 신선 과제에서 전통 없음/원로그/정제 자산 비교, 두 번째 모델 이주 비교 | 모든 프로젝트·모델의 보편적 효과, 고객 환경의 인과효과 |

단위·가상 시험을 모두 통과해도 “전통이 성능을 높였다”고 말하지 않는다. 그것은 구조가 요구대로 작동한다는 증거일 뿐이다.

## 28. 시스템 전체의 축소·폐기 조건

### 28.1 기능별 축소 순서

1. 자동 전달이 오검색·음의 전이를 만들면 수동 요청형으로 낮춘다.
2. 프로젝트 종류 공통화가 실패하면 프로젝트 전용 사례·자산만 유지한다.
3. 복잡한 계보 관계가 쓰이지 않으면 출처·판본·적용·철회에 필요한 관계만 남긴다.
4. 월간 종합이 형식화되면 사건·임계 신호 기반 검토로 줄인다.
5. 브랜드 외부 표현이 위험하면 내부 근거 기능만 유지한다.
6. 정제 자산이 원로그보다 낫지 않으면 자산 생성 절차를 폐기하고 사례 검색 또는 최소 체크리스트로 돌아간다.

### 28.2 전체 중단 조건

다음이 반복되고 안전한 축소로도 통제되지 않으면 중앙 시스템의 신규 수집·배포를 중단한다.

- 중대한 비밀·개인정보 침해 또는 기억 오염
- 공통 자산으로 인한 중대한 반복 품질 회귀
- 삭제·철회가 파생물과 공개 주장에 도달하지 못함
- 사람 관리시간과 총비용이 재사용·품질·위험 감소 가치를 지속적으로 초과
- 전통 없음 또는 단순 원로그 조건보다 신선한 과제 성과가 지속적으로 나쁨
- 프로젝트 자율성과 탐색이 중앙 규칙 때문에 실질적으로 훼손
- 공동 브랜드가 객관 근거 없이 오도하는 서사로만 기능

중단 시 법·계약상 보존 의무와 삭제 의무를 우선하고, 필요한 최소 계보와 철회 이력만 남긴다. 폐기는 실패를 숨기는 행위가 아니라 헌장의 자기정당화 원칙을 지키는 결과다.

## 29. 아직 결정하면 안 되는 사항

### 29.1 Project Brain과 통합

- 실제 메시지와 요청·응답 순서
- API, 파일, 이벤트, 플러그인 등 통신 방식
- Brain의 내부 역할과 완료 판정
- 실시간·배치·사람 중계 가운데 어느 방식을 쓸지
- 프로젝트 쪽에서 어떤 로그를 만들고 누가 서명·확정할지

### 29.2 기술 구조

- 파일, 관계형 데이터베이스, 그래프, 검색 인덱스, RAG의 선택
- 저장 위치와 배포 단위
- 정확한 객체 스키마, 디렉터리, 식별자 형식
- 검색·랭킹·요약 모델과 공급자
- 대시보드와 자동화 도구

### 29.3 운영 수치

- 공통화에 필요한 프로젝트·모델·반복 횟수
- 증거 확실성 등급의 정확한 문턱
- 성공·중단·비용 대비 가치의 수치 기준
- 월간·사건량 기반 검토 주기
- 첫 실제 시험의 과제 수와 표본 크기
- 사람 검토시간 상한과 자동화 위임 범위

### 29.4 장기 제품 형태

- Skill, 플러그인, 독립 서비스, 저장소 도구 중 최종 배포 형태
- 외부 고객에게 브랜드 근거를 어떤 형식으로 공개할지
- 제3자 검토자·다른 조직과 공통 전통을 공유할지

이 사항들은 앞 단계의 관찰과 Project Brain 경계가 생긴 뒤 결정한다.

## 30. 사용자 승인과 가치 판단이 필요한 사항

1. **프로젝트 간 공유 기본값:** 완전 비공개를 기본으로 하고 매번 파생 공유를 승인할지, 일부 프로젝트 종류에 사전 허용 범위를 둘지.
2. **긴급 중지 권한:** AI가 어떤 위험 신호에서 자동으로 전달을 멈추고, 사람이 얼마만큼의 검토 뒤 해제할지.
3. **저위험 자동 시험:** 프로젝트 전용·가역 자산을 사전 정책 안에서 자동 시험하게 할지.
4. **증거 보존과 삭제의 균형:** 법·계약상 허용되는 최소 삭제 이력을 얼마나 남길지.
5. **사람 관리비 상한:** 중앙 시스템을 위해 감수할 월간 능동시간과 비용의 범위.
6. **공통화의 보수성:** 전이 기회를 빠르게 시험할지, 거짓 일반화를 더 강하게 피할지.
7. **브랜드 공개 기준:** 어느 수준의 근거와 실패 공개가 있어야 외부 사례로 말할 수 있는지.
8. **독립 검토 비용:** 고위험 또는 브랜드 핵심 주장에 외부·독립 검토를 얼마나 사용할지.
9. **탐색 다양성:** 공통 자산과 다른 로컬 대안을 일부 유지하기 위해 감수할 추가 비용.
10. **전체 중단 기준:** 어느 안전·비용·효과 실패를 한 번만으로 중단하고, 어느 실패는 제한 재시험할지.

### 헌장에 대한 이의

현재 입력으로는 목적·철학 헌장에 대한 이의가 없다. 월간 주기는 영구 교리나 생산 할당량이 아니라 초기 검토 가설로 해석했다. 실제 자료량과 관리비가 이를 지지하지 않으면 주기를 바꾸는 것이 헌장에 더 부합한다.

| 조건부 채택 | 자동 검색·전달 | 권한·상태·반례 필터와 즉시 중지가 먼저 통과해야 함 |
| 조건부 채택 | 프로젝트 종류 공통 계층 | 실제 검색·전이 가치가 분류 부담보다 클 때 유지 |
| 조건부 채택 | 모델 중립 핵심과 모델별 어댑터 분리 | 두 번째 구성의 이주 시험에서 실익이 있을 때 유지 |
| 조건부 채택 | 월간 종합 | `변경 없음` 허용, 사건 기반 중지, 관리비 측정이 전제 |
| 조건부 채택 | 저위험 프로젝트 전용 자동 시험 | 사전 위임·가역성·결과 회수·인간 중지권이 전제 |
| 실험 후 결정 | 계보 관계의 세부 종류 | 첫 조각에서 단순 목록보다 오류·철회 이득이 있는지 확인 |
| 실험 후 결정 | 정제 자산 대 원로그 검색 | 신선 과제의 품질·비용·오검색·예외 손실 비교 |

| 폐기 | AI 합의·자기평가에 의한 자동 공통 승격 | 독립 증거가 아니며 자기강화 위험이 큼 |
| 폐기 | 중앙의 모든 과거를 매 과제 컨텍스트에 주입 | 검색 경쟁, 비밀, 비용, 음의 전이 위험 |
| 폐기 | 하나의 전역 점수로 증거·행동·공개를 결정 | 안전 금지와 약한 권고 등 다른 판단 축을 왜곡 |
| 폐기 | 월간 교리 생산 할당량 | 근거 없는 문서와 잘못된 승격을 유도 |

## 32. 이 설계의 가장 큰 위험과 반증 조건

| 핵심 위험 또는 가설 | 조기 신호 | 반증·중단 조건 | 대응 |
|---|---|---|---|
| 계보망이 과잉 복잡해진다 | 관계를 채우는 시간이 실제 프로젝트 검토보다 큼 | 단순 목록보다 검색·철회 오류가 줄지 않고 관리비만 증가 | 출처·판본·범위·적용·철회 관계만 남겨 축소 |
| 공통화가 음의 전이를 만든다 | 거부·변형·회귀가 특정 프로젝트군에서 집중 | 신선 과제의 품질·중대 오류·비용이 반복 악화 | 해당 범위 즉시 중지, 프로젝트 전용으로 되돌리고 분기 |
| 중앙집중이 탐색을 죽인다 | 모든 프로젝트가 같은 자산을 쓰고 대안·소수 의견이 사라짐 | 복잡 과제의 품질·tail-risk가 로컬 대안 조건보다 악화 | 경쟁 자산·독립 초안·로컬 거부권 강화, 자동 적용 축소 |
| 기억이 비밀·악성 지침을 지속시킨다 | 격리 우회, 권한 밖 검색, 이상한 지속 명령 | 중대한 유출·오염이 반복되고 영향 추적이 불완전 | 공통 검색·자동 전달 중단, 격리·삭제·수동 조사 |
| 자동화가 사람 승인만 형식화한다 | 승인시간은 짧지만 반례·영향 이해가 낮음 | 중요한 오승격·오해제가 반복 | 승인 묶음 개선, 자동화 범위 축소, 독립 검토 표본 |
| 정제 자산이 원로그보다 낫다 | 검색·채택은 많지만 결과 차이가 없음 | 원로그 대비 품질·비용·오검색에서 반복 우위가 없음 | 정제 절차 축소·폐기, 사례 중심 검색으로 복귀 |
| 모델을 넘어 계승된다 | 새 모델에서 표현 실패·오적용 증가 | 두 번째 모델 신선 과제에서 이득 소멸 또는 음의 전이 | 모델별 비호환 판정, 어댑터 시험, 주장 범위 축소 |
| 월간 종합이 C 활동을 개선한다 | 문서는 늘고 승격 정확성·A/B 성과 변화 없음 | 관리비만 증가하고 반복 오류·재사용에 변화 없음 | 사건 기반 검토로 축소하거나 월간 종합 폐기 |
| 공동 브랜드가 객관적 실체가 된다 | 외부 서술은 늘지만 블라인드 품질과 정정 이력 없음 | 이름·서사만 남고 검증·책임 특성이 재현되지 않음 | 외부 발행 중지, 내부 근거 체계만 유지 |
| 전체 시스템의 순가치가 양수다 | 사람 능동시간·토큰·대기 증가가 누적 | 여러 기간에 걸쳐 단순 운영보다 품질·비용·위험이 지속 악화 | 자동화·공통화부터 단계적으로 축소하고 필요 시 전체 중단 |

이 설계의 가장 큰 단일 위험은 중앙의 풍부한 기억이 권위 있는 오답과 비밀까지 더 오래, 더 넓게 전달하는 것이다. 따라서 검색 편의보다 프로젝트 경계, 증거 계보, 조건부 적용, 반례, 사람 승인, 즉시 철회를 먼저 검증한다. 그 안전장치를 갖춘 뒤에도 신선한 과제에서 더 나은 행동이 재현되지 않으면 중앙 전통의 범위를 줄이거나 폐기해야 한다.

**이 설계는 여러 프로젝트·여러 AI 세대의 공동 경험과 작업 전통을 프로젝트 경계가 보존된 증거 계보망과 범위별 작업 자산의 판본·적용 이력으로 보존하고, 현재 과제에 맞는 최소 자산과 반례를 Project Brain 또는 대표 AI에 선별 전달한 뒤 실제 채택·변형·결과를 다시 계보에 환류해 다음 프로젝트의 더 나은 행동으로 되돌린다.**
