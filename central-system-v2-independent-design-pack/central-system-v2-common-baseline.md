## 2. 공통으로 고정하는 현재 사실

1. 이 프로젝트의 목표는 여러 프로젝트와 여러 AI 세대의 경험을 연결하는 하나의 중앙 인간–AI 개발 전통 시스템이다.
2. 프로젝트마다 완성된 전통 시스템을 복사해 독립 운용하는 형태가 최종 목표가 아니다.
3. 사용자는 개인 성장 일지보다 AI 측 계승 능력과 인간–AI 공동 작업 체계의 성장을 원한다.
4. 실패뿐 아니라 성공, 결정, 실험, 방향 변경, 반례, 비용, 사람 수정, AI 간 충돌을 다뤄야 한다.
5. Skill, 프롬프트, 테스트, 체크리스트, 템플릿, 행동 규칙 등 다양한 작업 자산이 결과가 될 수 있다.
6. 원천 멀티 오케스트레이터는 별도 프로젝트에서 구축·시험·비용 판단 중이다.
7. Project Brain, 담당 AI 구성, 로그, 완료 보고, 통신 형식은 아직 안정되지 않았다.
8. 중앙 전통 시스템도 오케스트레이터와 병렬적으로 기획·설계·구축·단위 시험될 예정이다.
9. 이번 과업은 기획과 목표 시스템 설계까지만 수행하며 구현하지 않는다.
10. 현재 중앙 시스템의 운영 효과, 실제 Project Brain 통합 결과, 장기 전이 결과는 존재하지 않는다.

## 3. 의도적으로 열어두는 설계 선택

설계자는 다음을 독립적으로 선택할 수 있다.

- 중앙 내부를 어떤 능력과 책임으로 나눌지
- 사건·결정·실험·사례·교훈·원칙·작업 자산의 관계
- 고정 수명주기를 사용할지, 분기형 또는 다른 흐름을 사용할지
- 프로젝트 전용·프로젝트 종류 공통·전체 공통 지식을 어떻게 표현할지
- 정기 종합과 사건 기반 갱신의 관계
- 자동화와 사람 승인의 분담
- 어떤 첫 독립 구현 조각이 전체 구조를 가장 잘 시험할지
- 장기 저장·검색·선택 기술을 어느 단계에서 검토할지

다만 `central-system-v2-design-brief.md`의 사용자 목적, 중앙 시스템 전제, 구현 금지, Project Brain 통신 미정 경계는 변경할 수 없다. 이에 이의가 있다면 조용히 무시하지 말고 충돌·근거·대가·대안을 명시한다.

## 4. 설계자 입력에서 제외하는 자료

다음은 이전 문제 정의와 답에 설계자가 끌려가는 것을 막기 위해 제공하지 않는다.

- `system-design.md`
- `monthly-review-playbook.md`
- `roadmap-and-evaluation.md`
- `design-competition-brief.md`
- `design-competition-baseline-v1.md`
- `design-competition-baseline-v1.1.md`
- `candidate-system-design-v1.md`
- `docs/proposals/**`
- `docs/reviews/**`
- 기존 Claude 검토 프롬프트

이 자료들은 폐기된 것이 아니다. 두 v2 제안서가 동결된 뒤 최종 심사자가 다음을 감사할 때만 사용한다.

- 이전 과잉 설계가 되살아났는가
- 이전의 과도한 축소가 반복됐는가
- 기존 안전·검증 지적이 해결됐는가
- 새로운 중앙 시스템 전제가 실제로 반영됐는가

## 5. 독립성 규칙

- 두 설계자는 서로의 대화, 중간 결과, 최종 결과를 보지 않는다.
- 한쪽에 추가 사실을 제공해야 하면 다른 쪽에도 같은 내용을 제공하고 기록한다.
- 추가 웹 조사와 외부 자료 사용을 금지한다.
- 모델명, 문서 길이, 기능 수는 최종 심사의 품질 근거가 아니다.
- 두 안이 동의해도 같은 브리프와 연구에서 나온 상관된 수렴일 수 있으므로 독립 효과 증거로 세지 않는다.
- 두 결과가 나온 즉시 원문과 SHA-256을 동결하고, 수정 제안은 새 판본으로만 만든다.

## 6. 산출물 저장 권장 경로

```text
docs/proposals/v2/
├─ sol-ultra-central-tradition-system-v2-independent-proposal.md
└─ sol-pro-central-tradition-system-v2-independent-proposal.md
```

공홈이 삽입한 `sandbox:` 링크나 플랫폼 전용 인용 표식은 원본 판본에는 그대로 둘 수 있지만, 최종 심사와 합성 문서에는 옮기지 않는다. 원본 정리본이 필요하면 원문과 별도 파일로 만든다.

## 7. 완료 전 확인

- [ ] 공통 입력 네 문서의 해시가 표와 일치한다.
- [ ] 두 설계자에게 같은 시작 프롬프트를 사용했다.
- [ ] 설계자 입력에서 기존 설계·제안·심사 자료를 제외했다.
- [ ] 목표 제품 전체 구조와 첫 구현 범위를 분리했다.
- [ ] 중앙 시스템을 행동 패치 저장소 하나로 축소하지 않았다.
- [ ] 첫 구현에 전체 플랫폼을 요구하지 않았다.
- [ ] Project Brain의 실제 통신 규격을 만들어내지 않았다.
- [ ] 구현·코드·저장소 수정이 없다.
- [ ] 존재하지 않는 운영 결과를 주장하지 않았다.
- [ ] 사실·추론·설계 제안·미확인 사항을 구분했다.

## 8. 이 기준선의 효력

이 기준선은 v2 독립 제안서 두 개가 동결되고 최종 심사가 끝날 때까지 유지한다. 사용자 목적이나 중앙 시스템 전제가 바뀌면 두 설계자에게 대칭적으로 새 판본을 제공한다. 한 설계자의 편의를 위해 공통 기준을 조용히 수정하지 않는다.
