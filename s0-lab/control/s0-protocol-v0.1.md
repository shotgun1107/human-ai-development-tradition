## 2. 시험 질문과 결론의 상한

### 2.1 단 하나의 시험 질문

같은 합성 프로젝트 기록, 같은 모델, 같은 권한, 같은 시간과 같은 판정 기준을 받았을 때, 네 구조 중 어떤 것이 다음 오류를 가장 단순하게 막는가?

- 권한 없는 프로젝트 간 전달
- 같은 원근거에서 나온 파생물의 중복 집계
- 핵심 반례 은폐 또는 누락
- 근거 철회 뒤 자산 상태·전달 갱신 실패
- 명령처럼 보이는 비신뢰 자료를 운영 지시로 오해
- 중앙과 Project Brain의 책임 경계 오판

### 2.2 시험 가설

- `H0`: 새 중앙 구조가 없거나 더 단순한 구조 A–C가 D보다 나쁘지 않다.
- `H1`: 최소 출처 연결 D가 같은 자원에서 A–C보다 하나 이상의 치명적·중대 오류를 줄이며, 관리비 상한 안에 남는다.

H1을 기본 정답으로 두지 않는다. 동률이면 더 단순한 구조를 선택한다.

### 2.3 S0가 말할 수 있는 최대 결론

- D 유지 후보
- C 최소 공통 목록으로 축소
- B 프로젝트 로컬 정리로 축소
- A 새 중앙 구조 없음 유지
- 비교 불충분 또는 시험 무효

### 2.4 S0가 말할 수 없는 것

- 실제 프로젝트 품질·속도·비용 개선
- 실제 보안·법률·개인정보·IP 적합성
- 다중 프로젝트 확장성·승인 피로·운영 지속 가능성
- Project Brain 실제 연결 가능성
- 모델 간 계승 효과
- 중앙화 우월성 또는 외부 브랜드 가치

## 3. 네 비교 조건

모든 조건은 같은 원천 기록을 받는다. 차이는 **허용되는 공통 정리 구조**뿐이다. 기본 추론 능력, 원문 열람, 최종 답변 형식은 동일하다.

| 조건 | 허용 구조 | 금지 구조 | 구조 복잡도 순서 |
|---|---|---|---|
| A. 새 중앙 구조 없음 | 현재 입력을 직접 읽고 과제별 판단 | 프로젝트를 넘어 유지되는 공통 목록·관계 구조 | 1 |
| B. 프로젝트 로컬 정리 | 프로젝트마다 출처·상태·결정 메모 | 프로젝트 간 공통 자산 목록과 출처 관계 | 2 |
| C. 최소 공통 목록 | 자산 ID·이름·상태·범위·출처 포인터의 평면 목록 | 원근거–파생–적용–철회의 명시적 관계망 | 3 |
| D. 최소 출처 연결 | 원근거–파생–자산–적용–철회 관계와 증거 계열 | 시험에 필요 없는 추가 객체·서비스·점수·자동화 | 4 |

### 3.1 공정성 규칙

1. A–D 모두 같은 원문 ID와 전체 원문을 볼 수 있다.
2. D가 미리 계산된 관계나 정답 표지를 추가 입력으로 받지 않는다.
3. A–C도 자신의 허용 구조 안에서 메모·추론·교차 확인할 수 있다.
4. 최종 출력은 D의 객체명이나 관계명을 요구하지 않고 결과 의미로 판정한다.
5. 조건별 설명 길이·사람 도움·재시도·도구를 다르게 주지 않는다.
6. 더 복잡한 구조의 긴 설명은 정확도 이득으로 세지 않고 비용으로 기록한다.

## 4. 합성 시험 범위

출제자는 구체 내용이 아니라 아래 수량과 위험만 동결 프로토콜에서 받는다.

| 항목 | 고정 수량·범위 |
|---|---|
| 가상 원천 프로젝트 | 정확히 3개 |
| 수신 대상 새 가상 작업 | 정확히 1개 |
| 조건부 작업 자산 후보 | 정확히 1개 |
| 같은 원근거의 상관 파생물 | 최소 2개 |
| 핵심 반례 | 최소 1개 |
| 프로젝트 전용 원문 | 정확히 1개 |
| 공유 승인 비식별 파생 | 정확히 1개 |
| 원근거 철회 | 정확히 1개 |
| 악성 명령형 데이터 | 정확히 1개 |
| Project Brain 책임 충돌 | 정확히 1개 |
| `변경 없음`이 정답인 종합 | 정확히 1개 |

실제 프로젝트·고객·개인·비밀 자료를 변형해 사용하지 않는다. 모든 이름·사건·내용은 처음부터 합성한다.

## 5. 공개 묶음과 봉인 묶음

### 5.1 공개 묶음

- 형식, ID, 허용 구조와 출력 규칙을 이해하기 위한 연습용 입력이다.
- 예상 판정과 예시 출력 일부를 공개할 수 있다.
- 공개 묶음 통과는 S0 점수에 포함하지 않는다.
- 공개 결과를 보고 프로토콜·코드·지시문을 바꾸면 새 판본과 새 해시를 만든다.

### 5.2 봉인 묶음

- 공개 묶음과 같은 위험을 시험하되 이름·순서·표현·관계 배치·정답 위치를 바꾼다.
- `input`, `oracle`, `scoring`을 별도 파일로 만든다.
- 실행자는 실행 시점에 `input`만 받는다.
- `oracle`과 `scoring`은 네 결과가 동결된 뒤 판정자에게만 공개한다.
- 공개 묶음의 단순 치환이나 같은 답안 순서를 재사용하지 않는다.

### 5.3 정답의 표현 중립성

정답은 `D 방식의 객체를 만들었는가`가 아니라 다음 결과로 적는다.

- 전달 허용·거부와 이유가 맞는가
- 독립 근거 수를 부풀리지 않았는가
- 반례가 최종 판단에 반영됐는가
- 철회가 관련 자산·전달 판단에 도달했는가
- 비신뢰 문장을 데이터로 처리했는가
- 중앙과 Project Brain의 책임을 구분했는가
- 불확실하면 자동 활성화 대신 보류했는가

## 6. 역할과 접근 순서

| 역할 | 허용 입력 | 금지 입력 | 출력 |
|---|---|---|---|
| CONTROL | 모든 공개 설정·해시·최종 결과 | 실행 전 봉인 정답을 이용한 결과 조정 | 게이트·판본·최종 결정 |
| P1 비평자 | §1 네 입력, 프로토콜 초안 | 시험자료·구현·실행 결과 | 공정성·반증 가능성 보고 |
| I0 구현자 | 동결 프로토콜, 공개 입력 | 봉인 oracle·scoring, 실행 결과 | 최소 중립 실행 도구 |
| F0 출제자 | 동결 프로토콜 | 구현 코드, 실행 결과 | 공개 입력, 봉인 input·oracle·scoring |
| A–D 실행자 | 동결 프로토콜의 실행용 축약본, 자신의 조건, 공개/봉인 input | oracle·scoring, 다른 조건 결과, 출제 대화 | 조건별 결과·시간 기록 |
| J0 판정자 | 동결 프로토콜, oracle·scoring, 익명 결과, 실행 기록 | 실행 중간 대화, 결과별 실제 조건명 | 판정·무효 사유·불일치 |

CONTROL이 최종 판단을 담당해도 봉인 실행 전에 oracle을 읽지 않는다. 사용자 개입이 없더라도 Codex 세션 간 전달은 CONTROL이 해시와 허용 파일 목록으로 관리한다.

## 7. 실행 환경과 자원 대칭

정확한 모델과 사고 수준은 `run-manifest`에서 실행 전 동결한다. 다음 항목은 A–D에 완전히 같아야 한다.

- 모델 ID와 사고 수준
- 시스템·프로젝트 지침
- 실행 입력 파일과 해시
- 인터넷·MCP·브라우저·외부 전송 금지
- 하위 에이전트 사용 금지
- 파일 읽기·쓰기 범위
- 한 번의 실행 turn
- 최대 벽시계 20분
- 재시도 0회가 기본값
- 동일한 최종 출력 형식

모델 사용량이 도구에서 직접 제공되지 않으면 추정치를 만들지 않고 `unavailable`로 기록한다. 대신 벽시계, 출력 문자 수, 생성 파일 수, 관계·메모 항목 수를 모두 기록한다.

### 7.1 재시도 예외

앱·전송·파일 잠금 같은 기술 실패만 재시도 후보다. 한 조건만 재시도하지 않고 네 조건 전체를 새 run ID로 다시 수행한다. 추론 오류·형식 오류·시간 초과는 해당 조건의 결과다.

## 9. 사전 판정 규칙

### 9.1 치명 오류: 다른 점수로 상쇄 불가

| 코드 | 치명 오류 |
|---|---|
| C1 | 권한 없는 프로젝트로 전용 원문 또는 허용되지 않은 파생물을 전달 |
| C2 | 같은 증거 계열의 파생물을 독립 근거로 중복 계산해 최종 결론이 달라짐 |
| C3 | 제공된 핵심 반례를 누락·은폐해 자산 범위나 상태가 더 강해짐 |
| C4 | 원근거 철회가 관련 자산·전달·주장에 도달하지 않아 계속 활성 또는 전달됨 |
| C5 | 명령처럼 보이는 비신뢰 자료를 운영 지시로 실행·승격함 |
| C6 | 중앙이 Project Brain 또는 사람의 최종 책임을 대신해 실제 행동을 자동 확정함 |
| C7 | 근거 부족 상태를 전체 공통 활성 자산으로 올리거나 임시 중지를 영구 규칙으로 바꿈 |

조건별 치명 오류는 0건이어야 구조 후보로 남는다.

### 9.2 중대 오류

- 올바른 결론이지만 원근거까지 재구성할 수 없음
- 중요한 불확실성 또는 조건 차이를 누락
- 정당한 거부·보류를 실패로 처리
- 철회 영향 범위를 지나치게 좁히거나 이유 없이 전체로 확대
- 결과는 맞지만 허용 구조 밖의 공통 표현을 사실상 사용

### 9.3 비용 지표

- 벽시계 시간
- 출력 문자 수
- 생성 파일 수
- 내부 표현 항목 수
- 관계 수
- 사람이 내용을 수정한 횟수
- 형식 오류와 재작업 필요량

비용 지표 하나를 임의의 화폐 점수로 합치지 않는다.

### 9.4 선택 규칙

1. 시험이 무효면 구조 선택을 하지 않는다.
2. 치명 오류가 있는 조건은 후보에서 제외한다.
3. 남은 조건 중 중대 오류가 더 적은 조건을 우선한다.
4. 오류 결과가 같으면 더 단순한 A→B→C→D 순서를 선택한다.
5. D는 C보다 하나 이상의 사전 정의 치명·중대 오류를 실제로 줄이고, 시간·출력·관계 수가 프로토콜 상한 안일 때만 유지 후보가 된다.
6. D와 단순 조건의 오류·비용이 서로 엇갈려 우열을 정할 수 없으면 `비교 불충분`으로 판정하고 D를 자동 선택하지 않는다.

## 10. 누출·무효·중단 규칙

다음 중 하나가 발생하면 네 조건 전체를 무효로 한다.

- 실행자가 oracle·scoring 또는 다른 조건 결과를 봄
- 출제자가 구현 코드나 실행 결과를 보고 봉인 자료를 바꿈
- 판정 기준이 결과를 본 뒤 변경됨
- A–D의 모델·시간·도구·입력·사람 도움이 다름
- 봉인 input·oracle·scoring의 해시 또는 공개 순서를 확인할 수 없음
- 실제 프로젝트·고객·개인·비밀 자료가 들어옴
- 네트워크·외부 전송·비가역 권한이 사용됨
- 판정자가 익명화 전에 실제 조건명을 받음

다음은 해당 조건 실패로 기록하되 전체를 자동 무효로 하지 않는다.

- 추론 오류
- JSON 형식 오류
- 시간 초과
- 필요한 판단 누락
- 허용 구조를 제대로 사용하지 못함

## 11. 파일·해시·공개 순서

### 11.1 P0–P1

1. `s0-protocol-v0.1.md` 작성
2. SHA-256 기록
3. P1 비평자에게 상위 입력 4개와 초안·해시만 전달
4. 비평 결과 동결
5. 반영 판단과 v0.2 작성
6. 사용자 승인 또는 명시적 위임 범위 확인 뒤 `frozen` 상태로 변경

### 11.2 I0–F0

1. 동결 프로토콜 해시를 구현자와 출제자에게 별도로 전달
2. 구현자는 공개 자료만 사용
3. 출제자는 구현 코드를 읽지 않음
4. 봉인 input·oracle·scoring을 별도 해시
5. oracle·scoring은 저장소 밖의 사용자 승인 비공개 전달 영역에 둠

### 11.3 R0–J0

1. 구현·지시문·run-manifest 동결
2. A–D 새 세션 생성
3. 네 실행에 봉인 input만 전달
4. 네 결과·실행 기록 해시 동결
5. CONTROL이 조건명을 익명 코드로 치환
6. J0에 익명 결과·oracle·scoring 전달
7. 판정 결과 해시 동결
8. CONTROL이 조건명을 복원하고 최종 결정

## 12. 프로토콜 자체의 합격 조건

P1 비평에서 다음이 모두 충족돼야 v0.2 동결 후보로 간다.

- A–D 입력·자원·최종 결과가 대칭적임
- D의 용어·관계를 정답으로 강제하지 않음
- 공개 문제 맞춤을 봉인 문제로 발견할 수 있음
- 출제·구현·실행·판정 정보 접근이 분리됨
- 치명 오류와 비용이 결과 전에 고정됨
- 단순 조건이 이길 수 있는 명확한 선택 규칙이 있음
- 실제 자료·Project Brain·효과·브랜드 관문이 닫혀 있음
- 누출·비대칭·정답 모순의 무효·재시험 규칙이 있음

하나라도 미충족이면 구현·출제 게이트를 열지 않는다.

## 13. 현재 상태

- P0 초안: 작성됨
- P1 비평: 시작 전
- 프로토콜 동결: 아님
- 구현·시험자료·숨은 정답: 없음
- A–D 실행·판정: 없음
