# 회사→집 동기화 인수인계 — 2026-08-25

## 1. 가장 중요한 경고

집 PC의 기존 repository, local branch, worktree, stash, reflog와 dirty
state는 아직 확인되지 않았다. 모두 잠재적인 미동기화 작업으로 취급한다.

집에서 처음 할 일은 `pull`이나 branch 이동이 아니다. fetch보다 먼저 기존 집
repository의 경로, origin, branch, HEAD, upstream, worktree, index, untracked,
ignored, stash, local-only commit, local refs와 관련 reflog metadata를 읽기
전용으로 감사하고 보존해야 한다.

집 작업과 회사 handoff가 모두 존재하거나 상태가 불명확하면 어느 쪽도
덮어쓰지 않는다. 회사 tip은 별도 clean detached worktree에 배치하고, 사용자
결정 전에는 merge, rebase, cherry-pick, reset, clean, stash, prune, garbage
collection 또는 branch 삭제를 하지 않는다.

## 2. 목적과 증거 경계

이 문서는 회사 PC의 인증된 PUBLIC Git 상태를 집 PC에 안전하게 전달하기 위한
CONTROL handoff 기록이다. 첫 집 세션은 동기화·인증·보고만 하고 멈춰야 한다.

정본은 exact Git objects, 최신 root `AGENTS.md`, canonical sidecars와 아래
named PUBLIC artifacts다. 대화 기억, branch 이름, 회사 PATH와 관찰된 환경은
보조 정보이며 외부-pin authority가 아니다.

F0 세 경로군은 Git tree에 보존했지만 내용과 개별 filename을 열거나 검색하거나
출력하지 않았다. aggregate inventory와 quiet/anomaly 상태만 사용했다.

## 10. 집 PC에서 fetch보다 먼저 할 보존 감사

집 repository가 있으면 먼저 다음을 읽기 전용으로 기록한다.

- resolved repository path와 origin;
- branch, HEAD, tree, parent, upstream, detached 여부;
- worktree와 index quiet 상태;
- untracked/ignored aggregate와 unclassified ignored count;
- stash count;
- local-only commit IDs와 subjects;
- 모든 local branch/ref tip IDs와 subjects;
- worktree registry와 prunable/detached aggregate; and
- 필요한 관련 reflog commit IDs와 subjects.

fetch 전에 remote-tracking refs도 기록한다. 이 단계에서 `pull`, switch, reset,
clean, stash, rebase, merge, cherry-pick, prune, garbage collection 또는 branch
삭제를 하지 않는다.

집 작업이 있거나 상태가 불명확하면 기존 worktree를 움직이지 않는다. 회사
handoff는 명시적인 새 빈 경로의 detached worktree에 materialize하고, 두 계보의
commit/tree/parent/ancestry와 approved PUBLIC changed scope만 비교 보고한다.

## 11. 안전한 fetch와 exact Git 인증

집 local-state audit가 끝난 뒤에만 exact branch를 fetch한다. `git pull`은
사용하지 않는다.

```powershell
$handoffCommit = '<FINAL_HANDOFF_COMMIT>'
$handoffTree = '<FINAL_HANDOFF_TREE>'
$handoffBranch = 'codex/company-to-home-handoff-20260825'
$payloadCommit = 'defec54dd0f6bf9896bc22beab2732f4ae660e48'
$payloadTree = '3f6711d5d6491a250bde7c36b769051229fe7e43'
$payloadParent = 'dfa31376f11a7e2267f9ac1aaea38f99c194f846'

git -c core.longpaths=true fetch --no-tags origin `
  "+refs/heads/$handoffBranch`:refs/remotes/origin/$handoffBranch"

$remoteTip = git show -s --format=%H "refs/remotes/origin/$handoffBranch"
$remoteTree = git show -s --format=%T $remoteTip
$remoteParent = git show -s --format=%P $remoteTip
$payloadActualTree = git show -s --format=%T $payloadCommit
$payloadActualParent = git show -s --format=%P $payloadCommit

if ($remoteTip -ne $handoffCommit) { throw 'HANDOFF_TIP_MISMATCH' }
if ($remoteTree -ne $handoffTree) { throw 'HANDOFF_TREE_MISMATCH' }
if ($remoteParent -ne $payloadCommit) { throw 'HANDOFF_PARENT_MISMATCH' }
if ($payloadActualTree -ne $payloadTree) { throw 'PAYLOAD_TREE_MISMATCH' }
if ($payloadActualParent -ne $payloadParent) { throw 'PAYLOAD_PARENT_MISMATCH' }

git merge-base --is-ancestor $payloadParent $payloadCommit
if ($LASTEXITCODE -ne 0) { throw 'PAYLOAD_ANCESTRY_MISMATCH' }
git merge-base --is-ancestor $payloadCommit $remoteTip
if ($LASTEXITCODE -ne 0) { throw 'MAIN_PAYLOAD_NOT_HANDOFF_ANCESTOR' }
```

handoff-time `origin/main` pin은 payload commit/tree와 같다. 현재 집의 live
`origin/main`이 이후 이동했을 수 있으므로 branch 이름 자체가 아니라 위 exact
object와 ancestry를 검증한다.

집 repository가 dirty하거나 불명확하면 별도 clean detached worktree를 쓴다.

```powershell
$resumePath = 'C:\worktrees\human-ai-development-tradition-company-handoff-20260825'
git -c core.longpaths=true worktree add --detach $resumePath $handoffCommit
```

기존 경로를 삭제하거나 재사용하지 않는다. F0는 filename이나 내용을 출력하지
말고 `32 / 11 / 10` aggregate와 quiet/anomaly만 확인한다.
