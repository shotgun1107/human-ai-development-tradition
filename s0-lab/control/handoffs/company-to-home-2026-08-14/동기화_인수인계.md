## 8. 집 PC Git 복원·인증 절차

### 8.1 기존 작업을 먼저 보존한다

기존 repository가 있으면 clone이나 switch보다 먼저 path, origin, branch, HEAD,
upstream, tracked/staged/unstaged, untracked/ignored aggregate, stash, local-only
commit과 모든 worktree를 읽기 전용으로 확인한다.

dirty 작업, stash, local-only commit 또는 다른 worktree가 있으면 reset, clean,
stash, rebase, merge, prune 또는 덮어쓰기를 하지 않는다. exact final handoff
commit을 별도 clean worktree에 materialize한다.

### 8.2 exact remote ref를 fetch한다

완료 보고에서 받은 `<FINAL_HANDOFF_COMMIT>`과 `<FINAL_HANDOFF_TREE>`를 먼저
별도 변수에 넣는다. unpinned `git pull`은 사용하지 않는다.

```powershell
$handoffCommit = '<FINAL_HANDOFF_COMMIT>'
$handoffTree = '<FINAL_HANDOFF_TREE>'
$handoffBranch = 'codex/company-to-home-handoff-20260814'

git -c core.longpaths=true fetch --no-tags origin `
  "+refs/heads/$handoffBranch`:refs/remotes/origin/$handoffBranch"

$remoteTip = git show -s --format=%H "refs/remotes/origin/$handoffBranch"
$remoteTree = git show -s --format=%T $remoteTip
$remoteParent = git show -s --format=%P $remoteTip

if ($remoteTip -ne $handoffCommit) { throw 'HANDOFF_TIP_MISMATCH' }
if ($remoteTree -ne $handoffTree) { throw 'HANDOFF_TREE_MISMATCH' }
if ($remoteParent -ne 'dbcc2599a68ba7231f6e140f83f0bc112ac1a5c2') {
  throw 'HANDOFF_PARENT_MISMATCH'
}
```

### 8.3 F0 aggregate-only preflight

F0 내용과 개별 filename은 출력하지 않는다. 모든 Git stdout은 변수로 캡처하고
집계만 출력한다.

```powershell
$families = @(
  @{ Name = 'control'; Path = 's0-lab/control/f0-sealed'; Expected = 32 },
  @{ Name = 'staging'; Path = 's0-lab/f0-sealed-staging'; Expected = 11 },
  @{ Name = 'reviews'; Path = 's0-lab/reviews/f0-sealed'; Expected = 10 }
)

foreach ($family in $families) {
  $inventory = @(git ls-tree -r --name-only $handoffCommit -- $family.Path 2>$null)
  $inventoryRc = $LASTEXITCODE
  if ($inventoryRc -ne 0 -or $inventory.Count -ne $family.Expected) {
    throw "F0_$($family.Name)_INVENTORY_FAILURE"
  }
  "F0_$($family.Name)_COUNT=$($inventory.Count)"
}
```

materialization 전후의 worktree/index/untracked/ignored/special-index quiet 검사는
집에서 읽은 최신 루트 `AGENTS.md`의 절차를 그대로 적용한다.

## 10. 알려진 문제와 위험

1. 현재 implementation gate의 입력 권한이 bridge가 요구하는 전체 raw-byte
   closure보다 좁다. 명시적 확장 없이 구현하면 안 된다.
2. `s0-lab/assembly-rehearsal/public-end-to-end-v0.2/`는 아직 없다.
3. 현재 PC의 `jsonschema`와 `mkdocs`는 설치되지 않았다. 설치 명령은 기록했지만
   집 환경의 성공 여부는 미검증이다.
4. Docker Desktop 프로세스는 관찰됐지만 engine 연결과 repository 연관성은
   미검증이다. 현재 offline gate에는 Docker가 필요하지 않다.
5. `gh`는 인증되지 않았다. PR은 요청·생성하지 않았으며 handoff에는 필요 없다.
6. 회사의 다수 과거 worktree와 Python/Docker 프로세스는 Git payload가 아니다.
   삭제·복제·수동 이전하지 않는다.
