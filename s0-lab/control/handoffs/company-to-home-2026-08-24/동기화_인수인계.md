# 회사→집 동기화 인수인계 — 2026-08-24

## 1. 가장 중요한 경고

사용자는 집 PC에서 external-pin 관련 작성·검수 작업을 이미 했을 가능성이
있지만, 현재 그 완료 여부와 Git publication 상태를 확실히 기억하지 못한다.

따라서 집 PC의 local state는 **잠재적인 미동기화 정본 후보**로 취급한다.
원격에서 관련 branch가 보이지 않는다는 이유만으로 집 작업이 없다고 결론내리지
않는다.

집에서 처음 할 일은 `pull`이 아니다. fetch나 branch 이동보다 먼저 기존 집
repository의 branch, HEAD, upstream, worktree, stash, dirty state, local-only
commit, local refs와 reflog metadata를 읽기 전용으로 보존 점검해야 한다.

집 작업과 회사 handoff가 모두 존재하면 어느 쪽도 덮어쓰지 않는다. 회사 tip은
별도 clean worktree에 배치하고, 두 계보를 비교한 뒤 사용자 결정 전에는 merge,
rebase, cherry-pick, reset, clean, stash, prune 또는 branch 삭제를 하지 않는다.

## 9. 집 PC에서 반드시 먼저 할 보존 감사

### 9.1 fetch보다 먼저 기록할 것

집 repository가 있으면 먼저 다음을 읽기 전용으로 기록한다.

- resolved repository path와 origin;
- branch, HEAD, tree, parent, upstream, detached 여부;
- worktree와 index quiet 상태;
- untracked/ignored aggregate;
- stash count;
- local-only commit count와 commit IDs/subjects;
- 모든 local branch/ref의 tip IDs와 subjects;
- worktree 목록;
- pin, recovery, Authenticode, trust-profile 관련 branch/ref metadata; and
- 필요할 경우 reflog commit IDs와 subjects.

이 단계에서 `pull`, switch, reset, clean, stash, rebase, merge, cherry-pick,
prune, garbage collection 또는 branch 삭제를 하지 않는다. 오래된 remote-tracking
ref도 fetch 전에 따로 기록한다.

### 9.2 집 pin 작업이 발견되면

다음 중 하나라도 있으면 집 작업이 존재할 가능성이 있다.

- dirty/staged/untracked PUBLIC candidate work;
- stash;
- local-only commit;
- remote에 없는 local branch;
- detached worktree;
- pin/review/trust-profile 관련 reflog commit; or
- 회사 payload와 다른 manifest/hash.

이 경우 기존 worktree를 움직이지 않는다. 회사 handoff exact tip을 별도 clean
worktree에 배치하고 다음만 비교 보고한다.

- 양쪽 commit/tree/parent/ancestry;
- changed-path aggregate와 approved public package paths;
- package-manifest hash와 row count;
- review verdict/finding 기록 유무;
- 집 작업이 company v0.2보다 앞선 단계인지, 병렬인지, 후속인지; and
- 충돌 가능성.

사용자 결정 전에는 어느 쪽도 정본으로 승격하거나 합치지 않는다.

### 9.3 집 pin 작업이 없다고 판단하려면

단순히 remote branch가 없다는 사실만으로는 부족하다. dirty, stash,
local-only commit, local refs, detached worktree와 relevant reflog를 모두 확인한
뒤에만 `HOME-PIN-WORK-NOT-FOUND`라고 보고할 수 있다.

그 경우에도 회사 handoff를 materialize하고 첫 보고 후 멈춘다. 다음 기술 gate를
자동으로 열지 않는다.

## 10. 안전한 fetch와 materialization

집 local-state audit와 F0 preflight가 통과한 뒤에만 exact handoff branch를
fetch한다. `git pull`은 사용하지 않는다.

```powershell
$handoffCommit = '<FINAL_HANDOFF_COMMIT>'
$handoffTree = '<FINAL_HANDOFF_TREE>'
$handoffBranch = 'codex/company-to-home-handoff-20260824'

git -c core.longpaths=true fetch --no-tags origin `
  "+refs/heads/$handoffBranch`:refs/remotes/origin/$handoffBranch"

$remoteTip = git show -s --format=%H "refs/remotes/origin/$handoffBranch"
$remoteTree = git show -s --format=%T $remoteTip
$remoteParent = git show -s --format=%P $remoteTip

if ($remoteTip -ne $handoffCommit) { throw 'HANDOFF_TIP_MISMATCH' }
if ($remoteTree -ne $handoffTree) { throw 'HANDOFF_TREE_MISMATCH' }
if ($remoteParent -ne '2e743033b0f2ac10c964067adb0bd32a4e22cf75') {
  throw 'HANDOFF_PARENT_MISMATCH'
}
```

집 작업이 존재하거나 불명확하면 exact tip을 명시적 새 빈 경로의 detached
worktree로 배치한다.

```powershell
$resumePath = 'C:\worktrees\human-ai-development-tradition-company-handoff-20260824'
git -c core.longpaths=true worktree add --detach $resumePath $handoffCommit
```

기존 경로를 삭제하거나 재사용하지 않는다.
