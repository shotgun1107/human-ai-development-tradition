## 5. New design invariants introduced by v0.8

1. Same canonical cause key if and only if same cause; cause IDs are derived sorted positions.
2. A multi-coordinate error returns every false available coordinate, never an implementer-selected minimal explanation.
3. Strong three-valued evaluation fixes every `true OR unknown`, `false AND unknown`, and unresolved outcome.
4. Every schema-valid answer must make all C formulas two-valued; an unknown then is a comparator defect.
5. Every repeated metadata family and every generated catalog has a declared finite maximum.
6. Abstract catalog choice freezes before authoring; bank-instance projection is a deterministic later artifact, not a second design choice.
7. Every matrix input/output edge must match a ledger row and every ledger row a compatible positive allowlist.
8. Analysis receives opaque coefficients sufficient for all frozen statistics before calls and never receives semantic condition names before its hash freezes.
9. A non-record target never enters an affected-record array.

These invariants have not been implemented, mutation-tested, benchmarked, or independently shown consistent.
