# Response to external-pin recovery v0.1 independent review

## 1. Reviewed result

The authenticated v0.1 independent review returned
`REVISE-AND-REREVIEW` with `0 BLOCKING / 1 MAJOR / 0 MINOR`.

The preserved finding was `BRM-EPR-V01-IR-001`: the recovery plan recorded a
new bootstrapper's hash and version after download but did not authenticate
Microsoft origin before invoking that executable to create the offline layout.

## 2. Accepted criticism

The criticism is accepted. A newly calculated hash identifies bytes but does
not establish their supplier. A substituted executable can create a
self-consistent attacker layout and hashes.

The v0.1 plan also failed to bind the exact fixed 17.14.39 Build Tools target
and did not require signer, chain, timestamp, or revocation evidence before
first execution.

## 3. v0.2 correction

The v0.2 revision:

1. binds the exact official fixed 17.14.39 Build Tools target;
2. requires a separately authenticated Windows Authenticode trust profile;
3. requires valid embedded Authenticode, approved Microsoft signer, exact
   certificate chain and root, valid timestamp, and good entire-chain
   revocation before any process;
4. rejects every unknown, unchecked, stale, soft-fail, alternate-root, wrong-
   signer, or unverifiable state;
5. requires exact byte and file identity through first execution; and
6. retains signed layout-content verification after bootstrapper
   authentication.

Absent trust authority now terminates with process count zero. Certificates
created by the new layout cannot retroactively authenticate its creator.

## 4. Author disposition

`BRM-EPR-V01-IR-001` is
`CLAIMED-CLOSED-BY-V0.2-REVISION-PENDING-INDEPENDENT-REVIEW`.

This response is author-side reasoning, not independent evidence.

## 5. Nonclaims

No bootstrapper, certificate, source, toolchain, dependency, or runtime byte
was downloaded or authenticated. No process, installer, compiler, build,
materializer, native API, platform probe, rehearsal, S0, or E0 operation was
performed.
