## 2. Finding dispositions

### RPNP2-RR-001 — accepted and corrected in design

v0.3 freezes five ordered, generated command-line handle locators for the
three one-way pipe endpoints, one read-only output-root identity handle, and
one preloader process handle. Each locator has one canonical fixed-width
representation. It is explicitly non-authoritative.

An authenticated native bootstrap guard consumes the locators exactly once,
validates object kind, required and forbidden access direction, distinctness,
preloader process identity, root identity, explicit inheritance provenance,
and protocol binding, and returns private nonconstructible wrappers only after
the full bind transaction succeeds. Raw arguments are then scrubbed before
verifier-package import. No public Python wrapper or serialized integer gains
authority.

### RPNP2-RR-002 — accepted and corrected in design

v0.3 removes the create-then-open construction. The authenticated preloader
uses one parent-relative direct call to `ntdll.dll!NtCreateFile` with
`FILE_CREATE`, `FILE_DIRECTORY_FILE`, `FILE_OPEN_REPARSE_POINT`, and
`OBJ_CASE_INSENSITIVE | OBJ_DONT_REPARSE` against a parent whose per-directory
case-sensitive flag is disabled. The successful call both creates the absent
leaf and returns the retained directory handle. There is no pathname reopen or
fallback. The preloader validates and retains that exact returned handle,
then inherits a reduced-access duplicate into the verifier.

The package freezes the ABI, call constants, direct-import closure, status and
`IO_STATUS_BLOCK.Information` requirements, post-call identity checks, and a
targeted replacement-race mutation.

### RPNP2-RR-003 — accepted and corrected in design

v0.3 distinguishes nonterminal invalid transitions from terminal retries.
An invalid transition from `ROOT-CREATED-BOUND`, `COMMITTING`, or
`COMMIT-ACKED` advances to `REJECTED`. An attempt against `SPENT` or
`REJECTED` rejects without mutating the terminal state. No terminal state can
be revived or converted into the other terminal state.

## 3. Additional closure required by the corrections

The atomic root correction adds `ntdll.dll!NtCreateFile` to the preloader's
exact direct-import surface. The existing externally authenticated CONTROL
launcher and Windows-kernel trust base remain the only external roots of
trust. v0.3 additionally requires the exact loaded `ntdll.dll` identity,
SHA-256, PE identity, and export binding to be pinned and checked before the
preloader may call `NtCreateFile`.

The handle-locator correction adds one exact native bootstrap-guard extension
to the authenticated runtime-file and loaded-PE closure. This is not a general
FFI facility. Its only admitted entry point is the one-use v0.3 bind
transaction. `ctypes`, `_ctypes`, dynamic native loading, caller-selected
module origins, and generic handle wrapping remain forbidden.

## 4. CONTROL decision

The three rereview findings are answered at design level by the v0.3 package.
The corrections have not been implemented or tested on the target platform.
v0.3 therefore opens only a fresh independent design-rereview candidate. It
does not reopen implementation, runtime-profile capture, platform probing,
official rehearsal, S0, commit, or push authority.
