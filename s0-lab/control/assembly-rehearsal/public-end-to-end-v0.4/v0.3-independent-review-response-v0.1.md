## 1. Response boundary

review's closure of M-04 and M-07 and every v0.2 non-regression conclusion.

## 2. M-05A proposed closure

v0.4 freezes the literal C declaration and one supported binding:

- 64-bit CPython on 64-bit Windows 10/11;
- system `kernel32.dll!MoveFileExW`;
- Microsoft x64 Windows `WINAPI` convention;
- `ctypes.WinDLL("kernel32", use_last_error=True)`;
- `argtypes` exactly two `ctypes.c_wchar_p` plus
  `ctypes.c_uint32`;
- `restype=ctypes.c_int32`;
- absolute extended-length UTF-16 paths, flags zero;
- last error cleared before and captured immediately after a zero return; and
- no alternate DLL/export/type/flag/fallback/retry path.

The acceptance plan requires independent mutation of every declaration
element and real-primitive probes against that exact binding.

**Proposed disposition:** closed at public design-text level.

## 3. M-06A proposed closure

v0.4 withdraws the false claim that exact final files can prove publication.
The files are diagnostic and become `offline-not-success` after the verifier
process exits.

The only success decision now requires a verifier-owned observer to perform
and directly observe both exact ABI calls, bind their order and source/dest
file identities, and issue a private one-use process-local witness. A separate
verifier-owned live consumer accepts only that exact witness by object identity
with the matching trace, capability, root, current file identities, hashes,
receipt bindings, and nonquarantined state.

The candidate never receives the witness or FFI authority. Exact copied files
without a witness reject; a witness from another run rejects; and replacing a
valid moved final with an exact copy rejects because its file identity differs.

**Proposed disposition:** closed at public design-text level by narrowed claim
plus independent same-process observation.
