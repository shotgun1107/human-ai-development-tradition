## 3. Reasons the candidate is not integration ready

### 3.1 Frozen semantic Windows-call contract mismatch

The actual guard semantics rely on `PeekNamedPipe`, `IsProcessInJob`, and
`WaitForSingleObject`, with supporting `GetLastError` and
`GetCurrentProcess`. The frozen v0.4 profile schema's exact
`semantic_windows_calls` constant omits relied calls. The runtime liveness
behavior is fixed, but the source/profile contract is not closed.

### 3.2 Frozen launch-evidence grammar mismatch

Correction 9's four runtime-profile hashes fit the frozen runtime-package-
hashes semantic group. `external_pin_digest` and `workspace_root`, however,
were added to ordered `S0-LAUNCH-HANDLE-SET-EVIDENCE-1` bytes outside the
frozen eight semantic groups without changing the schema or evidence version.
The `70 / 70` producer/consumer rejection agreement proves pair agreement, not
compatibility with the frozen interface.

### 3.3 Physical output containment remains incomplete

The materializer's lexical overlap and leaf-only reparse checks do not close
ancestor junctions, volume mount points, or physical aliases. A non-reparse
leaf beneath an alias parent can place output physically beneath the base.
Reused alternate-data-stream evidence does not resolve ancestor identity or
physical containment.
