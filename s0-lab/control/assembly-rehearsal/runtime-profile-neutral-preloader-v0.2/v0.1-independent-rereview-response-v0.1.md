## 2. RPNP-RR-001 proposed closure

V0.2 replaces the ambiguous liveness-pipe pair with three strictly
unidirectional anonymous pipes:

1. preloader to verifier admission frame;
2. verifier to preloader commit request; and
3. preloader to verifier commit reply.

The verifier inherits only admission-read, commit-request-write, and
commit-reply-read. The preloader retains only the opposite ends. The verifier
also inherits one synchronize-only preloader process handle. Neither actor
possesses both ends of a channel after the preloader closes its post-launch
duplicates.

Each sender emits one exact frame and closes its write end. Each receiver must
read the exact bounded frame followed by EOF. Short read, missing EOF, extra
byte, wrong order, timeout, broken pipe, duplicate frame, self-read route, or
second commit is terminal failure.

**Proposed disposition:** closed at design-text and frozen-interface level.

## 3. RPNP-RR-002 proposed closure

V0.2 gives the private runtime admission an explicit state machine:

1. `ROOT-ABSENT-BOUND` binds the exact output-parent object identity and
   canonical absent ASCII leaf before verifier-package import;
2. `ROOT-CREATED-BOUND` is reached exactly once after the authenticated
   verifier exclusively creates, opens, authenticates, and retains the output
   root;
3. `COMMITTING` permits the exact commit handshake only after the publication
   witness carries the same retained root identity;
4. `COMMIT-ACKED` records the exact preloader reply but is not success; and
5. `SPENT` or `REJECTED` is terminal after the first live-consumer attempt.

The initial admission does not claim an identity for a nonexistent object.
Candidate launch is forbidden before `ROOT-CREATED-BOUND`. Root creation and
binding failure routes to post-launch boundary failure and cannot be repaired
or retried.

**Proposed disposition:** closed at design-text and frozen-interface level.
