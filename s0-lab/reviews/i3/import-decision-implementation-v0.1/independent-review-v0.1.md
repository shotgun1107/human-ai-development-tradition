## 5. Finding

### `I3-IIR-B01` - blocking - finalizer grants destination authority without I2 global-link validation

#### Required behavior

The implementation/test brief requires reuse of authenticated I2 event
parsing, serialization, hashing, lifecycle, **chains**, and supplied-set
validation. Its finalization tests expressly require every wrong chain to
fail. Binding `I3-B08` requires the exact I2 global chain as well as the
route-local chain. Binding `I3-B10` permits destination authority only after
an exact consumed event and persisted append agreement.

#### Observed implementation fact

`s0_i3.finalizer.validate_completion_event` rebuilds an I2 route context,
calls `parse_import_event`, and calls `classify_event_variant`. It never calls
I2's `validate_event_global_link` or `validate_event_global_chain`, accepts no
expected global sequence/predecessor evidence or authenticated validated-trace
handle, and therefore never establishes that the supplied completion event is
the next event in the caller-supplied public global chain. The existing test
suite mutates class, route, `H/Z`, state, and append status, but does not mutate
global sequence or predecessor evidence.

#### Independent reproduction fact

I constructed a canonical accepted classification, then serialized an
otherwise matching canonical I2 consumed event with:

- `sequence=999999999999999999999999999999999999999999999`; and
- `previous_event_sha256=` 64 lowercase `e` characters.

With caller-supplied append status `persisted`, the finalizer returned:

```text
disposition=consumed-accepted
destination_authority=available
destination_state=pop-context-bound
```

I2's public `validate_event_global_link` rejected that same parsed event
against expected sequence `3` and predecessor hash of 64 lowercase `f`
characters. It also rejected the huge sequence when the expected predecessor
remained the `f` hash. Thus the accepted event is canonical and route-local
compatible but demonstrably disagrees with separately supplied global-link
evidence that I2 supports.

#### Inference and impact

The finalizer equates a standalone structurally valid event with an exact I2
completion. A caller can obtain the implementation's sole destination-
authority result even when the event is not linked to the supplied global
predecessor. This is not a durability or real-provider demand: it is the
already supported public I2 structural link check. Because the defect reaches
`destination_authority=available`, it is blocking rather than major or minor.

#### Required bounded revision

Before granting authority, finalization must consume explicit authenticated
global-link/chain evidence or an I2-validated trace handle and invoke the
unchanged I2 validation path. The revision must add hostile tests that change
sequence and previous-event hash independently, supply wrong and missing
global predecessor evidence, and demonstrate `no-completion-claim` for each.
It must preserve exact route-local, class, `H/Z`, state, and append checks and
must not add a durability, witness, registry, provider, or operational claim.
