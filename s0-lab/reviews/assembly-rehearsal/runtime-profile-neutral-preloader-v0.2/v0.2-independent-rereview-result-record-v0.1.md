## 4. Preserved findings

### RPNP2-RR-001 — MAJOR — inherited-handle locator is undefined

The v0.2 design gives the verifier four inherited handles but freezes no
mechanism by which the Python bootstrap can determine which numeric handle is
the admission-read endpoint, commit-request-write endpoint,
commit-reply-read endpoint, or preloader process handle. Standard handles are
excluded, the environment has only the three frozen non-handle keys, and the
admission frame cannot identify the handle needed to read that frame.

Required correction: freeze explicit authenticated command-line locators or
an equally complete standard-handle mapping. Numeric values must be locators,
not authority. Before wrapping them, the bootstrap must validate kernel-object
type, access direction, peer/process binding, and one-use behavior.

### RPNP2-RR-002 — MAJOR — output-root create/open race

The v0.2 verifier exclusively creates the output directory and then opens it
separately with no-reparse flags. An attacker with relevant parent-directory
rights can replace the newly created directory between those operations, so
the retained handle may bind an attacker-controlled object rather than the
object created by the verifier.

Required correction: use an atomic parent-relative directory creation that
returns the retained directory handle, or freeze an equally explicit locking
construction that proves the replacement window is absent. The correction
must include a targeted race mutation.

### RPNP2-RR-003 — MINOR — terminal-state retry wording conflicts

The v0.2 state machine declares `SPENT` and `REJECTED` terminal but also says
any invalid transition sets `REJECTED`. A retry against `SPENT` therefore has
two incompatible prescribed results.

Required correction: invalid transitions from a nonterminal state advance to
`REJECTED`; attempts against either terminal state reject without changing
that terminal state.
