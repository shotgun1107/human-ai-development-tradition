## 2. Finding responses

### `BRM-AUTHV01-IR-001`

The v0.2 entry no longer accepts URL and redirect labels independently. It
requires an externally pinned canonical acquisition record plus the producer
manifest pin. The record binds fixed request/final URL, zero redirects,
transfer completion, same-process retained handle, handle contract, file ID,
volume serial, non-reparse status, length, and byte SHA-256.

The native observation embeds the exact record object and its authenticated
hash. The semantic validator reconstructs the canonical record bytes and
cross-binds both external pins, the runtime process and handle, and all lease
file measurements.

### `BRM-AUTHV01-IR-002`

The VERIFY call is inside cleanup before the state handle is inspected. Every
VERIFY attempt therefore issues CLOSE, including null-state and later-error
paths. A nonzero CLOSE result rejects.

`_build_chain` owns a returned context until its rows and call record are
complete. Any exception frees that context locally; only a successful return
transfers ownership to the outer lifecycle.

### `BRM-AUTHV01-IR-003`

The collector opens a verifier-owned `GENERIC_READ` lease with only
`FILE_SHARE_READ`, denying write/delete sharing while the lease remains open.
Windows also rejects that open when a conflicting write/delete handle or
writable mapping already exists.

The acquisition record, supplied handle, and lease must have identical path,
file ID, volume serial, non-reparse state, length, and SHA-256. WinTrust and
all three measurements use only the owned lease. Hashing uses `ReadFile`
directly and never duplicates a shared file pointer.

### `BRM-AUTHV01-IR-004`

The observed snapshot now covers local-machine Root, CA, My, Trust, AuthRoot,
and Disallowed certificates and CTLs. Null enumeration accepts only the
documented `CRYPT_E_NOT_FOUND` end condition; other errors reject. Entry and
encoding bounds are enforced, and store-close failure rejects.

The revision does not overstate this sentinel as the complete effective
Windows trust namespace. It fixes
`effective_trust_authority_claimed=false` and renames the relation to observed
chain-input stability. Chain, revocation, root-trust, explicit-disallow, and
policy results remain independently mandatory. A private authenticated chain
engine would be required before promoting this result to live authority.

### `BRM-AUTHV01-IR-005`

Package import is inert and no longer imports every implementation module.
The revision nevertheless accepts the review's fundamental point that a
mutable Python host cannot prove its own already executing code from later
disk hashes.

The bounded correction is explicit claim narrowing:

- `runtime_authority_scope=TRUSTED-HOST-DISK-CONSISTENCY-ONLY`;
- `executed_code_authority_established=false`;
- terminal success is
  `PASS-BOUNDED-TRUSTED-HOST-CONSISTENCY-NO-LIVE-AUTHORITY`; and
- `process_authority_granted=false` remains mandatory.

No live gate may treat this package as an independently authenticated runtime.
A separately pinned pre-import loader, interpreter, immutable snapshot, and
isolated process boundary remain required future work.

### `BRM-AUTHV01-IR-006`

The revision removes the asserted exact reference time. Each chain call now
records fixed-hex FILETIME values for call start, call return, verification
time, and exact cache-resync input. The call interval must be monotonic and at
most 30 seconds.

For every non-root element, the Windows freshness age plus the complete call
interval must remain within 86,400 seconds. This is conservative across any
instant Windows could have used during the call. No field claims that Windows
returned one exact current-time instant.

## 3. Additional correction discovered during revision

Actual Windows FILETIME values exceed the exact JSON integer range used by the
canonical codec. The v0.1 live collector would therefore have failed while
serializing a real observation even though small synthetic integers passed.

v0.2 serializes every FILETIME as fixed lowercase 16-hex text and converts it
to an integer only for bounded semantic arithmetic. Tests cover malformed,
reversed, and overlong intervals.

## 4. Verification and nonclaims

The successor suite must authenticate the complete v0.2 source snapshot and
exercise all 44 semantic relations. It must keep Python bytecode disabled and
must not call native trust APIs, certificate stores, a network, downloads,
installers, candidate processes, F0 roles, S0, or E0.

These are author-side responses. Fresh independent code and security rereview
is required before any finding is treated as closed.
