## 검증 결과

- 편집 전·후 A04/A06/A07/A08의 manifest 4개와 수록 파일 94개의 동결 해시가 모두 일치했다.

- 변경된 안내의 링크 대상 7개와 Git 승인 절의 anchor가 존재한다. 추적 문서는 `git diff --check` exit 0이었다. 새 문서 2개는 `git diff --no-index --check -- NUL <파일>`에서 각각 exit 1(신규 파일 차이), 공백 오류 출력 0개였다.

- 후보 실행 테스트는 수행하지 않는다. 과거 검사는 당시 HEAD·정책 해시·출력에 묶여 있으므로 이번 문서 도입을 위해 수정하거나 재실행하지 않는다.

## 커밋 준비 확인

- 제안 제목: `docs: 개발 규약과 AI 작업 기록 관리 방식 도입`. 대상은 위 4개 파일의 확인한 현재 내용이다.
- `AGENTS.md`의 전체 diff에는 이번 진입점뿐 아니라 이전에 합의된 9월 16일 제한적 세션 권한과 9월 17일 시간 정책의 미커밋 변경도 포함된다. 이를 숨기거나 되돌리지 않고 승인 요청 범위에 명시한다.
- 추적 파일 diff와 새 문서 전문을 확인했다. 작업 파일 공백 검사에 오류가 없고 명백한 인증정보 패턴은 발견하지 못했다. 적용 대상 4개 파일에는 같은 이름의 SHA-256 sidecar가 없어 해당 canonical sidecar 검사는 적용하지 않았다.
- Git 속성은 `eol=lf`, `text=auto`이고 활성 commit hook은 확인되지 않았다. 보호 자료는 32/11/10개이며 HEAD 대비 변경과 미추적·ignored·index flag 이상이 없었다. 내부 파일명·내용은 읽지 않았다.
- 범위 밖 기존 상태 4개 때문에 현재 규칙상 staging은 보류했다. 기존 1회 예외는 만료됐다. 새 예외가 승인되지 않은 상태에서 staged diff를 검사했다고 주장하지 않는다.
- 필요한 별도 결정: 범위 밖 항목을 그대로 보존하고, 이번 4개 파일만 예외 승인 후 staging하여 정확한 staged diff·바이트·공백 검사를 통과하면 로컬 커밋하는 1회 절차. 푸시·삭제·다른 파일의 내용 접근·상시 규칙 변경은 포함하지 않는다.
