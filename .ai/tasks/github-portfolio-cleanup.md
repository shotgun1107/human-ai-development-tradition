# GitHub 포트폴리오 정리 작업 기록

갱신일: 2026-10-02 (Asia/Seoul). 일반 Git·문서 유지보수 기록이며 연구 역할의 입력으로 자동 허용되지 않는다.

## 목표와 완료 조건

- 기존 저장소 URL과 비공개 설정을 유지하면서 제출용 소개, 현재 문서, 브랜치와 커밋 제목을 정리한다.
- 원격 main과 로컬의 서로 다른 변경을 잃지 않고 통합한다. 기존 하네스·동결 근거의 파일 바이트·위치를 바꾸지 않는다.
- 원래 refs와 커밋을 복구할 수 있게 보존한 뒤 제목만 한국어 규약으로 정돈한다. 작성자·개발 날짜·부모 관계·과거 결과를 꾸미거나 소급 수정하지 않는다.
- 원격 반영 후 main·보관 refs·정리한 브랜치·GitHub 안내와 로컬 범위 밖 상태를 확인한다.

## 승인 범위와 금지 범위

- 사용자는 제출용 GitHub의 문서·브랜치·과거 커밋 제목 정리, 원본 백업, 원격 반영을 요청했다.
- 미분류 항목 4개를 이름·내용 접근이나 변경 없이 그대로 둔 채 이번 작업에 필요한 백업·fetch·정리 브랜치·커밋·원격 main 이력 갱신·확인된 브랜치 삭제를 수행하는 1회 예외를 별도 질문으로 확인받았다.
- 역할은 root/CONTROL의 일반 유지보수다. 대상 저장소는 `shotgun1107/human-ai-development-tradition` 하나이며 기존 작업 폴더의 범위 밖 4개 항목은 입력·출력 대상이 아니다.
- 출력은 이 작업 기록, 현재 안내 문서, 저장소 설명, 필요한 Git 객체·refs와 저장소 `.git/portfolio-cleanup-20261002/` 아래 복구 자료에 한정한다. 일반 실행 도구나 새 검증 프레임워크를 만들지 않는다.
- F0 내용 접근, 숨은 oracle·S0/E0·모델 호출, 공개 여부 변경, 다른 저장소 변경, 시스템 설치, 기존 근거 바이트 수정은 승인하지 않았다. Git 보존·재전송은 AI 내용 접근을 허용하지 않는다.
- 동결 입력의 원래 SHA-256과 과거 검증 주장은 그대로 둔다. 새 커밋 ID를 과거 기대값에 덮어쓰지 않는다. 작업 기록·백업을 연구 실행자나 독립 검토자에게 자동 전달하지 않는다.
- 예외는 이번 정리와 사후 확인으로 끝난다. 원격 refs가 동결 값과 달라지거나 보호 집계·내용 보존 검사가 실패하면 해당 게시·삭제를 중단한다. 이후 Git 작업에는 정상 분류·승인 절차를 다시 적용한다.

## 변경과 검증

- 원격 브랜치 156개의 고정 SHA를 fetch 결과와 대조했다. 정리 전 전체 refs는 `.git/portfolio-cleanup-20261002/all-refs.bundle`에 보관했으며 `git bundle verify`를 통과했다. 크기 3,957,036 bytes, SHA-256 `da0a3746d8980d1b1af4ca7c8e2bbfc226f0c345af3762e50657de857fd497e3`.
- 원격과 로컬의 안내 문서 충돌 3개를 통합했다. 구현 파일 간 충돌은 없었다. README는 목적·실제 구현·기록된 시험·설치/실행 안내·미검증 범위로 재구성하고 문서 안내의 PC 전용 링크를 상대경로로 바꿨다.
- 원격 193개와 로컬 추가 4개 이력을 보존한다. 제목만 한국어 규약에 맞추며 tree·작성자·committer·날짜·기존 본문·부모 연결 구조는 유지한다. 재작성에 따라 commit ID는 바뀐다. 기존 서명 1개는 변경된 사본에 복사하지 않고 서명된 원본을 보관한다.
- 보관 계획은 원래 main·로컬 tip 및 별도 이력 16개를 가리키는 `archive/` 태그 18개다. main 보관 태그의 주석에는 정리 전 브랜치 156개의 이름→SHA 대응표를 둔다. 이 태그들은 역사 복구 지점이지 현재 실행·동기화 기준선이 아니다.
- 현재 안내 6개 문서에서 충돌 표시가 없고 저장소 내부 링크의 대상 누락이 0개임을 확인했다. F0 집계는 32/11/10이고 원래 범위 밖 상태 4개의 지문은 동일하다. 내용이나 이름은 읽거나 출력하지 않았다.
- 변경한 원장·workstream의 현재 sidecar는 정규 텍스트 검사기 SelfTest 및 파일별 검사에서 PASS했다. 새 main을 원래 작업 폴더에 적용한 뒤에도 다시 PASS했다. 과거 동결 문서·manifest·sidecar의 바이트와 기대 해시는 수정하지 않았다.
- 기존 하네스 시험과 native/S0/E0 실행은 다시 수행하지 않았다. README의 상대경로 명령은 기존 진입점에 맞춘 안내이며 새 PC에서의 실행 검증 결과가 아니다.

## 게시 경로와 재개

- 준비 브랜치는 `chore/portfolio-cleanup`, 제목 정리용 로컬 참조는 `chore/portfolio-history`다. 이 일반 유지보수는 새로운 기술 후보가 아니다.
- 완료: 보관 태그 18개와 정리된 main을 atomic push로 함께 게시하고 live SHA를 대조했다. 보관을 확인한 원격 작업 브랜치 155개를 원래 SHA에 대한 lease로 제거했다. 남은 원격 브랜치는 main 하나다. 브랜치 이름은 삭제했지만 커밋은 보관 태그와 bundle에서 복구할 수 있다.
- 첫 게시 기준점은 `59bc21b70bd604dee38b8b3324dee7b709393ce4`다. 당시 main의 커밋 198개 중 제목 변경은 196개였고, 원본 대비 tree·작성자·committer·날짜·본문·부모 연결 구조 보존을 확인했다. 이 완료 기록의 추가 커밋은 별도 일반 문서 변경이며 미래 자기 해시를 기입하지 않는다.
- GitHub API의 실제 README blob이 로컬 main과 일치하고 최근 커밋 제목도 한국어로 반영됐음을 확인했다. 저장소 설명과 주제를 갱신했다. URL·비공개 상태를 유지했으며 PR·release는 만들지 않았다. 포트폴리오 평가자의 접근 권한은 별도 확인이 필요하다.
- 원래 작업 폴더도 새 main과 origin/main 추적으로 맞췄다. 기존 범위 밖 4개 상태의 지문은 동일하다. 작업용 임시 worktree만 제거했으며 원본 bundle·refs 대응표·커밋 대응표는 `.git/portfolio-cleanup-20261002/`에 남겼다.
- 미실행: 새 하네스 시험·native/S0/E0 및 새 PC 환경 검증. 이 정리로 기존 연구 결과의 범위나 입력 권한은 늘어나지 않는다. 향후 기존 clone에서 작업할 때는 이력 재작성 전후를 섞어 일반 pull하지 말고 현재 상태를 확인해야 한다.
