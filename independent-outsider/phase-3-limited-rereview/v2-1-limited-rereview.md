## 4. 사전 기준 완화 여부

사전 기준의 완화·삭제·자동 통과 처리는 발견하지 못했다.

| 동결 항목 | 2단계 상태 | v2.1 제한 재심사 상태 | 판단 |
|---|---|---|---|
| R01–R16, R18–R24 | 23개 모두 `부분 통과 — 검증 전` | 그대로 검증 전 | 문서 보강은 운영 증거가 아니다. 완전 통과로 올릴 근거가 없다. |
| R17 | `실패` | 문서상 부분 반영, 운영 검증 전 | 설계 수준 누락은 D08로 보완됐지만 사람 협업의 실제 보고·거부·보복·인센티브·노동 결과는 없다. 따라서 완전 통과가 아니다. |
| 31개 치명 조건 | 확정 탈락 0, 현재 비해당 8, 판단 불가 23 | 같은 상태 유지 | `현재 비해당`은 안전 입증이 아니고 `판단 불가`는 관련 경계를 막는 미해제 관문이다. v2.1은 이를 해제했다고 주장하지 않는다. |

v2.1 §0.1은 문서 수정이 운영 증거를 만들지 않는다고 밝히고, §11은 독립 증거가 있을 때만 다음 단계를 열며 관련 `판단 불가` 치명 조건을 경계 직전에 재판정하도록 한다. §11의 `0단계 완료`는 심사 수행이 끝났다는 뜻일 뿐 24개 기준의 통과나 운영 승인이 아니다. 이 표현은 오독 가능성이 있으나 같은 행의 `운영 승인 없음`과 §11 말미의 총괄 잠금 때문에 실제 완화로 판단하지 않는다.

새 금지 주장도 발견하지 못했다. 특히 다음은 계속 금지되거나 검증 전 가설로 표시된다.

- Sol Ultra–Sol Pro 비교 완료 및 모델 수렴의 독립 증거화
- 최소 증거 계보 또는 중앙화의 우월성
- 실제 오류 감소, 품질, 전이, 안전, 경제성, 운영 순가치
- Project Brain 연결 완료
- 내부·외부 브랜드 가치와 대외 보증

## 5. S0의 판별 가능성과 남은 순환 검증 위험

### 판별 가능성

S0의 문서 구조는 준비 단계로 넘어갈 만큼 판별 가능하다.

| 점검 축 | 판정 | 근거와 한계 |
|---|---|---|
| 시험 지위 | 충족 | §10.1과 §10.9가 S0를 합성 논리 선행조건 시험으로 제한하고 제품·효과·안전 시험으로의 확대를 금지한다. |
| 네 대안 | 충족 | §10.2가 무공통층·프로젝트 로컬·최소 목록·최소 계보를 동일 자원과 결과로 비교한다. D는 목표 가설일 뿐 정답으로 고정되지 않는다. |
| 공개·봉인 분리 | 충족 | §10.3이 공개 개발용과 동결 뒤 공개할 봉인 판정용을 분리하고 누출 결과를 폐기한다. |
| 정보 접근 | 조건부 충족 | §10.5가 실행자의 봉인 입력·답 사전 접근을 막고 최소한 실행 측과 작성·판정 측의 정보 접근을 분리한다. 실제 사람·저장 위치·접근 이력은 미정이다. |
| 적대 사례 | 충족 | §10.4가 무단 전달, 중복 집계, 반례 은폐, 철회 누락, 악성 명령형 문자열, Brain 의미 충돌을 합성 사례에 포함한다. |
| 결과·중단 | 충족 | §10.8–10.10이 오류, 감사 재구성, 대안 품질, 사람 시간, 복잡도, 단일 중대 오류 실패, 누출 폐기, 새 봉인 재시험을 결과 관찰 전에 고정하도록 한다. |

### 남은 순환 검증 위험

다음은 v2.1의 구조적 결함이라기보다 1단계 S0 프로토콜에서 닫지 않으면 다시 순환 검증이 되는 위험이다.

1. **oracle 독립성:** fixture 작성자와 최종 판정자가 겸임하면 실행과의 정보 분리만으로 기대 판정 자체의 편향을 발견하기 어렵다. 겸임 결과를 독립 증거라 부르지 않는 데서 그치지 말고, S0 합격에 사용할 기대 판정은 독립 검토를 받게 하고 불일치 처리 규칙을 동결해야 한다.
2. **동일 정보의 정의:** 네 대안의 원천 corpus, 각 조건이 볼 수 있는 표현, 허용 전처리, 수동 정리 시간을 사전 동결해야 한다. `새 공통 계층 없음`을 의도적으로 불리하게 만들거나 D의 계보 표현을 무료 정보로 주면 비교가 비대칭이 된다.
3. **표현 중립적 판정:** 기대 답과 결과 채점이 D의 객체·상태명을 전제로 해서는 안 된다. 동일한 권한·철회·중복·반례 결과를 다른 표현으로 달성한 A–C도 같은 기준으로 점수를 얻어야 한다.
4. **설계 계열 과적합:** 단일 봉인 묶음만으로는 fixture 계열에 대한 간접 맞춤을 배제하기 어렵다. 표현·순서·무관 정보를 바꾼 손대지 않은 변형과 실패 수정 뒤 새 봉인 묶음이 필요하다.
5. **보관·누출 판정:** 봉인 입력, 기대 답, 해시의 작성·보관·공개 시점, 접근자, 접근 로그와 누출 시 폐기 범위를 프로토콜 해시에 포함해야 한다.

따라서 현재 문서는 **S0 프로토콜과 fixture를 준비할 논리적 전제**를 충족하지만, 아직 S0 실행 또는 합격을 입증하지 않는다.

## 6. 실제 단계 관문의 폐쇄 여부

현재 S0 범위에서 실제 단계는 닫혀 있다.

| 경계 | 폐쇄 여부 | 판단 |
|---|---|---|
| 실제 자료 | 닫힘 | §10.7에서 S0 입력을 합성 자료로 제한하고, §10.9와 §12.1에서 실제 자료 유입을 금지·즉시 중단 사유로 둔다. 4A는 실제 자료를 읽지 않는 준비 관문이고, 4B도 독립 재판정과 승인된 흐름 없이는 열리지 않는다. 다만 D04·D06의 세부 완료조건은 4B 전에 보강해야 한다. |
| 실제 검색·도구 권한·네트워크 | 닫힘 | S0에서 네트워크, 외부 전송, 실제 검색, 비가역 도구 권한을 배제하고 유입 시 중단한다. 실제 권한을 열기 전 D05의 공격·탐지·격리·복구 판정표와 독립 통과 증거를 별도로 요구해야 한다. |
| 실제 프로젝트 영향 | 닫힘 | 4B도 과거 자료를 실제 행동 영향 없이 비교하는 그림자 단계다. 5단계 이후의 실제 파일럿은 문제·비용 기준선과 직전 관문 증거가 필요하다. S0가 이를 자동 개방하지 않는다. |
| 복수 자산·다중 프로젝트 | 닫힘 | 복수 자산은 별도 3단계, 다중 프로젝트는 6단계이며 각각 별도 실패·철회·노동 관문을 가진다. |
| Project Brain | 닫힘 | 실제 규격과 기술 선택은 미정이다. 7단계는 의미 경계 안정, 수동 경로, export·restore 시험 통과 뒤에만 열린다. |
| 모델 이주·효과 | 닫힘 | 8단계에서만 신선 과제, 봉인 holdout, 오염 감사, 비용 기준선을 갖춘 비교를 허용한다. S0 결과로 효과나 모델 전이를 주장할 수 없다. |
| 브랜드 | 닫힘 | 내부 브랜드는 9단계, 제한 외부 표현은 10단계다. 실제 이력·독립 표본·감사·정정·철회·불만·이의·구제 없이는 열리지 않는다. D11의 세부 잔여도 외부 표현 전에 보강해야 한다. |

§11의 “문서가 있다는 이유가 아니라 해당 관문의 독립 증거가 있을 때만 열린다”는 총괄 잠금은 계획을 통과 증거로 오인하는 것을 막는다. 다만 4A의 `기준선 계획`과 4B의 실제 자료 사용 사이에는 기준선 측정의 위치가 모호하다. 이 모호성은 S0를 열어 두는 문제가 아니라 **4B를 열기 전에 해결해야 할 문서 잔여**다.

## 7. 새로 생긴 과잉 복잡성·모순·누락

새 서비스, 데이터베이스, 에이전트, 실제 통합, 승인 조직을 제품 기능으로 추가한 흔적은 없다. 네 대안, 공개·봉인 fixture, 역할·해시·재시험, 상태 분리는 D01–D03·D13과 N02·N04에 직접 필요한 시험 통제다. 사람 시간과 복잡도를 결과로 기록하고 이득이 없으면 관계를 줄이므로, 현재 추가분은 정당화 가능한 시험 복잡성이다.

다만 다음 관리상 잔여가 있다.

1. **규범 중복과 표현 과장:** §0.1, §10–12, §17이 같은 경계를 반복한다. 특히 §17은 D04–D06을 `추가`했다고 요약하지만 본문은 일부를 계획이나 일반 관문으로만 둔다. 반영 장부가 본문보다 강한 상태가 되지 않도록 본문을 보강하거나 `부분 반영·후기 관문 전 보강`으로 맞춰야 한다.
2. **기준선의 단계 모순:** 4A는 실제 자료를 읽지 않으면서 기준선 `계획`만 만들고, 4B는 곧 실제 자료를 읽는다. 어느 승인된 최소 측정이 4B 진입 전의 기준선 증거인지 정의되지 않았다.
3. **`첫 커널` 잔여 용어:** 비교 이력과 미결정 항목에 남은 `첫 커널` 표현은 현재 규범 용어인 S0와 제품 구축을 혼동시킬 수 있다. 규범적 문장에서는 `S0 합성 논리 시험` 또는 `S0 프로토콜`로 통일하는 편이 안전하다.
4. **0단계 `완료` 오독 가능성:** 수행 완료와 기준 통과를 혼동할 수 있다. 같은 행의 `운영 승인 없음`이 현재 모순을 막지만, 후속 판본에서는 `심사 수행 완료—기준 통과 아님`으로 명시하면 된다.
5. **S0 자원 대칭의 실행 정의 누락:** 같은 정보·권한·사람 시간을 선언했지만 조건별 허용 표현·전처리·수동 정리 비용의 회계 규칙은 아직 없다. 이는 1단계 프로토콜 산출물이어야 한다.

위 문제는 새 전체 설계나 S0 준비 금지를 요구하지 않는다. 그러나 후기 관문 문구를 실제 단계 진입 전에 보강하지 않으면 “계획 존재”가 “통과 증거”로 미끄러질 수 있다.

## 9. 시험으로만 판단할 잔여 항목

문서 표현을 더 늘려도 다음은 통과 처리할 수 없다.

### S0 실행으로만 판단할 항목

- 봉인 fixture가 실제로 실행자에게 미노출됐는지, 해시·접근 기록·시간 순서가 보존됐는지
- 공개 fixture 맞춤 규칙과 사례별 하드코딩이 새 봉인·교란 fixture에서 실패하는지
- 네 대안이 실제로 같은 정보·권한·사람 시간 한도와 표현 중립적 결과척도를 받았는지
- 무단 전달, 중복 집계, 반례 은폐, 철회 누락, 상태 오류, 명령형 문자열 오해가 0건인지
- 감사 근거 재구성, 판정자 일치, 사람 능동시간, 복잡도와 대안별 오류 차이
- 최소 증거 계보가 더 단순한 대안보다 오류를 줄이는지, 아니면 비용만 늘려 축소해야 하는지
- 한 자산 범위에서만 성립한 결과라는 한계를 보고서와 후속 의사결정이 실제로 지키는지

### 후속 실제 시험으로만 판단할 항목

- 실제 문제 분모, 미보고·누락 민감도, 예방 가능성, 현재 손실과 개입세
- 적응형 공격, 재식별, 오염, secret, 공급망, 권한 외 동작의 탐지·격리·복구 성능
- 실제 삭제·철회·파생물 추적, 법적 권한, 프라이버시·IP 준수
- 실제 사람 협업의 신고·거부·보복·종결·재발·이탈·인센티브 게임·검토 노동 집중
- 실제 품질·사용자 가치·음의 전이·꼬리 위험·비용·대기열·유지 가능성
- 독립 환경 export·restore·migration과 중앙 장애·공급자 종료 복구
- 실제 Project Brain 의미 보존, 모델 이주 효과, 내부·외부 브랜드 주장의 진실성

따라서 24개 기준의 운영 통과와 23개 `판단 불가` 치명 조건의 해제는 이 재심사 결과가 아니다.

## 10. 최종 판정과 허용 범위

### 현재 v2.1로 S0 준비 가능

판정 이유는 다음과 같다.

1. S0 준비를 직접 막았던 D01–D03·D12–D13과 N01–N06의 핵심 문서 수정이 반영됐다.
2. S0는 합성·격리·비권한 논리 선행조건 시험으로 일관되며 네 대안, 봉인 fixture, 정보 접근, 결과·중단·재시험 구조가 판별 가능하다.
3. 24개 기준과 31개 치명 조건을 완화하거나 통과 처리하지 않았다.
4. 실제 자료·검색·도구 권한·프로젝트 영향·복수 자산·Project Brain·모델 이주·브랜드 관문은 S0와 분리되어 닫혀 있다.
5. 부분 반영인 D04–D07·D09·D11은 해당 후기 경계를 열기 전에 반드시 보강해야 하지만, 운영 증거 부재를 이유로 합성 S0의 준비 자체를 금지할 사유는 아니다.

이 판정이 허용하는 최대 범위는 별도 1단계에서 공개·봉인 fixture, 네 대안, 역할과 정보 접근, 해시, 주요 결과, 중단·누출·재시험 규칙을 작성·동결하고 그 프로토콜을 실행 전 확인하는 것이다. 이 재심사 작업 자체에서는 fixture·구현·코드를 작성하지 않았다.

이 판정은 다음을 허용하지 않는다.

- S0 구현 완료 또는 S0 합격 주장
- 실제 자료, 실제 검색, 네트워크, 외부 전송, 실제 도구 권한 사용
- 실제 프로젝트·사람·고객에 대한 행동 영향
- 복수 자산이나 다중 프로젝트로의 일반화
- Project Brain 연결 또는 실제 규격 확정
- 실제 효과·안전·경제성·운영 순가치·중앙화 우월성 주장
- 모델 이주 완료, Sol Ultra–Sol Pro 비교 완료 주장
- 내부·외부 브랜드·인증·대외 가치 주장
- 24개 기준의 완전 통과 또는 23개 판단 불가 치명 조건의 해제

## 11. 확인 범위와 미확인 범위

### 확인한 범위

- 다섯 허용 입력의 파일 동일성 및 지정 SHA-256 일치
- v2.1의 문언과 구조가 D01–D14·N01–N06을 반영한 정도
- 1단계의 24개 기준과 31개 치명 조건이 문서상 완화·삭제·자동 통과되지 않았는지
- S0의 합성·격리 범위, 네 대안 대칭 원칙, 공개·봉인 fixture, 역할·정보 접근, 누출·재시험 규칙
- 임시 예방 중지, R17, Project Brain 미정 경계, 한 자산 일반화 금지
- 실제 자료·권한·영향·모델·브랜드 관문의 문서상 폐쇄와 새 금지 주장 유무
- 새 문서 구조가 만든 과잉 복잡성·내부 모순·누락

### 확인하지 못했거나 의도적으로 확인하지 않은 범위

- 금지된 내부 원문, 원 연구·브리프, Ultra·Sol Pro 원안, v1, 다른 심사·대화 기록의 내용과 진위
- 후보의 자기보고, 내부 인용 및 과거 판단의 외부 사실성
- 실제 S0 프로토콜, 공개·봉인 fixture, 기대 답, 담당자, 접근 통제, 해시, 실행 결과
- 코드·구현·저장소 동작·Project Brain 인터페이스·보안 구성
- 실제 자료의 대표성, 법적 권한, 프라이버시·IP 적합성, 공격·복구 성능
- 실제 품질·효과·안전·전이·경제성·사람 영향·브랜드 가치
- 24개 기준의 운영 통과 및 31개 치명 조건의 실증 해제
- 인터넷·외부 자료에 의한 재조사나 현재 법률·기술 상태 확인

이 보고서는 해시가 일치한 허용 문서의 정적 제한 재심사다. 결론의 범위는 **S0 준비 가능 여부**에 한정되며, 이후 어느 단계의 실행 결과나 운영 적합성을 대신하지 않는다.
