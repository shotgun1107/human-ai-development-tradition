# v2.1 제한 수정 후보 독립 재심사 프롬프트

너는 1단계 독립 조사 기준을 만들고 2단계에서 v2 통합 후보를 심사한 외부 심사자다. 이제 기존 기준을 바꾸지 않은 채 `v2.1 제한 수정 후보`가 네 지적을 실제로 반영했는지만 제한 재심사한다.

새 전체 설계를 만들거나 광범위한 문헌조사를 다시 하지 마라. 좋은 의도를 칭찬하는 것이 아니라 변경의 정확성, 사전 기준의 유지, S0 시험의 판별 가능성과 닫힌 운영 관문을 확인하라.

## 2. 재심사 범위

1. D01–D14와 N01–N06 각각에 대해 `충분히 반영 / 부분 반영 / 미반영 / 잘못 반영`을 판정한다.
2. 24개 기준과 31개 치명 조건이 v2.1에 맞춰 완화·삭제·통과 처리되지 않았는지 확인한다.
3. S0가 제품 구축·효과 시험이 아니라 합성 논리 선행조건 시험으로 일관되게 제한됐는지 확인한다.
4. 공개 fixture와 봉인 fixture, 작성·실행·판정의 정보 접근, 누출·재시험 규칙이 사례별 답안 맞춤을 발견할 수 있는지 확인한다.
5. `새 공통 계층 없음 / 프로젝트 로컬 / 최소 공통 목록 / 최소 증거 계보`가 같은 정보·권한·사람 시간·주요 결과로 대칭 비교되는지 확인한다.
6. 검증된 전체 공통 자산과 임시 예방 중지가 명확히 분리되고, 임시 중지가 만료·책임·재검증·자동 승격 금지를 가지는지 확인한다.
7. R17의 참여·보고·거부·보복·인센티브·검토 노동이 현재 단계와 미래 사람 협업 단계에 맞게 구분됐는지 확인한다.
8. Project Brain 실제 규격은 여전히 미정이며 S0가 의미 책임 충돌만 시험하는지 확인한다.
9. 자산 한 개의 S0 결과가 복수 자산·승인 피로·확장성의 증거로 확대되지 않는지 확인한다.
10. 실제 자료·검색·도구 권한·프로젝트 영향·모델 이주·브랜드 단계가 관련 보안·권리·거버넌스·비용·복구 관문과 치명 조건 재판정 전까지 닫혀 있는지 확인한다.
11. 수정이 불필요한 기능·역할·문서 생산을 늘려 관리 부담을 키웠는지 확인한다.
12. `Sol Ultra 대 Sol Pro 완료`, 중앙화 우월성, 실제 효과·안전·경제성·브랜드 가치 같은 금지 주장이 새로 생기지 않았는지 확인한다.

문서 수정으로 해결할 문제와 S0 또는 후속 실제 시험으로만 판단할 문제를 다시 분리하라. 운영 증거가 없다는 이유만으로 합성 S0 준비를 금지하지 말고, 반대로 계획이 있다는 이유로 운영 기준을 통과 처리하지 마라.

## 3. 출력

결과는 다음 파일 하나에 작성하고 다른 파일을 수정하지 마라.

`independent-outsider/phase-3-limited-rereview/v2-1-limited-rereview.md`

필수 구성:

1. 입력 해시와 독립성 확인
2. D01–D14 반영 판정표
3. N01–N06 반영 판정표
4. 사전 기준 완화 여부
5. S0의 판별 가능성과 남은 순환 검증 위험
6. 실제 단계 관문의 폐쇄 여부
7. 새로 생긴 과잉 복잡성·모순·누락
8. 문서 수정으로 해결할 잔여 항목
9. 시험으로만 판단할 잔여 항목
10. 최종 판정과 허용 범위
11. 확인 범위와 미확인 범위

최종 판정은 다음 중 하나만 선택하라.

- 기각
- 설계 단계로 복귀
- 중대한 수정 후 다시 재심사
- 제한 수정 후 S0 준비 가능
- 현재 v2.1로 S0 준비 가능

`S0 준비 가능`은 구현 완료, 실제 자료 사용, 실제 프로젝트 영향, Project Brain 연결, 효과·안전·경제성·브랜드 주장을 허용하지 않는다. 구현·코드·fixture 실제 작성·후보 원문 수정·Git 작업은 하지 마라.
