> 역할: 1단계에서 동결한 기준을 사후 완화하지 않는 외부 심사자  
> 대상: “중앙 인간–AI 개발 전통 시스템 v2 통합 후보”  
> 최종 판정: **제한된 수정 후 첫 시험 준비 가능**

## 1. 입력 해시와 독립성 확인

### 1.1 SHA-256 확인

지정된 순서대로 체크섬 파일을 확인한 뒤, 두 입력 문서의 SHA-256을 직접 계산했다.

| 입력 | 동결 기대값 | 직접 계산값 | 판정 |
|---|---|---|---|
| 1단계 독립 보고서 | ba1ff2f2783f50038627e82afcfba21a27400161f64c90edc8498c8dfe244069 | ba1ff2f2783f50038627e82afcfba21a27400161f64c90edc8498c8dfe244069 | 일치 |
| v2 통합 후보 | 7f51e0cfba2f56f9427facb6436d829b7d274a989fa3e8a5b4167f602256afb0 | 7f51e0cfba2f56f9427facb6436d829b7d274a989fa3e8a5b4167f602256afb0 | 일치 |

하나라도 달랐으면 내용 심사를 시작하지 않았을 것이다. 두 값이 모두 일치했으므로 동결 기준을 적용했다.

### 1.2 허용 입력과 독립성

심사에서 읽은 저장소 입력은 다음 세 파일뿐이다.

1. independent-outsider/phase-1-research/independent-research-and-review-criteria.sha256
2. independent-outsider/phase-1-research/independent-research-and-review-criteria.md
3. docs/proposals/v2/central-tradition-system-v2-integrated-candidate.md

다른 연구·목적·브리프·v1·원안·이전 심사·다른 AI 결과 파일은 열거나 검색하지 않았다. 후보 안의 CB, PH, R1, R2, DB, SU, GT 줄 인용은 후보가 보고한 provenance로만 보았다. 해당 원문은 허용 입력이 아니므로 그 내용, 해시, 모델 정체성, 독립성은 이번 심사에서 재확인하지 않았다. 후보도 시작 프롬프트와 숨은 입력을 자기보고 이상으로 올리지 않는다고 적는다(후보 §1.1–1.2, L34–60).

보조 검토는 24개 기준과 31개 탈락 조건의 누락을 찾는 문서 대조에만 사용했다. 여러 AI가 같은 입력에서 같은 결론을 냈다는 사실은 독립 근거로 세지 않았다. 판정을 좌우하는 새 외부 출처 재조사는 하지 않았다.

### 1.3 판정 용어

- **통과:** 후보 문서와 제출 증거가 해당 기준의 요구를 충족한다.
- **부분 통과 — 검증 전:** 문서가 위험과 검증 방향을 다루지만 실제 독립 증거가 없거나 핵심 요소가 빠져 있다.
- **실패:** 문서 수준에서도 기준의 핵심이 없거나 현재 시험이 그 기준을 판별할 수 없다.
- **판단 불가:** 구현·운영·독립 시험 자료가 없어 긍정도 부정도 확정할 수 없다.
- **해당 없음:** 후보의 목표·현재 단계 모두에 논리적으로 적용되지 않는다.

“검증 전”은 통과의 약한 표현이 아니다. 계획의 존재와 효과·안전의 증거를 분리하기 위한 상태다.

## 2. 후보의 중립적 요약

### 2.1 문서 지위와 제품 목적

후보는 자신을 외부 심사 전의 기획·목표 구조·첫 구축 범위로 한정하고, 최종 설계·운영 효과·확정 규격으로 부르지 않는다(§0, L3–11). 제품을 다음과 같이 정의한다.

- 여러 프로젝트와 여러 AI 세대의 작업 증거를 프로젝트 경계와 출처 계보를 유지한 채 연결한다.
- 그 증거에서 조건부 선례와 작업 자산을 만들고, 현재 과제에는 소수만 전달한다.
- 프로젝트가 채택·거부·변형·오적용한 결과와 철회를 다시 반영한다.
- 중앙은 프로젝트 실행 엔진이나 모든 원자료의 영구 창고가 아니라 장기 계보·전이의 “통제면”이다(§3.1, L150–152).

후보가 말하는 성공은 신선한 과제와 다른 구성에서의 중대 반복 오류, 품질, 비용, 위험, 음의 전이 탐지, 인간 관리비의 실제 변화다. 문서·자산·사용·승인 수를 성공으로 보지 않으며, 첫 구축의 통과를 실제 효과로 확대하지 않는다(§3.3, L166–179; §10.6, L552–554).

### 2.2 중앙의 책임과 경계

중앙 책임은 프로젝트·작업·실행·팀 구성의 장기 계보, 권한·비밀·삭제 경계, 상관된 파생물을 묶는 증거 계열, 성공·실패·결정·실험·비용·사람 수정의 비교, 자산의 범위·판본·효력·근거·반례, 허가된 파생 공유, 선택·전달, 사용 결과 환류, 모델·도구 이주, 사건·정기·메타 검토, 브랜드 근거 연결이다(§4.1, L183–195).

중앙은 프로젝트 일상 실행, Project Brain 내부 구성, 고객 납품의 최종 승인, 원자료 소유권 자동 이전, 로컬 native 자산 덮어쓰기, 모순의 강제 통합을 맡지 않는다. 중앙 불능도 프로젝트 전체 실행을 멈추지 않는다고 선을 긋는다(§4.2, L197–205).

사람 소유자, 프로젝트 책임 인간, Project Brain, 실행 AI, 중앙 자동화, 중앙 큐레이터, 독립 검토자의 역할을 구분한다. 자료 공유, 자산 효력, 외부 발행은 서로 다른 결정으로 기록하지만, 한 사람이 여러 인간 역할을 겸할 수 있다(§4.3, L207–219).

### 2.3 목표 구조와 흐름

목표 구조는 다음 연쇄다.

1. 경계·신뢰 확인
2. 원근거와 실행 계보
3. 사실·해석·가설의 분리와 사례 비교
4. 조건부 자산 포트폴리오
5. 권한·상태·조건에 맞는 소수 자산 선택
6. 채택·거부·변형·오적용과 결과 환류
7. 범위·상태 수정과 철회

상관된 AI 요약은 “증거 계열”로 묶고, 프로젝트 원본은 공통 영역으로 이동하지 않으며 승인된 파생물만 별도 계보로 만든다. 범위, 권한, 확실성, 행동 강도, 외부 공개 가능성은 하나의 점수로 합치지 않는다. 삭제 의무는 계보 완전성보다 우선한다(§5.1–5.2, L272–309).

작업 자산은 후보, 제한 시험, 활성, 중지, 폐기·대체의 다섯 효력 상태를 가진다. 프로젝트 전용이 기본이며 프로젝트 종류 공통과 전체 공통은 조건부 범위다. 공통화 정량 문턱은 아직 정하지 않았다(§6.3, L329–349).

### 2.4 첫 구축 범위

첫 구축은 세 가상 프로젝트, 조건부 자산 한 개, 수신 가상 작업 한 개로 구성된 합성 왕복이다. 같은 원근거에서 나온 AI 요약, 독립 원근거, 반례, 비밀 원문과 승인된 파생물, 채택·거부·변형·오적용, 원근거 철회를 고정 fixture로 둔다(§10.1–10.2, L494–513).

시험하려는 것은 다음뿐이다.

- 원근거와 파생물 및 증거 계열의 논리
- 프로젝트 권한과 파생 공유
- 사실·해석·조건부 주장·반례의 연결
- 자산 상태
- 전달 또는 거부
- 결과와 판본의 연결
- 원근거 철회의 파급
- 판정 근거 재구성
- 단순 목록보다 중복 증거 또는 철회 누락 한 종류를 더 잘 찾는지

실제 자료, 검색·RAG, 자동 추출·승인, Project Brain 연결, 실제 모델 이주, 장기 성과·수익·브랜드는 제외한다(§10.3–10.6, L515–554). 따라서 이 첫 구축은 전체 제품의 핵심 효과 가설을 시험하지 않고, 일부 논리적 선행조건만 시험한다.

### 2.5 단계와 미결정 사항

후보는 합성 fixture, 합성 커널, 10개 가상 상황, 비식별 그림자, 수동 내부 실제 파일럿, 다중 프로젝트 전이, Project Brain 어댑터, 모델 이주·효과 비교, 내부 브랜드, 제한 외부 표현의 순서를 제시한다(§11, L556–570).

메시지·API·파일·이벤트, 저장·검색 기술, 정확한 스키마, taxonomy, 정량 문턱, 검토 빈도, 자동 비식별 범위, 백업·복구, 실제 효과 시험 통계, 모델·평가자·공급자, 브랜드 표현은 미결정이다(§15, L649–665).

### 3.1 사실·연구·설계·가설 분리

판정은 **부분 통과 — 검증 전**이다.

- 후보는 확인 사실, 통합 결정, 검증 전 전제, 미결정을 정의한다(§0, L25–30).
- 검증 전 전제 10개를 별도 목록으로 둔다(§2.5, L120–133).
- 채택·수정·거부 결정을 비교표와 결정 장부에 남긴다(§2.2, L84–95; §13, L611–628).
- 첫 구축이 증명하지 않는 내용을 명시한다(§10.6, L552–554).
- 기술·문턱·모델·브랜드 표현의 미결정을 공개한다(§15, L649–665).

남은 문제는 세 가지다.

1. 네 표지가 모든 개별 주장에 붙지 않는다. 예를 들어 문제 서술(§3.2, L154–164)은 연구에서 가져온 관찰인지 제품 가설인지 문장만으로 구분되지 않는다.
2. 대안의 “목적 적합성” 평정(§2.6, L139–146)은 통합 결정이지만 표 안에서 근거가 확인 사실처럼 읽힐 수 있다.
3. 내부 일곱 문서의 내용은 이번 봉인 심사에서 확인할 수 없다. 그러므로 그 문서를 근거로 한 서술은 이번 심사에서는 후보의 자기보고다.

### 3.2 대안 공정성

판정은 **부분 통과 — 검증 전**이다.

후보는 네 목표 구조 대안의 강점과 대가를 함께 적고, 선택한 계보 구조가 단순 목록보다 낫지 않으면 레지스트리 또는 로컬 체계로 축소한다고 한다(§2.6, L135–146). 전통 없음·원로그·정제 자산 비교(§8.2, L459–465)도 계획한다.

그러나 다음은 충족되지 않았다.

- 중앙형·분산형·혼합형·최소 개입을 동일 정보·예산·기간·업무에서 대칭적으로 비교하지 않는다.
- “전통 없음”은 콘텐츠 조건이고, 중앙화 구조의 대안인 “새 공통 계층 없음”과 동일하지 않다.
- 첫 구축의 비교대안은 단순 목록 하나뿐이며, 프로젝트 로컬 방식과 최소 개입은 없다.
- D의 “목적 적합성 높음”은 운영 근거가 아니라 같은 통합 문서의 질적 판단이다. 후보도 이를 운영 실적이 아니라고 인정한다(§2.6, L137).

## 4. 31개 치명적 탈락 조건 판정표

요약은 **명백히 해당 0, 현재 문서상 비해당 8, 판단 불가 23**이다.

“현재 비해당”은 운영 안전성을 입증했다는 뜻이 아니다. 후보가 아직 구현·실제 자료·실제 권한·효과·브랜드 주장을 하지 않거나 해당 위험을 명시적으로 금지했기 때문에 현재의 즉시 탈락 사유가 아니라는 뜻이다. “판단 불가”인 치명 조건은 장점으로 상쇄되지 않으며 관련 단계로 가기 전에 독립 증거로 해제해야 한다.

## 5. 치명적·중요·경미 문제

### 5.1 치명적 문제

**현재 문서와 현재 합성 범위에서 확정된 치명적 문제는 0개다.** 이 판정은 다음 범위 제한에 의존한다.

- 합성 입력만 사용
- 실제 프로젝트·고객·개인·비밀 자료 없음
- 실제 도구·외부 전송·비가역 권한 없음
- 실제 작업과 고객 납품에 영향 없음
- 효과·안전·전이·경제성·브랜드 주장 없음

아래 경계를 넘으면 현재의 “비해당” 또는 “판단 불가”가 즉시 다시 열린다.

### 5.2 중요 문제

#### I1. 첫 구축은 전체 핵심 가설을 반증하지 못한다

후보는 이를 솔직히 인정한다(§10.6, L552–554). 첫 구축이 판별하는 것은 계보 관계가 고정 답안대로 작동하는지, 단순 목록보다 중복 증거 또는 철회 누락 한 종류를 찾는지뿐이다(§10.5, L539–550). 다음은 판별하지 못한다.

- 중앙 공통 계층이 분산·혼합·최소 개입보다 순효과가 큰가
- 실제 반복 오류·심각도·품질·시간·비용이 개선되는가
- 사람이 실제로 발견·이해·적용·거부하는가
- 부정적 전이·단일문화·운영세가 편익보다 작은가

따라서 “첫 구축”은 **핵심 가치 시험이 아니라 논리적 선행조건 시험**으로 명칭과 진입 결정을 제한해야 한다.

#### I2. 시험 답안과 설계를 같은 문서가 만들기 때문에 순환 검증 위험이 있다

합성 입력의 기대 판정을 사전 동결한다는 것만으로는 독립성이 생기지 않는다(§10.2, L513). 구현자가 fixture와 기대 답을 알고 있으면 일반 규칙 없이 사례별 답을 맞춰도 통과할 수 있다. 동일 입력의 재현성은 타당성보다 결정론적 답안 일치를 측정할 수 있다.

첫 시험 전 최소한 구현 전 공개 fixture와 구현 동결 후 공개하는 봉인 fixture, 독립 판정자, 허용된 수정 규칙, 대안별 동일 정보·예산을 분리해야 한다.

#### I3. 대안 비교가 대칭적이지 않다

네 구조 대안은 질적으로 비교되지만 같은 브리프·설계 입력에서 나온 판단이며 운영 자료가 아니다(§2.6, L135–146). 첫 시험의 상대군은 단순 목록뿐이다(§10.5, L550). 프로젝트 로컬 체계, 최소 공통 색인, 아무 새 공통 계층도 없는 조건은 같은 fixture로 비교되지 않는다.

선택한 D가 “높은 목적 적합성”이라는 판단은 가설로 유지해야 하며, 다른 대안보다 더 많은 정보·관계·사람 시간을 받아 생기는 우위를 통제해야 한다.

#### I4. 문제 기준선과 누락 분모가 없다

반복 오류가 실제로 얼마나 크고 어떤 비율이 지식 부재 때문에 예방 가능한지 자료가 없다. 후보는 성공·실패·반례를 보존하지만, 중단·무사고·미보고와 전체 노출을 포획하는 계획이 부족하다. 실제 자료 단계 전에 이 분모가 없으면 입력 자료의 편향과 제품 필요성을 동시에 판정할 수 없다.

#### I5. 참여·심리적 안전·인센티브가 설계상 비어 있다

R17은 유일한 실패다. 프로젝트가 충분한 사용·거부·변형 결과를 반환한다는 것을 검증 전 전제로 두지만(§2.5, L126), 누가 왜 정직하게 실패를 보고하는지, 실패 보고 뒤 불이익이 있는지, 누가 검토 노동을 떠맡는지 다루지 않는다. 피드백 객체가 존재해도 진실한 표본은 생기지 않는다.

#### I6. 독립 심사와 이의제기가 역할명에 머문다

독립 검토자를 적었지만 한 사람이 여러 역할을 겸할 수 있고(§4.3, L217–219), 심사 대상·비용·일정 책임자로부터의 재정·지휘 독립, 이해충돌 회피, 이의·재심·피해 구제가 없다. “서로 다른 결정으로 기록”하는 것과 실제 권력 분리는 다르다.

#### I7. 보안·프라이버시가 원칙이고 단계 관문은 아니다

최소권한·격리·도구 호출 검증·사람 승인은 올바른 방향이지만(§7.2, L410–420), 단계표에는 실제 자료 전에 통과할 위협모형, 적응형 공격, 권한 외 행동, 공급망 변조, canary, 탐지·대응 기준이 없다. 프라이버시도 재식별 위험을 인정하지만 데이터 흐름·관할·적법 근거·IP·보존·통지 판정이 없다.

#### I8. 운영 지속성·종료·복구가 미결정이다

중앙 불능 시 로컬 실행을 계속한다는 경계는 중요하지만, 중앙에 쌓인 의미·계보·권한·철회 상태를 내보내고 복구하는 방법과 시험은 없다. 1인 운영 가능성은 검증 전 전제이고, 검토 빈도·시간 상한·공급자·재해복구도 미정이다. “프로젝트가 계속 실행된다”와 “중앙 지식·책임이 복원된다”는 다른 주장이다.

#### I9. 높은 위해와 가역성만으로 “전체 공통” 범위를 열 수 있는 문구가 있다

후보는 여러 조건의 제한 재현 외에도 “위해가 크고 조치가 가역적인 안전 원칙”을 전체 공통 범위 주장으로 둘 수 있다고 한다(§6.3, L347). 위해의 크기는 그 조치가 효과적이라는 근거가 아니다. 이 문구는 예방 원칙을 근거 확실성과 혼동하고 공통 실패 모드를 만들 수 있다. 임시 예방 중지와 검증된 공통 자산을 명확히 구분해야 한다.

#### I10. 봉인 심사 패키지가 자기완결적이지 않다

후보는 일곱 내부 문서의 줄 번호와 해시를 근거로 사용하지만 이번 심사자는 그 문서를 읽을 수 없다. 이는 독립성 보호의 의도와 충돌하지 않지만, “확인 사실”의 상당 부분이 이번 심사에서는 자기보고가 된다. 외부 심사가 검증할 핵심 주장에는 허용된 패키지 안에서 확인 가능한 최소 근거가 필요하다.

## 6. 후보의 강점 중 실제로 유지할 것

다음은 효과가 입증됐다는 뜻이 아니라, 수정 과정에서 잃지 말아야 할 문서적·논리적 강점이다.

1. **주장 한계:** 외부 심사 전 후보이며 첫 구축이 실제 효과를 증명하지 않는다고 명시한다(§0; §10.6).
2. **활동량과 결과 분리:** 등록·사용·승인 수가 아니라 품질·비용·위험·최악 결과를 성공 조건으로 둔다(§3.3; §8.1).
3. **원근거와 파생물 분리:** AI 요약을 원근거와 같게 보지 않고 상관된 파생물을 증거 계열로 묶는다(§5).
4. **프로젝트 경계:** 원본은 전용이 기본이고 공유는 승인된 파생으로만 하며, 삭제 의무를 계보 완전성보다 우선한다(§5.2).
5. **모순·반례 보존:** 최신 답·다수결로 모순을 지우지 않고 경쟁 선례·보류·분기를 허용한다(§6.2).
6. **로컬 자율성과 연속성:** 중앙 자산이 native 자산을 덮지 않고 중앙 불능이 프로젝트 실행 불능이 되지 않게 한다(§4.2; §5.2).
7. **상태와 철회:** 후보·제한 시험·활성·중지·폐기 상태와 원근거 철회의 파급을 첫 논리 시험에 포함한다(§6.3; §10).
8. **거부를 유효 신호로 취급:** 프로젝트의 거부·변형을 자동 실패로 보지 않고 중앙 오검색·비용·맥락 실패와 구분한다(§6.5).
9. **변경 없음과 축소 허용:** 정기 교훈 생산을 의례화하지 않고, 목록·로컬·원사례 중심으로 축소하거나 전체 중단할 조건을 둔다(§6.6; §12).
10. **단계적 위험 제한:** 합성에서 시작해 실제 자료·실제 영향·Brain 연결·브랜드를 뒤로 미루고 각 단계의 비증명 범위를 적는다(§10–11).
11. **비용 범위:** 사람 시간·대기·토큰·현금·재작업·기회비용을 함께 보려 한다(§8.3).
12. **브랜드 지연:** 외부 표현을 후기 단계로 두고 정정·철회·오도 시 중단을 연결한다(§11–12).

이 강점들은 아래 수정 요구를 통과한 뒤에도 유지해야 하며, 그 존재만으로 운영 효과나 안전을 주장해서는 안 된다.

| T04 | 다른 프로젝트·미래·새 모델로 안전하게 전이되는가 | leave-one-context-out, 시간 전진, 모델·도구 교차, 무관·오래된 경험 대조 | IID에서만 이득, 무경험보다 해로움, 효과 방향 불안정 |
| T05 | 평가가 오염·답안 맞춤·평가자 편향이 아닌가 | 봉인 holdout, 의미·답 오염 감사, 독립 판정자, 표현·순서 교란 | 공개 fixture에서만 통과하거나 표현 변경에 판정이 뒤집힘 |
| T06 | 공통 지식의 오류가 격리·철회되는가 | 잘못된 항목·상관 실패·파생 복사를 심은 영향 추적·철회 훈련 | 사용처를 열거하지 못하거나 철회 뒤 구 판본이 사용됨 |
| T07 | 보안 경계가 실제 공격을 막는가 | 간접 인젝션·오염·secret·권한 외 읽기·쓰기·전송·공급망 공격 | 업무 허용도 밖의 권한 행동·유출이 한 번이라도 재현됨 |
| T08 | 진단과 프라이버시·IP 권리가 양립하는가 | 민감 canary, 재식별 공격, 삭제·접근·통지·라이선스 요청 추적 | 검증에 무권한 자료가 필수이거나 최소화 뒤 미검증을 숨김 |
| T09 | 인간 승인이 실제 안전장치인가 | 시간압박 속 정확·오류 권고, 직급별 거부·중단, 수동 복구·기술 유지 | 근거 없는 승인, 중단권 부재, 수동 능력 저하 |
| T10 | 참여가 정직하고 지속 가능한가 | 독립 사건 분모와 제출·종결·재발·보복·이탈·검토 노동을 역할별 추적 | 수량만 증가, 실패·낮은 지위 보고자 불이익, 유지자 소진 |
| T11 | 생애주기 순편익과 복원력이 유지되는가 | 검토·보안·재검증·철회·기회비용, 규모별 대기, 장애·export·restore·종료 | 총비용 역전, 단일 장애, 의미·권한 복원 실패, 인력 용량 초과 |
| T12 | 공동 브랜드가 적절한 신뢰를 만드는가 | 동일 품질에서 표시 유무를 비교하고 외부 사고·정정·철회·불만을 추적 | 검증 행동은 줄고 과신만 증가하거나 구성원 통제보다 평판 노출이 큼 |

첫 합성 시험은 T02의 “논리적 중복·철회 탐지” 일부와 T06의 합성 경로 일부만 다룰 수 있다. T01, T03–T05, T07–T12를 통과한 것으로 해석해서는 안 된다.

## 9. 공개 후 새 쟁점

아래는 후보를 본 뒤 구체적인 형태가 드러난 쟁점이다. 1단계 기준을 사후 수정하거나 후보가 이미 통과한 것으로 소급하지 않는다. 기존 기준과 관련되더라도 **후보 공개 후 발견한 구체적 시험 위험**으로 별도 기록한다.

| ID | 공개 후 새 쟁점 | 왜 새로 드러났는가 | 요구되는 처리 |
|---|---|---|---|
| N01 | 봉인 심사 패키지의 자기완결성 부족 | 후보가 금지된 일곱 내부 원문의 줄 인용을 핵심 근거로 사용한다(§0–2). | 이번 심사에서 그 주장은 자기보고로 유지하고, 다음 후보에는 독립 심사에 필요한 최소 증거와 반대 근거를 허용 패키지 안에 둔다. |
| N02 | 합성 oracle 누출과 사례별 하드코딩 | fixture와 기대 판정이 후보 안에서 함께 공개된다(§10.2 L502–513). | 구현 동결 후 공개되는 독립 봉인 fixture와 독립 판정자를 둔다. 공개 fixture 통과만으로 합격시키지 않는다. |
| N03 | Project Brain 경계 위험의 후기 발견 | 의미 어댑터가 7단계까지 미뤄져 중앙 핵심의 가정이 실제 Brain 책임과 맞지 않을 위험을 늦게 발견할 수 있다(§11 L567). | 실제 연결·규격을 정하지 않는 경계를 유지하되, 초기 합성 단계에서 양쪽 역할의 의미 충돌만 독립 fixture로 시험한다. |
| N04 | 예방 원칙의 “전체 공통” 우회 | 높은 위해와 가역성만으로 전체 공통 범위를 열 수 있는 예외 문구가 있다(§6.3 L347). | 검증된 자산과 임시 예방 중지를 분리하고, 예방 중지에 만료·범위·책임·재검증을 둔다. |
| N05 | 역할 분리와 사람 분리의 불일치 | 후보는 결정을 분리하지만 한 사람이 여러 역할을 맡을 수 있다고 한다(§4.3 L219). | 독립 심사가 필요한 고위험·브랜드·이의 사건에는 동일인의 겸임을 통과로 보지 않는 조건을 명시한다. |
| N06 | 정확히 한 자산인 첫 시험의 조합 사각지대 | 충돌·승인 피로·선택부담은 복수 자산과 복수 반례에서 생기지만 첫 범위는 자산 한 개다(§10.2 L509). | 첫 시험의 한계로 명시하고, 이를 단순성·확장성 증거로 쓰지 않는다. 복수 항목 시험은 별도 단계와 별도 합격조건으로 둔다. |

## 10. 최종 판정과 근거

### 10.1 최종 판정

**제한된 수정 후 첫 시험 준비 가능**

이 다섯 개 선택지 중 이 판정을 고른 이유는 다음과 같다.

1. 해시가 모두 일치했고 후보는 최종 설계·운영 효과를 자칭하지 않는다.
2. 확정된 치명적 탈락 조건은 0개다. 이는 안전성 입증이 아니라 첫 범위가 합성·비권한·비운영으로 제한됐기 때문이다.
3. 후보는 원근거–파생 분리, 증거 계열, 프로젝트 경계, 삭제 우선, 반례·거부 보존, 철회, 중앙 불능 시 로컬 지속, 단계적 축소를 일관되게 포함한다.
4. 24개 기준 중 완전 통과는 0개이고 23개는 검증 전 부분 통과다. R17 참여·심리적 안전·인센티브는 설계 수준에서 실패했다.
5. 31개 치명 조건 중 23개는 판단 불가다. 실제 자료·권한·효과·운영·브랜드 단계는 승인할 수 없다.
6. 첫 구축은 전체 핵심 가설을 반증하지 못하지만, 계보·권한·증거 중복·철회의 일부 논리적 선행조건을 낮은 위험으로 반증할 수 있다.
7. 다만 현재 시험은 답안 순환, 대안 비대칭, 보안·거버넌스 단계 관문 부재가 있어 그대로 준비해서는 안 된다.
8. 필요한 변경은 제품 전체 구조를 다시 쓰는 수준은 아니다. 첫 시험의 주장 범위, 독립 fixture, 대칭 비교, 단계 관문을 고치는 제한 수정으로 합성 시험의 판별력을 회복할 수 있다.

### 10.2 이 판정이 허용하지 않는 것

- 통합 후보 또는 중앙화의 승인
- 실제 오류 감소·품질·비용·전이·안전·브랜드 효과 주장
- 실제 고객·개인·비밀·프로젝트 자료 사용
- Project Brain 또는 실제 도구 연결
- 프로젝트 간 실제 전달
- 고위험·비가역 권한
- 외부 공개·인증·공동 브랜드
- 23개 판단 불가 치명 조건을 “문서에 원칙이 있다”는 이유로 해제

### 10.3 판정이 달라지는 조건

- D01–D04와 D12–D13을 반영하지 않거나 봉인 fixture 없이 기존 답안만 구현하려 하면 판정은 **중대한 수정 후 재심사**로 낮아진다.
- 합성 범위를 넘어 실제 자료·권한·영향을 넣으면서 관련 치명 관문을 해제하지 않으면 **기각** 또는 **설계 단계로 복귀** 사유가 된다.
- 반대로 제한 수정과 독립 시험 프로토콜이 확인되면, 이 문서는 첫 합성 시험의 결과를 보지 않고도 그 시험을 “준비 가능”으로만 판단할 수 있다. 통과 결과는 별도 심사 대상이다.

## 11. 다음 단계 진입 전 필수 조건

### 11.1 첫 합성 시험 준비 전

다음을 모두 충족해야 한다.

1. D01에 따라 첫 시험을 논리적 선행조건 시험으로 명확히 한정한다.
2. D02에 따라 구현자가 보지 못한 봉인 fixture와 독립 판정자를 지정하고 입력·답안의 해시를 구현 전에 별도로 동결한다.
3. D03에 따라 동일 정보·권한·사람 시간의 최소 목록, 프로젝트 로컬, 최소 계보 비교를 넣고 “새 공통 계층 없음”을 배제하지 않는다.
4. 합격·실패·중단·허용 수정 규칙과 주요 결과를 결과 관찰 전에 동결한다.
5. 권한 없는 전달, 상관 파생의 중복 집계, 반례 은폐, 철회 누락 각각에 독립 음성·적대 fixture를 둔다.
6. 악성 명령형 문구를 운영 지시로 해석하지 않는 합성 사례를 넣되 실제 외부 도구 권한은 부여하지 않는다.
7. 사람 능동시간·판정 불일치·대안별 복잡도를 기록한다. 기능 수나 테스트 통과 수를 가치로 쓰지 않는다.
8. D12에 따라 핵심 주장 유형과 자기보고 범위를 봉인 심사 패키지 안에서 식별 가능하게 만든다.
9. D13에 따라 임시 예방 중지와 검증된 전체 공통 자산을 구분한다.
10. 수정 후보의 새 SHA-256과 변경 목록을 동결하고, 수정이 사전 기준을 완화하지 않았는지 제한 재심사한다.

첫 합성 시험의 실행 환경은 합성 데이터, 격리, 네트워크·외부 전송·비가역 도구 권한 없음, 실제 프로젝트 영향 없음이어야 한다.

### 11.2 비식별 그림자 또는 실제 자료 단계 전

첫 합성 시험 통과만으로 진입할 수 없다. 추가로 다음이 필요하다.

1. R02·R04의 실제 문제 기준선, 독립 분모, 누락 감사
2. 관할별 데이터·IP·영업비밀·삭제·통지의 독립 검토
3. 재식별과 민감 canary를 포함한 프라이버시 시험
4. 간접 인젝션·오염·secret·권한 외 행동·공급망의 독립 보안 시험
5. 실질 독립 심사, 이해충돌, 이의·재심·보호 신고·구제 절차
6. R17 참여·보복·인센티브·검토 노동 측정 계획
7. 실제 생애주기 비용·인력 상한·중단 문턱의 사전 동결
8. export·restore·장애·종료 시험 계획
9. 관련 치명 조건 #2–#8, #12–#14, #18, #20–#23, #27–#31의 독립 재판정

### 11.3 실제 영향·모델 이주·Project Brain 연결 전

1. 전통 없음·원로그·정제 자산과 구조 대안을 같은 자원으로 비교한 전향 결과
2. 미래·미참여 맥락의 외부 검증과 부정적 전이·꼬리위험 결과
3. 봉인 holdout·오염 감사·반복 신뢰성
4. 실제 인간의 시간압박 속 오류 탐지·거부·중단과 수동 복구
5. 실제 철회·영향 추적·잔여 호출·의사결정 재심 훈련
6. 중앙 불능·공급자 변경·내보내기·복구 결과
7. 편익보다 총비용·유지 노동·탐색 손실이 작다는 증거

### 11.4 외부 브랜드 전

1. 정확한 주장 문구와 대상 버전·범위·기간·근거 수준
2. 외부 독립 표본 결과와 실패·폐기·정정 공개 원칙
3. 구성원 간 통제·감사권과 공동 평판·책임 노출의 일치
4. 심사 독립성·이해충돌·감시·정지·철회·불만·이의·구제의 실제 사례 시험
5. 브랜드 표시가 적절한 신뢰를 높이고 검증 행동을 줄이는 과신을 만들지 않는다는 결과
6. 치명 조건 #24–#26의 독립 재판정

## 12. 확인 범위와 미확인 범위

### 12.1 확인한 것

- 지정된 두 SHA-256과 실제 파일의 일치
- 동결된 1단계 보고서의 24개 기준과 31개 치명 조건
- v2 후보의 문서상 목적, 책임, 경계, 목표 구조, 단계, 첫 구축, 미결정, 중단 조건
- 후보 안의 각 주장과 결정이 어느 절·줄에 있는지
- 후보가 무엇을 효과로 주장하지 않는지
- 첫 합성 시험이 논리적으로 판별할 수 있는 것과 없는 것

### 12.2 확인하지 않은 것

- 후보가 인용한 CB, PH, R1, R2, DB, SU, GT 원문의 내용·해시·문맥
- Ultra·GPT-5.6 Thinking 원안, v1, 기존 심사, 목적·연구·브리프 원문
- 후보 작성 과정의 실제 모델·숨은 입력·대화·상호 노출·독립성
- 실제 구현, 스키마, 저장·검색·RAG·에이전트·Project Brain 통신
- 실제 조직의 오류 분모, 비용, 참여·보복, 권한·이해충돌, 사용자 피해
- 보안 침투, 프라이버시·재식별, 법률·IP, 공급망, 철회·복구 시험
- 실제 효과, 외부 전이, 모델 이주, 반복 신뢰성, 생애주기 비용, 브랜드 신뢰
- 조사 기준일 이후 변경된 외부 자료나 법·표준

### 12.3 최종 한계

이 심사는 후보가 좋은 문서인지 평가하는 문체 심사가 아니다. 동결된 기준에 비추어 **무엇이 이미 증명됐는지, 무엇이 계획일 뿐인지, 어떤 상태에서는 다음 단계로 가면 안 되는지**를 판정한다.

현재 증명된 것은 후보 문서의 해시 무결성, 위험 인식과 범위 제한, 그리고 합성 논리 시험으로 만들 수 있는 일부 판별 가능성이다. 실제 반복 오류 감소, 인간–AI 협업 향상, 중앙화의 순효과, 보안·권리·지속 가능성, 공동 브랜드 가치는 모두 미확인이다.
