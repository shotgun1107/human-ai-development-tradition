# 독립 외부 조사자 2단계 통합 후보 심사 프롬프트

1단계에서 네가 독립적으로 만든 조사 결과와 심사 기준을 먼저 고정한 상태에서, 이제 처음으로 중앙 인간–AI 개발 전통 시스템의 `v2 통합 후보`를 공개한다. 이번 역할은 새 설계 작성자가 아니라 **사전 동결 기준을 적용하는 외부 심사자**다.

## 1. 허용된 입력과 무결성

다음 파일만 순서대로 읽어라.

1. `independent-outsider/phase-1-research/independent-research-and-review-criteria.sha256`
2. `independent-outsider/phase-1-research/independent-research-and-review-criteria.md`
3. `docs/proposals/v2/central-tradition-system-v2-integrated-candidate.md`

먼저 SHA-256을 확인하라.

- 1단계 독립 보고서: `ba1ff2f2783f50038627e82afcfba21a27400161f64c90edc8498c8dfe244069`
- v2 통합 후보: `7f51e0cfba2f56f9427facb6436d829b7d274a989fa3e8a5b4167f602256afb0`

하나라도 다르면 심사를 시작하지 말고 불일치만 보고하라.

## 2. 독립성 규칙

- 위 세 파일 외의 저장소 문서와 파일을 열거나 검색하지 마라.
- Ultra·GPT-5.6 Thinking 원안, 기존 v1 설계, 이전 심사, 목적·연구·브리프 원문을 읽지 마라.
- 1단계 심사 기준과 치명적 탈락 조건을 통합 후보에 맞춰 수정·삭제·완화하지 마라.
- 통합 후보를 본 뒤 새로 발견한 쟁점은 제시할 수 있지만 반드시 `공개 후 새 쟁점`으로 분리하고, 사전 기준을 통과한 것처럼 소급하지 마라.
- 후보의 문서 길이, 기능 수, 문체, 자신감 또는 내부 일관성만으로 타당성을 인정하지 마라.
- 같은 전제를 반복한 문장이나 여러 AI의 합의를 독립 증거로 세지 마라.
- 필요한 경우 판정을 좌우하는 출처만 직접 재확인할 수 있다. 새 광범위 문헌조사나 새 설계 탐색은 하지 마라.

## 3. 심사 작업

1. 통합 후보가 주장하는 제품 목적, 중앙의 책임, 첫 구축 범위와 미결정 사항을 중립적으로 재구성한다.
2. 1단계의 24개 비보상형 심사 기준을 각각 `통과 / 부분 통과 / 실패 / 판단 불가 / 해당 없음`으로 판정하고 근거 위치를 적는다.
3. 31개 치명적 탈락 조건을 각각 확인하고, 하나라도 해당하면 다른 장점으로 상쇄하지 않는다.
4. 후보의 확인된 사실, 연구에서 가져온 주장, 설계 선택, 검증 전 가설이 실제로 분리됐는지 확인한다.
5. 중앙형·분산형·혼합형·최소 개입 대안이 공정하게 다뤄졌는지 확인한다.
6. 잘못된 경험의 확산, 음의 전이, 모델·도구 변화, 보안·프라이버시, 권한, 참여 유인, 운영비, 승인 부담, 공동 브랜드 위험을 점검한다.
7. 목표 제품과 첫 구축 범위가 분리됐는지, 첫 구축이 핵심 가설을 실제로 반증할 수 있는지 판정한다.
8. 문서만으로 해결할 문제와 실제 시험 전에는 해결할 수 없는 문제를 분리한다.
9. 수정 요구마다 대상 절, 이유, 필요한 변경, 변경 후 확인 방법을 적는다.
10. 후보를 대신하는 새 전체 설계는 작성하지 않는다.

## 4. 최종 산출물

결과는 다음 파일 하나에 작성하고 다른 파일은 수정하지 마라.

`independent-outsider/phase-2-review/integrated-candidate-independent-review.md`

문서는 다음 순서를 따른다.

1. 입력 해시와 독립성 확인
2. 후보의 중립적 요약
3. 24개 사전 심사 기준 판정표
4. 31개 치명적 탈락 조건 판정표
5. 치명적·중요·경미 문제
6. 후보의 강점 중 실제로 유지할 것
7. 문서 수정으로 해결할 항목
8. 실제 시험으로만 판단할 항목
9. 공개 후 새 쟁점
10. 최종 판정과 근거
11. 다음 단계 진입 전 필수 조건
12. 확인 범위와 미확인 범위

최종 판정은 다음 중 하나만 선택하라.

- 기각
- 설계 단계로 복귀
- 중대한 수정 후 재심사
- 제한된 수정 후 첫 시험 준비 가능
- 현재 상태로 첫 시험 준비 가능

구현·코드 작성·후보 원문 수정·Git 작업은 하지 마라. 칭찬을 채우지 말고, 후보를 살리기 위한 변호도 하지 마라. 근거가 없으면 `판단 불가`, 시험이 필요하면 `검증 전`이라고 써라.
